## 3. 只想尽快能开发？走这条三小时捷径

**只走一条数据流，别铺开**：

```
proto 里的 snapshot
  → RoomBattleService.Tick()            （服务端出快照）
  → NetSession 收到                      （客户端入口）
  → SnapshotView.Apply()                 （变成视图数据）
  → NetDebugWindow 里那一行文字           （先看文字，再看 3D）
```

把这条链读通，日常 80% 的改动（加字段、加规则、加提示）你都能自己下手。

## 5. 一页纸：两条链，一个接缝

| | 状态同步（大世界/副本） | 帧同步（PVP） |
|---|---|---|
| 客户端上行 | `PlayerInput` | `lockstep_input`（输入帧） |
| 服务端 | `RoomBattleService.Tick()` 推进权威世界 | `LockstepService.Tick()` 收集输入、广播帧 + `server_hash` |
| 下行 | `WorldSnapshot`（整份世界） | `LockstepFrame`（输入 + 服务端哈希） |
| 客户端 | `SnapshotView.Apply` | `LockstepClient` **自己 Step** 并与 `server_hash` 对账 |
| 表现层 | ← 同一个 `SnapshotView` → | ← 经 adapter 转成同一份 `WorldSnapshot` → |

**关键**：两条链**共用同一个表现层接缝**。理解这一点，就理解了"混合同步"在这个项目里怎么落地。
