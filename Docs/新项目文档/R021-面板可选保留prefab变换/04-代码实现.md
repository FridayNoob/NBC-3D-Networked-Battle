## 二、功能概述

面板根上挂 `KeepPrefabTransform` ⇒ `UIManager` 挂载时**只挂不改**，prefab 里摆的位置与尺寸原样保留；
没挂的面板照旧归零铺满（全屏面板行为不变）。

| `UIManager.AttachToLayer(instance, panelName, layer)` | 面板实例 / 名字 / 层 | 无 | 内部多一个 `if` |

## 四、逐段讲解

1. **为什么用标记组件而不是参数**：面板是被 `UIManager.ShowPanel("名字")` 按名字打开的，调用点分散；把开关写进 prefab，调用方一行都不用改。
2. **`SetParent(parent, false)` 绝不能动**：默认参数会让 Unity 为保持世界坐标反算 `localScale`，UI 会被拉伸变形 —— 这条原代码注释里就有，本次在注释里又强调一次。
3. **为什么「跳过」而不是「归零后还原」**：少写两次赋值，也不会中间态触发一次 UI 布局重建。
4. **锚点非拉伸的面板为什么必须归零**：`anchorMin == anchorMax` 时 `offsetMin/offsetMax = 0` 等价于 `sizeDelta = 0`，所以归零对这类面板是「位置+尺寸一起抹平」—— 这正是 `HpBarPanel` 现象的原因。

## 五、完整代码

### `Client/Assets/_Project/Framework.UI/KeepPrefabTransform.cs`（新增）

```csharp
// 这个文件里有：
//   KeepPrefabTransform（组件）：挂在面板根上，表示「这个面板保留 prefab 里摆好的位置与尺寸」。

using UnityEngine;

namespace NBC.Framework.UI
{
    // 主要功能：给 UIManager 一个开关 —— 见到这个组件就**不把面板的 RectTransform 归零**。
    // 主要数据成员：无（纯标记，没有字段也没有方法）。
    // 主要外部方法：无。
    // 谁在用它：UIManager.AttachToLayer 检查；HUD 类小面板（如 HpBarPanel）的 prefab 根上挂着它。
    // 注意：只有「固定在屏幕某处、不想铺满」的面板才挂；全屏面板别挂，否则会停在 prefab 摆的位置。
    [DisallowMultipleComponent]
    public sealed class KeepPrefabTransform : MonoBehaviour
    {
    }
}
```

### `Client/Assets/_Project/Framework.UI/UIManager.cs`（改 `AttachToLayer`）

```csharp
            rect.SetParent(parent, false);

            // 挂了 KeepPrefabTransform 的面板（HUD 小面板）保留 prefab 里摆好的位置与尺寸，不归零。
            if (instance.GetComponent<KeepPrefabTransform>() != null)
            {
                return;
            }

            rect.localPosition = Vector3.zero;
            rect.localScale = Vector3.one;
            rect.offsetMax = Vector2.zero;
            rect.offsetMin = Vector2.zero;
```

## 七、风险与幻觉自查

- 幻觉自查：只用 `MonoBehaviour`、`GetComponent<T>()`、`RectTransform`，既有 API。
- 编码中处理的点：
  1. 注释缩进是 10 空格（我第一版按 12 空格替换，没匹配上，已改正）；
  2. 两个入口（池中复活 `:276`、首次加载 `:813`）都经过 `AttachToLayer`，改一处两条生效（已核实）。

- 风险：以后有人给全屏面板误挂标记 ⇒ 它会停在 prefab 摆的位置（组件注释里已写明）。
