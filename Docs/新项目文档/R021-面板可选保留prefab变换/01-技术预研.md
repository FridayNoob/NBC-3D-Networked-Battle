# 01 技术预研

需求：R021-面板可选保留 prefab 变换
所属阶段：M4
作者：AI　状态：已确认（2026-11-06）

## 一、调研目标与约束

- 目标：让「HUD 类小面板」能**保留 prefab 里摆好的位置与尺寸**，不再被 `UIManager` 归零。
- 约束：
  1. **不改变现有面板行为**（默认仍然铺满/归零）；
  2. 只给显式挂了标记的面板开例外（opt-in）；
  3. 不动 `SetParent(parent, false)` 这条（它防的是 UI 被拉变形）。

## 二、现象与定位（已确认）

| 项 | 事实 |
| --- | --- |
| 现象 | Play 后 `HpBarPanel` 的 `anchoredPosition` / `sizeDelta` 与 prefab 不一致 |
| prefab 值 | anchorMin/Max `(0,1)`、pivot `(0,1)`、anchoredPosition `(125.6,-83.5)`、sizeDelta `(330,2)` |
| 运行后 | `anchoredPosition (0,0)`、`sizeDelta (0,0)`（因 `offsetMin/offsetMax = 0` 且锚点非拉伸） |
| 根因 | `UIManager.AttachToLayer` 挂载后强制归零：`localPosition=0 / localScale=1 / offsetMin=offsetMax=0` |
| 设计意图 | 全屏面板自动铺满；同时 `SetParent(parent,false)` 避免 Unity 反算 localScale 把 UI 拉变形 |

## 三、为什么不能直接删归零

| 若直接删掉 | 后果 |
| --- | --- |
| 全屏面板 | 会停在 prefab 摆的位置，不再铺满，多个面板会错位 |
| 现有 UI | 全部要重新在 prefab 里逐个调位置，回归面大 |

⇒ 必须是 **opt-in 开关**，默认行为一点不变。

## 四、方案对比

| 方案 | 做法 | 评价 |
| --- | --- | --- |
| **A（采用）** | 新增标记组件 `KeepPrefabTransform`；`AttachToLayer` 见到它就只 `SetParent(parent,false)`，不归零 | 改动 3 行 + 1 个 15 行组件；默认行为不变 |
| B | `UIManager.ShowPanel` 加一个 `bool keepTransform` 参数 | 调用点要全改，且面板打开方式分散在多处 |
| C | 改 prefab 锚点为 stretch，由子物体摆位 | 要重摆 UI，且 HUD 类面板仍被撑满 |

## 五、已知坑

1. **`SetParent(parent, false)` 必须保留**：只跳过归零，不能改成默认的 `SetParent(parent)`（那会反算 localScale，UI 被拉伸）。
2. **两个实例化路径**：`ShowPanel`（池中复活）与 `OnPanelLoaded`（首次加载）都要走到 `AttachToLayer`，改这里一处即可；需确认两条都调它。
3. **优先级/排序不受影响**：归零的是位置与尺寸，不是 sibling 顺序。
4. **响应式**：保留 prefab 变换后，屏幕分辨率变化时该面板**不会**自适应（HUD 固定尺寸是预期行为）。

## 六、结论与改动清单

结论：新增 `KeepPrefabTransform` 标记组件，`AttachToLayer` 见到它**只挂不改**；给 `HpBarPanel` prefab 挂上。

要改：
- 新增 `Framework.UI\KeepPrefabTransform.cs`
- 改 `Framework.UI\UIManager.cs`（`AttachToLayer` 一处分支）
- `HpBarPanel.prefab` 挂标记组件
