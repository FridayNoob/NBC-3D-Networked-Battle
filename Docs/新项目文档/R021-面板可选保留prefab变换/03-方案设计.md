# 03 方案设计

需求：R021-面板可选保留 prefab 变换
所属阶段：M4
作者：AI 起草　状态：已确认（2026-11-06）

## 一、整体架构

```
UIManager.ShowPanel / OnPanelLoaded
        └─ AttachToLayer(instance, name, layer)
              ├─ rect.SetParent(parent, false)          ← 两条路径都保留（防拉变形）
              └─ if (挂了 KeepPrefabTransform) 跳过归零  ← 新增分支
                 else 归零 localPosition / localScale / offsetMin / offsetMax（原行为）
```

## 二、模块划分

| 模块 | 本次改动 | 不负责什么 |
| --- | --- | --- |
| 新增 `Framework.UI\KeepPrefabTransform` | 一个空标记组件（15 行） | 不做任何逻辑 |
| `Framework.UI\UIManager`（改） | `AttachToLayer` 里加一个 `if`，见到标记就不归零 | 不改 `SetParent` 参数、不改其它流程 |
| `HpBarPanel.prefab`（改） | 根上挂标记组件 | 不改它的布局与子物体 |

## 三、接口（★ 先定死）

```
Framework.UI.KeepPrefabTransform : MonoBehaviour    // 无字段、无方法，纯标记
    [DisallowMultipleComponent]

UIManager.AttachToLayer(...)：
    bool keep = instance.GetComponent<KeepPrefabTransform>() != null;
    rect.SetParent(parent, false);        // 始终执行
    if (!keep)
    {
        rect.localPosition = Vector3.zero;
        rect.localScale = Vector3.one;
        rect.offsetMax = Vector2.zero;
        rect.offsetMin = Vector2.zero;
    }
```

## 四、数据结构

无（一个空组件）。

## 五、时序与流程

1. 面板加载/池中取出 ⇒ `AttachToLayer`。
2. `SetParent(parent, false)`：保持 local 值，世界位置由父节点决定，**不反算 scale**。
3. 有标记 ⇒ 到此为止，prefab 的 anchoredPosition / sizeDelta 原样保留。
4. 无标记 ⇒ 照旧归零（铺满所在层）。
5. `HpBarPanel` 挂标记后，Play 时它的 `anchoredPosition`/`sizeDelta` 与 prefab 一致。

## 六、技术选型与理由

| 选择 | 选定 | 理由 | 被否的方案 |
| --- | --- | --- | --- |
| 开关形式 | **标记组件** | 面板 prefab 自带声明，打开它的代码一行不用改 | `ShowPanel` 加 bool 参数（调用点分散，要全改） |
| 归零策略 | **跳过归零**（不是「归零后还原」） | 少写两次赋值，也不会因中间态触发 UI 布局重建 | 归零后立刻写回原值（多一次 layout dirty） |
| 默认值 | **不挂标记 = 旧行为** | 零回归风险 | 默认保留（所有面板都要重调） |

## 七、风险与对策

- **回归风险**：改的是所有面板的挂载入口。对策：未挂标记的面板走原路径（代码结构上是 `if (!keep)` 包住原四行），并回归 `NetHudPanel` / `QuestPanel` 打开正常。
- **池化复活路径**：`AttachToLayer` 有两个调用点（`:276` 池中复活、`:813` 首次加载），都经过同一函数 ⇒ 一处改完两条生效。
- **反算 scale**：`SetParent(parent, false)` 必须保留；若误改成默认参数，UI 会被拉伸（这条写进注释）。
- **分辨率变化**：保留变换的 HUD 不随分辨率重排，这是预期（固定尺寸 HUD）。
- **面板根不是 RectTransform**：原代码已抛异常，本次不动。
