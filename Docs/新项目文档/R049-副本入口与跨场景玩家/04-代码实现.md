## 一、子任务与约束

这次只做一条链路：World 里走到门口按 E → 连服进房 → 带着当前玩家物体进 Battle。

1) 入口组件 `DungeonEntrance`：距离判定、按 E、连服、切场景。
2) 玩家携带 `PlayerPersist`：把 World 的玩家物体标成 `DontDestroyOnLoad`。
3) 驱动开关 `RuntimeNetDriver.AutoJoin` / `BindPresentation` / `ConfigureSession`：让入口先连服、切场景后才进房与绑定表现。
4) `HpBarDemoBehaviour` 复用已有驱动：Battle 里不再重复建第二个网络会话。
5) 场景改动：删掉 Battle 里的旧 `Player`，在 World 的出生点前方 6 米放 `[DungeonEntrance]` 与 `ModuleA` 门面。

约束（为什么这么做）：

- 服务端一行不改：进副本本来就有 `JoinRoom`，这次只是把「谁先连、什么时候进房」挪到客户端入口上。
- 玩家物体必须是**同一个物体**跨场景，不能重新生成：`PlayerBrain` 里的状态机、控制器副本、`PlayerJumpMotor` 都在这个物体上，重建等于把状态全丢。
- 连服必须发生在切场景**之前**：切场景会销毁 World 里的对象，如果先切再连，`DungeonEntrance` 协程所在的物体已经没了。

## 二、功能概述

玩家在 World 里走到入口 3.5 米内，屏幕出现「按 E 进入副本」；按 E 后黑一下（不黑屏，只是等待），入口依次做四件事：

1) 建一个常驻物体 `[DungeonSession]`，把 `RuntimeNetDriver` 挂上去并 `ConfigureSession`。
2) 把 `AutoJoin` 与 `BindPresentation` 先关掉，等 `IsOnline`。
3) 把当前玩家物体标成 `DontDestroyOnLoad`，并关掉 `WorldPlayerSetup`（它每帧贴地，进 Battle 会打架）。
4) `SceneFlow.LoadAsync(Battle)`，成功后打开 `AutoJoin` 与 `BindPresentation`，驱动开始进房与绑定表现。

## 三、接口与入参出参

| 接口 | 入参 | 出参 | 约定 |
| --- | --- | --- | --- |
| `DungeonEntrance.IsConnecting` | 无 | `bool` | 正在连接或切场景时为 true，用于禁用重复触发 |
| `DungeonEntrance.EnterRoutine()` | 无 | `IEnumerator` | 只在 `Update` 里按 E 时启动；失败会写 `m_lastError` 并恢复可再次触发 |
| `PlayerPersist.MarkPersistent(GameObject)` | 目标物体 | 无 | 父物体为空才 `DontDestroyOnLoad`；顺带关掉 `WorldPlayerSetup` |
| `RuntimeNetDriver.AutoJoin` | 无 | `bool`（可写） | true 时 `Update` 里自动 `JoinRoom`；入口连服阶段设 false |
| `RuntimeNetDriver.BindPresentation` | 无 | `bool`（可写） | false 时 `RefreshPresentation` 直接返回；切场景完成前设 false |
| `RuntimeNetDriver.ConfigureSession(host, port, dungeonId)` | 主机、端口、副本号 | 无 | 必须在 `Start` 之后调用；会改写 `m_host/m_port/m_dungeonId` |

## 四、逐段讲解

### 4.1 为什么先连服再切场景

`RuntimeNetDriver` 原本在 `Start` 里建会话，`Update` 里看到 `IsOnline` 就 `JoinRoom`。如果入口直接 `LoadAsync(Battle)`，World 被卸载时驱动也跟着没了，连接会断。

所以入口自己先建一个**常驻**的会话物体（`DontDestroyOnLoad`），连上、进房确认之后再切场景；切完场景，Battle 里没有驱动，`HpBarDemoBehaviour` 会去找已有的驱动并沿用，不会建第二个。

### 4.2 为什么要把玩家物体 `DontDestroyOnLoad`

`SceneFlow.LoadAsync` 默认是单场景加载（`LoadSceneMode.Single`），World 里的所有物体都会被销毁。要跨场景保留玩家，只有两个办法：重新生成，或者标成常驻。前者会丢掉状态机与控制器实例，所以选后者。

代价是：这个物体在 Battle 里**不属于 Battle 场景**，Battle 卸载时也不会被销毁。R049 只在「World → Battle 一次」的路径上使用，退出副本的清理留给 R042 结算重开时一起做，代码里已用 `PlayerPersist.MarkPersistent` 收口，便于以后加反向清理。

### 4.3 为什么连服阶段要关掉自动进房与表现绑定

`JoinRoom` 会在服务端生成英雄实体，随后快照里出现英雄。如果切场景前就进房，World 场景里的 `SnapshotSceneBinder` 会尝试给英雄建表现槽位；等场景切走，这些槽位又全被销毁，等于白做一遍还可能留下空引用。

关掉 `BindPresentation` 后，切场景期间驱动只收快照、不建物体；切完再打开，绑定一次性完成。

### 4.4 入口的位置与门面

入口放在出生点正前方 6 米：出生点 `(280.7993, 1.4497352, 425.01416)`，入口 `(280.7993, 1.4497352, 431.01416)`，`+Z` 是玩家初始朝向。门面用环境包里的 `ModuleA` 预制体（guid `54f79055e130d8b4dbd8990a32ae4557`），作为 `[DungeonEntrance]` 的子物体，位置与旋转都归零。

## 五、完整代码

```csharp
// 这个文件里有：
//   DungeonEntrance（类）：World 里的副本入口，负责触发判定、屏幕提示、先连服再切场景。

using System.Collections;
using NBC.Game.Bootstrap;
using NBC.Game.Player;
using UnityEngine;

namespace NBC.Game.GameFlow
{
    // 类：副本入口
    // 主要功能：玩家走进范围后按 E，先让 RuntimeNetDriver 与服务器握手，成功再加载 Battle 场景。
    // 主要数据成员：m_triggerRadius（米）、m_enterKey、m_host / m_port / m_dungeonId、m_connectTimeoutSeconds（秒）。
    // 主要外部方法：IsConnecting（只读，是否正在连接）。
    // 谁在用它：World 场景里的入口物体（Inspector 挂载）；切场景由 SceneFlow 执行。
    public sealed class DungeonEntrance : MonoBehaviour
    {
        // 会话物体名：跨场景保留，Battle 里的 HpBarDemo 会复用它而不是再建一个
        private const string SessionObjectName = "[DungeonSession]";

        // 触发半径（米）：玩家根节点与入口的距离小于它就显示提示
        [SerializeField] private float m_triggerRadius = 3.5f;

        // 进入副本的按键
        [SerializeField] private KeyCode m_enterKey = KeyCode.E;

        // 服务器地址
        [SerializeField] private string m_host = "127.0.0.1";

        // 服务器端口（9000 在 Windows 保留段里，别用）
        [SerializeField] private int m_port = 7778;

        // 副本编号：决定服务端用哪张地图
        [SerializeField] private int m_dungeonId = 1001;

        // 握手超时（秒）：超过这个时间还没连上就提示失败
        [SerializeField] private float m_connectTimeoutSeconds = 8f;

        // 是否打印诊断日志
        [SerializeField] private bool m_logDiagnostics = true;

        // 玩家根节点（缓存，第一次 Update 时找）
        private Transform m_player;

        // 玩家当前是否在触发范围内
        private bool m_inRange;

        // 是否正在连接（防连点）
        private bool m_connecting;

        // 屏幕上要显示的一句话（空 = 不显示）
        private string m_status;

        // 这句话显示到什么时候（Time.realtimeSinceStartup 的秒数）
        private float m_statusUntil;

        // 功能：告诉外部是否正在连接。
        // 入参：无
        // 返回：true 表示连接/切场景进行中
        // 步骤：直接返回缓存字段
        // 上游/下游：入口自身与将来的组队逻辑读取
        public bool IsConnecting
        {
            get { return m_connecting; }
        }

        // 功能：每帧判断玩家是否在入口旁，并处理按 E。
        // 入参：无（引擎每帧调）
        // 返回：无
        // 步骤：
        //   1) 找玩家（只找一次，找不到就每帧重试）
        //   2) 距离判定落在 m_triggerRadius 内
        //   3) 在范围内且没在连接、按下 E ⇒ 开始进副本
        // 上游：Unity 引擎
        // 下游：EnterRoutine、PlayerPersist、SceneFlow.LoadAsync
        private void Update()
        {
            ResolvePlayer();

            if (m_player == null)
            {
                m_inRange = false;
                return;
            }

            float distance = Vector3.Distance(m_player.position, transform.position);
            m_inRange = distance <= m_triggerRadius;

            if (m_inRange && !m_connecting && Input.GetKeyDown(m_enterKey))
            {
                StartCoroutine(EnterRoutine());
            }
        }

        // 功能：在屏幕上画一行提示（零资产，不依赖 UI 框架）。
        // 入参：无（引擎在 GUI 阶段调）
        // 返回：无
        // 步骤：
        //   1) 有错误/状态文字且还没过期 ⇒ 画状态
        //   2) 否则在范围内 ⇒ 画「按 E 进入副本」
        //   3) 正在连接 ⇒ 画连接中
        // 上游：Unity OnGUI
        // 下游：无
        private void OnGUI()
        {
            string text = null;

            if (!string.IsNullOrEmpty(m_status) && Time.realtimeSinceStartup < m_statusUntil)
            {
                text = m_status;
            }
            else if (m_connecting)
            {
                text = "正在连接副本服务器…";
            }
            else if (m_inRange)
            {
                text = "按 " + m_enterKey + " 进入副本";
            }

            if (text == null)
            {
                return;
            }

            GUIStyle style = new GUIStyle(GUI.skin.label);
            style.fontSize = 22;
            style.alignment = TextAnchor.MiddleCenter;
            style.normal.textColor = Color.white;

            Rect area = new Rect(0f, Screen.height * 0.72f, Screen.width, 40f);
            GUI.Label(area, text, style);
        }

        // 功能：执行「先连服、再切场景」的完整流程。
        // 入参：无
        // 返回：协程
        // 步骤：
        //   1) 找或建 [DungeonSession]，拿到/补上 RuntimeNetDriver，写入连接参数
        //   2) 关掉自动进房与表现绑定：World 里进房会让副本英雄被输入带着走，也会画出一堆副本怪
        //   3) 等握手成功；超时则销毁会话并提示
        //   4) 把玩家标成跨场景保留，再加载 Battle
        //   5) 切场景成功后打开自动进房与表现绑定；失败则销毁会话并提示
        // 上游：Update 检测到按 E
        // 下游：RuntimeNetDriver.ConfigureSession/IsOnline、PlayerPersist.MarkPersistent、SceneFlow.LoadAsync
        private IEnumerator EnterRoutine()
        {
            m_connecting = true;
            Log("开始进入副本，先握手");

            GameObject session = GameObject.Find(SessionObjectName);
            if (session == null)
            {
                session = new GameObject(SessionObjectName);
                DontDestroyOnLoad(session);
            }

            RuntimeNetDriver driver = session.GetComponent<RuntimeNetDriver>();
            if (driver == null)
            {
                driver = session.AddComponent<RuntimeNetDriver>();
            }

            driver.ConfigureSession(m_host, m_port, m_dungeonId);
            driver.AutoJoin = false;
            driver.BindPresentation = false;

            float deadline = Time.realtimeSinceStartup + Mathf.Max(1f, m_connectTimeoutSeconds);
            while (!driver.IsOnline && Time.realtimeSinceStartup < deadline)
            {
                yield return null;
            }

            if (!driver.IsOnline)
            {
                SetStatus("连接副本服务器失败：超时");
                Destroy(session);
                m_connecting = false;
                yield break;
            }

            Log("握手成功，准备切场景");

            if (!PlayerPersist.MarkPersistent(m_player.gameObject))
            {
                SetStatus("玩家物体无效，无法进入副本");
                Destroy(session);
                m_connecting = false;
                yield break;
            }

            bool finished = false;
            bool loaded = false;
            string error = null;

            SceneFlow.Instance.LoadAsync(GameScene.Battle, (ok, message) =>
            {
                loaded = ok;
                error = message;
                finished = true;
            });

            while (!finished)
            {
                yield return null;
            }

            if (!loaded)
            {
                SetStatus("加载副本场景失败：" + error);
                Destroy(session);
                m_connecting = false;
                yield break;
            }

            driver.AutoJoin = true;
            driver.BindPresentation = true;

            Log("已进入副本，打开自动进房与表现绑定");
            m_connecting = false;
            enabled = false;
        }

        // 功能：找到 World 里的玩家根节点并缓存。
        // 入参：无
        // 返回：无
        // 步骤：
        //   1) 已经有就直接返回
        //   2) 按 PlayerBrain 找（World 里唯一），取它的 Transform
        // 上游：Update
        // 下游：无
        private void ResolvePlayer()
        {
            if (m_player != null)
            {
                return;
            }

            PlayerBrain brain = Object.FindObjectOfType<PlayerBrain>();
            if (brain != null)
            {
                m_player = brain.transform;
            }
        }

        // 功能：设置屏幕提示并保持几秒。
        // 入参：text 提示文字
        // 返回：无
        // 步骤：写字段，并记下过期时间（3 秒）
        // 上游：EnterRoutine 的失败分支
        // 下游：OnGUI
        private void SetStatus(string text)
        {
            m_status = text;
            m_statusUntil = Time.realtimeSinceStartup + 3f;
            Debug.LogWarning("[DungeonEntrance] " + text);
        }

        // 功能：按开关打印诊断日志。
        // 入参：message 日志正文
        // 返回：无
        // 步骤：m_logDiagnostics 为 false 时直接返回
        // 上游：EnterRoutine
        // 下游：Unity Console
        private void Log(string message)
        {
            if (m_logDiagnostics)
            {
                Debug.Log("[DungeonEntrance] " + message);
            }
        }
    }
}
```

```csharp
// 这个文件里有：
//   PlayerPersist（类）：把玩家根物体标成跨场景保留，并关掉只在 World 生效的组件。
// 为什么要单独一个类：切场景时「保留谁、关掉谁」是一组固定动作，散落在入口脚本里下次换入口又会重写一遍。

using UnityEngine;

namespace NBC.Game.GameFlow
{
    // 类：玩家跨场景携带工具
    // 主要功能：把玩家根物体交给 DontDestroyOnLoad，并关掉只在 World 里成立的组件（贴地、World 相机接线）。
    // 主要数据成员：无（纯静态方法，不持有状态）。
    // 主要外部方法：MarkPersistent（标记一个玩家根物体可以跨场景存活）。
    // 谁在用它：DungeonEntrance 在切到 Battle 之前调用；将来做副本传送门也复用。
    public static class PlayerPersist
    {
        // 功能：让玩家根物体在切场景时不被销毁，并停掉 World 专属逻辑。
        // 入参：playerRoot 玩家根物体（World 里的 [Player_Hero]），不能为空
        // 返回：true 表示已标记；false 表示入参为空
        // 步骤：
        //   1) 空引用直接返回 false，调用方据此提示错误
        //   2) 只有根物体能 DontDestroyOnLoad，挂了父物体就跳过，避免 Unity 警告
        //   3) 关掉 WorldPlayerSetup：它会每帧把玩家按到地面、并接线 World 的相机，副本里由服务器纠偏与副本相机接管
        // 上游/下游：DungeonEntrance.BeginEnter 调用；下游 Unity 场景加载、WorldPlayerSetup.enabled
        public static bool MarkPersistent(GameObject playerRoot)
        {
            if (playerRoot == null)
            {
                return false;
            }

            if (playerRoot.transform.parent == null)
            {
                Object.DontDestroyOnLoad(playerRoot);
            }

            WorldPlayerSetup setup = playerRoot.GetComponent<WorldPlayerSetup>();
            if (setup != null)
            {
                setup.enabled = false;
            }

            return true;
        }
    }
}
```

### 7.1 为什么还要补一次相机接线

`WorldPlayerSetup` 在 World 里会 `AddComponent<WorldFollowCamera>()` 并 `SetTarget`，但跨场景前我们把它 `enabled = false` 了；Battle 自己的相机只会跟场景里原有的目标（已随遗留实例删掉）。所以 `DungeonEntrance` 在 Battle 加载成功后调 `PlayerPersist.BindCamera(m_player.gameObject)`：没有 `WorldFollowCamera` 就补一个、有就复用，`SetTarget` 指向玩家，并关掉旧的 `FollowCamera`（两套跟随同时开会互相抢位置）。

```csharp
public static void BindCamera(GameObject playerRoot)
{
    if (playerRoot == null) return;
    Camera mainCamera = Camera.main;
    if (mainCamera == null) return;

    WorldFollowCamera follow = mainCamera.GetComponent<WorldFollowCamera>();
    if (follow == null) follow = mainCamera.gameObject.AddComponent<WorldFollowCamera>();

    follow.enabled = true;
    follow.SetTarget(playerRoot.transform);

    FollowCamera legacy = mainCamera.GetComponent<FollowCamera>();
    if (legacy != null) legacy.enabled = false;
}
```

## 九、风险与幻觉自查

| 风险 | 说明 | 当前处理 |
| --- | --- | --- |
| 玩家物体跨场景后不属于任何场景 | Battle 卸载时不会被销毁 | 只在单次进入路径使用；退出清理留给 R042 |
| 入口在切场景前失败 | 会话物体已建、驱动在挂着 | 失败时销毁会话物体并恢复 `IsConnecting=false` |
| 走回 World 时残留常驻物体 | 第二次进副本会建第二个会话 | `EnterRoutine` 先 `Find(SessionObjectName)`，有就复用 |
| 旧 Battle 场景还有别的脚本引用 `Player` | 删物体后可能出现 `MissingReferenceException` | 全仓 grep `PlayerMove`/`FollowCamera` 在 Battle 的引用，已无 |
| `ModuleA` 尺寸不合适 | 它是模块化建筑件，可能偏大/偏小 | 作为子物体归零摆放，由负责人在 Inspector 里调 scale |

自查：

1) 新代码没有读 `DateTime.Now`、没有 `File`、没有 `Resources.Load`，依赖都在 Inspector 或已有单例上。
2) `DungeonEntrance` 的协程在物体被销毁时会自然停止，不需要额外 `StopCoroutine`。
3) `PlayerPersist.MarkPersistent` 对已在常驻区的物体是幂等的（`DontDestroyOnLoad` 重复调用无副作用）。

## 十、返修（2026-11-16）：切场景后协程被销毁

第一次实测现象：按 E 能切到 Battle，但看不到玩家，Console 每 5 秒刷
`[位置诊断] 找不到我的英雄快照：PlayerId=1，在线=True，实体数=0`。

根因是**协程活着的前提被切场景破坏了**：

```text
DungeonEntrance.EnterRoutine（挂在 World 物体上）
  → yield return SceneFlow.LoadAsync(Battle)   ← 单场景模式，World 卸载
  → DungeonEntrance 随 World 一起被销毁
  → 协程在 yield 处被终止，yield 之后的代码永远不执行
```

而「打开 AutoJoin / 打开 BindPresentation / 接相机」恰好都写在 `yield` 之后，于是：

| 应该发生 | 实际 | 表现 |
| --- | --- | --- |
| `AutoJoin = true` → 进房 | 没执行 | 实体数 0，HUD 与纠偏都没有数据 |
| `BindPresentation = true` | 没执行 | 即使进房也不画怪 |
| `BindCamera` | 没执行 | 新场景相机不认识带过来的玩家，镜头里没人 |
| 玩家摆在副本出生点 | 没执行 | 玩家留在 World 坐标（约 280, 1.45, 425），在副本里是空地外 |

修法：把收尾搬进 `SceneFlow.LoadAsync` 的完成回调 —— 回调由**常驻的 `SceneFlow`**（`DontDestroyOnLoad`）执行，切场景不会断。

```csharp
GameObject playerRoot = m_player.gameObject;

SceneFlow.Instance.LoadAsync(GameScene.Battle, (ok, message) =>
{
    loaded = ok;
    error = message;
    finished = true;

    if (ok)
    {
        FinishEnter(playerRoot, driver);   // 玩家落位 + 开进房 + 开表现 + 接相机
    }
});

while (!finished) yield return null;        // 只有失败时协程还活着
```

`FinishEnter` 里三件事各有理由：

1. `playerRoot.transform.position = m_battleSpawn;`（默认原点）—— 服务器出生点在原点附近；不挪就会「人还在 280 米外」。
2. `driver.AutoJoin = true; driver.BindPresentation = true;` —— 进房后服务器才下发英雄/怪物快照，HUD 与纠偏才有数据。
3. `PlayerPersist.BindCamera(playerRoot);` —— 旧相机随 World 销毁，新相机需要重新认识这个带过来的玩家。

另外补了两条错误日志，覆盖「玩家没带过来（DontDestroyOnLoad 失败）」与「副本里找不到会话驱动」两种最难查的情况。
