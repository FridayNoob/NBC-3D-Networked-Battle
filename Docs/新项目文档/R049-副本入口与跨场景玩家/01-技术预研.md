# R049 副本入口与跨场景玩家 —— 01 技术预研

需求编号：R049
所属阶段：M4
作者：AI 辅助
状态：开发中

## 1. 调研目标与约束

目标：World 场景里有一个可见入口，玩家走过去按提示就能进 Battle（副本）；进副本时**身上这套玩家物体跟着过去**（模型、控制器、相机、状态机都还在）；Battle 场景自带的旧玩家物体删除。

约束：

- 服务端不改协议：进副本仍然走 `RuntimeNetDriver` 现有的「连服 → JoinRoom → 收快照」。
- 复用 `SceneFlow` 与 `GameScene` 枚举，不新写加载器。
- 只动客户端场景与少量脚本；Battle 的服务器权威逻辑（怪物、伤害、判定）一律不碰。
- 一次性把 World → Battle 的路走通，Battle → World 的返回沿用 R041 的退出逻辑。

## 3. 最小可运行示例

```csharp
// 入口脚本（挂在触发器上）：按 E 进副本
if (Input.GetKeyDown(KeyCode.E) && m_playerInRange)
{
    DontDestroyOnLoad(m_playerRoot);              // 1) 玩家物体跨场景存活
    SceneFlow.Instance.LoadAsync(GameScene.Battle, (ok, err) =>
    {
        if (!ok) Debug.LogError("[副本入口] 切场景失败：" + err);
    });                                            // 2) 切场景
}
```

Battle 侧：`RuntimeNetDriver` 连服后由 `SnapshotSceneBinder` 负责怪物与其它玩家；本地英雄就是被带过来的这个物体，`RuntimeNetDriver.ReconcileHeroPosition` 每帧按快照纠偏。

## 4. 方案对比

| 决策点 | 方案 A | 方案 B | 方案 C |
| --- | --- | --- | --- |
| 入口形式 | 触发器 + 屏幕提示「按 E 进入副本」 | 走进区域自动切场景 | 场景里放 NPC，对话后进入 |
| 优点 | 不会误触、可取消、可加等级/条件判断 | 零操作 | 有剧情表现力 |
| 缺点 | 多一个按键与提示 UI | 走过去就切，容易误触；想取消得走开 | 要做对话系统，成本最高 |
| 玩家携带 | `DontDestroyOnLoad` 直接带过去 | 切场景后按预制体重新生成 | 只带数据（位置/血量/装备），物体重建 |
| 优点 | 模型/控制器/相机/状态机原样保留，改动最小 | 场景干净，Battle 不依赖 World 的物体 | 最干净，但需要序列化一套玩家数据 |
| 缺点 | Battle 里要处理「World 的贴地/环境逻辑不该跑」 | 要维护一份玩家预制体 + 重新绑定相机与输入 | 工作量大，等于做存档 |
| 连服时机 | 入口处先连服 + 进房，成功后再切场景 | 保留 Battle 的 `HpBarDemo` 自动连服 | 切过去再连，失败时人在 Battle 里干等 |

## 5. 已知坑与版本兼容

1. **两个 AudioListener**：Battle 自带 `Main Camera`，被带过去的玩家相机也有 ⇒ 进副本必须关掉一方（保留玩家相机、关 Battle 的）。
2. **Battle 自带旧玩家**：`Battle.unity` 里有个 `m_IsActive: 0` 的 `Player`（`PlayerMove` + `FollowCamera` + `CapsuleCollider`），必须删，否则会和带过去的玩家抢输入/相机。
3. **`HpBarDemo` 会自动加 `RuntimeNetDriver`**：如果入口处已经连服，Battle 里会再挂一个驱动 ⇒ 双连接。要决定「谁负责连服」。
4. **World 的环境叠加**：`WorldEnvLoader` 只在 World 生效；切到 Battle 时 additive 的环境场景要确认被卸载，否则两套天空盒/地形叠着。
5. **`WorldPlayerSetup` 的贴地射线**：它在 World 里每帧把玩家按到地面，进 Battle 后地面/地形不同，可能和 `PlayerJumpMotor` 抢 y。
6. **`PlayerDeathFlow` 的分流**：它按 `SceneManager.GetActiveScene().name` 判断 World / 副本，Battle 里应走「退出副本」分支，要先确认名字匹配。
7. **`SnapshotSceneBinder` 会给本地英雄建槽位**：它用 `ownerPlayerId` 跳过「我的英雄」，被带过去的物体必须能对上这个编号，否则会出现两个自己。

## 6. 结论

推荐组合：**入口 = 触发器 + 按 E 提示（A）**、**玩家 = `DontDestroyOnLoad` 携带（A）**、**连服 = 入口处先连服再切场景（A，`HpBarDemo` 改为兜底或删除）**。

理由：改动集中在「一个入口脚本 + 一个携带脚本 + Battle 场景清理」，不改服务端、不动协议，也不引入玩家数据序列化；代价是要处理 6 条场景冲突，都能用「进 Battle 时关掉 World 专属组件」一次性解决。

预估代码量约 260 行：`DungeonEntrance.cs`（触发器 + 提示 + 连接 + 切场景，约 150 行）、`PlayerPersist.cs`（跨场景携带 + 进 Battle 后关 World 专属组件，约 80 行）、`HpBarDemoBehaviour` 适配（约 30 行）。
