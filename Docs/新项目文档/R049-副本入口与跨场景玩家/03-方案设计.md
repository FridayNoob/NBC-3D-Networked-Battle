# R049 副本入口与跨场景玩家 —— 03 方案设计

需求编号：R049
所属阶段：M4
作者：AI 辅助
状态：开发中

## 1. 整体架构

```
World：玩家走到入口
  DungeonEntrance（触发器判定 + 屏幕提示 + 按 E）
        │ 1) 找/建 [DungeonSession]（DontDestroyOnLoad）
        │ 2) AddComponent<RuntimeNetDriver>，配 host/port/dungeonId，AutoJoin=false
        │ 3) 等 IsOnline（握手完成）或超时
        │ 4) 标记玩家 DontDestroyOnLoad
        ▼
  SceneFlow.LoadAsync(Battle)
        ▼
Battle：RuntimeNetDriver 已存在 → HpBarDemo 不再重复创建
        │ AutoJoin=true → JoinRoom → 收快照 → SnapshotSceneBinder
        ▼
  本地英雄 = 被带过来的 [Player_Hero]；位置由 ReconcileHeroPosition 纠偏
```

## 2. 模块划分

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| `DungeonEntrance`（新） | 触发判定、屏幕提示、发起连接、等握手、切场景、失败提示 | 不进房、不画怪物、不管战斗 |
| `PlayerPersist`（新，静态工具） | 把玩家根物体标成跨场景保留、关掉 World 专属组件 | 不重建玩家、不管相机 |
| `RuntimeNetDriver`（改） | 新增 `AutoJoin` / `BindPresentation` 两个开关，允许「先连后进房」 | 不改协议、不改重连 |
| `HpBarDemoBehaviour`（改） | 只在场景里没有驱动时才 `AddComponent` | 不再决定连服时机 |
| `Battle.unity`（改） | 删掉旧 `Player` 物体 | 不动怪物/地形/相机 |

## 3. 接口

```csharp
public sealed class DungeonEntrance : MonoBehaviour
{
    // 触发半径（米），玩家根节点进入这个球就算「在入口旁」
    [SerializeField] private float m_triggerRadius = 3.5f;
    // 进入副本的按键
    [SerializeField] private KeyCode m_enterKey = KeyCode.E;
    // 服务器地址与副本编号
    [SerializeField] private string m_host = "127.0.0.1";
    [SerializeField] private int m_port = 7778;
    [SerializeField] private int m_dungeonId = 1;
    // 握手超时（秒）
    [SerializeField] private float m_connectTimeoutSeconds = 8f;
    [SerializeField] private bool m_logDiagnostics = true;

    // 当前是否正在连接（防连点）
    public bool IsConnecting { get; }
}

public static class PlayerPersist
{
    // 功能：把玩家根物体标成跨场景保留，并关掉只在 World 生效的组件
    // 入参：playerRoot 玩家根物体（[Player_Hero]）
    // 返回：true 表示标记成功
    public static bool MarkPersistent(GameObject playerRoot);
}

// RuntimeNetDriver 新增
public bool AutoJoin { get; set; }        // 默认 true；false 时只连接不 JoinRoom
public bool BindPresentation { get; set; } // 默认 true；false 时不建绑定器、不纠偏英雄
```

约定：

- `DungeonEntrance` 不直接 `new NetSession`，一律复用 `RuntimeNetDriver`，避免两套连接。
- 切入 Battle 成功后才把 `AutoJoin` 置 true，保证「在 World 里不会因为输入把副本英雄挪走」。
- `PlayerPersist.MarkPersistent` 必须幂等（重复调用不报错）。

## 4. 数据结构

| 数据 | 存放 | 说明 |
| --- | --- | --- |
| 入口位置 | 场景物体 Transform | 由负责人摆位置，默认出生点前方 6 米 |
| 触发半径 / 按键 / 服务器参数 | `DungeonEntrance` 序列化字段 | Inspector 可调 |
| 连接状态 | `RuntimeNetDriver.IsOnline` / `IsJoined` | 只读轮询 |
| 提示文字 | 常量 + `OnGUI` 绘制 | 不依赖 UI 框架，R046 再换 |

## 5. 时序与流程

1. `Update`：算玩家到入口的距离，`<= m_triggerRadius` 时 `m_inRange = true` 并显示提示。
2. 玩家按 `m_enterKey` 且 `m_inRange` 且不在连接中 → `BeginEnter()`。
3. `BeginEnter()`：找 `[DungeonSession]`（没有就建 + `DontDestroyOnLoad`）→ 取/加 `RuntimeNetDriver` → 写 host/port/dungeonId → `AutoJoin = false`、`BindPresentation = false`。
4. 轮询 `driver.IsOnline`；超时 → 销毁 session、提示「连接失败：超时」。
5. 在线后：`PlayerPersist.MarkPersistent(playerRoot)` → `SceneFlow.LoadAsync(GameScene.Battle, callback)`。
6. 回调成功：`driver.AutoJoin = true`、`driver.BindPresentation = true`；失败：销毁 session 并提示。
7. Battle 里 `HpBarDemo` 发现已有驱动 → 只注册输入，不再建驱动。

## 6. 选型与理由

| 选择 | 理由 | 备选为何不选 |
| --- | --- | --- |
| 距离判定代替物理触发器 | 玩家只有一个、每帧一次距离比较，零物理配置，不会漏 `Layer` | 触发器要配 Layer/Trigger 回调，容易因层设置失效 |
| 复用 `RuntimeNetDriver` 而不是新建连接 | 心跳/重连/进房/表现全在它里面，另写一套必然分叉 | 自建 `NetSession` 会绕过重连与统计 |
| `OnGUI` 画提示 | 零资产、零依赖，R046 会统一换 UI 框架 | 现在建 Canvas 又要多一套与 `DeathScreenOverlay` 重复的代码 |
| 入口用场景里已有的建筑件当标记 | 遵守 §0.5「不程序化生成美术资产」 | 拿圆柱当传送门属于糊弄 |

## 8. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 带过去的玩家与 Battle 快照英雄重复 | `SnapshotSceneBinder` 已按 `ownerPlayerId` 跳过「我的英雄」，先实测确认 |
| World 的 `WorldPlayerSetup` 在 Battle 里继续贴地 | `PlayerPersist` 关闭它 |
| 两个 `AudioListener` | 进 Battle 时关掉 Battle 场景相机上的监听，保留玩家的 |
| 握手成功但进房失败 | 进房失败由驱动自己的 `LastError` 提示；入口只负责握手 |
| 连点 E 造成多次连接 | `IsConnecting` 闸门 + 进入后禁用入口 |
| 返回 World 后 `[DungeonSession]` 残留 | R042 退出流程里销毁；本轮先在 `LeaveRoom` 处记录待办 |
