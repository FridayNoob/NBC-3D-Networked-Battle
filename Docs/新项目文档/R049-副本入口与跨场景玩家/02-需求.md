# R049 副本入口与跨场景玩家 —— 02 需求

需求编号：R049
所属阶段：M4
作者：AI 辅助
状态：开发中

## 1. 业务目标（一句话）

玩家在 World 走到副本入口、按 E，连着服务器进房，然后带着自己这套角色进 Battle 打副本。

## 2. 用户与场景

- 玩家在 World 出生点附近看到一处「副本入口」（有可见的标记物，走近屏幕提示「按 E 进入副本」）。
- 按 E 后：先连服务器、进房；成功才切到 Battle；失败留在 World 并提示原因。
- 进 Battle 后：还是这个角色（模型、动画、相机、状态机都在），位置由服务器快照纠偏。
- 死亡按 R041 的规则：倒计时归零后退出副本回 World（沿用已有逻辑）。

## 3. 功能列表

| 优先级 | 功能 |
| --- | --- |
| P0 | World 里有一个可交互入口（触发器 + 屏幕提示「按 E 进入副本」） |
| P0 | 按 E 时先连服 + 进房，成功才 `SceneFlow.LoadAsync(Battle)`，失败提示并留在 World |
| P0 | 玩家物体跨场景保留（`DontDestroyOnLoad`），进入 Battle 后相机/输入/动画都正常 |
| P0 | Battle 场景自带的旧 `Player` 物体删除，避免双玩家抢输入与相机 |
| P0 | Battle 里不重复创建 `RuntimeNetDriver`（`HpBarDemo` 不再自动加） |
| P1 | 入口有高亮/呼吸光效，靠近时有明显提示 |
| P1 | 连接失败提示具体原因（超时 / 拒绝 / 服务器未开） |
| P2 | 多人同房时提示「当前房间 N 人」 |

## 4. 边界（不做什么）

- 不做副本匹配、排队、房间列表（R042 之后再说）。
- 不改服务端协议与判定；进房仍用现有 `JoinRoom(空房号, dungeonId)`。
- 不做 Battle → World 的结算（R042 的职责）。
- 不为入口新增美术资产（用场景里已有建筑件当标记物，后续可替换）。

## 5. 优先级

P0 全做；P1 只做「连接失败提示」，高亮用现有材质，不新增资产；P2 不做。

## 6. 验收标准

| # | 当…时，应… |
| --- | --- |
| 1 | 当玩家走到入口触发区，应出现「按 E 进入副本」提示 |
| 2 | 当走出触发区，提示应消失 |
| 3 | 当按 E 且服务器可达，应在 3 秒内完成连服 + 进房并切到 Battle |
| 4 | 当服务器不可达，应按 E 后留在 World 并显示失败原因，不切场景 |
| 5 | 当进入 Battle 后，应看到自己的角色（不是灰胶囊）、能移动、相机跟随 |
| 6 | 当进入 Battle 后，场景里不应有第二个 `Player` 物体或第二个 `AudioListener` |
| 7 | 当进入 Battle 后，Console 不应出现「已有 RuntimeNetDriver」类的重复驱动日志 |
| 8 | 当在 Battle 里死亡并倒计时归零，应按 R041 规则退出副本回 World |
| 9 | 当回到 World 后，角色应回到出生点、能动、能再次进入副本 |
| 10 | 当连续两次进出副本，不应出现相机叠加、物体残留、连接泄漏 |
