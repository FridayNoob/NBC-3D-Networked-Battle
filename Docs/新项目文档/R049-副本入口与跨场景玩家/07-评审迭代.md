## 三、根因分析

1) 端口有两份真源：`Server/NBC.Server.Host/appsettings.json` 写 9000，客户端 Inspector 写 7778；服务器实际监听以 appsettings 为准，客户端只认 Inspector。9000 当年被选是因为 7778 曾进 Windows 保留段，后来保留段变了但没人回头统一。
2) `--dev-accounts` 是内存调试账号开关，不开时服务端查 MySQL；客户端默认 `dev1/dev-pw1` 只存在于调试账号表。
3) `SceneFlow.LoadAsync` 是单场景加载；`DungeonEntrance` 挂在 World 物体上，切场景时被销毁，**协程随组件终止**，`yield` 之后的「进房 / 接相机 / 摆出生点」永远不执行。日志显示「在线=True、实体数=0」正是「TCP 通了但没进房」。
4) `Battle.unity` 里保存着旧版玩家预制体实例（`SwordGirl_FullBody` 命名），预制体自带 `PlayerMove/PlayerAnimation/PlayerBrain`，与从 World 带过来的玩家并存。
5) 删除实例后，`FollowCamera` 的 `m_target` 变成 `{fileID: 0}`，相机没有跟随目标。
6) Test Runner 的 `SaveModiedSceneTask` 会在启动前保存当前场景，Play 模式下不允许。
7) 副本出生点由需求方给（原点附近），先写死默认值，后续可进配置。
8) `ModuleA`/`SwordGirl_FullBody` 仍在美术包内，仓库克隆者可能拿不到（`Art/Model`、`Art/Scenes` 在 `.gitignore`）。
