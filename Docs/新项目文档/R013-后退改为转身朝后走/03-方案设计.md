# 03 方案设计

需求：R013-后退改为转身朝后走
所属阶段：M4
作者：AI 起草　状态：已确认（2026-10-31）

## 一、整体架构

不变：`PlayerMove` 读输入 → 算出四向之一 → 转身 + 位移 → 拆前后 / 左右分量 → `PlayerAnimation` 喂 Animator。
**本次只是把「S 走特例分支」删掉**，让四向共用一条路径。

## 二、模块划分

| 模块 | 本次改动 | 不负责什么 |
| --- | --- | --- |
| `PlayerMove`（改） | 删 `backpedal` 变量与它的分支；S 与 W/A/D 一样「转身 + 沿 targetDirection 前进」；同步更新方法注释 | 不碰 Animator、不改输入映射 |
| `PlayerAnimation` | **零改动**（按分量喂 Speed，朝向跟着走时恒正） | — |
| `UnityChanLocomotions.controller` | **零改动**（`WalkBack` 状态留着不用） | — |
| `FollowCamera` | **零改动**（世界固定偏移，本来就不跟转身） | — |

## 三、接口（★ 先定死）

```
PlayerMove
    删：Update 内的 bool backpedal、以及 if (backpedal) {...} 整个分支
    保留：ForwardSpeed / SideSpeed / MoveSpeed / CurrentSpeed（签名不变）
    保留：m_moveSpeed = 5、m_turnSpeed = 720
    行为：
        W → targetDirection = (0,0,+1)，转身后前进
        S → targetDirection = (0,0,-1)，转身后前进      ← 本次改变
        A → targetDirection = (-1,0,0)，转身后前进
        D → targetDirection = (+1,0,0)，转身后前进
```

## 四、数据结构

无变化（没有新增字段、没有新增状态）。

## 五、时序与流程

1. 读 `(x, z)` → 空输入直接返回（三个速度清零）。
2. 主导轴：`|z| >= |x|` 用前后，否则用左右（R012 规则，不变）。
3. **统一路径**：`RotateTowards(目标朝向, m_turnSpeed * dt)`；位移 = `targetDirection * m_moveSpeed * dt`。
4. 位移后按 `forward / right` 点乘拆分量（不变）。
5. `PlayerAnimation.LateUpdate` 归一化喂 `Speed` / `Direction`（不变）。

## 六、技术选型与理由

| 选择 | 选定 | 理由 | 被否的方案 |
| --- | --- | --- | --- |
| S 的实现 | **与 A/D 同一条路径** | 代码更少、行为一致，没有特例 | 在 backpedal 分支里加转身（等价但更绕） |
| 是否留开关 | **不留** | 一个行为就够，少一个要维护的状态 | Inspector bool「S 是否转身」 |
| 转身速度 | **沿用 720°/秒** | 180° 约 0.25 秒，够快也不突兀 | 为 S 单独设更快转速（多一个参数） |

## 七、风险与对策

- **`WalkBack` 动画不再触发**：这是行为改变的结果，不是缺陷；Controller 保持零改动，以后要恢复只需把分支加回来（07 会写恢复方法）。
- **180° 转身需 0.25 秒**：期间位移已沿 -Z 生效（位移用目标方向），所以不会「先站定再走」；若观感慢，调大 `m_turnSpeed`。
- **转身瞬间可能闪回 Idle**：R012 已记录同类现象（前后分量短暂偏小），必要时调 `m_turnSpeed`。
- **主导轴规则不变**：S+A 同按时仍只走前后（相等时前后优先），不会出现斜走。
