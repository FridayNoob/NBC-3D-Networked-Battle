# 01 技术预研

需求：R013-后退改为转身朝后走
所属阶段：M4
作者：AI　状态：已确认（2026-10-31）

## 一、调研目标与约束

- 目标：按 **S** 时，角色**转身朝后（180°）并前进**，行为与 A/D 完全一致；不再是「保持朝向倒退」。
- 约束（负责人 2026-10-31 定）：
  1. 只在 `PlayerMove` 一处改动，不碰动画控制器；
  2. 不改移动速度（仍 5 米/秒）；
  3. 保留「禁止斜走」「镜头不跟随转身」这两条既有约束（R012 定的）。

## 二、现状（读代码确认，含行号）

`Client\Assets\_Project\Game\Player\PlayerMove.cs`：

| 位置 | 现状 |
| --- | --- |
| 第 111 行 | `bool backpedal = forwardWins && z < 0f;` —— S 走「不转身」分支 |
| 第 114~116 行 | `targetDirection` 已按四向算出（S 就是世界 -Z） |
| 第 120~131 行 | `if (backpedal)` 分支：位移用 `-transform.forward`，**不改朝向** |
| 第 132~140 行 | 否则分支：`RotateTowards` 转身 + 沿 `targetDirection` 前进 |

**结论：改动点就是「删掉 backpedal 分支，让 S 也走转身分支」** —— `targetDirection` 已经是 -Z，转身逻辑现成。

## 三、连带影响（必须先说清）

1. **`WalkBack` 动画状态以后不会再被触发**：因为朝向始终等于移动方向，实测前后分量恒为正。
   ⇒ `UnityChanLocomotions` 里 `Speed < -0.1 → WalkBack` 这条转移从此走不到（不是 bug，是行为改变的结果）。
2. **按 S 的转身需要 180°**：`m_turnSpeed = 720 度/秒` ⇒ 约 **0.25 秒** 转完；期间位移已沿 -Z 生效（因为位移用目标方向），所以不会「先站半秒再走」。
3. **相机不受影响**：`FollowCamera` 用世界固定偏移，角色转身不会带动镜头（R012 已定）。

## 四、方案对比

| 方案 | 做法 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| **A. 删掉 backpedal 分支** | S 与 W/A/D 同一条路径 | 代码更简单（少一个分支）；行为一致 | `WalkBack` 动画弃用 | **采用** |
| B. 保留分支，但改成「转身 180° 后再走」 | 在 backpedal 分支里加转身 | 可保留未来「真倒退」的开关 | 多一套逻辑，和 A 效果相同却更绕 | 否 |
| C. 用参数控制（Inspector 开关「S 是否转身」） | 加一个 bool 字段 | 两种行为都留着 | 你明确要「和左右一样」，开关只是多一个要维护的状态 | 否 |

## 五、已知坑与版本兼容

1. **转身 0.25 秒内**实测前后分量会短暂偏小 ⇒ 可能瞬间回 Idle 再进 Walk（R012 已记录过同类现象）；若观感明显，再把 `m_turnSpeed` 调大。
2. 若以后要恢复「倒退走」，需要**重新引入分支**（本次会删掉），所以 07 里要记一条「如何恢复」。
3. `PlayerAnimation` 不改：它按分量喂 `Speed`，朝向跟着走时自然恒正。

## 六、结论与要改的东西

结论：**删掉 `backpedal` 分支与相关注释，让 S 与 W/A/D 走同一条「转身 + 沿目标方向前进」路径**；只改 `PlayerMove.cs` 一个文件。
