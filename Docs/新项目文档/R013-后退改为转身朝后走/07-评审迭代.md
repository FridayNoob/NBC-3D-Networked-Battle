## 二、优先级

三条都在本次处理：1 改代码；2、3 写进文档与注释（不改代码）。

## 三、根因分析

- #1 不是 bug，是**当初的设计选择变了**：R012 时负责人要「S 倒退」，这次要「S 转身」。
  说明一件事：**移动手感这类需求会反复**，所以 02 里把「四个方向各自的行为」逐条写死是对的（改的时候一眼知道改哪条）。
- #2 是 #1 的必然结果：朝向永远等于移动方向 ⇒ 实测前后分量恒正 ⇒ `Speed < -0.1` 走不到。
- #3 同理：`ForwardSpeed = Dot(位移, forward)`，朝向跟着走时它不可能为负。

## 四、改进方案（改哪 + 怎么改 + 影响面）

| 问题 | 改哪 | 怎么改 | 影响面 |

| #2 | 文档 + 代码注释 | `注意：` 里写明「WalkBack 从此不再触发，Controller 零改动」 | 无代码影响 |
| #3 | `04` 的接口表 | 标注 `ForwardSpeed` 恒 ≥ 0 | 无代码影响 |

## 八、教训（可复用判据）

1. **已验收需求的行为变更，要开新需求**（本次 R013），并在旧需求里留一条指向 —— 否则历史文档会自相矛盾。
2. **手感类需求会反复**：02 里「逐键写死行为」的价值就在这里，改的时候不用重新讨论全部。
3. **删一个分支也要检查「谁依赖它的副作用」**：`WalkBack` 动画就是被这次删除顺带废掉的，必须显式记录。
4. **接口语义变了要单独标注**（`ForwardSpeed` 不再为负），否则以后有人按负数写逻辑就会静默错。

## 九、遗留与恢复方法（如实）

- **如何恢复「倒退走」**：在 `PlayerMove.Update` 里把分支加回来 ——
  `bool backpedal = forwardWins && z < 0f;`，`if (backpedal) { moveDirection = -transform.forward; } else { 转身 + targetDirection }`。
  Controller 无需改动（`WalkBack` 状态一直在）。
- 转身 180° 需约 0.25 秒（720°/秒）；若嫌慢，调 `m_turnSpeed`。
- 本版没有「走路时身体倾斜/加减速缓冲」—— 属 R002 起就记着的遗留。
