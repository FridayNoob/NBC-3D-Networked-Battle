## 二、模块文档

### 2.1 `ConfigTableWindow`

- 简介：编辑器里唯一的配置表窗口，用下拉切 10 张表，表格直接改 SO，工具栏负责校验 / 导出 / 导入。
- 接口：`[MenuItem("Tools/NBC/配置表/配置表（SO ↔ CSV）", false, 0)]`；窗口状态 `m_tableIndex` / `m_asset` / `m_rows` / `m_columns` / `m_buffers`。
- 示例：菜单打开 → 选 `Monster` → 双击「生命值」改 301 → 顶部红字 → 点「导出到 CSV」。
- 原理：窗口**不保存第二份数据**，它直接编辑 `Config` SO 的内存对象；「红字」是 `IsDirty` 用「磁盘 CSV」与「SO 重拼文本」逐字比较得出的。
- 坑：
  1. 单元格必须用 `m_buffers`（按「行号:列名」缓存输入），否则每帧从 SO 取值会把正在输入的逗号吞掉。
  2. 资产可能被外部重新导入（ConfigKit / 手动 Reimport），窗口要每秒比对一次对象身份并 `Load()`，否则改的是旧对象。
  3. 窗口生命周期里不能假设 `m_asset` 一直有效。
- 维护：加表不用改窗口，只需在 `ConfigTableRegistry` 加一条；改列宽改 `ColumnWidth`。

### 2.2 菜单约定

- 简介：所有编辑器入口收进 `Tools/NBC/` 五个分组：配置表 / 资源 / UI / 调试 / 行为树。
- 现有入口：`Tools/NBC/配置表/配置表（SO ↔ CSV）`、`Tools/NBC/行为树/行为树编辑器`、`Tools/NBC/调试/诊断 M0 探针依赖`。
- 原理：Unity 顶层菜单是全局命名空间，散落会越加越乱；用 `Tools/NBC/` 前缀保证「本项目的东西只在这里」。
- 坑：改 `[MenuItem]` 路径后旧路径不会报错消失，要主动验证旧路径不可用。
- 维护：新增菜单项先想「属于哪一组」，没有合适的组再讨论加组，不新开顶层菜单。

## 三、踩坑清单

1. **判据两侧都要归一化**：`IsDirty` 只归一化一侧 ⇒ 导出后永远红字。
2. **Excel 的千位分隔符**：`2002,2003` 会变 `20,022,003`，解析时要能还原。
3. **GBK 进、UTF-8 出**：编辑器的桥统一写 UTF-8 BOM，读的时候三种编码都要认。
4. **struct 不能和 null 比**：`ConfigColumn` 是 struct，`column != null` 编译不过。
5. **自己开的文件自己关**：模拟 Excel 占用用 `FileShare.None`，别忘了 `using` 释放，否则后续导出全失败。
