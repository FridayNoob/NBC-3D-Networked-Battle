## 调研目标与约束

目标：把 R050 的「一张表一个窗口」换成「一个窗口管 10 张表」，并把编辑器菜单统一收进 `Tools/NBC`。

约束：

1. 复用 R051 的 `ConfigTableRegistry` / `ConfigTableBridge`，不新造数据模型。
2. 只动编辑器程序集 `NBC.Editor`，不碰运行时与服务器。
3. 菜单改名只改 `[MenuItem]` 字符串，不改方法体。
4. 窗口必须能在没有任何 CSV 被 Excel 占用的情况下完整走完「改 → 校验 → 导出 → 导入」。
5. 旧的 `DungeonConfigWindow` 被通用窗口取代，直接删除。

## 核心 API 清单

| API | 用途 |
| --- | --- |
| `EditorWindow.GetWindow<T>(string)` | 打开/聚焦窗口 |

    GetWindow<ConfigTableWindow>("配置表").Show();

## 方案对比

| 方案 | 做法 | 取舍 |
| --- | --- | --- |
| A 每张表一个窗口 | 复制 10 份窗口代码 | 维护成本 ×10，加表还要加文件 → 否 |
| **B 单窗口 + 表下拉** | 一个窗口用注册表切换 | 新增表零成本；单元格是通用文本 → 采用 |
| C 全用 Inspector | 只做导出/导入菜单项 | 没有表格视图、不能批量改 → 否 |

## 已知坑与版本兼容

1. `ConfigColumn` 是 **struct**，写 `column != null` 会编译失败（`CS0019`）。
2. 删除 `DungeonConfigWindow.cs` 后，R050 的 04 文档仍引用它 —— 需要在 R052 的 07/08 里留指向说明。
3. 域重载会丢窗口字段，`OnEnable` 必须重新 `Load()`。
4. 单元格直接 `TextField` 会在每次按键写回：解析失败要保留原文（缓冲），否则用户输到一半就被清空。
5. 资产被外部重新导入后，旧对象引用会失效 —— 需要每秒按路径比对并 `Load()`。
6. 菜单改名会让旧习惯失效（`AI工具/BehaviorTree Editor` 变 `Tools/NBC/行为树/行为树编辑器`），需要写进 FIXES/索引。

## 结论

用方案 B：新增 `ConfigTableWindow`，删除 `DungeonConfigWindow`；菜单统一 `Tools/NBC/配置表|资源|UI|网络|调试|行为树|怪物`。预估 430 行窗口 + 2 处菜单字符串。
