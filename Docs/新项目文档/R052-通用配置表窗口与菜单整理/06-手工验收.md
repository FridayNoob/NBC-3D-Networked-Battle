# 06 手工验收

需求编号：R052
所属阶段：M4
作者：AI（负责人评审）
状态：待验收

## 计划

- 正常：打开窗口 → 选表 → 改值 → 校验 → 导出 → 关闭重开看值。
- 异常：Excel 打开 CSV 时导出/导入；表里填非法值。
- 边界：只有 1 行/0 行的表；10 张表轮一遍。
- 性能：切换表不超过 1 秒；窗口打开不超过 2 秒。

## 正常流程走查

| 步骤 | 操作 | 预期 |
| --- | --- | --- |
| 1 | 菜单 `Tools/NBC/配置表/配置表（SO ↔ CSV）` | 打开「配置表」窗口，默认显示 Achievement |
| 2 | 下拉切到 `Dungeon` | 6 列中文表头（编号/名称/最大人数/出生点半径（毫米）/普通怪/BOSS），2 行数据 |
| 3 | 把 1001 的「最大人数」改成 3 | 立刻生效，顶部出现红字「SO 与 CSV 不一致」 |
| 4 | 点「校验」 | 底部显示通过 |
| 5 | 点「导出到 CSV」 | 状态栏提示已导出并重新生成；`Configs/Design/Dungeon.csv` 该行变 3 |
| 6 | 关掉窗口再打开 | 值仍是 3，红字消失 |
| 7 | 点「从 CSV 导入」 | 弹确认，确认后表格刷新为 CSV 的值 |

## 异常场景

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| Excel 占用 | 用 Excel 打开 `Dungeon.csv`，再点「导出」 | 不崩，提示「读不到/写不进 CSV（可能正被 Excel 打开）…请先关闭 Excel」 |
| 非法值 | 最大人数填 9 | 保留 9 在原位，校验报「最大人数 范围(2,4)」 |
| 怪物编号不对 | 普通怪填 9999 | 校验报「怪物 9999 不在 Monster 表」 |
| 空表 | 切到行数为 0 的表 | 只显示表头，可点「增加一行」 |
