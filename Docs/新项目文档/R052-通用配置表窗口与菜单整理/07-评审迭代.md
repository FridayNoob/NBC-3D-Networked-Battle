## 三、根因分析

- 问题 1：`IsDirty` 只对「磁盘文本」做了 `Normalize`（去尾部换行），而「从 SO 重拼的文本」仍带结尾 `\n`，两边永远不相等。典型「判据只归一化了一侧」。
- 问题 2：Excel 把 `2002,2003` 当成数字，显示并保存为 `20,022,003`；桥按逗号切分得到 20/22/3，校验命中「Skill 表没有该编号」→ 整表回滚。用户看到的却是「导入失败」。
- 问题 3：Excel 默认存 GBK，服务端 `File.ReadAllLines(path, Encoding.UTF8)` 硬读 ⇒ 中文变 `?`、数字列被 `IntOr` 静默回落成 0。
- 问题 7：`[MenuItem]` 改名后旧路径不会自己消失，但也不能假设「改了就对」，必须用 `ExecuteMenuItem` 对旧路径断言 False。

## 四、改进方案

| 改哪 | 怎么改 | 影响面 |
| --- | --- | --- |
| `ConfigTableBridge.IsDirty` | 两侧都 `Normalize` | 所有表的脏判断 |
| `ConfigTableBridge.TryParseCell` | `int[]` 分支加「千位分隔符还原」（任一 < 1000 时按 4 位一组重组） | 所有引用列 |
| `ConfigTableBridge.GetCellText` | 显示层不再复用 `FormatCell` 的引号 | 10 张表的显示 |
| `ServerTables` | 新增 `ReadAllLinesAuto` / `DecodeAuto`（BOM → 严格 UTF-8 → GBK；坏字符抛错点名表名） | 服务端读表 |
| 菜单 | 删除旧 `AI工具/...` 特性路径，用 MCP 断言旧路径不可用 | 编辑器菜单 |
