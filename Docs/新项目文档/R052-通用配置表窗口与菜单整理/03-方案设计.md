# 03 方案设计

需求编号：R052
所属阶段：M4
作者：AI（负责人评审）
状态：开发中

## 整体架构

```text
菜单 Tools/NBC/配置表/配置表（SO ↔ CSV）
        │
        ▼
ConfigTableWindow (EditorWindow)
        │ 选表
        ▼
ConfigTableRegistry ──► ConfigTableEntry（CSV 路径 / SO 路径 / 行类型）
        │
        ▼
ConfigTableBridge（ReadColumns / GetRows / TrySetCell / Validate / Export / Import）
        │
        ├──► ScriptableObject（Config_*）
        └──► Configs/Design/*.csv ──► ConfigKit ──► Generated/*
```

## 模块划分

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| `ConfigTableWindow` | 选表、画表格、编辑单元格、工具栏事件 | 读写文件、解析、校验（全交给桥） |
| `ConfigTableBridge` | 已有能力 + 三个窗口需要的小接口 | 不知道 UI 存在 |
| `ConfigTableRegistry` | 表清单 | 不知道 UI 存在 |
| 菜单字符串 | 收纳到 `Tools/NBC` | 不改方法体 |

## 接口（方法 + 入参 + 出参 + 约定）

窗口内部（私有）：

| 方法 | 入参 | 出参 | 约定 |
| --- | --- | --- | --- |
| `Load()` | 无 | 无 | 清缓冲、读列、读资产、取 rows；失败写 `m_columnError` |
| `DrawToolbar()` | 无 | 无 | 下拉切表即 `Load()` |
| `DrawCell(int rowIndex, object row, ConfigColumn column)` | 行号/行/列 | 无 | 解析失败保留原文到 `m_buffers` |
| `ExportNow()` / `ImportNow()` | 无 | 无 | 结果写 `m_status`，成功后 `Load()` |
| `AddRow()` / `RemoveRow(int)` | 行号 | 无 | 改 rows 后 `MarkDirty()` |
| `CheckAssetReplaced()` | 无 | 无 | 每秒一次，对象换了就 `Load()` |

桥新增（公开，给窗口用）：

| 方法 | 入参 | 出参 | 约定 |
| --- | --- | --- | --- |
| `GetRows(ScriptableObject)` | 资产 | `IList` | 反射 `rows`，没有返回 null |
| `CreateRow(ConfigTableEntry)` | 表登记 | `object` | `Activator.CreateInstance(RowType)` |
| `GetCellText(entry, row, column)` | 行/列 | `string` | 与 CSV 一致的格式 |
| `TrySetCell(entry, row, column, text, out problem)` | 文本 | `bool` | 失败不改字段 |

## 数据结构

- `m_tableIndex : int`（0..9）
- `m_asset : ScriptableObject`
- `m_rows : IList`
- `m_columns : List<ConfigColumn>`（struct：`Name/Label/Type/Rule`）
- `m_buffers : Dictionary<string,string>`（键 `行号:列名`）
- `m_status : string`、`m_columnError : string`

## 时序与流程

1. 打开窗口 → `OnEnable` → `Load()`。
2. 改单元格 → `TrySetCell` → 成功则 `SetDirty` + `SaveAssets` + 清缓冲。
3. 导出 → `Validate` → 备份 → 替换 → ConfigKit → 成功 `Load()`。
4. 导入 → 有未导出改动则确认 → 解析 → 校验 → 覆盖 rows → `Load()`。
5. 增删行 → `m_rows.Add/RemoveAt` → `MarkDirty()`。
6. 每帧 `CheckAssetReplaced()`（节流 1 秒）。

## 选型与理由

| 选择 | 理由 |
| --- | --- |
| 单窗口 + 下拉 | 10 张表零重复代码，加表只加注册表一行 |
| 单元格用文本 + 类型解析 | 与 CSV 一致，避免为每种类型写控件 |
| 解析失败保留原文 | 用户输到一半不能清空，否则没法继续打字 |
| 删掉 `DungeonConfigWindow` | 与通用窗口功能重复，留着会让人打开错的 |
| 菜单改名只动字符串 | 风险最小，方法体一字不改 |

## 风险与对策

| 风险 | 对策 |
| --- | --- |
| `ConfigColumn` 是 struct，判空编译错 | 不判空，直接读字段 |
| 删除旧窗口导致文档失联 | R052 的 07/08 写明 R050 的 `DungeonConfigWindow` 已被取代 |
| 域重载丢状态 | `OnEnable` 重新 `Load()` |
| 每次按键写盘太频繁 | 只 `SetDirty` + `SaveAssets`，不跑 ConfigKit |
| 大表渲染慢 | 先不做虚拟滚动，超过 200 行再优化 |
