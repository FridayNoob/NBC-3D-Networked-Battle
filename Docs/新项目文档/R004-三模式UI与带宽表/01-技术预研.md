## 二之二、网络侧现状核查（2026-10-28，负责人问「会不会有逻辑缺失」）

| 链路 | 状态 | 证据 |

| 客户端：收快照 | 已有 | `NetSession.HandleSnapshot` → `SnapshotView.Apply`（tick 单调、`StaleIgnored` 计数） |
| 协议：锁步 | 已有 | `LockstepStart` / `LockstepFrame` / `LockstepInput` |
| 服务端：锁步 | 已有 | `LockstepService.cs`（`ServerHash` 对账、共享 `CountKills`） |
| 客户端：锁步 | 已有 | `Shared\Sim\LockstepClient`（`StepsExecuted` / `LastSteppedFrame` / `Desync`）+ `SendLockstepInput` |
| **离线** | **没有「离线模式」开关** | 移动/动画/R012 全本地，不连也能走；网络功能不可用 |

**两个既有缺口（HUD 会照出来，不是本需求造成的）：**

1. **纯运行时没有锁步驱动者**：推进 `Step` 的是 Editor 窗口（`NetDebugWindow` 的 `StepsExecuted`）⇒ 纯 Play 时锁步帧号不会自己前进。补它属「运行时会话生命周期 + 步进驱动」（R008/R007 一类）。
2. **两种模式的「帧号」语义不同**：状态同步用 `SnapshotView.ServerTick`（服务端 tick）；帧同步用 `LastSteppedFrame`（已步进帧）。HUD 必须**按模式取不同来源**。

**决定（负责人 2026-10-28）**：R004 **只读、只显示**——连上就显示真实数据，没连显示「离线」，缺口如实呈现，不做假数据。

## 四、方案对比

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| **装饰器 `CountingTransport` + 静态 `NetRuntimeStats`** | 一对收发点覆盖**所有包**（含心跳）；`TcpTransport` / `SimulatedTransport` 都自动生效；HUD 不关心谁持有会话 | 引入一份静态状态 | **采用** |
| 在 `TcpTransport` / `SimulatedTransport` 各加计数 | 不用装饰器 | 两处重复实现；模拟器容易漏 | 否 |
| 在 `NetSession` 按业务消息大小统计 | 不改传输层 | 漏掉心跳等非业务包，**带宽会偏小**；会话不在运行时也读不到 | 否 |
| 只扩展现有 Editor 窗口 | 工作量最小 | 不是「游戏 UI」，且运行时看不到 | 否 |

## 五、已知坑与版本兼容

1. **运行时代码目前不建连**：transport 只在 Editor 里创建 ⇒ 第一次验收得靠 Editor 窗口连上，HUD 才有数据；否则永远显示「离线」。
2. **带宽不滑窗必然乱跳**：必须用 1 秒滑动窗口算 B/s，否则每帧数字都在蹦。
3. **两处显示必须同源**：Editor 窗口与 HUD 若各算一套，数字不一致时极难排查 ⇒ 都读同一个静态统计。
4. **`FrameReceived` 的字节数**：事件只给 `byte[]`，长度即 payload 字节；**不含** TCP 头与分帧头（要说明「这是业务字节，不是线缆字节」）。
5. **`SimulatedTransport` 也要计数**：它外面包一层装饰器即可，但要注意它内部已有延迟/丢包模拟，装饰器必须包在**最外层**。
6. **每帧刷文本会掉 GC**：文本每 0.25 秒刷一次即可，且用缓存字符串。
7. **状态同步的「帧号」**：需要确认是快照序号还是服务端 tick；本需求先显示 `LastSteppedFrame`（帧同步）或快照序号（状态同步），具体取值在 03 定。

## 六、结论与要改的东西

结论：**装饰器统计 + 静态 `NetRuntimeStats` + 复用 R003 的面板管线**。

- 新增 `NetRuntimeStats`（`Framework.Net`）：总字节、1 秒滑窗带宽、模式、帧号、RTT（后三者由会话写、HUD 只读）。
- 新增 `CountingTransport`（`Framework.Net`）：包住任意 `ITransport`，两个方向计数。
- 新增 `NetHudPanel`（`Game\UI`，继承 `BasePanel`）+ prefab（负责人做，控件名固定）。
- Editor 窗口：建 transport 时包一层，并把模式 / 帧号 / RTT 写进静态统计（**与 HUD 同源**）。
