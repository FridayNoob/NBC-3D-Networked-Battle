## 二、模块文档

### 简介与使用场景

`NetRuntimeStats`（Framework.Net，纯 C#）+ `CountingTransport`（装饰器）+ `NetHudPanel`（Game.UI）。
任何地方只要把传输层包一层 `CountingTransport`，`NetHudPanel` 就能显示上下行带宽；模式/帧号/RTT 由**建会话的一方**写入。

### 核心接口

| 接口 | 入参 | 出参 | 说明 |
| --- | --- | --- | --- |
| `NetRuntimeStats.AddSent/AddReceived` | 字节数 | — | 统计点调；0 与负数忽略 |
| `NetRuntimeStats.SetMode/SetRtt/SetFrame` | 枚举 / ms / 帧号 | — | **建会话方**调 |
| `NetRuntimeStats.Reset` | — | — | 连接前 / 断开时调 |
| `NetRuntimeStats.Snapshot` | — | `NetStatsSnapshot` | HUD 每 0.25 秒读一次；内部惰性推进滑窗 |
| `CountingTransport(inner)` | 任意 `ITransport` | — | 包在最外层（含 `SimulatedTransport`） |
| `NetHudPanel` 控件 | — | — | `Text_Mode` / `Text_Speed` / `Text_Rtt` / `Text_Frame` + 容器 `Box` |

### 使用示例（负责人亲手跑通，2026-10-28）

```text
1) 服务器：NBC.Server.Host.exe --port=7778 --dev-accounts --fill-seats=4
2) Play → 右上角面板出现（离线 / 0 B/s / RTT -- / 帧 --）
3) 网络调试窗口连 127.0.0.1:7778（dev1 / dev-pw1）→ 模式「状态同步」、带宽与 RTT 有数
4) 进房 → 帧号开始递增；勾「帧同步（锁步）」→ 模式变「帧同步」，帧号仍动
5) F1 收起 / 展开
```

### 实现原理（简要）

`CountingTransport` 在 `Send` 与 `FrameReceived` 两处把 payload 长度交给 `NetRuntimeStats`；
`NetRuntimeStats` 用 4 个 0.25 秒采样槽算 1 秒窗口的 B/s，**读时惰性推进**（不依赖外部 Tick）；
`NetHudPanel` 每 0.25 秒取一次 `Snapshot()` 写文本（自适应 `B/s` / `KB/s`）。

### 已知限制与坑点

- 只统计**业务字节**，不含 TCP 头与分帧头。
- 帧号语义随模式变：状态同步 = 快照 `ServerTick`；帧同步 = `LastSteppedFrame`。
- 未进房时状态同步帧号是 `--`（没有快照）。
- 纯 Play 时没有锁步步进器（依赖 Editor 窗口）。

### 修改维护注意事项

- 新增一种传输层：**不用改**，包一层 `CountingTransport` 即可。
- 新增显示字段：只加 `NetStatsSnapshot` 字段与文本控件，不要另开统计。
- 别在 Editor 窗口里另算一份带宽（会与 HUD 数字打架）。

## 三、踩坑清单（现象 / 原因 / 解决）

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `CS0535` 装饰器少实现成员 | `ITransport` 还有 `State` / `Stats` / `Description` | 补齐三个转发属性 |
| F1 收起后按不回来 | `Box` 不是 `UIBehaviour`，`GetControl` 拿不到 ⇒ 兜底隐藏了自己 | `transform.Find("Box")` |
| 带宽恒 0.0 | 固定 KB/s + 一位小数，几十 B/s 被抹成 0.0 | < 1024 B/s 用 `B/s` |
| 连上但帧号 `--` | 还没进房，没有快照 | 进房后自然递增（预期行为） |
| 面板数字与 Editor 窗口不一致 | 两边各算一套 | 只留 `NetRuntimeStats` 一份 |
| 面板根尺寸为 0 | 面板根会被 `UIManager` 铺满 | 内容放进固定尺寸的 `Box` |
