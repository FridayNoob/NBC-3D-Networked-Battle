# 03 方案设计

需求：R004-三模式 UI + 带宽表
所属阶段：M4
作者：AI 起草　状态：已确认（2026-10-28）

## 一、整体架构

四块：**统计点**（`CountingTransport` 装饰器，包住任意 `ITransport`）→ **数据源**（静态 `NetRuntimeStats`，含 4 采样点滑窗）
→ **表现**（`NetHudPanel`，每 0.25 秒读一次快照）→ **写入口**（建会话的一方：今天 Editor 窗口，以后运行时启动器）。

## 二、模块划分

| 模块 | 负责什么 | **不负责**什么 |
| --- | --- | --- |
| `CountingTransport`（新增，Framework.Net） | 包住 `ITransport`，两个方向累加字节 | 不做统计计算、不管模式 |
| `NetRuntimeStats`（新增，Framework.Net） | 累加字节、滑窗算带宽、保存模式 / 帧号 / RTT | 不建连、不读会话、不渲染 |
| `NetHudPanel`（新增，Game.UI） | 每 0.25 秒读快照写 4 个文本；F1 显隐 | 不统计、不判断模式对错 |
| `NetDebugWindow`（改一处，Editor） | 建 transport 时包一层；连接/断开/切锁步时写模式；写帧号与 RTT | 不重复算带宽（避免两套数字） |
| `UIManager` / prefab（沿用 R003） | 加载面板、挂到 `Bot` 层 | — |

## 三、接口（★ 先定死）

// Framework.Net
public enum NetSyncMode { Offline = 0, StateSync = 1, Lockstep = 2 }

public readonly struct NetStatsSnapshot
{
    NetSyncMode Mode; long TotalBytesOut; long TotalBytesIn;
    float BytesPerSecondOut; float BytesPerSecondIn; int RttMs; int Frame;
}

public static class NetRuntimeStats
{
    void AddSent(int bytes);         // CountingTransport 调
    void AddReceived(int bytes);     // CountingTransport 调
    void SetMode(NetSyncMode mode);  // 建会话方调
    void SetRtt(int rttMs);
    void SetFrame(int frame);
    void Reset();                    // 断开 / 换局
    NetStatsSnapshot Snapshot();     // 读时惰性推进滑窗，返回一次一致的快照
}

public sealed class CountingTransport : ITransport
{
    CountingTransport(ITransport inner);
    // Send 前 AddSent(len)；FrameReceived 先 AddReceived(len) 再往外抛
}

## 四、数据结构与滑窗

| 数据 | 类型 | 含义 / 单位 | 谁改它 |
| --- | --- | --- | --- |
| 累计字节 | long | 业务字节（payload，不含 TCP 头） | `AddSent/AddReceived` |
| 4 个采样槽 | int[4] | 每 0.25 秒一段的字节数 | 读时惰性推进 |
| `BytesPerSecond*` | float | 4 槽求和 ÷ 1 秒 ⇒ B/s | `Snapshot()` |
| `Mode` / `Frame` / `RttMs` | 枚举 / int / int | 会话状态 | 建会话方 |

**滑窗怎么推进（不依赖外部 Tick）**：`AddSent/AddReceived/Snapshot` 内部都会调一次 `Advance(now)`：
按 `0.25 秒` 步长推进槽位，把「当前累计」写进槽、当前清零；跨度超过 4 槽直接把槽清 0（不追历史）。
⇒ 面板隐藏时不会卡住，流量停了带宽也会自然回落。

## 五、时序与流程

1. 建会话方 `new CountingTransport(new TcpTransport())` → 连接成功 → `SetMode(StateSync|Lockstep)`。
2. 每次 `Send` / 收到帧：装饰器累加字节（`AddSent/AddReceived`）。
3. 会话方在锁步/快照回调里 `SetFrame(...)`；心跳回来 `SetRtt(...)`。
4. `NetHudPanel.Update`：每累计 0.25 秒 → `Snapshot()` → 写 4 个文本（`Text_Mode` / `Text_Speed` / `Text_Rtt` / `Text_Frame`）。
5. 断开 → `SetMode(Offline)`（或 `Reset()`）→ 面板显示「离线」。

## 六、技术选型与理由

| 选择 | 选定 | 理由 | 被否的方案 |
| --- | --- | --- | --- |
| 统计点 | **装饰器包 `ITransport`** | 一对收发点覆盖全部流量，两种实现都自动生效 | 各实现内加计数（重复、易漏） |
| 滑窗 | **4 槽 × 0.25 秒，读时惰性推进** | 无分配、无需外部 Tick、隐藏时不卡 | 时间戳队列（每包分配）、每秒一次（跳） |
| 数据源 | **静态 `NetRuntimeStats`** | HUD 不需要知道谁持有会话 | 静态实例注入（运行时尚无持有者） |
| 模式写入 | **建会话的一方写** | 今天 Editor、以后启动器，不锁死 | HUD 自己推断（拿不到会话） |
| 刷新 | **0.25 秒** | 数字够跟手，又不至于每帧刷文本 | 每帧刷（GC）、1 秒（迟钝） |

## 七、风险与对策

- **静态状态**：测试间会串味 ⇒ 提供 `Reset()`，并在断开时调用；文档写明「只读表现，不参与决策」。
- **只统计业务字节**：不含 TCP/分帧头 ⇒ HUD 数字比抓包工具小，界面文案写「业务字节」避免误解。
- **面板根会被铺满**（R003 已踩）⇒ prefab 里用固定尺寸容器 `Box` 锚在右上角。
- **Editor 与 HUD 必须同源** ⇒ 都在 Editor 侧只调 `NetRuntimeStats`，不自己算。
- **纯 Play 时无会话** ⇒ 显示「离线」，这是既有缺口（R008），本需求不补。
- **`FrameReceived` 事件的字节**：先计数再抛出，避免订阅者抛异常导致漏计；用 `try/finally` 保证。
