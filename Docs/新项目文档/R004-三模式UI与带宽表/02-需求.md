# 02 需求

需求：R004-三模式 UI + 带宽表
所属阶段：M4
作者：LYF（口述确认，AI 落稿）　状态：已确认（2026-10-28）

## 一、业务目标（一句话）

**一眼看出「现在是什么同步模式、花了多少带宽、延迟多少、跑到第几帧」** —— 联调时不用切到 Editor 窗口。

## 二、用户与使用场景

- 用户：开发期负责人（联调、给面试官演示时也用）。
- 场景：进游戏右上角常驻一块小面板；连服务器前显示「离线」，连上后按真实模式显示状态同步或帧同步的数据。

## 三、功能列表（P0 / P1 / P2）

| 功能 | 优先级 | 说明 |
| --- | --- | --- |
| 显示模式 | P0 | 离线 / 状态同步 / 帧同步（三选一，由会话状态决定） |
| 显示上下行带宽 | P0 | 业务字节 KB/s，1 秒滑动窗口，保留 1 位小数 |
| 显示 RTT | P0 | 毫秒；没有会话时显示 `--` |
| 显示帧号 | P0 | 状态同步 = 快照 `ServerTick`；帧同步 = `LastSteppedFrame`；离线显示 `--` |
| 面板刷新 4 次/秒 | P0 | 不每帧刷文本（省 GC） |
| 快捷键隐藏/显示 | P1 | 例如 F1 切换；演示时可收起 |
| 历史曲线 / 峰值记录 | P2 | 本版不做 |

## 四、边界（**本版明确不做**）

- **只读**：不参与任何同步/模拟决策，不写会话状态，不做假数据。
- 不补「运行时锁步驱动」缺口（纯 Play 时帧号不动是既有事实，如实显示）。
- 不做丢包率、不做快照序号之外的新统计指标。
- 不改 `NetDebugWindow` 的既有功能（只在建 transport 处加一层计数）。

## 五、优先级

**P0**。依赖：R003（UI 面板管线）、`Framework.Net`（`ITransport` 两个收发点）。

## 六、验收标准（「当…时，应…」）

- [ ] 当 没有连接任何服务器时，模式应显示「离线」，带宽 `0.0 KB/s`，RTT 与帧号显示 `--`
- [ ] 当 连上并以状态同步跑动时，模式应显示「状态同步」，帧号应等于快照 `ServerTick` 且持续递增
- [ ] 当 切到帧同步并跑动时，模式应显示「帧同步」，帧号应等于已步进帧且随步进递增
- [ ] 当 有数据收发时，上行 / 下行带宽应显示非零值，且**数字不剧烈跳动**（1 秒滑窗）
- [ ] 当 RTT 有效时，应显示毫秒数并在网络变差时增大
- [ ] 当 按 F1 时，面板应隐藏/显示切换（P1）
- [ ] 当 面板显示时，Editor 窗口与 HUD 的数字应**一致**（同源）
