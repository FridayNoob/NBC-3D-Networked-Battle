## 3. 根因分析

1. **高度**：0.9 米是 01 里按「半人高」拍的，没跟负责人确认；01 已补「6.5 负责人决策」。
2. **入地**：三条 Mixamo clip 导入时 `Root Transform Position (Y)` 勾了 `Bake Into Pose`，`Mixamo_FallingToLanding` 自带根 Y 曲线 1.561 → 0.609 被烘进骨骼姿势，身体整体被压到原点以下；`PlayerJumpMotor` 又把根节点钉在地面高度 ⇒ 叠加成半身入地。
3. **贴地无效**：修的是「脚骨与地面的厘米级偏差」，而真问题是「身体被整体压下去 0.86 米」；另外 0.8 米的修正上限把更大的偏差直接跳过了。
4. **僵硬**：UnityChan 的 JUMP01/JUMP00 是完整动作（2 秒级），被 `speed=2.5` + 短 offset 截成 0.35 秒/0.2 秒的小段，只剩定格姿势。
5. **0 个 clip**：Humanoid 的 Avatar 复制要求骨骼名一致；Mixamo 用 `mixamorig:*`，剑士用自定义名，映射不上就一个 clip 都生成不了。正确做法是 `CreateFromThisModel` 让 Unity 自己建 Avatar。
6. **clip 名被覆盖**：`SaveAndReimport` 会按 take 名重建 `defaultClipAnimations`，名字与 Loop 都要在同一个 importer 修改批次里显式写回。
7. **方向不对**：`PlayerMove` 的兜底是「没参考体就用 `Camera.main`」，而 `ApplyJumpDirection` 自己拼轴时兜底是世界轴 ⇒ 两处口径不一致。
8. **恒 +Z**：`ApplyJumpDirection` 用了 Inspector 字段 `m_move`，而场景里 `m_move: {fileID: 0}` 是空的；`Awake` 真正解析出来的是 `m_motion = m_move ?? GetComponent<PlayerMove>()`。空引用没报错，直接退化成 `Vector3.forward`。
9. **卡编译**：编辑器失焦时脚本编译请求会挂着；判断依据应为反射能否拿到新方法，而不是 `isCompiling` 之外的猜测。
10. **超预算**：跳跃涉及「物理 + 动画 + 控制器 + 方向」四块，01 估 340 行、03 估 888 行、实际约 900 行；已在 03 写明例外，07 只做记录。

## 4. 改进方案

| 改哪 | 怎么改 | 影响面 |
| --- | --- | --- |
| 01 §6.6 | 写明 `Root Transform Position (Y)` 不能烘，竖直高度交给物理 | 只影响文档 |
| importer（三个 fbx） | `lockRootHeightY=false`、`keepOriginalPositionY=true` | 只影响跳跃三段 |
| `PlayerJumpMotor` | 跳高 1.2；脚底贴地上限 2 米、死区 5 毫米、打日志；新增 `SetJumpDrift` 与空中漂移 | 跳跃表现 |
| `PlayerMove` | 抽出 `GetMoveDirection`，走路/跳跃共用 | 走路方向（行为不变） |
| `PlayerBrain` | 用 `m_motion` 求方向；无输入时清零漂移 | 只影响跳跃 |
| 控制器副本 | `S_Jump/S_Fall/S_Land` 指向 Mixamo 三段，offset 0.30/0/0.33、`S_Land` speed 1.6 | 跳跃动画 |
