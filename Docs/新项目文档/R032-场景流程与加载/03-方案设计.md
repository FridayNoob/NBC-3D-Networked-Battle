## 一、整体架构

`
业务（按钮 / 快捷键 / 传送门）
        │ SceneFlow.Instance.LoadAsync(scene, onDone)
        ▼
SceneFlow（常驻单例，跑协程）
        ├─ AssetManager.IsInitialized ? YooAsset 加载（地址 = 文件名）
        └─ 否 → SceneManager.LoadSceneAsync（兜底）
        ▼
GameSceneAddress（枚举 → 地址表）
`

## 四、时序

1. 业务调 LoadAsync → IsLoading 为 true 则立刻回调失败。
2. 起协程：取地址 → 资源层可用？是：LoadSceneAsync 轮询 IsDone/Progress → 完成后 Dispose 句柄；否：SceneManager 兜底。
3. 成功后回调 (true, "")；失败记 LastError 并 Debug.LogError。
4. IsLoading=false，Progress=1。

## 五、选型与理由

| 选择 | 理由 | 被否方案 |
| --- | --- | --- |
| 单例 + 协程 | 场景加载是 Unity 异步对象，必须有宿主 | 纯静态 async（要自己管 Task/主线程） |
| 地址 = 文件名 | 与收集器 AddressByFileName 一致 | 写全路径（收集器一变就断） |
| 保留 SceneManager 兜底 | 编辑器单场景调试不黑屏 | 只走 YooAsset（调试成本高） |
| 未登记抛异常 | 配置错要立刻暴露 | 返回空串（会静默黑屏） |

## 七、SOLID 自检

| 原则 | 怎么满足 |
| --- | --- |
| **S** | 地址表、加载器、调试键三件事分开 |
| **O** | 新场景 = 枚举加一项 + 地址表加一行（不改加载逻辑） |
| **L** | SceneFlow 对两条加载路径给出同样的回调契约 |
| **I** | LoadAsync 只有一个回调，不塞"加载完成后做什么业务" |
| **D** | 业务不直接摸 AssetManager/SceneManager，只调 SceneFlow |
