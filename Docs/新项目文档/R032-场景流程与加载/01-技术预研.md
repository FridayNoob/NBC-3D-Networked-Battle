# 01 技术预研

需求：R032-场景流程与加载
所属阶段：M4
作者：AI　状态：待确认（2026-11-13）

## 一、调研目标与约束

- 目标：让 `Login → World`（以及 `World → Battle/PVP_Room`）能**用代码切场景**，且走项目既有的资源层（YooAsset），为后面的开放世界铺路。
- 约束：
  1. 不新建场景（负责人已建好 5 个）；
  2. 走 YooAsset（负责人选 B），但要能在"资源层没初始化"时兜底，否则编辑器单场景调试会黑屏；
  3. 代码量 ≤ 500 行；
  4. 不改服务端。

## 二、核心 API 清单

| API | 出处 | 用途 |
| --- | --- | --- |
| `AssetManager.IsInitialized` | `Framework/Asset/AssetManager.cs` | 判断资源层是否可用 |
| `AssetManager.LoadSceneAsync(address, LoadSceneMode)` | 同上 | 走 YooAsset 加载场景 |
| `ISceneHandle.IsDone / Progress / Error / Dispose` | `Framework/Asset/SceneTypes.cs` | 轮询进度、拿错误、释放句柄 |
| `SceneManager.LoadSceneAsync(name, mode)` | UnityEngine | 兜底路径 |
| `EditorBuildSettings.scenes` | UnityEditor | 场景必须注册，否则真机加载失败 |

## 三、现状与关键事实

| 事实 | 影响 |
| --- | --- |
| YooAsset 收集器只收集 `Assets/_Project/Scenes`（`scene_dev` 组，`AddressByFileName` + `SupportExtensionless=1`） | 场景必须放进这个目录才会被打包 |
| 负责人新建的 5 个场景原本在 `Assets/Scenes` | **已移到 `Assets/_Project/Scenes`**（含 .meta） |
| Build Settings 原本只有 `Scene_AOTProbe` | **已重写为 5 个正式场景**（Login/World/PVP_Room/Battle/Test） |
| 项目里从未真正调用过场景加载 API | 需要新写一个入口，且要处理"没初始化"的情况 |

## 四、方案对比

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| A. 直接 `SceneManager.LoadScene` | 最简单 | 绕开资源层，日后要改 | 只做兜底 |
| B. 只走 `AssetManager`（YooAsset） | 与资源/热更体系一致 | 资源层未初始化时会抛异常 | 主路径 |
| **B + A 兜底** | 主路径规范、调试不黑屏 | 两条路径要各测一次 | **采用** |

## 五、已知坑

1. **地址是"文件名去扩展名"**：`World.unity` 的地址是 `World`，不是 `Assets/...`（收集器 `AddressByFileName`）。
2. **场景不在 Build Settings** ⇒ 真机/真包加载失败，编辑器里却可能正常。
3. **YooAsset 的 `Dispose` 只释放句柄**，卸载要 `UnloadScene`；本需求是"切走"，由引擎卸载旧场景即可，只释放句柄。
4. **重复点击**会导致两个协程抢着激活场景 ⇒ 必须加 `IsLoading` 闸门。
5. 场景移动后 **Build Settings 里的旧路径会失效**（必须重写，已处理）。

## 六、结论

- 新增 `GameSceneAddress`（枚举→地址）与 `SceneFlow`（单例 + 协程加载 + 兜底），再加 `SceneFlowDebugKeys` 方便手工验收。
- 场景位置与 Build Settings 已经就绪。
