# 01 技术预研

需求：R034-World 玩家角色（本地可操控）
所属阶段：M4
作者：AI　状态：待确认（2026-11-13）

## 一、调研目标与约束

- 目标：在 `World` 里能用 WASD 操控一个角色走动，相机跟着他，人贴着地形走。
- 约束：**先本地**（不连服务端）；不新建美术（复用美术包里的剑士模型）；代码 ≤ 500 行。

## 二、现状（实测）

| 项 | 事实 | 出处 |
| --- | --- | --- |
| Battle 的 Player | 一个**胶囊占位**（MeshFilter + MeshRenderer + CapsuleCollider）+ `PlayerMove` | `Battle.unity` 解析 |
| 移动逻辑 | `PlayerMove` 读 `InputManager.Instance.Current`，直接改 `Transform.position`，四向转身 | `PlayerMove.cs` |
| 输入 | `InputManager : Singleton<InputManager>`，第一次访问自动创建 | `InputManager.cs:17` |
| 相机 | `FollowCamera` 在 Main Camera 上，靠 `m_target` 跟人；**没有公开的改目标方法** | `FollowCamera.cs` |
| World 现状 | 只有 `WorldOrbitCamera`（观察相机），没有玩家 | `World.unity` |
| 环境可走性 | 环境场景有 Terrain + TerrainCollider + 52 个 MeshCollider | R033 实测 |

## 三、方案对比

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| A. 复用 Battle 的胶囊占位 | 零美术成本 | 白胶囊在森林里很难看 | 否 |
| **B. 剑士模型 + PlayerMove + 跟随相机** | 好看、复用现成移动逻辑 | 需要接线（模型/相机/贴地） | **采用** |
| C. 自己做一套移动 | 完全可控 | 重复造轮子（违反规则 12） | 否 |

## 四、关键技术判断

| 判断 | 理由 |
| --- | --- |
| 移动直接复用 `PlayerMove` | 四向转身/输入量化都调好了，别重写 |
| 相机复用 `FollowCamera` | 已有平滑跟随与"镜头不跟转身"的约定（2026-10-28 定的） |
| 要给 `FollowCamera` 加 `SetTarget` | 玩家是运行时才确定的，必须能改目标 |
| 贴地用向下射线 | 环境是起伏地形；不贴会浮空/陷地 |
| 有玩家就关观察相机 | 两套相机都写 `transform.position` 会打架 |

## 五、已知坑

1. `FollowCamera.m_target` 是 `private` + `[SerializeField]`，没有 setter ⇒ 必须先加 `SetTarget`。
2. `PlayerMove` 依赖 `InputManager.Instance`；它自动创建，但**必须有焦点**（Game 视图）。
3. 环境里的树/房子有 MeshCollider，人也可能卡在里面（本版不做碰撞体，先穿过去）。
4. 贴地射线要忽略 Trigger，否则会被装饰物的触发器挡住。
5. 玩家模型朝向：与狼一样，美术模型默认朝 +X 的要加朝向偏移（本版先看效果再定）。

## 六、结论与改动清单

- 新增 `WorldPlayerSetup`（接线 + 贴地）
- 修改 `FollowCamera`（加 `SetTarget`，7 行）
- World 场景：新增 `[Player_Hero]`（剑士模型 + `PlayerMove` + `WorldPlayerSetup`），Main Camera 加 `FollowCamera`
