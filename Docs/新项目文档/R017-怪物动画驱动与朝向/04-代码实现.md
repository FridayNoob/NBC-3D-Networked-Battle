## 一、子任务与约束

- 只改 `SnapshotSceneBinder` 一个文件；怪物 prefab、controller、服务端、协议全部零改动。

| 子任务 | 落点 |
| --- | --- |
| 走路参数 | 常量 `WalkParameter = "Walk"` + `Animator.SetBool` |
| 朝向 | `FacingDeg` + `m_facingOffsetDegrees` → `localRotation` |
| 参数缺失保护 | `Slot.HasWalkParameter` / `Slot.WarnedMissingWalk`（只告警一次） |
| Root Motion | 创建槽位时强制 `applyRootMotion = false` |
| 两个 Inspector 参数 | `m_facingOffsetDegrees`、`m_moveAnimationThreshold` |

## 二、功能概述

每帧按「当前到目标的水平距离」判断是否在移动 → 设 `Walk` Bool；按快照 `FacingDeg` 写朝向后，再交给位置推进（R006/R015 的链路不变）。

## 三、接口与入参出参

| 成员 | 入参 | 出参 | 说明 |
| --- | --- | --- | --- |
| `DriveAnimation(Slot, int facingDeg, Vector3 target)` | 槽位、朝向、目标 | 无 | 每帧每实体一次 |
| `m_facingOffsetDegrees` | — | 度 | 模型前向不是 +Z 时纠正 |
| `m_moveAnimationThreshold` | — | 米 | 移动判定阈值（默认 0.05） |
| `Slot.HasWalkParameter` | — | bool | controller 是否有 Walk(Bool) |

## 四、逐段讲解

1. **为什么用「到目标的距离」而不是速度**：刚体速度有噪声，停下瞬间会抖；距离是确定值。
2. **为什么参数要先查**：不同怪的 controller 参数名不一样（狼是 `Walk`，别的包可能是 `Speed`/`MoveSpeed`），直接 `SetBool` 会每帧抛异常/刷日志。
3. **为什么 Root Motion 必须在运行时关**：狼的 controller 里同时有 `Walk With Root Motion` 与 `Walk Without Root Motion` 两套状态，prefab 上的开关可能被改成 true。
4. **朝向偏移为什么做成 Inspector**：模型前向（+Z/−Z/±X）无法从数据推断，只能试；做成字段就能不改代码纠正。

// ① 常量
// 怪物 controller 里的走路参数名（Bool）；狼的 controller 就是靠它从 Idle 切到 Walk
private const string WalkParameter = "Walk";

// ② 两个 Inspector 参数

[SerializeField]
private float m_facingOffsetDegrees = 0f;

[SerializeField]
private float m_moveAnimationThreshold = 0.05f;

// ③ Slot 新增
public readonly Animator Animator;          // 子物体上的动画器
public readonly bool HasWalkParameter;      // controller 有没有 Walk(Bool)
public bool WarnedMissingWalk;              // 只告警一次

// ④ LateUpdate 里调用
DriveAnimation(slot, e.FacingDeg, target);
MoveSlotTo(slot, target);

## 七、风险与幻觉自查

- 幻觉自查：只用 `Animator.SetBool` / `Animator.parameters` / `Quaternion.Euler` / `Transform.localRotation`，均既有 API。
- 行为变化：怪物开始播动画；朝向从「永远 +Z」变成「跟快照」。
- 风险：`FacingDeg` 是 30Hz 更新 ⇒ 转向会「跳格」（R006 只平滑了位置，朝向未平滑）。
- 风险：不同怪的 controller 若没有 `Walk` 参数，会只告警一次且不播动画（位置/朝向仍正常）。
