# 02 需求

需求：R017-怪物动画驱动与朝向
所属阶段：M4
作者：LYF（口述确认，AI 落稿）　状态：已确认（2026-11-05）

## 一、业务目标（一句话）

**怪物走动时播走路动画、并朝着它走的方向**，不再是「滑行的模型」。

## 二、用户与使用场景

- 用户：开发期负责人；最终玩家。
- 场景：狼朝你走过来时，腿在动、脸朝你；停下时腿停。

## 三、功能列表（P0 / P1 / P2）

| 功能 | 优先级 | 说明 |
| --- | --- | --- |
| 移动时播走路动画 | P0 | 设 `Walk` Bool（狼 controller 已备好这条转移） |
| 停下回 Idle | P0 | `Walk` = false |
| 朝移动方向转身 | P0 | 用快照 `FacingDeg` |
| 朝向偏移可配 | P0 | 模型前向未必是 +Z，加一个 Inspector 偏移（不给代码留后门） |
| 参数缺失只报一次 | P1 | 不同怪 controller 参数名可能不同 |
| 跑步动画 | P2 | 暂时 `Run` 恒 false（服务端没有跑的概念） |
| 攻击/受击/死亡动画 | P2 | 需要战斗逻辑，另开需求 |

## 四、边界（**本版明确不做**）

- 不改服务端与协议（`FacingDeg` 早就有）。
- 不改本地玩家的动画链路（`PlayerAnimation` 只管自己）。
- 不做转向平滑（30Hz 快照驱动，朝向会每 33ms 更新一次；先接受）。
- 不做跑步、攻击、受击、死亡动画。

## 五、优先级

**P0**。依赖：R015（模型接入）、R006（位置平滑）。

## 六、验收标准（「当…时，应…」）

- [ ] 当 狼朝玩家移动时，应**播放走路动画**（腿在动），而不是滑行
- [ ] 当 狼停下时，应**回到 Idle**（腿停）
- [ ] 当 狼往不同方向移动时，模型应**朝着移动的方向**（不是固定朝一个方向）
- [ ] 当 模型朝向反了时，改一个 Inspector 偏移量应能纠正（**不用改代码**）
- [ ] 当 controller 里没有 `Walk` 参数时，应只警告一次并继续运行（不刷屏、不崩）
- [ ] 当 播放动画时，模型不应「自己往前跑」（Root Motion 必须关）
