# 01 技术预研

需求：R017-怪物动画驱动与朝向
所属阶段：M4
作者：AI　状态：已确认（2026-11-05）

## 一、调研目标与约束

- 目标：怪物**会播走路动画**、**朝着它走的方向**（用快照里的 `FacingDeg`），不再是「滑行的模型」。
- 约束：
  1. 不改服务端、不改协议；
  2. 不改 `PlayerMove`/`PlayerAnimation`（那只管本地玩家）；
  3. 动画由**怪物自带的 controller** 驱动，不新建状态机。

## 二、素材与控制器的真实情况（实测）

| 项 | 结论 |
| --- | --- |
| 狼 prefab | 有 `Animator`，controller = `Forest Wolf - Controller`，**默认状态 Idle** |
| 参数 | `Walk`(Bool)、`Run`(Bool)、`Jump`(Trigger)、`Spell Cast`、`Die`、`Take Damage`、`Claw Attack`、`Bite Attack`、`Breath Attack` |
| 关键转移 | `Idle → Walk Without Root Motion`：条件 **`Walk` = true**；反向：`Walk` = false |
| 另一条 | `Idle ↔ Run`：条件 `Run` = true/false |
| 命名含义 | 包里把「带 root motion / 不带 root motion」拆成两套状态，我们只用**不带 root motion** 的那套 |

⇒ **驱动方式极简**：移动时 `SetBool("Walk", true)`，停下 `false`；`Run` 保持 false。

## 三、朝向数据

| 项 | 结论 |
| --- | --- |
| 协议 | `EntitySnapshot.FacingDeg`（字段号 8）存在 |
| 表现层 | `PresentationSource` 已经把 `FacingDeg` 复制进缓冲（`target.FacingDeg = source.FacingDeg`） |
| 使用方 | **binder 完全没用它** ⇒ 朝向从未被写进场景 |

## 四、方案对比

| 方案 | 做法 | 评价 |
| --- | --- | --- |
| **A（采用）** | 在 `SnapshotSceneBinder` 里：按「当前到目标的水平距离」判定移动 ⇒ 设 `Walk` Bool；按 `FacingDeg` 写 `localRotation` | 改动集中一处；不用新建组件 |
| B | 给每个槽位挂一个 `MonsterAnimatorDriver` 组件 | 更适合「以后每只怪逻辑不同」，但现在没必要 |
| C | 按速度阈值驱动（用刚体 velocity 大小） | 刚体速度有噪声，且停下瞬间会抖动 |

## 五、已知坑

1. **Root Motion 必须关**：狼有「With Root Motion」的状态，若 `applyRootMotion = true`，动画会把模型再推一次（与 `velocity` 叠加，跑飞）。
2. **朝向偏移未知**：模型前向未必是 +Z。先用 0° 试，方向反了就调一个可配偏移（不加代码）。
3. **刚体冻结旋转**：`freezeRotation = true` 时用 transform 写旋转是安全的（物理不改旋转）。
4. **`Walk` 参数可能不存在**：不同怪物 controller 的参数名可能不同；要**先检查再 SetBool**，缺了只报一次告警（否则每帧刷屏）。
5. **停下瞬间抖动**：用「到目标的水平距离 > 阈值」判定（阈值 5 厘米），不要用速度。
6. **朝向跳变**：30Hz 快照 ⇒ 朝向每 33ms 更新一次，转向会「跳格」；先接受（R006 只平滑了位置）。

## 六、结论与改动清单

结论：**在 binder 里根据「到目标的距离」驱动 `Walk` Bool，并写 `FacingDeg`**；`Run` 恒 false；`applyRootMotion` 强制关。

要改：
- `SnapshotSceneBinder`：`Slot` 缓存 `Animator` 与 `Walk` 参数是否存在；`LateUpdate` 里判定移动、设 Bool、写朝向；新增两个 Inspector 参数（朝向偏移、移动判定阈值）。
