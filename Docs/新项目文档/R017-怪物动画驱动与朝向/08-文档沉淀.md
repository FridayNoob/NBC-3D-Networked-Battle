## 二、模块文档

### 简介与使用场景

`SnapshotSceneBinder`（`Game\View\`）除了搬位置，现在还会**驱动怪物动画**与**朝向**：
- 移动判定 → `Animator.SetBool("Walk", moving)`
- 朝向 → `localRotation = Euler(0, FacingDeg + 偏移, 0)`

### 核心契约

| 项 | 值 | 谁在用 |
| --- | --- | --- |
| Animator 参数 | **`Walk`（Bool）** | 狼的 controller：`Idle ↔ Walk Without Root Motion` |
| 快照字段 | `EntitySnapshot.FacingDeg`（度） | 朝向 |
| `m_facingOffsetDegrees` | Inspector，默认 0 | 模型前向不是 +Z 时纠正 |
| `m_moveAnimationThreshold` | Inspector，默认 0.05 米 | 「多远算在动」 |
| `applyRootMotion` | **强制 false** | 防止素材包的 Root Motion 与物理叠加 |

### 使用示例（负责人亲手跑通，2026-11-05）

```text
Play → 狼朝你走来：腿在动、脸朝你
      停下：回 Idle
换一只怪：把它的 prefab 指给 HpBarDemo；若参数名不是 Walk，Console 会提示一次
```

### 已知限制与坑点

- **朝向没有插值**：30Hz 快照驱动，转向会跳格。
- 只驱动 `Walk`；`Run`/攻击/受击/死亡未接。
- 参数名写死 `Walk`：换包若不同名需要加映射（当前只告警一次）。
- 动画步频与物理速度（1.2 米/秒）未对齐，可能有轻微脚滑。
- 朝向偏移只能覆盖「整体旋转」，模型若轴系歪斜（pitch/roll）还得在 prefab 里改。

### 修改维护注意事项

- **换素材**：先看它的 controller 有没有 `Walk`(Bool)；没有就加参数映射，别硬设。
- **别在 state 里读 `Time`**：状态机是数据驱动，动画只是表现。
- **朝向与位置同源**：都来自同一快照，别一者插值一者不插值导致「脸和身体不同步」。
- **Root Motion 永远运行时强制关**。

## 三、踩坑清单（现象 / 原因 / 解决）

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 怪物滑行没动画 | 从没驱动过 Animator | `SetBool("Walk", moving)` |
| 模型自己往前跑 | Root Motion 开着 | 运行时强制关 |
| 朝向永远是 +Z | `FacingDeg` 没人读 | 写 `localRotation` |
| Console 每帧刷参数缺失 | 没做存在性检查 | 建槽位时查一次 + 只告警一次 |
| 朝向反了 180° | 模型前向不是 +Z | 调 `Facing Offset Degrees` |
