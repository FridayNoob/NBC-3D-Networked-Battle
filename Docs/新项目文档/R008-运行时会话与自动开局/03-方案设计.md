所属阶段：M4
作者：AI 起草　状态：已确认（2026-10-29）

## 一、整体架构

一个 MonoBehaviour 把六件事按顺序做完，**复用 Editor 窗口已有的同一份逻辑**（不是重写）：

```
RuntimeNetDriver (Game.Net)
  ├─ CountingTransport → NetSession          （R004 的装饰器，HUD 有字节）
  ├─ PresentationFeed                        （Game.Net 已有：快照 / 锁步二选一）
  ├─ SnapshotSceneBinder.Ensure(feed.View)   （Game.View 已有：分发到 3D）
  └─ NetRuntimeStats.SetMode/SetRtt/SetFrame （R004 的静态统计，HUD 只读）
```

## 二、模块划分

| 模块 | 负责什么 | **不负责**什么 |
| --- | --- | --- |
| `RuntimeNetDriver`（新增） | 建会话、每帧 `Pump`、自动进房、节流发输入、喂表现层、写 HUD 统计 | 不重连（R007）、不做 UI |
| `PresentationFeed`（复用） | 决定「读快照还是读锁步世界」，并处理卡帧回退 | 不管连接 |
| `SnapshotSceneBinder`（复用） | 把 `SnapshotView` 分发到 3D 物体 | 不管数据来源 |
| `NetRuntimeStats`（复用） | HUD 的只读数据源 | 不建连 |
| `HpBarDemoBehaviour`（改） | 资源层装好后 `AddComponent<RuntimeNetDriver>()` 并注入参数 | 不碰网络细节 |

## 三、接口（★ 先定死）

```
// Game.Net
public enum ERuntimeSyncMode { StateSync = 0, Lockstep = 1 }

public sealed class RuntimeNetDriver : MonoBehaviour
{
    // Inspector
    string m_host = "127.0.0.1";
    int    m_port = 7778;
    string m_account = "dev1";
    string m_password = "dev-pw1";
    int    m_dungeonId = 1001;
    ERuntimeSyncMode m_mode = ERuntimeSyncMode.StateSync;
    float  m_inputSendInterval = 0.05f;   // 20Hz

    // 只读状态（调试/测试用）
    bool   IsOnline { get; }       // 握手成功
    bool   IsJoined { get; }       // 已进房
    string LastError { get; }

    // 生命期
    void Start();   // 建传输/会话、订阅事件
    void Update();  // Pump → 进房 → 发输入 → 喂表现 → 写统计
    void OnDestroy(); // 主动断开 + Reset 统计
}

// 复用（不改签名）
PresentationFeed.Refresh(long playerId, SnapshotView snapshot, WorldState lockstepWorld, int lockstepFrame, bool lockstepStarted, int matchSerial)
PresentationFeed.View
SnapshotSceneBinder.Ensure(SnapshotView view, long ownerPlayerId)
```

## 四、数据结构

| 数据 | 类型 | 含义 / 单位 | 谁改它 |
| --- | --- | --- | --- |
| `deltaMs` | int | 本帧毫秒，**真实值** | `Update` |
| `m_inputSendInterval` | float | 上行节流间隔，秒（默认 0.05） | Inspector |
| 上次发送时刻 | float | 用于节流累加 | `Update` |
| 状态 | 内部枚举 | Idle / Connecting / Handshaking / Online / Joined / Failed | 事件回调 |

## 五、时序与流程

1. `Start`：`CountingTransport(new TcpTransport())` → `new NetSession(...)` → 订阅 `HandshakeCompleted` / `StateChanged`。
2. 每帧 `Update`：
   1. `m_session.Pump(round(Time.deltaTime * 1000))`；
   2. 若 Online 且未进房 → `JoinRoom("", m_dungeonId)`（只发一次）；
   3. 若已进房 → 按 `m_inputSendInterval` 节流发输入（锁步：`SendLockstepInput`；状态同步：`SendInput`）；
   4. `feed.UseLockstep = (m_mode == Lockstep)` → `feed.Refresh(...)`；
   5. `m_binder = SnapshotSceneBinder.Ensure(feed.View, playerId)`（缓存，不每帧找）；
   6. 写统计：`SetMode` / `SetRtt(m_session.RttMs)` / `SetFrame(帧号)`。
3. 失败/断开：`LastError` 记一句人话 + `Debug.LogError` + **停止发输入** + `SetMode(Offline)`。

## 六、技术选型与理由

| 选择 | 选定 | 理由 | 被否的方案 |
| --- | --- | --- | --- |
| 表现层复用 | **用 `PresentationFeed`** | 与 Editor 同一条路径，行为一致、不会两套逻辑 | 运行时另写一份选择逻辑 |
| 输入节流 | **20Hz** | 60Hz 上行对状态同步没意义，只会让带宽表难看 | 每帧发 |
| 会话持有 | **驱动程序持有** | 单一持有者，`OnDestroy` 能干净断开 | 静态单例（谁都能建，容易双份） |
| 进房时机 | 握手成功后**一次性** | 简单；服务端 `fill-seats` 自动开局 | 定时重试进房 |
| 装配位置 | Boot 侧 `AddComponent` | 资源层装好后才该建会话（顺序重要） | 场景里手挂（容易漏） |

## 七、风险与对策

- **与 Editor 窗口同时连** ⇒ 两个座位、两份会话。对策：文档与 06 明确「验收时二选一」。
- **`Pump` 用固定 16ms** ⇒ 时钟漂移、心跳超时误判。对策：真实 `Time.deltaTime * 1000`。
- **上行不节流** ⇒ 带宽表难看、服务端压力大。对策：默认 20Hz，可调。
- **断开后继续发输入** ⇒ `Send` 会抛/静默失败。对策：失败即置状态并停止上行。
- **`SnapshotSceneBinder` 每帧 `Ensure`** ⇒ 有 `FindFirstObjectByType` 开销。对策：缓存引用。
- **锁步未开始时 `feed.View` 可能为空世界** ⇒ `PresentationFeed` 已有卡帧回退逻辑，直接复用（`StallRefreshThreshold`）。
