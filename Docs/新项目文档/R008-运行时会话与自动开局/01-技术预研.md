## 〇、先纠正一条昨天的错误判断

昨天在 R004 的 01 里我写过「纯运行时没有锁步步进驱动者」。**核查源码后这句是错的**：

- `NetSession.DrainInbox` 收到 `LockstepFrame` → `HandleLockstepFrame` → `LockstepClient.ApplyFrame` → **当场 `WorldStep.Step`**（`LockstepClient.cs:436`）。
- 也就是说 **帧一到就步进**，不需要额外的「步进器」。

真正缺的是另外三件事：**谁建会话、谁每帧调 `Pump`、谁发本地输入**。Editor 窗口只是恰好把这三天都包了。
本需求就是把这三件事搬到运行时。

## 一、调研目标与约束

- 目标：**Play 之后不打开任何 Editor 窗口**，程序自己连接、进房、跑起来（角色能走、能看到别人/怪）。
- 约束（负责人 2026-10-29 定）：
  1. 连接参数放 **Inspector 字段**（host / port / 账号 / 密码 / 副本号），Play 后自动连；
  2. **自动进房**（房号留空 = 服务端安排）；
  3. **发本地输入**（状态同步走 `SendInput`，帧同步走 `SendLockstepInput`）；
  4. 运行时同步方式由 **Inspector 枚举**决定（状态同步 / 帧同步）。

## 五、已知坑与版本兼容

1. **`Pump` 的 `deltaMs` 必须是真实毫秒**：传固定 16 会在低帧率下把内部时钟拖慢，心跳/超时全偏。
2. **上行要节流**：状态同步每帧发一条 = 60 条/秒，带宽表会很难看；按 `~50ms`（20Hz）发。锁步用 `SendLockstepInput`，它自己有前导帧判断（重复帧会被 `CanSendLockstepInput` 挡掉）。
3. **两种模式不能同时发**：服务端两条链都在跑，同时发会让权威数据打架 ⇒ 按枚举二选一。
4. **HUD 同源**：驱动必须写 `NetRuntimeStats.SetMode/SetRtt/SetFrame`，否则面板永远显示「离线」。
5. **别和 Editor 窗口同时连**：会占两个座位/两份会话，验收时二选一。
6. **断开只停不重连**：重连属 R007，本需求遇到断开就标状态并停止上行。
7. **`SnapshotSceneBinder.Ensure` 幂等**：内部 `FindFirstObjectByType`，每帧调也只会有一个；但仍建议缓存。
8. **`fill-seats=4`**：服务端填满座位自动开局，客户端不需要按「开始」。

## 六、结论与要改的东西

结论：**新增一个运行时驱动（`RuntimeNetDriver`），把「建会话 + 每帧 Pump + 进房 + 发输入 + 喂表现层 + 写 HUD 统计」六件事按顺序做完**；由 Boot 侧负责创建它。

- 新增 `Client\Assets\_Project\Game\Net\RuntimeNetDriver.cs`（MonoBehaviour）。
- 改 `Boot\HpBarDemoBehaviour.cs`：资源层装好后 `AddComponent<RuntimeNetDriver>()` 并按 Inspector 参数初始化（或由场景直接挂）。
