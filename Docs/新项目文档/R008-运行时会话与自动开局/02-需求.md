# 02 需求

需求：R008-运行时会话与自动开局
所属阶段：M4
作者：LYF（口述确认，AI 落稿）　状态：已确认（2026-10-29）

## 一、业务目标（一句话）

**Play 之后不打开任何 Editor 窗口，程序自己连服务器、进房、让角色动起来** —— 这样「游戏」才成立，而不是「调试面板」。

## 二、用户与使用场景

- 用户：开发期负责人（以后也是玩家）。
- 场景：开服 → Play → 3 秒内进房 → 用 WASD 走 → 有别人/怪时也能看到它们动。
- 反面场景：没开服就 Play —— 要有明确提示，不许崩、不许静默卡住。

## 三、功能列表（P0 / P1 / P2）

| 功能 | 优先级 | 说明 |
| --- | --- | --- |
| 自动连接 | P0 | Play 后自动连 Inspector 上的 host:port，用给定账号 |
| 自动进房 | P0 | 握手成功后 `JoinRoom("", 副本号)`（空房号 = 服务端安排） |
| 每帧驱动会话 | P0 | `Pump(deltaMs)`，真实毫秒 |
| 发本地输入 | P0 | 状态同步走 `SendInput`（节流 20Hz）、帧同步走 `SendLockstepInput` |
| 运行时选择同步方式 | P0 | Inspector 枚举：状态同步 / 帧同步 |
| 写 HUD 统计 | P0 | 模式 / 帧号 / RTT 写进 `NetRuntimeStats`（否则面板永远「离线」） |
| 失败提示 | P0 | 连不上/握手失败/断开 ⇒ Console 一句人话 + 停止上行 |
| 自动重连 | P1 | **本版不做**，归 R007 |
| 登录界面 / 选角色 | P2 | 以后再做 |

## 四、边界（**本版明确不做**）

- 不做断线重连、不做重试退避（R007）。
- 不做登录/选服 UI（参数在 Inspector）。
- 不改服务端。
- **不与 Editor 窗口同时连**（会占两个座位、两份会话）。
- 不做「暂停/恢复会话」。

## 五、优先级

**P0**。依赖：R004（HUD 统计同源）、`NetSession`（已有）、`SnapshotSceneBinder`（已有）。

## 六、验收标准（「当…时，应…」）

- [ ] 当 服务端已启动（`--port=7778 --dev-accounts --fill-seats=4`）且 Play 时，应 3 秒内握手成功并自动进房
- [ ] 当 进房后按住 W 时，角色应移动，且上行带宽明显**大于**空闲时（说明输入真的发出去了）
- [ ] 当 把枚举切到「帧同步」并重进 Play 时，HUD 模式应显示「帧同步」、帧号随广播递增
- [ ] 当 枚举为「状态同步」时，HUD 帧号应等于快照 tick 并递增
- [ ] 当 会话断开（把服务端关掉）时，HUD 应回到「离线」，且不再刷帧号
- [ ] 当 没开服务端就 Play 时，Console 应有明确失败提示，**不许崩、不许静默卡住**
