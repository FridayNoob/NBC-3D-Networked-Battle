## 二、模块文档

### 简介与使用场景

`RuntimeNetDriver`（Game.Net）：Play 后自动连服、进房、发输入、喂表现层、写 HUD 统计。
**它是「游戏能自己跑起来」的入口**；以前这些事只有 Editor 窗口能做。

### 核心接口

| 项 | 类型 | 说明 |
| --- | --- | --- |
| `m_host` / `m_port` | Inspector | 默认 `127.0.0.1` / `7778` |
| `m_account` / `m_password` | Inspector | 开发账号 `dev1` / `dev-pw1` |
| `m_dungeonId` | Inspector | 副本编号，默认 `1001` |
| `m_mode` | Inspector | `StateSync` / `Lockstep`（**改完要重进 Play**） |
| `m_inputSendInterval` | Inspector | 上行节流，默认 `0.05`（20Hz） |
| `IsOnline` / `IsJoined` / `LastError` | 只读属性 | 给测试与调试用 |

### 使用示例（负责人亲手跑通，2026-10-30）

```text
1) 开服：NBC.Server.Host.exe --port=7778 --dev-accounts --fill-seats=4
2) 断开 Editor「网络调试」窗口的连接（避免两个座位）
3) Play → Console「握手完成」→ HUD 显示状态同步、帧号递增
4) 按 WASD → 角色动，上行带宽明显变大
5) 想看帧同步：把 Mode 改 Lockstep，重进 Play
```

### 实现原理（简要）

`Start` 建 `CountingTransport` + `NetSession` 并 `Connect`；`Update` 里 `Pump(deltaMs)` → 在线则 `JoinRoom("", dungeonId)`（只一次）
→ 进房后按 20Hz 发输入（锁步 `SendLockstepInput` / 状态同步 `SendInput`）→ `PresentationFeed.Refresh` 喂 `SnapshotSceneBinder`
→ 写 `NetRuntimeStats`（HUD 只读）。

### 已知限制与坑点

- 无重连、无登录 UI、只验单客户端。
- 与 Editor 窗口同时连会占两个座位。
- `Mode` 改动需重进 Play。
- 断开后要重进 Play 才能再连。

### 修改维护注意事项

- **不要**在驱动里另算带宽或另建统计 —— HUD 只读 `NetRuntimeStats`。
- 加新上行类型：只在 `PumpInput` 里按模式分派，别开第二条路径。
- `Pump` 的 `deltaMs` 必须真实毫秒。

| 现象 | 原因 | 解决 |
