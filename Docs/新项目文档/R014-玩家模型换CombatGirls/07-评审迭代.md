## 三、根因分析

- #1：之前调试 Unity-chan 时**重复挂过**脚本（`AddComponent` 点了两次），一直没清；两份 `Update` 都在跑 ⇒ 位移与动画各算两遍。
  教训：**换模型前先体检旧物体**（组件是否重复、是否还有演示脚本）。
- #2#3：模型是「从包里整包拖进来的」，它的 Animator 沿用包里的示例配置（借 Humanoid_F 的 Avatar、开 Root Motion），而我们的项目约定是「代码直接改 transform」。
  教训：**换模型必须核对三样**：Avatar 归属、Apply Root Motion、Controller 绑定。
- #4：我按 `PlayerAnimation` 里只看到了 `Speed`，实际它**同时**要 `Speed` 与 `Direction`（读代码时漏了下半段）。
  教训：**加参数前把 `ValidateParameter` 的调用点读全**，别凭印象。
- #5：`SwitchSocket` 是**动画事件**，接收者在美术脚本里；我按「演示脚本一律删」处理，删多了。
  教训：删演示脚本前，先在 Console 看有没有它的动画事件；**动画事件是隐式依赖**。
- #6：我用文件里搜到的 `IDLE`/`WALK` 当状态名，其实那是**动画片段名**；真正的状态名是 `S_Idle` 等。
  教训：状态名要用 `stateMachine.states` 枚举，**不要用 grep 猜**。

## 八、教训（可复用判据）

1. **换模型体检三样**：Avatar 是否属于本模型、`Apply Root Motion` 是否为 false、Controller 是否指向预期控制器。
2. **加 Animator 参数前，把校验代码读全**（本需求要 `Speed` + `Direction` 两个）。
3. **状态名要从 `stateMachine.states` 枚举**，不要用 grep 猜（`S_Idle` ≠ `IDLE`）。
4. **删美术脚本前先看有没有动画事件**（`SwitchSocket` 这类隐式依赖）。
5. **换模型前清旧物体的重复组件**（同一脚本挂两份 = 双倍执行）。

## 九、遗留（如实）

- 控制器里有 4 个打包残留 Float 参数（名字是 `----normal` 之类），无害；要清理得另开需求（清错会让转移条件失效）。
- 只做了 `S_Idle` / `S_Walk` 两态；跑（Run）、攻击、受击、死亡都还没接。
- SwordGirl 带 Magica Cloth，比 Unity-chan 重；多角色同屏（PVP）时要复测帧率。
- Unity-chan 物体仍在场景里（**已禁用**），日后确认不需要再删。
