## 二、模块文档

### 简介与使用场景

玩家角色 = `SwordGirl_FullBody`（来自 `CombatGirlsCharacterPack`），动画由 `Sword_Controller` 用 **Float `Speed`** 驱动 Idle/Walk。
移动逻辑完全复用 `PlayerMove`（R013：四向转身），动画由 `PlayerAnimation` 喂参数 —— **两者与模型无关**，所以这次**零代码改动**。

### 核心接口（Animator 契约）

| 项 | 值 | 谁在用 |
| --- | --- | --- |
| Float `Speed` | −1..1，`ForwardSpeed / 5` | `PlayerAnimation.LateUpdate` |
| Float `Direction` | −1..1，`SideSpeed / 5` | 同上（当前两态动画未用它做混合） |
| 状态 `S_Idle` | 默认状态 | — |
| 状态 `S_Walk` | 移动状态 | — |
| 转移 | `S_Idle → S_Walk`：`Speed > 0.1`；`S_Walk → S_Idle`：`Speed < 0.1`；**Has Exit Time 取消**；0.15 秒 | — |

### 使用示例（负责人亲手跑通，2026-10-31）

```text
Play → 站着：S_Idle
     → 按 W/A/S/D：S_Walk，角色朝该方向走
     → 松手：0.15 秒内回 S_Idle
```

### 实现原理（简要）

`PlayerMove` 每帧算实测位移 → 拆前后/左右分量 → `PlayerAnimation.LateUpdate` 除以 `MoveSpeed` 后写 `Speed`/`Direction`（带 damping）
→ 控制器按阈值在 `S_Idle` / `S_Walk` 之间过渡。

### 已知限制与坑点

- 只有 Idle / Walk 两态（无 Run、无攻击、无受击、无死亡）。
- `Sword_Controller` 是**动作展示台**，有 41 个参数，其中 4 个是打包残留的分隔线 Float；多出来的演示 Trigger 不要发送。
- `Character_Weapon_Controller` **必须保留**：`S_Idle` 上有 `SwitchSocket` 动画事件依赖它。
- `SDFFaceShadowController` 要保留（面部阴影）。
- 模型不在仓库（授权不明 + 体积），别人 clone 后这个物体会缺模型。

### 修改维护注意事项

- **换/加模型必查三样**：Avatar 属于本模型、`Apply Root Motion = false`、Controller 指向正确。
- **加 Animator 参数前先把 `PlayerAnimation` 的校验读全**（要 `Speed` + `Direction`）。
- **状态名用 `stateMachine.states` 枚举**，别 grep（`S_Idle` ≠ `IDLE`）。
- 想退回 Unity-chan：把 `unitychan` 重新启用即可（重复组件已清理；它的 Controller 仍指向 `UnityChanLocomotions`）。

## 三、踩坑清单（现象 / 原因 / 解决）

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 移动速度翻倍 | 旧物体上挂了两份 `PlayerMove` | 删掉重复组件 |
| 模型扭曲拉长 | Avatar 借的是别的模型 | 导入设置改 `Create From This Model`，重新指定 Avatar |
| 角色自己漂移 | `Apply Root Motion = true` | 置 false |
| Console：`没有 Float 参数 Direction` | 只加了 `Speed` | 补 `Direction` |
| Console：`SwitchSocket ... has no receiver` | 删了 `Character_Weapon_Controller` | 加回该脚本 |
| 按状态名 `IDLE` 找不到状态 | 真实状态名是 `S_Idle` | 用 `states` 枚举真实名字 |
