## 一、文档范围

本需求只覆盖 `Login` 场景的主菜单与「点开始才连服」的入口流程；不含 World/Battle 内的界面，也不含设置项的真实功能（R047）。

## 二、模块文档

### 2.1 MainMenuState（纯逻辑）

- 简介：昵称规范化、能不能点开始、提示文案，三件事都在这里。
- 接口：`NormalizeName(string)`、`SetPlayerName(string)`、`BeginConnect()`、`Fail(string)`、`Succeed()`；只读 `PlayerName/CanStart/IsConnecting/IsSucceeded/Hint`。
- 示例：`if (!state.BeginConnect()) return;` —— 连点第二次直接返回 false。
- 原理：把「按钮能不能点」变成状态判断，界面只是消费者；所以连点保护能单测，不依赖 Play。
- 坑：`Succeed()` 之后 `CanStart` 必须保持 false，否则切场景时会话被重复创建。
- 维护：新增按钮/流程时只加方法，不要往 View 里塞判断。

### 2.2 MainMenuView（运行时 UGUI）

- 简介：用代码搭标题、昵称框、剑士卡片、三个按钮与提示行。
- 接口：`Bind(Action,Action,Action)`、`ReadName/SetName`、`SetStartLabel/SetStartInteractable/SetHint`。
- 示例：`view.SetStartLabel(state.IsConnecting ? "连接中…" : "开始游戏");`
- 原理：`BuildIfNeeded` 幂等，重复调用不会叠两层 Canvas。
- 坑：**锚点坐标不是像素**。参考分辨率 1080 高，中心到边缘只有 540，写 `-570` 就在屏幕外（本需求栽过一次）。
- 维护：R046 迁预制体时保留 `Bind/Set*` 这组接口，控制器不用改。

### 2.3 MainMenuController（流程）

- 简介：串「存昵称 → 建常驻会话 → 连服 → 切 World 或失败提示」。
- 接口：`StartGame()`、`State`（只读，测试用）。
- 示例：`EnsureSession(); StartCoroutine(ConnectRoutine());`
- 原理：会话物体 `[MenuSession]` + `DontDestroyOnLoad`，`AutoJoin=false`、`BindPresentation=false`——只连服，不进房、不接管表现；进 World 后再由入口物体接管。
- 坑：失败必须销毁会话物体，否则下次点开始会复用一条坏连接。
- 维护：改端口/超时只动常量与序列化字段。

### 2.4 Login 场景挂载

- 简介：场景里只有一个 `[MainMenu]` 物体，挂 `MainMenuController`。
- 接口：无。
- 示例：Hierarchy → `[MainMenu]` → Inspector 里 `m_connectTimeoutSeconds: 3`、`m_logDiagnostics: 1`。
- 原理：视图不落场景，避免场景里塞一堆运行时 UI。
- 坑：手写 YAML 时 `.meta` 的 guid 必须与场景里 `m_Script` 一致，否则 Inspector 显示 Missing。
- 维护：以后新增场景物体一律在 Unity 里加并保存。

## 三、踩坑清单

1. **锚点坐标越界**：提示行 `-570`，屏幕半高 540，肉眼看不见；排查顺序是「Console 有没有日志 → RectTransform 的 Anchored Position」。
2. **失败路径没有日志**：界面是唯一输出时，一旦界面出错就彻底失明；任何失败分支都要留 `Debug.LogWarning`。
3. **报「测试已跑」前先确认 MCP 能连编辑器**：`unity_list_instances` 超时就是没有可用编辑器。
4. **手写场景 YAML 只能应急**，且必须让负责人确认 Inspector 没有 Missing。
5. **连点保护写进状态层**而不是只置灰按钮，否则别的入口还能再触发一次。
