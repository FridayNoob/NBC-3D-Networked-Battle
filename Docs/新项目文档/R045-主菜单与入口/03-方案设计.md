# 03 方案设计

需求编号：R045
所属阶段：M4
作者：AI（DeepSeek）
状态：开发中

## 一、整体架构

```
Login 场景
  [MainMenu]  GameObject
    ├─ MainMenuController   （逻辑：昵称、连服、切场景）
    └─ （运行时）Canvas      MainMenuView（标题/输入框/卡片/按钮/提示）
                                  ↕
                         MainMenuState（纯数据，可单测）
  [MenuSession] （点开始后才建，DontDestroyOnLoad）
    └─ RuntimeNetDriver（AutoJoin=false, BindPresentation=false）
```

## 二、模块划分

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| `MainMenuState` | 昵称规范化、按钮可用性、提示文案 | 不碰 Unity |
| `MainMenuView` | 建 Canvas、控件、布局、把点击转成回调 | 不做业务判断 |
| `MainMenuController` | 串起来：读昵称 → 连服 → 切场景 → 出错提示 | 不画 UI、不直接发协议 |
| `RuntimeNetDriver` | 提供连接能力 | 不改网络层 |

## 三、接口

```csharp
public sealed class MainMenuState
{
    public string PlayerName { get; }        // 规范化后的昵称（空 → "玩家"，最长 12 字）
    public bool CanStart { get; }            // 非连接中且未成功
    public bool IsConnecting { get; }
    public string Hint { get; }              // 按钮下方的提示（空 = 不显示）
    public void BeginConnect();
    public void Fail(string reason);
    public void Succeed();
}

public sealed class MainMenuView
{
    public void Bind(Action<string> onStart, Action onSettings, Action onQuit);
    public void SetStartLabel(string text);
    public void SetHint(string hint);        // 空串 = 隐藏
    public string ReadName();                // 输入框当前文本
    public void SetName(string name);
}
```

## 四、数据结构

| 项 | 取值 | 说明 |
| --- | --- | --- |
| `PlayerPrefs` 键 | `nbc.menu.playerName` | 上次昵称 |
| 默认昵称 | `玩家` | 空输入时 |
| 昵称长度 | 1~12 字 | 超出截断 |
| 连接超时 | 3 秒 | 超时提示「连不上服务器」 |
| 端口/主机 | `127.0.0.1:7778` | 与 `RuntimeNetDriver` 一致 |

## 五、时序与流程

1. `Start`：读 `PlayerPrefs` → 建视图 → 绑定按钮 → 回填昵称。
2. 点「开始游戏」：`state.BeginConnect()`（按钮变「连接中…」并禁用）→ 昵称存盘 → 建 `[MenuSession]` + `RuntimeNetDriver` → `ConfigureSession` + 关 `AutoJoin`/`BindPresentation`。
3. 轮询 `driver.IsOnline`：
   - 3 秒内成功 → `state.Succeed()` → `SceneFlow.LoadAsync(GameScene.World)`。
   - 失败/超时 → `state.Fail(driver.FailureReason ?? "连不上服务器")`，销毁会话物体，按钮恢复。
4. 点「设置」：`SetHint("音量/画质在 R047")`，再点一次收起（占位，不建真面板——避免多一个空 Canvas）。
5. 点「退出」：`Application.isEditor` → `EditorApplication.isPlaying = false`（用 `#if UNITY_EDITOR`）；否则 `Application.Quit()`。

## 六、选型与理由

1. **运行时 UGUI**（不是预制体）：与 R041 黑幕一致，零资源依赖；R046 统一迁预制体。
2. **复用 `RuntimeNetDriver`**：网络/重连/账号逻辑都在里面，重写等于第二套真值。
3. **连接放主菜单**：失败能当场看到；进副本才连要等玩家走到门口。
4. **设置只做提示**：R047 才做真设置，避免现在造两套设置读写。
5. **`MainMenuState` 抽纯逻辑**：连点保护、昵称规范化可以单测，不必进 Play。

## 八、风险与对策

| 风险 | 对策 |
| --- | --- |
| 连点开出两个会话 | `MainMenuState.CanStart` + 查找已有 `[MenuSession]` 复用 |
| `World` 里 `DungeonEntrance` 再建一个驱动 | 它已经「找或建 `[DungeonSession]`」，本步不新增，进副本时另建 |
| 编辑器里 `Application.Quit()` 没反应 | `#if UNITY_EDITOR` 走 `EditorApplication.isPlaying=false` |
| 昵称带换行/空格 | 规范化时去首尾空白、压掉换行 |
| 运行时 UI 字体缺失 | 复用 `DeathScreenOverlay` 的 `LegacyRuntime.ttf` → `Arial.ttf` 兜底 |
