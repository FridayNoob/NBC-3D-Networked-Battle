# 02 需求

需求编号：R045
所属阶段：M4
作者：AI（DeepSeek）
状态：开发中

## 一、业务目标（一句话）

从 `Login` 场景用鼠标点进 `World`，全程不打开编辑器窗口。

## 二、用户与场景

- **谁**：面试演示时第一次打开游戏的人。
- **场景**：启动游戏停在 `Login` → 输入昵称 → 看剑士卡片 → 点开始 → 连上服务器 → 进 `World` 村口。
- **失败场景**：服务器没开 / 端口不对 / 账号被拒 → 按钮下方直接写明原因，不用翻 Console。

## 三、功能列表

| 优先级 | 功能 |
| --- | --- |
| P0 | 主菜单：标题 + 昵称输入框 + 剑士卡片 + 「开始游戏」「设置」「退出」三个按钮 |
| P0 | 昵称存 `PlayerPrefs`，下次启动回填；空则用「玩家」 |
| P0 | 点开始 → 建常驻会话 → 连服（3 秒内没连上算失败）→ 成功切 `World` |
| P0 | 失败时在按钮下方显示 `FailureReason`，可以重试 |
| P1 | 设置页：占位面板，写明「音量/画质在 R047」+ 返回 |
| P1 | 退出：编辑器里停止播放，构建版 `Application.Quit()` |
| P2 | 开始按钮在连接中显示「连接中…」并禁用，防连点 |

## 四、边界（不做什么）

1. 不做账号密码输入（沿用 `dev1/dev-pw1`，R047 或后续再说）。
2. 不做注册/找回密码。
3. 不做多角色选择（当前只有剑士 1001）。
4. 不做 loading 过场动画（`SceneFlow` 已有进度，本步不展示进度条）。
5. 不改 `World`/`Battle` 的场景内容与既有流程。

## 五、优先级

P0 全做；P1 两项都做（成本低）；P2 做，避免连点时开两个会话。

## 六、验收标准（当…时，应…）

| # | 当 | 应 |
| --- | --- | --- |
| 1 | 打开 `Login` | 看到标题、昵称输入框、剑士卡片、三个按钮，鼠标可用 |
| 2 | 输入昵称后点开始 | 昵称存进 `PlayerPrefs`，下次打开自动回填 |
| 3 | 服务器未启动时点开始 | 3 秒内显示「连不上服务器：…」，不切场景 |
| 4 | 服务器正常时点开始 | 3 秒内切到 `World`，Console 出现「已连接，进入世界」 |
| 5 | 点设置 | 出现占位面板，写明音量/画质在 R047，点返回回到主菜单 |
| 6 | 点退出 | 编辑器里停止播放；构建版退出进程 |
| 7 | 连接中 | 按钮文字变「连接中…」且不可再点 |
| 8 | 切到 `World` 后 | 场景里只有一个 `[Player_Hero]`，且能正常移动 |
| 9 | 昵称留空点开始 | 用「玩家」作为昵称，不报错 |
| 10 | 连点开始 3 次 | 只建一个会话物体、只发起一次连接 |
