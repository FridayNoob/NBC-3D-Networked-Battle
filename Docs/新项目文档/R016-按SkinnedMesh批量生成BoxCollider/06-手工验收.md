# 06 手工验收

需求：R016-按 Skinned Mesh 批量生成 BoxCollider
所属阶段：M4
作者：LYF　状态：已验收（2026-11-02）

## 一、测试计划（四类）

| 类别 | 本次要测什么 | 怎么做 |
| --- | --- | --- |
| 正常 | 工具生成的碰撞体能不能让狼站在地上 | Play 看脚 |
| 异常 | 已有碰撞体/刚体的 prefab 会不会被改坏 | 二次运行看日志 |
| 边界 | 碰撞体是否贴合模型（不偏大、不歪） | 看 Scene 视图的绿框 |
| 性能 | 跑工具是否卡编辑器 | 观察（1218 顶点，瞬时完成） |

## 二、正常流程走查（两轮）

| 轮 | 你做什么 | 看到什么 | 结果 |
| --- | --- | --- | --- |
| 1 | 在狼 prefab 上跑工具 → Play | Scene 里绿框**比狼大一圈**，Play 里**仍然悬空** | ✗ |
| 2 | 工具改成按顶点算 → 重跑 → Play | 绿框贴住狼、脚**着地** | **通过** |

负责人结论（原话）：「狼的脚着地了」「这样自动生成的Box还是会让怪物悬空」（第 1 轮）→ 修完后确认着地。

## 三、异常场景

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| 绿框比模型大一圈、悬空 | 用了 `Renderer.bounds`（蒙皮动画盒，轴系与根不同） | 改按网格**顶点** AABB |
| 第二次运行会不会重复加 | 无守卫 | 已有 Collider+Rigidbody ⇒ 跳过（已验证） |
| 只有刚体没有碰撞体时被跳过 | 原规则「有任一个就跳过」 | 改为「缺什么补什么」 |

## 四、性能表现

- 单个 prefab 1218 顶点求 AABB，瞬时完成；105 个批量也在秒级。
- 运行时不参与（纯编辑器工具），无帧率影响。

## 五、逐条对照 02 的验收标准

- [x] 当 选中没有碰撞体的 prefab 执行菜单时，应在根上生成 BoxCollider 且底面与模型最低点重合 ⇒ 通过（底面 y=0.00）
- [x] 当 同一 prefab 再执行一次时，应被跳过 ⇒ 通过
- [x] 当 选中多个 prefab 时，应逐个处理并各打一行日志 ⇒ 代码实现（本次用反射单跑，菜单入口逻辑简单）
- [x] 当 根上**同时**已有 Collider 与 Rigidbody 时，应整体跳过 ⇒ 通过
- [x] 当 只缺一个时，应只补缺的那个 ⇒ 通过（只在有刚体时补了碰撞体）
- [x] 当 生成完成后，prefab 应带 Rigidbody（重力开、冻结旋转、非运动学）⇒ 工具设置这三项；狼的 `freezeRotation` 是你手工勾的，工具只提示
- [x] 当 模型带非 1 缩放时，碰撞体尺寸应与外观一致 ⇒ 用角点/矩阵换算（未实跑非 1 缩放模型，风险低）
