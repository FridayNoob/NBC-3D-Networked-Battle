# 开放世界方向调研（原神式）

> 触发：负责人 2026-11-12 提出"开放世界 + 采集/背包 + 野怪 + NPC 任务 + 好友联机 + 单人/多人副本（状态同步）+ 多人 PVP（帧同步）"。
> 本文只做**调研与可行性判断**，不含实施；实施需重新拆需求并逐条走 8 步。

## 一、从公开资料能确认的原神做法

| 维度 | 做法（公开信息/逆向资料能确认的部分） | 对我们的意义 |
| --- | --- | --- |
| 客户端定位 | **客户端承载大部分模拟与表现**（角色移动、动画、场景表现），服务端做**结果校验与业务权威** | 与你想的"大部分逻辑放客户端"一致，但**伤害/掉落/背包/任务必须服务端权威** |
| 传输 | 二进制协议（protobuf 一类）+ 长连接；按场景/实体同步 | 我们已经是 TCP + protobuf，方向一致 |
| 世界组织 | 世界按**场景（scene/world）+ 区域**划分；客户端只拿**附近**实体（兴趣管理） | 开放世界必须做 AOI，否则带宽爆炸 |
| 联机 | 好友"进入对方世界"本质是**进同一个世界/场景**，由一端（或服务器）托管 | 我们的房间/副本层可以直接复用改造成"世界" |
| 战斗 | 服务端权威结算；客户端预测 + 表现 | 我们已有（`DungeonBattle` + 快照） |
| PVP | 原神本体没有动作 PVP；你要的"多人传送进另一个副本对战"是**自选方案**，可以用帧同步 | 我们 `Shared/Sim` 已有确定性内核（`WorldStep`/`Fix64`），但**尚未接入游戏层** |

相关的同步选型依据（权威状态 / 帧同步 / AOI 的取舍）见
[GameDevMind · 网游网络同步](https://gonglei007.github.io/GameDevMind/mds/3.%E7%A0%94%E5%8F%91%E8%83%BD%E5%8A%9B/3.2.2.%E7%BD%91%E6%B8%B8%E7%BD%91%E7%BB%9C%E5%90%8C%E6%AD%A5.md)，
以及 Glenn Fiedler 的 [State Synchronization](https://gafferongames.com/post/state_synchronization/) /
[Snapshot Interpolation](https://gafferongames.com/post/snapshot_interpolation/)。

## 二、你的愿景 → 技术要素拆解

| 玩法 | 必须有的系统 | 同步方式 | 权威方 |
| --- | --- | --- | --- |
| 登录 → 大世界 | 账号/存档、世界（场景）管理、玩家实体 | 状态同步 | 服务端 |
| 采集资源进背包 | 交互物、背包、事务（幂等） | 请求-确认（可靠消息） | **服务端** |
| 打野怪 | 怪物 AI（行为树）、掉落 | 状态同步 | 服务端 |
| NPC 对话/接任务 | 对话配置、任务状态机、进度 | 请求-确认 | **服务端** |
| 好友联机 | 世界/房间、加入/离开、可见性 | 状态同步 | 主机或服务端 |
| 单人/多人副本 | 副本创建、实例隔离、结算 | 状态同步 | 服务端 |
| 多人 PVP 决斗 | 匹配/传送进 PVP 场景、确定性模拟 | **帧同步** | 各端模拟 + 服务端校验 |

## 三、关键判断（必须先说清）

1. **开放世界是量级问题，不是几个功能**：地形/场景流式加载、AOI、持久化存档、任务与背包事务，任一项都比现在的"一个副本"大。
2. **"大部分逻辑放客户端"要分区**：
   - 放客户端：移动、动画、表现、输入预测、远处插值的平滑。
   - **必须服务端**：伤害、掉落、背包、任务进度、PVP 胜负、反作弊。
   否则"客户端说是就是"，联机必然崩。
3. **状态同步与帧同步不能混用在同一场战斗里**：一个玩法选一种；PVP 单独场景、单独模式（我们已有的 `ERuntimeSyncMode` 就是干这个的）。
4. **我们的现有资产可复用**：房间/席位、快照下行、输入上行、确定性数学与 `WorldStep`、行为树（服务端）、编辑器（客户端）。

## 四、现实可行的三个方案

| 方案 | 范围 | 工作量（估） | 适合 |
| --- | --- | --- | --- |
| **A. 开放世界切片** | 1 个区域（60×60 米）+ AOI 九宫格 + 采集/背包 + 野怪 + NPC 任务 + 1 个副本 + 好友进世界 | 约 **6~8k 行** | 想讲"开放世界架构" |
| **B. 世界 + 副本 + PVP 三合一（推荐）** | A 的基础 + 一个多人 PVP 场景（帧同步最小版：移动/普攻/胜负） | 约 **8~10k 行** | 面试最完整，能讲两种同步 |
| **C. 保持副本 demo** | 不加开放世界，只把现有副本做完整（技能/结算/流程） | 约 **3k 行** | 时间紧、只要"能玩" |

**我的建议**：如果目标是面试展示"网络同步能力"，**B** 最有说服力但周期长；**A 先做**（两周量级）再补 PVP 切片，是更稳的路径。

> 场景素材：按 AGENTS.md §0.5，**不使用程序化生成的树/石头/建筑**，改用外部下载的现成包（登记到 `Docs/05-依赖清单.md`）。

## 五、与现有代码的差距（粗）

| 需要 | 现在 | 差距 |
| --- | --- | --- |
| 世界/场景管理 | 只有"副本"一个场景 | 需拆出 `World/Scene` 概念与切换 |
| AOI | 无（全量下发） | 新增九宫格兴趣管理 |
| 背包/采集 | 无 | 新系统（事务 + 幂等） |
| NPC/对话 | 无 | 对话配置 + UI |
| 任务 | 有条件/成就内核 | 需接 NPC 与持久化 |
| 好友进世界 | 房间/副本可复用 | 需"世界宿主"与权限 |
| PVP 帧同步 | `Shared/Sim` 内核存在 | 需接玩法层 + 校验 + 回放 |
| 存档 | 部分（账号/战绩） | 角色/背包/任务需落库 |
