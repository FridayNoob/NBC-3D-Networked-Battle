## 二、功能概述

Play 后进副本，走到怪旁边按 **J**：角色挥剑（本地动画）→ 上行 `PlayerInput{ActionBits=1, TargetEntityId=最近的怪}` → 服务端 `ResolveBasicAttack` 判定 → 扣血/死亡。

## 三、接口与入参出参

## 四、逐段讲解

1. **为什么动作编号必须是 0**：服务端写死 `ActionBits & 1u`；客户端 `Declare(0,"Attack")` 才让第 0 位对应 J 键。
2. **为什么攻击不走 50ms 节流**：按键可能只持续一两帧，套节流会丢手感；所以 `PumpInput` 里先判攻击、发了就 `return`。
3. **为什么没目标就不发**：服务端对不存在的目标会打一行「目标 0 不存在」日志，每次按键刷一行会把真日志淹掉。
4. **为什么客户端给 3 米、服务端判 2 米**：留 1 米余量，避免"看起来贴脸了却选不到目标"；超出射程由服务端拒绝（日志可见），客户端不做预测。
5. **`ValidateParameter` 为什么要加类型重载**：原来只校验 Float（移动参数），攻击是 Trigger；顺手让它同时服务两种类型，并在 `Awake` 里显式报错。

```csharp
        // 功能：把攻击键登记成一个输入动作（动作 0 = 服务端约定的普攻位）。
        // 入参：无（键位来自 Inspector 的 m_attackKey）
        // 返回：无
        // 步骤：
        //   1) 建一张键位表（构造时自带 WASD 默认键）
        //   2) 声明动作 0（名字 Attack）并绑到 m_attackKey
        //   3) 把键位表注入 InputManager，再登记该动作 —— 不登记就永远产不出动作位
        // 上游：HpBarDemoBehaviour 装配流程
        // 下游：LegacyInputSource、InputManager.TrackAction、RuntimeNetDriver（读 ActionBits 第 0 位）
        // 注意：动作 0 是**服务端约定**（RoomBattleService 里 `ActionBits & 1u` 就是普攻），别改成别的编号
        private void RegisterAttackInput()
        {
            if (InputManager.Instance == null)
            {
                Debug.LogError("[HpBarDemo] InputManager 还没就绪，攻击键登记失败。");
                return;
            }

            InputMapping mapping = new InputMapping();
            InputActionId attack = InputActionId.Declare(0, "Attack");
            mapping.Bind(attack, m_attackKey);

            InputManager.Instance.Source = new LegacyInputSource(mapping);
            InputManager.Instance.TrackAction(attack);

            Debug.Log("[HpBarDemo] 攻击键已登记：" + m_attackKey + "（动作 0 = 普攻）");
        }
```

```csharp
        // 功能：本帧若按下了攻击键，就选最近的怪并把「攻击位 + 目标」发出去，同时播本地攻击动画。
        // 入参：无
        // 返回：true = 本帧发了攻击（调用方这一帧就不要再发普通输入了）
        // 步骤：
        //   1) 读当前输入；没有动作位就直接返回 false
        //   2) 只有第 0 位（普攻）算攻击 —— 与服务端约定一致
        //   3) 选最近的活怪；没有目标就不发（免得服务端一直刷「目标 0 不存在」）
        //   4) 状态同步模式下带 targetId 发送；锁步模式暂不发攻击（动作位处理未确认）
        //   5) 播本地攻击动画（命中仍由服务端裁决）
        // 上游：PumpInput
        // 下游：NetSession.SendInput、PlayerAnimation.PlayAttack
        // 注意：不能用「按住」判 ——— ActionBits 是「本帧新按下」，按住不会重复置位
        private bool TrySendAttack()
        {
            InputManager input = InputManager.Instance;

            if (input == null || !input.IsEnabled)
            {
                return false;
            }

            InputCommand command = input.Current;

            if ((command.ActionBits & AttackBitMask) == 0u)
            {
                return false;
            }

            int targetId = FindNearestMonster();

            if (targetId == 0)
            {
                return false;
            }

            if (m_mode == ERuntimeSyncMode.Lockstep)
            {
                // 锁步链的远程攻击还没做（服务端只处理了状态同步的输入）
                return false;
            }

            m_session.SendInput(command.MoveX, command.MoveY, command.ActionBits, command.ActionReleaseBits, targetId);

            if (m_playerAnimation == null)
            {
                m_playerAnimation = UnityEngine.Object.FindObjectOfType<PlayerAnimation>();
            }

            if (m_playerAnimation != null)
            {
                m_playerAnimation.PlayAttack();
            }

            return true;
        }

        // 功能：在表现层的快照里找最近的「活着的怪」（OwnerPlayerId == 0），限定半径内。
        // 入参：无（半径用常量 AttackTargetRangeMm）
        // 返回：目标实例编号；没有目标返回 0
        // 步骤：
        //   1) 没有数据或没有本地英雄位置 ⇒ 0（无法算距离）
        //   2) 遍历实体：跳过自己、跳过别人的英雄（OwnerPlayerId != 0）、跳过死的
        //   3) 算水平距离（毫米），取最近且不超过半径的
        // 上游：TrySendAttack
        // 下游：无
        // 注意：这里只负责「选一个看起来能打到的」，命中判定仍然在服务端（客户端不做预测）
        private int FindNearestMonster()
        {
            if (m_feed == null || m_feed.View == null)
            {
                return 0;
            }

            EntitySnapshot hero = m_feed.View.FindHero(m_session.PlayerId);

            if (hero == null)
            {
                return 0;
            }

            IReadOnlyList<EntitySnapshot> entities = m_feed.View.Entities;
            int bestId = 0;
            int bestDistance = int.MaxValue;

            for (int i = 0; i < entities.Count; i++)
            {
                EntitySnapshot entity = entities[i];

                if (!entity.Alive || entity.OwnerPlayerId != 0L)
                {
                    continue;
                }

                int dx = entity.PosXMm - hero.PosXMm;
                int dz = entity.PosZMm - hero.PosZMm;
                int distance = (int)Math.Sqrt((double)dx * dx + (double)dz * dz);

                if (distance > AttackTargetRangeMm)
                {
                    continue;
                }

                if (distance < bestDistance)
                {
                    bestDistance = distance;
                    bestId = entity.EntityId;
                }
            }

            return bestId;
        }
```

```csharp
public const string AttackTrigger = "ATTACK 1";

private bool m_attackTriggerReady;
private bool m_attackTriggerWarned;
```

```csharp
        // 功能：播一次攻击动画（触发一次 Trigger），供攻击输入调用。
        // 入参：无
        // 返回：无
        // 步骤：
        //   1) 没有动画器或没有该 Trigger 参数 ⇒ 只告警一次，直接返回（不抛、不刷屏）
        //   2) 有就 SetTrigger
        // 上游：RuntimeNetDriver（玩家按下攻击键时）
        // 下游：Animator.SetTrigger
        // 注意：Trigger 是「一次性」的，连按会重入动画；冷却由服务端裁决，客户端不做节流
        public void PlayAttack()
        {
            if (m_animator == null)
            {
                return;
            }

            if (!m_attackTriggerReady)
            {
                if (m_attackTriggerWarned)
                {
                    return;
                }

                m_attackTriggerWarned = true;

                if (!ValidateParameter(AttackTrigger, AnimatorControllerParameterType.Trigger))
                {
                    Debug.LogWarning("[PlayerAnimation] controller 里没有 Trigger 参数 " + AttackTrigger +
                                     "，攻击时不会播动作（战斗逻辑仍由服务端裁决）。", this);
                    return;
                }

                m_attackTriggerReady = true;
            }

            m_animator.SetTrigger(AttackTrigger);
        }
```

同时把 `ValidateParameter` 拆成「按类型校验」的一个重载，`Awake` 里对两个 Float 参数显式报错。

## 七、风险与幻觉自查

- 幻觉自查：只用了 `InputActionId.Declare` / `InputMapping.Bind` / `LegacyInputSource` / `InputManager.TrackAction` / `Animator.SetTrigger` / `EntitySnapshot`，全部是既有 API。
- 编码中踩到并修掉的 4 处：
  1. 缺 `using NBC.Game.Player`（`PlayerAnimation` 类型找不到）；
  2. `SendInput` 的 `targetEntityId` 是 `int`，我一开始写了 `long`；
  3. 缺 `using System;` / `System.Collections.Generic`（`Math` 与 `IReadOnlyList`）→ 之后又撞 `Object` 二义性，改成 `UnityEngine.Object`；
  4. **把整个方法插进了 `ShowPanel` 的调用链里**（锚点是方法体内的注释）→ 语法错，改成按行边界剪切后插到 `Update` 之前。
- 行为变化：J 键现在会发上行攻击；服务端首次收到后 `AttacksLanded` 才会增长。
- 风险：锁步模式下攻击**不发**（服务端锁步链未处理动作位），已如实写在注释里。
