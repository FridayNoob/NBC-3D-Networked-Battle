# 01 技术预研

需求：R019-攻击输入与技能释放
所属阶段：M4
作者：AI　状态：草稿（待负责人确认）

## 一、调研目标与约束

- 目标：**客户端能打人** —— 按键 → 上行输入带「攻击位 + 目标」→ 服务端判定 → 客户端播攻击动画。
- 约束：
  1. 不改协议、不改服务端结算规则（服务端**已经**能打）；
  2. 简单优先（面试 Demo）：不做技能条/多技能/连招，先接通「普攻」这一条；
  3. 伤害表现（飘字/受击）留给 R020。

## 二、服务端现状（**已经完整**）

| 项 | 结论 | 出处 |
| --- | --- | --- |
| 攻击位 | `ActionBits & 1u` = 技能1（当前就是普攻） | `RoomBattleService.HandleInput` |
| 结算入口 | `ResolveBasicAttack` → `battle.TryBasicAttack(attacker, input.TargetEntityId)` | 同上 |
| 已校验 | 出手者活着、不在冷却、**目标必须存在**、目标活着、在射程内（`BasicAttackRangeMm = 2000`） | `DungeonBattle.TryBasicAttack` |
| 伤害 | 来自 **Skill 表**（`battle.BasicAttackDamage`） | 同上 |
| 可观测 | `AttacksLanded` / `AttacksRefused` + 日志「普攻打中单位 X」 | `RoomBattleService` |

⇒ **服务端一个字都不用改。**

## 三、客户端现状（三处缺口）

| # | 缺口 | 证据 |
| --- | --- | --- |
| 1 | **从未登记过任何动作** ⇒ `ActionBits` 永远是 0 | Console 实测警告：「[InputManager] 还没有登记任何动作（TrackAction）」 |
| 2 | 上行 `SendInput` 的 `targetEntityId` 默认 **0** ⇒ 服务端 `Find(0)` 找不到 ⇒ 必定被拒（「目标 0 不存在」） | `NetSession.SendInput(command)` 重载；`DungeonBattle.Find` |
| 3 | 没有攻击动画反馈 | `PlayerAnimation` 只喂 `Speed`/`Direction`，从不触发 |

## 四、可复用的现成写法

`M2DemoBehaviour`（旧的编辑器演示路径）已经写过一遍：

```csharp
InputMapping mapping = new InputMapping();                    // 自带 WASD 默认键
m_skillAction = InputActionId.Declare(0, "Skill1");
mapping.Bind(m_skillAction, m_skillKey);
InputManager.Instance.Source = new LegacyInputSource(mapping);
InputManager.Instance.TrackAction(m_skillAction);
```

运行时的装配处 `HpBarDemoBehaviour` **完全没有输入装配**（`grep TrackAction` 只在 M2DemoBehaviour 里），所以运行时那条路动作位是空的。

## 五、动画侧

| 项 | 值 |
| --- | --- |
| 本地玩家 controller | `Sword_Controller`（R014 配的） |
| 攻击触发参数 | **`ATTACK 1`**（`ATTACK 2` / `ATTACK 3` 也在，本次只用 1） |
| 现状 | 参数存在但从未 `SetTrigger` |

## 六、方案

| 改动 | 内容 |
| --- | --- |
| `HpBarDemoBehaviour`（装配） | 加 `m_attackKey`（默认 `J`）；建 Mapping（自带 WASD）+ `Bind(攻击动作, J)` + 注入 `LegacyInputSource` + `TrackAction`；把动作传给驱动 |
| `RuntimeNetDriver` | 加 `AttackAction` 属性；`PumpInput` 里检测「本帧新按下」→ **选最近活怪**（`PresentationFeed.View.Entities`，`OwnerPlayerId == 0` 且 `Alive`，3 米内）→ `SendInput(..., targetEntityId)` → 调本地攻击动画 |
| `PlayerAnimation` | 加 `PlayAttack()`：`SetTrigger("ATTACK 1")`；参数缺失只告警一次 |

**为什么目标由客户端选**：服务端要 `TargetEntityId`，协议里没有「自动选目标」语义；客户端挑最近的怪是这类 Demo 的常规做法（命中仍由服务端裁决）。

## 七、已知坑

1. **射程**：服务端射程 2 米，客户端选目标给 3 米余量；超出射程服务端会拒（日志可见），属正常。
2. **冷却**：服务端 15 tick（0.5 秒）；按太快会被拒，不报错（只记日志）—— 符合预期。
3. **一帧一次**：要用「本帧新按下」（`ActionBits`），不能用「按住」（否则每帧都发）。
4. **锁步模式**：`SendLockstepInput` 也带动作位，但服务端锁步链是否处理攻击未确认 —— 本次只做**状态同步**模式的攻击，锁步模式留待 R030 一起做。
5. **替换 Source 会不会丢 WASD**：`new InputMapping()` 自带 W/S/A/D 默认键（已核源码），不会丢。

## 八、结论与改动清单

结论：**补上客户端三段（登记动作键、发送时带目标、播攻击动画）**，服务端与协议不动。

要改 3 个文件：`HpBarDemoBehaviour`（装配）、`RuntimeNetDriver`（发送与选目标）、`PlayerAnimation`（攻击动画）。
