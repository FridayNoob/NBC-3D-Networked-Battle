# 03 方案设计

需求：R019-攻击输入与技能释放
所属阶段：M4
作者：AI 起草　状态：已确认（2026-11-05）

## 一、整体架构

```
HpBarDemoBehaviour（装配）        RuntimeNetDriver（每帧）             服务端
  new InputMapping()               读 InputManager.Current
  Bind(攻击动作, J)                 ├─ 移动轴 → 照旧
  Source = LegacyInputSource        └─ 本帧按下攻击位？
  TrackAction(攻击动作)                 ├─ 选最近活怪（3 米内）
  driver.AttackAction = 动作             ├─ SendInput(..., targetId) → RoomBattleService.ResolveBasicAttack
                                        └─ PlayerAnimation.PlayAttack() → 本地播挥剑
```

## 二、模块划分

| 模块 | 本次改动 | 不负责什么 |
| --- | --- | --- |
| `HpBarDemoBehaviour`（Boot） | 加 `m_attackKey`（默认 `J`）；装配输入（Mapping + Bind + Source + TrackAction）；把动作传给驱动 | 不选目标、不发消息 |
| `RuntimeNetDriver`（Game） | `AttackAction` 属性；按下时选目标 + 带 targetId 发送 + 播动画 | 不判定命中、不算伤害 |
| `PlayerAnimation`（Game） | 加 `PlayAttack()`（`SetTrigger("ATTACK 1")`，缺参数只告警一次） | 不管别的角色的动画 |
| 服务端 / 协议 | **零改动** | — |

## 四、数据结构

无新增集合；选目标只在已有 `m_feed.View.Entities` 上遍历一帧一次（几十个实体，可忽略）。

## 五、时序与流程

1. Boot：建 `InputMapping`（自带 WASD）→ `Bind(攻击动作, J)` → `Source = new LegacyInputSource(mapping)` → `TrackAction(攻击动作)` → 把动作交给驱动。
2. 玩家按 J：`InputManager.Tick` 产出 `ActionBits` 的对应位（本帧新按下）。
3. 驱动 `PumpInput`：若该位为 1 ⇒ 选最近活怪 ⇒ `m_session.SendInput(moveX, moveY, actionBits, releaseBits, targetId)` ⇒ `PlayAttack()`。
4. 服务端：`ActionBits & 1` ⇒ `ResolveBasicAttack` ⇒ 冷却/射程/目标校验 ⇒ 扣血 + 日志。
5. 客户端：位置与血量随下一次快照更新（血条已在 HUD 面板上）。

## 六、技术选型与理由

| 选择 | 选定 | 理由 | 被否的方案 |
| --- | --- | --- | --- |
| 键位 | **J** | 与 M2DemoBehaviour 的技能键一致，手顺 | 鼠标左键（会和 UI 点击冲突） |
| 目标 | **客户端选最近怪** | 协议没有「自动选目标」；命中仍服务端裁决 | 服务端自动选（要改协议/服务端） |
| 动画触发 | **`ATTACK 1`** | `Sword_Controller` 现成参数 | 新建状态机（没必要） |
| 命中反馈 | 留给 R020 | 保持本次最小 | 一起做（会变大） |

## 七、风险与对策

- **按太快被拒**：服务端冷却 15 tick；客户端不报错，只打日志（避免刷屏可用「被拒不发」—— 服务端没有回执，先接受）。
- **没目标时按 J**：客户端直接不发送（避免服务端刷「目标 0 不存在」）。
- **射程不一致**：客户端 3 米选目标、服务端 2 米判定 ⇒ 2~3 米之间会被拒；这是刻意的余量，日志能看出来。
- **锁步模式**：本次只在状态同步模式下发攻击；锁步模式的动作位处理未确认（R030 再一起看）。
- **动画参数缺失**：`PlayAttack` 里先查参数，缺了只告警一次。
