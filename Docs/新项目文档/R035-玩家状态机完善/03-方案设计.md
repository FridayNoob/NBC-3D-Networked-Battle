# 03 方案设计

需求：R035-玩家状态机完善（Idle/Move/Attack/Hit/Die）
所属阶段：M4
作者：AI　状态：待确认（2026-11-13）

## 一、整体架构

```
输入（J / WASD）与外部事件（NotifyHit / NotifyDead）
        │
        ▼
PlayerBrain（唯一决策者）
   ├─ 优先级：Die > Hit > Attack > Move/Idle
   ├─ 计时：m_actionFramesLeft（帧数，StateTick 没有 DeltaTime）
   └─ 状态机 StateMachine<EPlayerState>
        ├─ Idle（禁移动）
        ├─ Move（启用移动）
        ├─ Attack（禁移动 + PlayAttack）
        ├─ Hit（禁移动 + PlayHit）
        └─ Die（禁移动 + PlayDeath，不可离开）
```

## 四、时序（一次攻击）

1. 按 J → `PlayerBrain.Update` 检测到攻击键 → `NotifyAttack()`。
2. 若当前是 Die → 忽略；否则 `TryChangeState(Attack)`，`m_actionFramesLeft = m_attackFrames(36)`。
3. `PlayerAttackState.OnEnter`：`PlayerMove.enabled = false`；`PlayerAnimation.PlayAttack()`。
4. 每帧 `Update`：`m_actionFramesLeft--`；到 0 → 按有无输入回 Move/Idle。
5. Hit 同流程（18 帧）；Die 一旦进入不再评估输入。

## 五、选型与理由

| 选择 | 理由 | 被否方案 |
| --- | --- | --- |
| 计时用帧数累加 | `StateTick` 只有 Frame/DeltaFrames，语义稳定 | 用 `Time.time`（暂停/缩放时会飘） |
| 优先级写在 `PlayerBrain` | 一个地方就能看懂"谁打断谁" | 每状态各自判断（分散、易漏） |
| 状态类只管开关移动 + 播动画 | 单一职责，好测 | 状态类里塞计时与优先级 |
| `CanEnterFrom` 拦 Die→其它 | 死后不能再动是硬规则 | 每帧判 IsDead（容易漏一处） |

## 七、风险与对策

| 风险 | 对策 |
| --- | --- |
| 帧数计时在不同帧率下时长不同 | 默认值按 60fps 标注；Inspector 可调 |
| Battle 已经在自己调 PlayAttack | 新入口是"额外能力"，Battle 不改；两者同时调也只会重播一次 |
| 死亡后相机/输入没停 | Die 只禁移动；输入仍读但不产生移动（PlayerMove 被禁用） |
| 调试键误触 | `m_enableDebugKeys` 默认关，只在 World 打开 |
