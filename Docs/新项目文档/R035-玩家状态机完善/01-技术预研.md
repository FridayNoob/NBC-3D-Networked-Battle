# 01 技术预研

需求：R035-玩家状态机完善（Idle/Move/Attack/Hit/Die）
所属阶段：M4
作者：AI　状态：待确认（2026-11-13）

## 一、调研目标与约束

- 目标：把玩家从"只有 Idle/Move"扩成**能表达战斗**的状态机：攻击、受击、死亡。
- 约束：
  1. 复用项目自己的 `StateMachine<S>` / `StateBase<S>`（规则 12：不造轮子）；
  2. 状态只管**规则**（能不能动、能不能被打断），画面交给 `PlayerAnimation` + Animator；
  3. 代码 ≤ 500 行；Battle（有网络）与 World（本地）共用同一套状态机。

## 二、现有能力（读代码确认）

| 项 | 事实 | 出处 |
| --- | --- | --- |
| 状态枚举 | `EPlayerState { Idle=0, Move=1 }` | `EPlayerState.cs` |
| 状态机 | `StateMachine<S>`：`Register / Start / TryChangeState / Tick`，状态变化有 `StateChanged` 事件 | `Framework/Fsm/StateMachine.cs` |
| 状态基类 | `StateBase<S>`：`OnEnter / OnUpdate(in StateTick) / OnExit / OnEvent / CanEnterFrom` | `Framework/Fsm/StateBase.cs` |
| 时间基准 | `StateTick` 只有 `Frame` 与 `DeltaFrames`（**没有 DeltaTime**） | `Framework/Fsm/StateTypes.cs:22` |
| 现用状态 | `PlayerIdleState`（禁用 PlayerMove）/ `PlayerMoveState`（启用） | `PlayerStates.cs` |
| 动画接口 | `PlayAttack()` / `PlayHit()`；**没有 PlayDeath** | `PlayerAnimation.cs:71/110` |
| 攻击输入 | Battle 里由 `RuntimeNetDriver` 转发；**World 没有攻击输入** | `RuntimeNetDriver.cs:537` |

## 三、方案对比

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| A. 在 `PlayerBrain` 里堆 if/else | 代码少 | 状态一多就不可维护，且和框架 FSM 重复 | 否 |
| **B. 扩 `EPlayerState` + 每个状态一个类** | 与框架一致、每个状态独立可测、加状态=加文件 | 文件数变多 | **采用** |
| C. 换成行为树驱动玩家 | 表现力强 | 玩家状态机需要"确定性优先级"，行为树反而绕 | 否 |

## 四、状态与规则（本需求的核心）

| 状态 | 能进的条件 | 进入时 | 退出时 | 持续时间 |
| --- | --- | --- | --- | --- |
| **Idle** | 非 Die | 禁用 `PlayerMove` | — | 直到有输入 |
| **Move** | 非 Die、非 Hit、非 Attack | 启用 `PlayerMove` | — | 直到没输入 |
| **Attack** | Idle/Move（不能从 Hit/Die） | 禁用移动 + `PlayAttack()` | — | `m_attackFrames`（默认 36 帧 ≈ 0.6s） |
| **Hit** | 任何非 Die 状态 | 禁用移动 + `PlayHit()` | — | `m_hitFrames`（默认 18 帧 ≈ 0.3s） |
| **Die** | **任何状态** | 禁用移动 + `PlayDeath()` | 不再退出 | 永久 |

优先级：**Die > Hit > Attack > Move/Idle**。

## 五、已知坑

1. `StateTick` 没有 DeltaTime ⇒ 计时用**帧数累加**（暂停/时间缩放语义稳定），帧率不同需要换算说明。
2. `StateBase.OnEvent` 存在，但我们的"攻击/受击"是**外部调用**（网络事件/输入），用 `PlayerBrain` 的公开方法转发更直白，不必走 EventId。
3. `PlayerMove` 被禁用时会在 `OnDisable` 把速度清零 ⇒ 动画自动回 Idle，这点正好可复用。
4. **Die 必须能挡住 Move 的进入**（`CanEnterFrom`），否则死后按 W 会活过来。
5. 攻击/受击期间必须**禁移动**，否则会"边打边滑"。
6. `PlayerAnimation` 没有死亡触发 ⇒ 需要补 `PlayDeath()`（控制器里有 `DIE` Trigger，已实测存在）。

## 六、结论与改动清单

- `EPlayerState` 加 `Attack / Hit / Die`
- 新增 `PlayerAttackState / PlayerHitState / PlayerDeadState`（各一个类，放一个文件）
- `PlayerBrain`：加公开入口 `NotifyAttack / NotifyHit / NotifyDead`，优先级判定与超时回到 Idle/Move
- `PlayerAnimation`：补 `PlayDeath()`
- World 场景：攻击键（J）+ 调试键（K 模拟受击 / L 模拟死亡）用于验收
