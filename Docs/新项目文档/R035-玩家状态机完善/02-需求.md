# 02 需求

需求：R035-玩家状态机完善（Idle/Move/Attack/Hit/Die）
所属阶段：M4
作者：AI 起草／LYF 确认　状态：待确认（2026-11-13）

## 一、业务目标（一句话）

**玩家能"打、被打、会死"**：状态机把这三件事表达出来，并保证"打的时候不能跑、死后不能动"。

## 二、用户与场景

- 用户：玩家（在 World 里按 J 挥剑、被怪打到会僵直、血空了会倒下）。
- 场景：Play World → 按 J 挥剑（0.6 秒内不能移动）→ 按 K 模拟受击（0.3 秒僵直）→ 按 L 模拟死亡（永久倒地，按 WASD 无效）。

## 三、功能列表

| # | 功能 | 优先级 | 说明 |
| --- | --- | --- | --- |
| 1 | Idle / Move 保留 | P0 | 现有行为不变 |
| 2 | Attack 状态 | P0 | 禁移动 + 播攻击动画，超时回 Idle/Move |
| 3 | Hit 状态 | P0 | 禁移动 + 播受击动画，超时回 Idle/Move |
| 4 | Die 状态 | P0 | 禁移动 + 播死亡动画，永久不可离开 |
| 5 | 优先级规则 | P0 | Die > Hit > Attack > Move/Idle |
| 6 | 公开入口 `NotifyAttack/NotifyHit/NotifyDead` | P0 | 给以后的网络事件用 |
| 7 | 本地按键 | P1 | J 攻击；K/L 模拟受击/死亡（调试） |
| 8 | 状态变化日志 | P0 | 每次切换打一行，验收靠它 |

## 四、边界（本版明确不做）

- 不做技能状态（等技能系统 R043）。
- 不做复活（死亡就是终点，R041 再做）。
- 不做受击方向（左右交替已由 `PlayerAnimation` 内部处理）。
- 不改 Battle 的现有链路（它自己调 `PlayAttack/PlayHit`，本需求只加能力不破坏）。

## 五、优先级

**P0**。依赖：R034（World 玩家角色）。

## 六、验收标准（「当…时，应…」）

- [ ] 当 按 W 时，状态应从 Idle 切到 Move（日志可证）
- [ ] 当 按 J 时，应进入 Attack，且 **0.6 秒内 WASD 不能移动**
- [ ] 当 Attack 结束时，若有输入应回 Move，无输入回 Idle
- [ ] 当 触发受击时，应进入 Hit，0.3 秒内不能移动
- [ ] 当 触发死亡时，应进入 Die，之后 WASD/J 全部无效
- [ ] 当 处于 Die 时，任何操作都不应让它离开 Die
- [ ] 当 状态切换时，Console 应有一条 `[PlayerBrain] A → B`
- [ ] 当 死亡后，应播放死亡动画（`DIE` 触发器）
