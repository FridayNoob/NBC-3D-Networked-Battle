# 01 技术预研

需求：R031-AOI 兴趣管理（九宫格可见集）
所属阶段：M4
作者：AI　状态：待确认（2026-11-12）

## 一、调研目标与约束

- 目标：把"每 tick 给全房发**全量**实体"改成"**每个观察者只收到附近实体**"，为开放世界打地基。
- 约束：
  1. 不改协议（仍用 `WorldSnapshot`，只是**条目少了**）；
  2. 不改客户端（`SnapshotView` 对"消失的实体"本来就按看不到处理）；
  3. 服务端权威不变：AI/伤害仍按**全量**世界计算，AOI 只影响"发什么"；
  4. 代码量预估 **≈440 行**（见 §七），符合 §0.1。

## 二、现状（已确认）

| 项 | 事实 | 出处 |
| --- | --- | --- |
| 快照怎么发 | `battle.ToSnapshot()` 序列化**一次**，`SendToRoom` 发全房 | `RoomBattleService.BroadcastSnapshot` |
| 快照内容 | 全量 `_entities` → `EntitySnapshot`（`PosXMm/PosZMm` 等） | `DungeonBattle.ToSnapshot` |
| 客户端收 | `SnapshotView.Apply`，没有的实体按"消失"处理 | `SnapshotView` |
| 场地范围 | ±5000mm（10×10 米） | `DungeonBattle.PlayAreaHalfExtentMm` |
| 每房玩家 | 最多 2（当前 demo 席位 2） | `RoomRegistry` 席位定义 |

## 三、方案（九宫格 AOI）

```
DungeonBattle（全量世界，权威）
        │ ToSnapshot() 全量
        ▼
AoiGrid（格子 10m）
  ├─ 每个观察者（英雄）→ 自己所在格子的 3×3 邻域
  ├─ 可见实体 = 位置落在邻域内的实体 + 自己
  └─ 同一格子的多个玩家合并成一份 payload（省序列化）
        ▼
按「观察者分组」序列化 + 发送（不再全房同一份）
```

**关键取舍**：

| 选择 | 理由 |
| --- | --- |
| 九宫格固定网格（不是四叉树） | 场地小、实体少、实现与测试都简单；开放世界再换分层索引 |
| 格子 10 米（= 整个 demo 场地） | demo 里等于"全可见"，行为不突变；参数可配 |
| 观察者=英雄；怪不发给"怪" | 只有玩家需要快照 |
| 事件（伤害/死亡）暂不过滤 | 量小，先不做；后续按可见集过滤 |

## 四、关键技术判断

| 判断 | 理由 |
| --- | --- |
| AOI 只做"下发过滤"，不做"模拟裁剪" | 服务端权威必须看到全世界，否则怪物会"你不在就不动" |
| 按格子分组序列化 | 同格玩家共用一份字节；比每人一份省 CPU |
| 客户端零改动 | `SnapshotView` 已经按"当前条目"渲染，消失即隐藏 |
| 配置化格子尺寸 | 用常量 + 注释，后续挪到 `Dungeon` 表 |

## 五、已知坑

1. **只发可见实体会让"远处事件"看起来凭空出现**：进视野第一帧要包含完整状态（我们是全量字段，天然满足）。
2. **自己必须永远可见**：否则本地英雄会被隐藏（表现层会疯狂追一个不存在的实体）。
3. **死亡实体**：仍要在可见集里（否则死亡动画/事件对不上）；`Alive=false` 的照常发。
4. **同格合并**：同一格子的玩家用同一份 payload，注意别让"某人的自己"被过滤掉——自己的实体一定加入可见集。
5. **测试要两只玩家分开站**：否则永远看不出差异。

## 六、结论与改动清单

- 新增 `Server/NBC.Server.Game/Aoi/AoiGrid.cs`（格子计算 + 邻域可见判断）
- 修改 `RoomBattleService.BroadcastSnapshot`（按观察者分组、过滤后序列化）
- 修改 `DungeonBattle`（新增 `ToSnapshotVisible(predicate)` 或在 `ToSnapshot` 上重载，避免复制逻辑）
- 新增探针用例（两名玩家相距远/近，比较各自收到的实体集合）
