## 一、整体架构

```
DungeonBattle（全量世界，权威）
   │ ToSnapshot(filter)            ← 新增重载：按条件过滤
   ▼
RoomBattleService.BroadcastSnapshot
   ├─ 按每个玩家英雄所在格子分组（同格共用一份 payload）
   ├─ 过滤：自己的实体 或 3×3 邻域内
   └─ 逐会话发送（不再"一份发全房"）
        ▼
客户端 SnapshotView（不改：没出现 = 看不到）
```

## 四、时序（一帧）

1. `RoomBattleService.Tick` → 推进世界 → `BroadcastSnapshot`。
2. 遍历席位：取英雄 → 算格子 → 归组（记下该组的自身实体 id）。
3. 每组一份 `ServerMessage{Snapshot}`：`ToSnapshot(e => 自身 || IsVisible(...))`。
4. 组内逐会话发送；**找不到英雄的会话**单独发全量（兜底）。
5. 客户端照常 `Apply`。

## 五、选型与理由

| 选择 | 理由 | 被否方案 |
| --- | --- | --- |
| 九宫格固定网格 | 场地小、实现/测试简单；开放世界再换分层索引 | 四叉树（过度设计） |
| 按格子分组序列化 | 同格玩家可见集相同，省 CPU | 每人一份 |
| 过滤放在 `ToSnapshot` | 世界不知道网络，序列化层决定发什么 | 在世界里维护可见集合 |
| 兜底全量 | 找不到英雄时不至于整屏空白 | 什么都不发（会出现"地图空"难排查） |
| 客户端不改 | 已支持"消失即隐藏" | 加"离开视野"协议（不必要） |

## 七、SOLID 自检

| 原则 | 怎么满足 |
| --- | --- |
| **S** | 网格只算格子；世界只拍快照；服务只分组发送 |
| **O** | 换算法（四叉树/分层）只替换 `AoiGrid`，服务层接口不变 |
| **L** | `ToSnapshot(null)` 与旧行为完全一致（全量） |
| **I** | `AoiGrid` 只有 3 个公开成员，不暴露内部容器 |
| **D** | 分组逻辑依赖 `AoiGrid` 抽象，不直接算坐标 |

## 八、风险与对策

| 风险 | 对策 |
| --- | --- |
| 只发可见实体导致"远处事件凭空出现" | 每条快照都是完整状态（不是增量），进视野即完整 |
| 自己不见 | 过滤条件里强制包含自身实体 id（有实测用例） |
| 死亡实体被过滤掉 | 不看 `Alive`，只看格子 |
| 同格分组误判 | 同格可见集确实相同（半径固定 1 格） |
| 测试调小格子后忘记恢复 | 用例末尾恢复默认并断言"全可见" |
