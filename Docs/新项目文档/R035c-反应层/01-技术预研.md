# R035c 反应层 —— 01 技术预研

需求编号：R035c
所属阶段：M4
作者：AI 辅助
状态：开发中

## 1. 调研目标与约束

目标：把「受击（左右）」「硬直」「死亡」三件事做成能被外部事件驱动的反应层，优先级高于动作层与移动层，且死亡是终态。

约束：

1. 复用 R035a 的 `HierarchicalStateMachine` 与 `EPlayerState` 已经留好的 `HitLeft=201 / HitRight=202 / Stun=203 / Die=204`，不新加枚举。
2. 动画继续只由 bool/float 参数驱动，**零新增 Trigger**，不改美术包，只改控制器副本。
3. 逻辑不读 `Time`/`Input`，时长走 `PlayerTimings`（已有 `HitFrames=88`、`StunFrames=120`）。
4. 受击与硬直的口径（负责人 2026-11-14 定）：**硬直期间免疫受击**；死亡拒绝一切。
5. 调试入口：`K` 左受击、`Y` 右受击、`T` 硬直、`L` 死亡（仅编辑器/开关）。

## 2. 核心 API 清单

| API | 签名 | 用途 |
| --- | --- | --- |
| 现有 | `bool NotifyHit(bool fromLeft)` | 写 `StackSide`（-1 左 / +1 右）并进 `HitLeft/HitRight` |
| 现有 | `bool NotifyDead()` | `ForceChange(Reaction, Die)` + `Dead=true` |
| 新增 | `bool NotifyStun()` | 进 `Stun`，写 `ActionId=11`、`ActionBusy=true` |
| 新增 | `bool IsStunned { get; }` | 给 `NotifyHit` 做免疫判断 |
| 控制器 | AnyState → `S_Stun` | 条件 `ActionBusy && ActionId∈(10.5,11.5)` |

## 3. 最小可运行示例

```csharp
public bool NotifyStun()
{
    if (m_context.Dead || IsStunned)
    {
        return false;
    }

    m_comboQueued = false;
    m_blocking = false;
    return BeginAction(EPlayerState.Stun, PlayerActionId.Stun, m_timings.StunFrames);
}

public bool IsStunned => m_context.ActionBusy && m_context.ActionId == PlayerActionId.Stun;
```

## 4. 方案对比

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A 复用动作层 | 反应也用 `BeginAction` + `ActionId`，只加一条控制器过渡 | 与 R035b 完全同构，代码最少（约 60 行） | 需要「免疫」这类额外布尔 |
| B 独立反应子系统 | 反应层自己管计时与打断 | 语义更清 | 与动作层两套计时，重复代码 |
| C 全放 `PlayerBrain` | 不进状态机，靠组件开关 | 快 | 绕开 HSM，`CurrentPath`/日志失效 |

结论：**采用 A**。反应层本来就是 HSM 的第三层，`ForceChange`/`BeginAction` 已经够用，不重复造计时。

## 5. 已知坑与版本兼容

| 坑 | 现象 | 对策 |
| --- | --- | --- |
| `S_Stun` 的 clip 是**循环**的（2 秒，`loop=True`） | 计时没结束就一直循环 | `StunFrames=120` 正好一圈；到点 `EndAction` 清 `ActionBusy`，靠「回移动层」过渡离开 |
| `S_Die` 是 2.167 秒、`loop=False` | 播完停在最后一帧 | 死亡后不再 `Tick` 换状态，正好停在倒地姿势 |
| `StackSide` 是 float，AnyState 用 `Less 0` / `Greater 0` | 若写成 0 则两条都不命中 | 只写 -1 / +1 |
| 受击打断攻击时 `ActionBusy` 一直是 true | 受击过渡要求 `ActionBusy` | `BeginAction` 会保持 true，符合预期 |
| 死亡后再 `NotifyHit` | 会把 `Dead` 角色拉回受击 | `NotifyHit` / `NotifyStun` / `NotifyAttack` 都要先判 `Dead` |
| 硬直免疫受击若只看 `ActionId==11` | 硬直最后一帧 `ActionId` 已清 | 用 `ActionBusy && ActionId==11` 判断 |

## 6. 结论

反应层不新造系统：新增 `NotifyStun()` 与 `IsStunned`，在控制器副本加一条 `S_Stun` 过渡，`PlayerBrain` 补三个调试键，其余全部复用现有 `BeginAction` / `ForceChange`。预计代码量约 155 行（状态机 55 + Brain 25 + 测试 75），控制器只加 1 条过渡。
