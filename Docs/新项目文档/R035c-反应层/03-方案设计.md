# R035c 反应层 —— 03 方案设计

需求编号：R035c
所属阶段：M4
作者：AI 辅助
状态：开发中

## 1. 整体架构

```
外部事件（K/Y/T/L 或将来网络消息）
        ↓
PlayerBrain.HandleActionKeys
        ↓
PlayerStateMachine.NotifyHit(bool) / NotifyStun() / NotifyDead()
        ↓ 写 context：StackSide / ActionId / ActionBusy / Dead
PlayerStateMachine.Tick（每帧快照 BuildParams）
        ↓
PlayerAnimatorPublisher.Apply（幂等写参数）
        ↓
Animator AnyState：Dead→S_Die、ActionId≈10→S_Hit_L/R、 ActionId≈11→S_Stun
```

## 2. 模块划分

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| `PlayerStateMachine` | 受理三事件、免疫规则、计时、写 context | 读输入、写 Animator |
| `PlayerStateContext` | 承载 `StackSide/ActionId/ActionBusy/Dead` | 决定优先级 |
| `PlayerBrain` | 按键 → 事件；日志 | 决定受击方向语义 |
| `PlayerAnimatorPublisher` | 每帧幂等写 10 个参数 | 判断该不该受击 |
| 控制器副本 | 按参数选状态 | 业务规则 |

## 3. 接口（与最终代码逐字一致）

```csharp
// 功能：请求播受击；硬直期间免疫，死亡后拒绝。
// 入参：fromLeft 为 true 表示从左侧被打（StackSide=-1），false 表示右侧（StackSide=+1）。
// 返回：true 表示已受理；false 表示已死或在硬直中。
public bool NotifyHit(bool fromLeft)

// 功能：请求进入硬直；优先级高于动作层，低于死亡。
// 入参：无。
// 返回：true 表示已受理；false 表示已死或已在硬直中。
public bool NotifyStun()

// 功能：当前是否处于硬直（ActionBusy 且 ActionId 为 11）。
// 入参：无。
// 返回：true 表示硬直中。
public bool IsStunned { get; }

// 功能：请求死亡；之后任何请求都返回 false。
// 入参：无。
// 返回：true 表示这次真的死了；false 表示之前已死。
public bool NotifyDead()
```

## 4. 数据结构

| 字段 | 类型 | 含义 | 取值 |
| --- | --- | --- | --- |
| `StackSide` | float | 受击来自哪一侧 | -1 左 / +1 右 |
| `ActionId` | float | 当前动作编号 | 10 受击 / 11 硬直 / 0 无 |
| `ActionBusy` | bool | 是否有动作占位 | 受击/硬直期间为 true |
| `Dead` | bool | 是否已死 | 死亡后恒 true |
| `PlayerTimings.HitFrames` | int | 受击帧数 | 88（1.467 秒 @60） |
| `PlayerTimings.StunFrames` | int | 硬直帧数 | 120（2.0 秒 @60） |

死亡不进计时：`S_Die` 播完停在最后一帧，状态机不需要帧数，`130` 只是文档与验收用的观察值。

## 5. 时序与流程

**受击**：`NotifyHit` → 判 `Dead`、判 `IsStunned` → 写 `StackSide` → `BeginAction(HitLeft/HitRight, 10, 88)` → 下一帧 `ActionBusy=true`，AnyState 命中 #36/#37 → 播受击；88 帧后 `EndAction` 清 `ActionBusy`，回移动层。

**硬直**：`NotifyStun` → 判 `Dead`、判 `IsStunned` → `BeginAction(Stun, 11, 120)` → AnyState 新过渡命中 `S_Stun`；120 帧后回移动层。`S_Stun` 的 clip 是循环的，帧数与一圈时长相等，不会多播。

**死亡**：`NotifyDead` → 置 `Dead`、清动作/闸门 → `ForceChange(Reaction, Die)` → 之后 `Tick` 走死亡分支，只 `m_fsm.Tick` 维持状态，不再算移动/动作。

## 6. 选型与理由

| 选择 | 理由 |
| --- | --- |
| 复用 `BeginAction` | 与动作层同一套计时，不引入第二套帧计数 |
| 硬直免疫受击用 `IsStunned` 布尔判断 | 只改一个入口，不污染 `NotifyHit` 的调用方 |
| 死亡用 `ForceChange` 而不是 `TryChange*` | 死亡跳过 `CanEnterFrom`，任何层都能立即死 |
| 新增 1 条 AnyState，而不是给 `S_Stun` 加 Trigger | 维持「零 Trigger」的总体约束 |

## 8. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 硬直免疫判断写在错误位置，导致死亡后还能受击 | `NotifyHit` 第一行判 `Dead`，第二行判 `IsStunned`；单测覆盖 |
| 新增过渡插在 `S_Attack_*` 之后，硬直打断不了攻击 | 插在 #38（`S_Attack_1`）之前，靠 AnyState 顺序优先 |
| `S_Stun` 循环导致多播 | 帧数 120 = 一圈 2 秒；到点 `ActionBusy=false` 立刻离开 |
| 死亡后 `Tick` 仍按输入算移动 | 死亡分支提前 return，只 `m_fsm.Tick` |
| 受击打断攻击后 `StackSide` 残留影响下一次受击方向 | 每次 `NotifyHit` 都重写 `StackSide` |
