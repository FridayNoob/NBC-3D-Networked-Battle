# 08 文档沉淀

需求：R009-闸门加「跨程序集 using」检查
所属阶段：M4
作者：AI　状态：已确认（2026-11-05）

## 一、这条检查是什么

`Client\Assets\_Project\Tests\EditMode\Framework\AsmdefReferenceGuardTests.cs`

它读每个 asmdef 的 `references`，再扫那个目录下源码里的 `using NBC.*`；
如果某个 `using` 指向的程序集**没有**被该 asmdef 引用 ⇒ 测试红，并给出「哪个文件、哪一行、缺哪个引用」。

例：
```
NBC.Editor / NetDebugWindow.cs 里 using NBC.Shared.Condition;
但 NBC.Editor.asmdef 的 references 里没有 NBC.Shared
⇒ 红：「缺 Program Files…」不，是「NBC.Editor 缺引用 NBC.Shared（来自 NetDebugWindow.cs:12）」
```

## 二、怎么跑（三种，按成本从低到高）

| 方式 | 命令 | 成本 |
| --- | --- | --- |
| **MCP 反射调**（最快，不开窗口） | 见下方片段 | 2~3 秒 |
| Unity Test Runner | Window → General → Test Runner → EditMode → Run All | 手动 |
| CI（若以后要） | `Unity -batchmode -runTests -testPlatform EditMode` | 分钟级、独占工程 |

MCP 反射片段（本次验证用的就是它）：

```csharp
var t = ...AppDomain 里找 "NBC.Tests.EditMode.AsmdefReferenceGuardTests"...;
var inst = Activator.CreateInstance(t);
t.GetMethod("EveryAsmdef_ReferencesTheAssembliesItsSourcesUse").Invoke(inst, null);   // 真正扫描
t.GetMethod("Guard_ActuallyDetectsMissingReference").Invoke(inst, null);              // 负向对照
```

## 三、它和编译闸怎么分工（不要以为重复了）

| 检查 | 抓什么 | 抓不到 |
| --- | --- | --- |
| `AsmdefReferenceGuardTests`（本条） | `using` 了但没引用的程序集 | 全限定名、通过方法签名泄漏的类型 |
| `Tools\Check-AsmdefBoundaries.ps1` | 按 12 个 asmdef **分别编译** ⇒ 上面两类也能抓 | 报错信息不够直白（CS0012/CS0246） |

结论：**先跑 using 扫描定位，再用逐 asmdef 编译兜底。**

## 四、维护注意

- **新增程序集**：要在测试的 `NamespaceToAssembly` 映射里加一行，否则新命名空间不会被检查。
- **新增 asmdef 引用**：不用改测试（它读 asmdef 文件本身）。
- **别把这条测试删了**：它是「负向对照」过的检查（`Guard_ActuallyDetectsMissingReference` 证明它真会红），删了就没有早期预警。
- **全限定名写法**：如果以后大量使用 `NBC.Shared.Xxx` 这种全限定名，记得这条检查看不见，靠编译闸。
