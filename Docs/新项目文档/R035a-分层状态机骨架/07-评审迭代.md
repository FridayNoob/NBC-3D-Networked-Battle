## 三、根因分析

- **问题 1**：`PlayerBrain.m_enableDebugKeys` 代码默认 `false`，`World.unity:775` 的序列化值也是 `0`；`HandleActionKeys` 整段包在 `if (m_enableDebugKeys)` 里。Unity 运行时用的是场景实例值，改代码默认值对新实例才生效 ⇒ 键根本没被读到。
- **问题 2**：`WorldPlayerSetup` 的日志条件是 `selfAnimation != null && selfAnimation.enabled`；`PlayerBrain.Awake` 先执行并已经把它关了，到 `Start` 时条件不成立 ⇒ 行为正确、日志被跳过。
- **问题 3**：`SwordGirl_FullBody` 是美术预制体实例，赋值 `runtimeAnimatorController` 后调用 `RecordPrefabInstancePropertyModifications`、`SerializedObject.ApplyModifiedPropertiesWithoutUndo`、`Undo.RecordObject` 三种方式都不产生 `m_Controller` 覆盖（`GetPropertyModifications` 恒为 20 条）。Inspector 手动拖拽可以，脚本不行。
- **问题 4**：新增的「回移动层」AnyState 只判 `!Crouch && !ActionBusy && !Dead`，没有排除 `ActionId==8`；格挡按设计是常驻动作，会被这条立刻拉走。
- **问题 5**：骨架（枚举/参数/上下文/状态机/发布器/Brain/控制器）本身耦合紧，拆两半会让同一套骨架各写一遍；负责人已特批，但预估仍偏乐观。
- **问题 6**：插值必须在真实时间上推进；`Time.deltaTime` 只出现在表现层的发布器里，核心状态机仍是纯逻辑。
- **问题 7**：混合树要复用 `S_Idle`/`S_Walk`/`S_Run`/`S_Sprint` 等状态的 clip，删状态会连带删 clip 引用；先留作回滚点。
