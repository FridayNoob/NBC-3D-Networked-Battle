# 03 方案设计

需求：R035a-分层状态机骨架（移动层 + 参数驱动）
所属阶段：M4
作者：AI　状态：待确认（2026-11-13）

## 一、整体架构

```
Input（WASD/Alt/Shift/Ctrl/J/K/L）+ 外部事件（NotifyAttack / NotifyHit / NotifyDead）
        │
        ▼
PlayerBrain（Unity 适配层：只读输入、不判规则）
        │  PlayerInput + Tick(frame)
        ▼
PlayerStateMachine（纯 C#：优先级 + 计时 + 参数计算）
        │  HierarchicalStateMachine<EPlayerState>
        ├─ Locomotion(上层) ─ Idle / Walk / Run / Sprint / CrouchIdle / CrouchWalk / CrouchJog
        ├─ Action(上层)     ─ Attack1（本步只接回第 1 段）
        └─ Reaction(上层)   ─ HitLeft / Die
        │  PlayerAnimatorParams
        ▼
PlayerAnimatorPublisher ──► Animator（副本控制器，bool/float 过渡）

IPlayerMotion（PlayerMove 实现）◄── 移动闸门 + 目标速度
```

**一条原则**：规则只在 `PlayerStateMachine`；Unity 只出现在 `PlayerBrain` / `PlayerAnimatorPublisher` / `PlayerMove`。

## 二、模块划分

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| `PlayerStateCatalog` | 枚举、层归属、是否禁移动、层入口 | 具体时长、具体速度 |
| `PlayerStateContext` | 本帧数据（速度/蹲/动作计时）+ 组装参数结构体 | 决定状态 |
| `PlayerStateMachine` | 优先级、状态切换、动作计时、产生 `PlayerAnimatorParams` | 读输入、碰 Animator |
| `PlayerBrain` | 读键、把输入喂给状态机、每帧发布参数、打日志 | 判优先级 |
| `PlayerAnimatorPublisher` | 把结构体写进 Animator（值没变不写） | 决定值 |
| `PlayerMove` | 位移与转身；`IPlayerMotion` 实现（闸门/目标速度） | 决定"现在该多快" |

## 三、接口（与最终代码逐字一致）

```csharp
public interface IPlayerMotion
{
    bool MovementEnabled { get; set; }          // true=允许位移；动作期间由状态机置 false
    float CurrentSpeed { get; }                 // 当前水平速度，米/秒
    void SetMoveSpeed(float metersPerSecond);   // 目标速度，米/秒；0 表示站住
}

public interface IPlayerAnimatorSink
{
    void Apply(in PlayerAnimatorParams parameters); // 每帧一次；实现方负责幂等
}

public sealed class PlayerStateMachine
{
    public PlayerStateMachine(PlayerStateContext context, PlayerTimings timings, PlayerSpeeds speeds);
    public EPlayerLayer Layer { get; }              // 当前上层
    public EPlayerState State { get; }              // 当前下层
    public string CurrentPath { get; }              // 形如 "Locomotion/Run"
    public bool IsDead { get; }
    public PlayerAnimatorParams Parameters { get; } // Tick 之后有效
    public event Action<StateChangeRecord> StateChanged;
    public void Tick(int frame, in PlayerInput input);
    public bool NotifyAttack();                     // 返回是否真的进了攻击
    public bool NotifyHit(bool fromLeft);
    public bool NotifyDead();
}
```

约定：
- `Tick` 的 `frame` 必须单调递增（HSM 会校验）；`PlayerBrain` 用自己的计数器，不用 `Time.frameCount`。
- `Notify*` 在 `Tick` 之前调用；内部只改"待进入的动作"，真正的层切换发生在下一次 `Tick`。
- 进入动作层时 `MovementEnabled=false` 且 `Speed=0`；回移动层立即恢复。

## 四、数据结构

```csharp
public enum EPlayerLayer { Locomotion = 0, Action = 1, Reaction = 2 }

public enum EPlayerState
{
    Locomotion = 0, Action = 100, Reaction = 200,          // 上层标识
    Idle = 1, Walk = 2, Run = 3, Sprint = 4,
    CrouchIdle = 5, CrouchWalk = 6, CrouchJog = 7,
    Jump = 8, Fall = 9,
    Attack1 = 101, Attack2 = 102, Attack3 = 103,
    Skill1 = 104, Skill2 = 105, Skill3 = 106,
    Dash = 107, Block = 108, Pose = 109,
    HitLeft = 201, HitRight = 202, Stun = 203, Die = 204,
}

public readonly struct PlayerInput
{
    public readonly float MoveX;      // -1~1，右为正
    public readonly float MoveY;      // -1~1，前为正
    public readonly bool WalkHeld;    // Alt
    public readonly bool SprintHeld;  // Shift
    public readonly bool CrouchToggle;// Ctrl 按下这一帧
}

public readonly struct PlayerAnimatorParams
{
    public readonly float Speed;          // 米/秒，0~8
    public readonly float Direction;      // -1~1，右为正
    public readonly bool  Crouch;
    public readonly bool  Grounded;
    public readonly float VerticalSpeed;  // 米/秒，上升为正
    public readonly bool  ActionBusy;
    public readonly float ActionId;       // 0 无 / 1-3 攻击 / 4-6 技能 / 7 冲刺 / 8 格挡 / 9 姿势 / 10 受击 / 11 硬直
    public readonly float StackSide;      // -1 左 / +1 右
    public readonly float PoseIndex;      // 0~6
    public readonly bool  Dead;
}

public struct PlayerTimings { public int AttackFrames, HitFrames, SkillFrames, DashFrames, StunFrames, PoseFrames; }
public struct PlayerSpeeds  { public float Walk, Run, Sprint, CrouchWalk, CrouchJog; }
```

## 五、时序（按一次攻击）

1. `PlayerBrain.Update`：读键 → `NotifyAttack()`（若不在 Die/动作中）→ `Tick(frame, input)` → `publisher.Apply(machine.Parameters)`。
2. `NotifyAttack` 只写 `context.PendingAction = Attack1`（含 `ActionId=1`、`ActionFrames=36`、`ActionFrame=0`）。
3. `Tick`：先把动作计时 `+1`（到 36 帧自动结束）；再判优先级；发现 `PendingAction` ⇒ `TryChangeUpper(Action, Attack1)`。
4. 进入 Action 层后：`MovementEnabled=false`、`Speed=0`、`ActionBusy=true`、`ActionId=1` ⇒ 参数写进 Animator。
5. 36 帧后：`ActionBusy=false`、`ActionId=0`，切回 `Locomotion`（按当前输入选 Idle/Walk/Run/Sprint）。
6. 全程 `StateChanged` 事件打一行日志，验收靠它。

## 六、选型与理由

| 选择 | 理由 |
| --- | --- |
| 单枚举同时做"上层 + 下层"标识 | HSM 的 `S` 只有一个类型参数；框架测试也是这么用的（`LayeredId.Ground/Action/Idle/Run`） |
| 状态类做成一个通用的 `PlayerLayeredState` | 真正的行为差异在"层 + 时长"，用表描述即可；加状态 = 加一行注册，不用加类 |
| 输入驱动状态（不是按当前速度反推） | 起步那一帧 `CurrentSpeed` 还是 0，按速度反推会先播一帧 Idle；按输入算目标速度可以直接给 5 |
| 控制器用 AnyState + `canTransitionToSelf=false` | 一个状态只需一组"去哪"的条件，不必为 7 个移动态写 42 条互转 |
| 参数只在变化时写 | Animator 的 `SetFloat` 每帧写同值也会打断混合；幂等写入是硬要求（验收第 10 条） |

## 八、风险与对策

| 风险 | 对策 |
| --- | --- |
| AnyState 过渡自循环导致动画卡在第 0 帧 | 全部 `canTransitionToSelf = false`，改完用 MCP 打印过渡表核对 |
| 旧控制器 33 条 Trigger 过渡仍生效 | 复制后全部 `mute = true`，并在 05 用脚本断言"未静音的旧过渡 = 0" |
| `Speed` 语义从 -1~1 变 0~8，`PlayerAnimation` 同时写会打架 | World 里禁用 `PlayerAnimation`；Battle 用它自己的原件控制器，互不影响 |
| 参数缺失时动画不动且无报错 | 启动校验 10 个参数，缺一个告警一次并列出名字 |
| 动作结束后出现"先站一下再跑"的闪帧 | 用 AnyState 直连目标移动态（不走 S_Idle 中转） |
| 帧率变化导致动作时长漂移 | 时长以 60fps 帧数配置，`PlayerBrain` 用 `Time.deltaTime` 累积到 1/60 才 `Tick` 一次 |
