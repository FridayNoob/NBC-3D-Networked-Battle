# 01 技术预研

需求：R035a-分层状态机骨架（移动层 + 参数驱动）
所属阶段：M4
作者：AI　状态：已确认（2026-11-13，含混合树追加）

## 一、调研目标与约束

- 目标：把玩家从「单层 5 状态 + Trigger 驱动」换成**三层分层状态机 + bool/float 参数驱动**：
  移动层（站/走/跑/冲/蹲三态）、动作层（攻击三段·技能·冲刺·格挡·姿势）、反应层（受击左右·硬直·死亡）。
- 约束：
  1. 复用 `Framework/Fsm` 的 `HierarchicalStateMachine<S>`，不另写状态机（规则 12）；
  2. 动画**零新增 Trigger**，只用 bool/float（负责人 m01197）；
  3. 控制器**复制**到 `Client/Assets/_Project/Animator/`，美术包原件不动（Battle 仍用原件）；
  4. 逻辑层不读 `Time.deltaTime` / `Input`，纯 C#（EditMode 可测，服务端也能编）；
  5. 单个上层同一时刻只有一个下层在跑，优先级只在驱动层判一次。
- 预算：实测骨架约 900 行 > §0.1 的 500 行，**负责人 2026-11-13 已特批**（再拆会把同一套骨架切两半）。

## 二、核心 API 清单（读源码确认）

| API | 签名要点 | 语义 / 坑 |
| --- | --- | --- |
| `HierarchicalStateMachine<S>` | `(int historyCapacity = 32)` | 上层/下层共用同一个 `S` 枚举；上层也要有自己的取值（`Locomotion/Action/Reaction`） |
| 注册上层 | `RegisterUpper(S upper, IState<S> state, S entrySub)` | 同一上层重复注册 ⇒ `InvalidOperationException` |
| 注册下层 | `RegisterSub(S upper, S sub, IState<S> state)` | **第一个注册的下层自动成为该上层入口**；下层不共享 |
| 启动 | `Start(S upper)` / `Start(S upper, S sub)` | 只能调一次；未注册上层 ⇒ 异常 |
| 推进 | `Tick(int frame)` | 帧号**倒退抛异常**；先下层 `OnUpdate`、后上层，最后统一执行排队转移 |
| 切层 | `TryChangeUpper(S)` / `TryChangeUpper(S, S)` / `TryChangeLower(S)` | 走目标状态 `CanEnterFrom(来源)`；拒绝触发 `TransitionRejected` |
| 强切 | `ForceChange(S upper, S sub)` | 跳过准入（死亡用） |
| 观测 | `UpperCurrent` / `LowerCurrent` / `CurrentPath` / `StateChanged` | `CurrentPath` 形如 `Locomotion/Run`；事件参数是 `StateChangeRecord` |
| 状态基类 | `StateBase<S>`：`Name` / `OnEnter(S)` / `OnUpdate(in StateTick)` / `OnExit(S)` / `OnEvent` / `CanEnterFrom` | `CanEnterFrom` 默认 true；`StateTick` 只有 `Frame`/`DeltaFrames`，**没有 DeltaTime** |

## 三、最小可运行示例

```csharp
var fsm = new HierarchicalStateMachine<EPlayerState>(32);
fsm.RegisterUpper(EPlayerState.Locomotion, new LocomotionUpper(), EPlayerState.Idle);
fsm.RegisterSub(EPlayerState.Locomotion, EPlayerState.Idle, new GroundState(EPlayerState.Idle));
fsm.RegisterSub(EPlayerState.Locomotion, EPlayerState.Run, new GroundState(EPlayerState.Run));
fsm.Start(EPlayerState.Locomotion);            // 走入口 Idle
fsm.Tick(1);
fsm.TryChangeLower(EPlayerState.Run);          // Idle -> Run，CurrentPath = "Locomotion/Run"
fsm.Tick(2);
```

## 四之一、混合树预研（2026-11-13 负责人追加：走跑应做成混合树）

| 项 | 结论 |
| --- | --- |
| 用什么 API 建树 | `new UnityEditor.Animations.BlendTree { blendType = Simple1D, blendParameter = "Speed", useAutomaticThresholds = false }`，再 `AddChild(clip, 阈值)`；`AssetDatabase.AddObjectToAsset(tree, controller)` 让它成为控制器的子资产 |
| 怎么挂到状态 | `AnimatorState.motion = tree`；状态的 `motion` 类型从 `AnimationClip` 变成 `BlendTree`，运行时照常播 |
| 一棵树能控几档 | 1D 树的参数只有 **一个**（这里是 `Speed`），阈值必须单调递增；站立 0/2/5/8 与蹲 0/1.5/3 有重叠 ⇒ **必须两棵树**，用 `Crouch` 布尔切 |
| 谁来切树 | AnyState → `S_Locomotion`（`Crouch == false`）/ `S_Crouch`（`Crouch == true`），都要求 `!ActionBusy && !Dead`，`canTransitionToSelf=false` 防止每帧重入把树重置 |
| 平滑从哪来 | `Speed` 仍是档位跳变（0→5），混合树会直接跳权重 ⇒ 在 `PlayerAnimatorPublisher` 里先线性插值（0.12 秒），再把连续值写进 Animator |
| 为什么不用 dampTime | `SetFloat(hash, v, damp, dt)` 必须每帧调才推进，会破坏「值没变不写」；而且曲线不可测。自己插值是纯逻辑，EditMode 能用固定步长断言 |

## 五、方案对比

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| A. 继续加 Trigger + 单层 5 态 | 改动最小 | Trigger 是「一次性事件」，无法表达「按住格挡」「持续蹲」；状态一多互相打架 | 否（正是当前问题） |
| **B. 三层分层 + bool/float 参数** | 参数是「持续量」，可表达按住/持续；层级把优先级固定死；加状态=加一行表 | 要重写控制器过渡 | **采用** |
| C. 改用动画蓝图/子状态机（Sub-State Machine） | 编辑器里更整齐 | 增加一层资产复杂度，收益只有「看起来整齐」 | 否（后续可加） |
| D. 全代码驱动 `Animator.Play(hash)` | 不用配过渡 | 失去混合与过渡曲线，改一个动作要改代码 | 否 |

## 六、已知坑与版本兼容

1. `sm.states` 是 `ChildAnimatorState[]`，读名字要写 `st.state.name`（先写成 `st.name` 编译失败过）。
2. 33 条 Trigger 过渡**必须 Mute 掉**，否则复用同一控制器时旧 Trigger 会突然抢状态。
3. `Speed` 现在被 `PlayerAnimation` 写成 **-1~1 的归一化值**，新方案要写 **0~8 米/秒**；两者同时写会打架
   ⇒ World 里必须关掉 `PlayerAnimation`（Battle 不受影响，它不用这套）。
4. Animator 上不存在的参数名 `SetFloat` **不报错也不生效**，只会「动画不动」⇒ 启动时校验 + 缺参告警。
5. `AnimationClip` 是 Humanoid（`animationType: 3`），重定向到剑士骨架可用，但**脚部贴合会变**，跳跃要单独调。
6. 过渡 `Has Exit Time` + `duration` 决定「动作播完才回流」，代码侧只负责把 `ActionBusy` 置 false。
7. 混合树是控制器的**子资产**：只 `new BlendTree()` 不 `AddObjectToAsset` 会在保存时丢掉；改完必须回读 `state.motion` 确认类型是 `BlendTree`。
8. AnyState 过渡的 `canTransitionToSelf=false` 是「防每帧重入」的关键；漏了就表现为角色原地抽搐（树每帧被重置）。
