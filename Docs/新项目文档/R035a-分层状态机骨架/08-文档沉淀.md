所属阶段：M4
作者：AI　状态：已验收（2026-11-13）

## 一、文档范围

本需求沉淀「玩家三层分层状态机 + bool/float 参数驱动动画」这套骨架。覆盖：

- 状态怎么分层、谁优先、动作期间为什么不能移动；
- 动画参数怎么从逻辑层流到 Animator，为什么不用 Trigger；
- 两棵 1D 混合树与 0.12 秒速度平滑；
- 控制器副本的改造方式与「预制体实例覆盖」的限制。

不覆盖：动作层的连击/技能/格挡（R035b）、受击左右与硬直的细节（R035c）、跳跃下落（R035d）。

## 二、模块文档

### 1. PlayerStateMachine（逻辑层）

- **简介**：纯 C# 的驱动层，持有 `HierarchicalStateMachine<EPlayerState>`，按输入决定该在哪个上层、哪个下层，并把「速度/方向/动作状态」写进 `PlayerStateContext`。
- **接口**：`PlayerStateMachine(PlayerStateContext, PlayerTimings, PlayerSpeeds)`；`Tick(int frame, in PlayerInput input)`；`NotifyAttack()`；`NotifyHit(bool fromLeft)`；`NotifyDead()`；只读 `Layer`/`State`/`CurrentPath`/`IsDead`/`Parameters`；事件 `StateChanged`。
- **示例**：每帧一次 `machine.Tick(frame, input)`，再把 `machine.Parameters` 交给发布器；攻击时调 `NotifyAttack()`，死亡调 `NotifyDead()`。
- **原理**：`EPlayerState` 一个枚举靠数值分段（`<100` 移动、`<200` 动作、`>=200` 反应）同时表达「层」和「状态」，省掉两套枚举与映射表。上层决定「能不能动」，下层只决定「播什么」。
- **坑**：`NotifyAttack` 在 `ActionBusy` 时返回 false（连击留给 R035b）；`Speed` 写的是**米/秒**（0~8），不是归一化的 -1~1。
- **维护**：加一个移动档位 = 枚举加值 + `PlayerSpeeds` 加字段 + 混合树加阈值点，不改状态机主流程。

### 2. PlayerAnimatorPublisher（表现层）

- **简介**：把 `PlayerAnimatorParams` 幂等地写进 `Animator`，负责缺参数告警与速度平滑。
- **接口**：`void Apply(in PlayerAnimatorParams parameters)`；Inspector 字段 `m_speedSmoothSeconds`（默认 0.12）。
- **示例**：`PlayerBrain.Update` 末尾 `m_publisher.Apply(m_machine.Parameters)`，不需要判断值有没有变。
- **原理**：先查 `Animator.parameters` 建名字→类型表，之后只写存在的参数；每个值记住上次写入结果，没变就不调 `SetFloat`/`SetBool`。平滑用 `PlayerSpeedSmoother` 把 `Speed` 从旧值线性推到目标值，变化 > 0.01 才写。
- **坑**：控制器缺参数时 Unity 会静默忽略 `SetFloat`，所以必须自己校验并只警告一次。
- **维护**：加参数 = `PlayerAnimatorParams` 加字段 + 命名常量 + 发布器加哈希/上次值；混合树阈值改了只动资产。

### 3. PlayerBrain（适配层）

- **简介**：World 里唯一把「玩家输入 → 状态机 → 参数」串起来的组件。
- **接口**：`NotifyAttack()`、`NotifyHit(bool)`、`NotifyDead()`、只读 `IsDead`/`CurrentState`；Inspector 可调速度档位、动作帧数、按键、`Animator Controller Override`。
- **示例**：挂 `[Player_Hero]` 根节点，与 `PlayerMove` 同物体；`PlayerAnimation` 会被它自动关掉。
- **原理**：固定 60fps 累加步进（最多补 4 帧），保证不同帧率下动作帧数一致；每帧只读一次输入，`CrouchToggle` 只让第一步消费，避免一帧内翻两次。
- **坑**：`Animator Controller Override` 为空会退回美术包控制器（旧 Trigger 驱动）。
- **维护**：换模型只需改这个字段；Battle 不挂本组件，旧的 `PlayerAnimation`+Trigger 链路不受影响。

### 4. 控制器副本（资产层）

- **简介**：`Client/Assets/_Project/Animator/Player_Sword_Controller.controller`，从美术包复制而来，只改副本。
- **接口**：10 个参数（`Speed`/`Direction`/`Crouch`/`Grounded`/`VerticalSpeed`/`ActionBusy`/`ActionId`/`StackSide`/`PoseIndex`/`Dead`），41 个状态，48 条过渡（Active 7）。
- **原理**：把 33 条 Trigger 过渡 Mute，换成 7 条 AnyState 条件过渡；移动内部交给两棵 1D 混合树（站立 0/2/5/8、蹲 0/1.5/3）。
- **坑**：预制体实例的 Controller 覆盖脚本写不进去，只能 Inspector 手动拖（或用 `PlayerBrain.m_animatorControllerOverride` 在运行时换）。
- **维护**：改过渡前先看 Active 7 条的顺序；新增动作要在最前面插，否则会被「回移动层」抢先。

## 三、踩坑清单

1. 序列化字段的「场景实例值」优先于代码默认值；排查开关类问题先读 `SerializedObject`，别只看代码。
2. `Awake` 早于所有 `Start`；两个组件改同一个字段时，后执行者看到的已是前者改过的值。
3. 预制体实例上的引用型覆盖，脚本三套写法都可能无效，Inspector 手动拖是可靠路径。
4. 1D 混合树只有一个参数，站立与蹲的数值区间重叠时必须拆两棵树。
5. `Speed` 从 0 跳到 5 仍会硬切，参数本身要连续（驱动端插值）。
6. 状态切换本身不该写动画参数；统一由每帧快照 + 幂等发布，避免两处写同一个值。
7. 死亡用 `ForceChange` 跳过 `CanEnterFrom`，否则「从任何状态都能死」要靠每个状态重写守卫。
