# 06 手工验收：Dungeon 表的 SO ↔ CSV 双向

## 一、计划
| 类别 | 内容 |
| --- | --- |
| 正常 | 改 SO → 导出 → CSV 与生成物变化；改 CSV → 导入 → SO 变化 |
| 异常 | 非法值被拦下；ConfigKit 路径缺失时的提示（只看文案，不真删） |
| 边界 | 名字含逗号、多只怪、删除最后一行再导出 |
| 性能 | 导出含 2 行的表应在 2 秒内完成（含 ConfigKit） |

## 二、正常流程走查
1. 打开 `Tools/NBC/配置表/副本表（SO ↔ CSV）`，**表头应显示中文列名**：编号 / 名称 / 最大人数 / 出生点半径（毫米）/ 普通怪（写重复＝刷多只）/ BOSS；鼠标悬停应看到字段名、类型与取值范围。
2. 展开「列说明（来自 CSV 表头）」，应逐列列出中文名、字段名、类型与规则（如 `range(2,4)`）。
3. 应看到 2 行副本（1001 狼巢、1002 蛛网洞穴）。
4. 把 1001 的「出生点半径」从 3000 改成 3500，顶部应出现红字「SO 有未导出改动：… 行数 …」。
5. 点「导出到 CSV」，状态栏出现「已导出 2 行 … 请重启服务端让新配置生效」；用记事本看 `Configs/Design/Dungeon.csv`，第 5 行第 4 列应为 3500。
6. 看 `Client/Assets/_Project/Game/Config/Generated/Dungeon.tsv` 与 `Config_Dungeon.cs` 是否同步（TSV 里也应是 3500）。
7. 点「从 CSV 导入」，确认框点「导入」，SO 应重载且红字消失。
8. 把值改回 3000 再导出一次，恢复仓库干净（`git status` 不应有 `Configs/` 或 `Generated/` 改动）。

## 三、异常场景
1. 把 1001 的「最大人数」改成 5，点「导出到 CSV」，应弹出「校验没通过，磁盘没有改动：第 1 行（id=1001）：最大人数只能是 2~4」，且 CSV 未被修改。
2. 把怪物编号改成 9999，导出应报「怪物 9999 不在 Monster 表里」。
3. 把 BOSS 改成 0，导出应通过（0 表示没有 BOSS）。
4. 名字清空，导出应报「名称不能为空」。
5. 用 Excel 打开 `Configs/Design/Dungeon.csv` 改一个数并保存（Excel 通常存成 GBK），回到窗口点「从 CSV 导入」：应能读回新值，状态栏提示「文件编码 GBK」，不出现乱码。
6. 在 Excel 里把怪物列改成 `6001,6001` 保存：该格会被 Excel 加千位分隔符变成 `600,160,016,001`，导入或导出应报「编号不足 4 位，像是 Excel 给 6001,6001 自动加了千位分隔符」；把该列设成「文本」重填即可恢复。

## 四、性能
导出一次（含启动 ConfigKit 进程）实测应在 2 秒内；若超过 5 秒，先看是不是杀毒软件拦了 `NBC.ConfigKit.Cli.exe`。
