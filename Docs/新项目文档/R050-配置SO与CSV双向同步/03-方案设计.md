# 03 方案设计：Dungeon 表的 SO ↔ CSV 双向
## 一、整体架构
```
DungeonConfigWindow ──改──> DungeonConfig.asset (rows)
   ├─ 校验/导出 ──> DungeonCsvBridge ──> Configs/Design/Dungeon.csv ──> ConfigKit.Cli
   └─ 导入 ──────> DungeonCsvBridge <── 解析 CSV（引号感知）
```
## 二、模块划分
| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| `DungeonConfigWindow`（新） | 列表/字段编辑、按钮、脏标记、确认框 | 不拼 CSV、不写文件 |
| `DungeonCsvBridge`（新） | 拼文本、解析、校验、读写、跑 ConfigKit | 不画 UI |
## 三、接口（与最终代码逐字一致）
```csharp
public static class DungeonCsvBridge
{
    public const string CsvRelativePath = "Configs/Design/Dungeon.csv";
    public static string ResolveCsvPath();
    public static string BuildCsvText(DungeonConfig asset, string headerBlock);
    public static bool IsDirty(DungeonConfig asset, out string detail);
    public static bool Validate(DungeonConfig asset, List<string> errors);
    public static bool Export(DungeonConfig asset, out string message);
    public static bool Import(DungeonConfig asset, out string message);
    public static bool RunConfigKit(out string message);
    public static string[] SplitLine(string line);
    public static List<CsvColumn> ReadColumns(out string error);
}

public sealed class CsvColumn
{
    public string Name;
    public string Label;
    public string Type;
    public string Rule;
}
```
窗口 `DungeonConfigWindow : EditorWindow`，菜单 `Tools/NBC/配置表/副本表（SO ↔ CSV）`，`OnGUI` 只调上面这些方法；表头的中文名与规则由 `ReadColumns` 从 CSV 前 4 行读出，不在代码里写死。
## 四、数据结构
- 行：直接用生成的 `Config_Dungeon`，不建镜像类。
- 文本：磁盘前 4 行表头原样 + 每行 `id,name,maxPlayers,spawnRadiusMm,"m1,m2",bossId`；备份 `Dungeon.csv.bak`。
## 五、时序与流程
1. 打开窗口：加载资产 → `IsDirty` → 脏则红字。
2. 导出：`Validate` → 读前 4 行 → `BuildCsvText` → `.bak` → 临时文件 → 替换 → `RunConfigKit`（失败回滚）→ `SaveAssets` → 提示重启服务端。
3. 导入：读文件 → 解析 → 构造 `rows` → `Validate` → 确认框 → 覆盖并 `SaveAssets`。
## 六、选型与理由
1. 直接用生成类：少一层映射，字段名与 CSV 天然对齐。
2. 校验两份（C# 即时 + ConfigKit 闸门）：规则漂移时不会静默通过。
3. 「临时文件 + 替换」写盘：中途失败不留半截 CSV；导出后立刻跑 ConfigKit，避免 `.tsv` 错位。
