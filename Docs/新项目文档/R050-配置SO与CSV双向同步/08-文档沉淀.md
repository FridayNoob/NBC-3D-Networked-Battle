# 08 文档沉淀：Dungeon 表的 SO ↔ CSV 双向

## 一、文档范围
本需求新增一套「客户端 SO ↔ CSV」同步工具（先做 Dungeon 一张表），沉淀三个模块与六条踩坑。

## 二、模块文档

### 2.1 DungeonCsvBridge（`Editor/Config/DungeonCsvBridge.cs`）
- 简介：把 `DungeonConfig`（SO）与 `Configs/Design/Dungeon.csv` 互转，并在导出后调用 ConfigKit 重新生成两端代码。
- 接口：`ResolveCsvPath()`、`ReadCsvText(path, out encodingNote)`、`ReadColumns(out error)`、`BuildCsvText(asset, headerBlock)`、`IsDirty(asset, out detail)`、`Validate(asset, errors)`、`Export(asset, out message)`、`Import(asset, out message)`、`RunConfigKit(out message)`。
- 示例：窗口点「导出到 CSV」→ `Export` 备份 → 临时文件 → 替换 → ConfigKit → 失败回滚。
- 原理：CSV 前 4 行是「字段名/中文名/类型/规则」表头，导出只重写数据行；编码读写都过 `ReadCsvText`/UTF-8 BOM。
- 维护：新增表时复制本类，改 `CsvRelativePath`、`Config_*` 类型与 `Validate` 规则。

### 2.2 DungeonConfigWindow（`Editor/Config/DungeonConfigWindow.cs`）
- 简介：编辑器窗口，表格形式编辑 SO 行，带中文表头、tooltip、列说明、脏提示与导入/导出按钮。
- 接口：菜单 `Tools/NBC/配置表/副本表（SO ↔ CSV）`；内部 `DrawToolbar` / `DrawTable` / `DrawColumnHelp` / `CheckAssetReplaced`。
- 示例：改「出生点半径」→ 顶部红字「SO 有未导出改动」→ 导出。
- 原理：窗口不持有独立数据，直接改 SO 实例；`CheckAssetReplaced` 防止编辑被重新导入替换的旧对象。
- 维护：加列时改表头数组与 tooltip 文本，数据仍从 `Config_Dungeon` 反射式读取。

### 2.3 测试（`Tests/EditMode/Config/DungeonCsvBridgeTests.cs`）
- 简介：桥的纯逻辑与 IO 容错用例（10 条）。
- 覆盖：表头保留、引号往返、GBK、UTF-8 BOM、别人占用时读取、真实行校验、越界与重复。
- 维护：改解析规则先加用例，再改实现。

## 三、踩坑清单
1. **Excel 会改编码**：另存后是无 BOM 的 GBK，按 UTF-8 读就是乱码。读写统一走 `ReadCsvText`（BOM → 严格 UTF-8 → GBK 兜底）。
2. **Excel 会给数字加千位分隔符**：`6001,6001,6001` → `"600,160,016,001"`。导入端按 4 位还原并提示改文本格式。
3. **共享冲突**：`File.ReadAllBytes` 默认 `FileShare.Read`，Excel 打开时读不了。用 `FileShare.ReadWrite` + 重试。
4. **OnGUI 不能抛异常**：`IsDirty` 每帧调用，异常会让整块 IMGUI 中断。失败降级为红字提示。
5. **文化敏感比较**：`StartsWith("\uFEFF")` 会忽略 BOM，必须 `StringComparison.Ordinal`。
6. **校验失败是整行回滚**：看起来「导入成功但值没变」，实际被另一列拦下；提示必须写明哪一行哪一列。
