## 三、根因分析
| # | 根因 |
| --- | --- |
| 1 | 第一版只画了 `id/name` 等字段名，没读 CSV 第 2 行中文名，也没写 tooltip |
| 2 | `File.ReadAllText(path)` 假定 UTF-8；Excel 保存时按本地代码页写 GBK，中文列名全成替换字符 |
| 3 | Excel 把 `6001,6001,6001` 当数字加了千位分隔符；解析出 600/160/16/1，`Validate` 报「怪物 600 不在 Monster 表」，导入整体回滚，连半径一起没写 |
| 4 | `File.ReadAllBytes` 默认 `FileShare.Read`，Excel 持有写句柄时连打开都被拒；异常抛在 OnGUI 里导致 IMGUI 中断 |
| 5 | 窗口把 `DungeonConfig` 实例缓存在字段里，`ConfigImporter` 重新导入后旧实例已被替换 |
| 6 | 黑幕/编码/共享读/校验/中文表头全部堆在一个需求里；窗口从预估 210 行涨到 505 行 |

## 四、改进方案
| # | 改哪 | 怎么改 | 影响面 |
| --- | --- | --- | --- |
| 1 | `DungeonCsvBridge.ReadColumns` + 窗口 `DrawToolbar` | 读表头 4 行 → 中文名/类型/规则 → 表头 + tooltip + 可展开列说明 | 只影响窗口显示 |
| 2 | `ReadCsvText` | BOM 探测 → 无 BOM 严格 UTF-8 → 解不开按 GBK；导出统一 UTF-8 带 BOM | 全部读写路径 |
| 3 | `ParseMonsterIds` | 正常解析失败时，去掉逗号按 4 位一组还原，全部命中 Monster 表才接受，并提示修复 | 只影响导入的怪物列 |
| 4 | `ReadAllBytesShared` + `IsDirty`/`ReadColumns` 捕获 | `FileShare.ReadWrite \| Delete` + 重试 5×80ms；异常转红字提示；Import/Export 给「请先关闭 Excel」 | 全部读写路径 |
| 5 | 窗口 `CheckAssetReplaced` | 每秒按路径比对实例，变了就 Reload 并提示 | 只影响窗口 |
| 6 | 03/04 | 如实写 1645 行、229%，按 §0.1 走特批 | 文档 |
