# 01 技术预研：配置以 SO 为编辑真值、导出 CSV 给服务端
## 一、调研目标与约束

目标：负责人在客户端直接编辑 `Client/Assets/_Project/Configs/*.asset`（SO），一键导出成 `Configs/Design/*.csv`；服务端仍只读 CSV 并保持权威；同时支持「CSV → SO 覆盖导入」，两边不留第二份真值。

约束：① 只做试点表 **Dungeon**，跑通再推广（负责人 2026-11-16 定）；② **SO 是编辑真值，导出后 CSV 才更新**；③ 不改 ConfigKit 产物契约（`Config_<表>.cs` / `<表>Config.cs` / `.tsv` / `.json`）；④ 不改服务端读表方式（`ServerTables` 仍读 CSV）；⑤ 工具放 `NBC.Editor`，不进包。

## 二、核心 API 清单（实读）

| 项 | 位置 | 要点 |
| --- | --- | --- |
| CSV 源 | `Configs/Design/Dungeon.csv` | 4 行表头（字段名/中文名/类型/规则）+ 数据行；UTF-8 无 BOM、LF |
| 生成器 | `Tools\ConfigKit\src\ConfigKit.Cli\bin\Debug\net8.0\NBC.ConfigKit.Cli.exe` | `--source Configs\Design --out Client\Assets\_Project\Game\Config\Generated`；`--check` 只校验，退出码 0/2/1 |
| SO 导入与资产 | `Client/Assets/_Project/Editor/ConfigImporter.cs`、`Client/Assets/_Project/Configs/DungeonConfig.asset` | 菜单 `Tools/NBC/配置表/导入 TSV → ScriptableObject`；`AssetDirectory = "Assets/_Project/Configs"`；`monsters` 在 YAML 里是十六进制（`0x1771`=6001），只走代码读写 |
| SO 与行类型 | `Game/Config/Generated/DungeonConfig.cs` / `Config_Dungeon.cs` | `List<Config_Dungeon> rows`；字段 `id/name/maxPlayers/spawnRadiusMm/monsters(int[])/bossId` |
| CSV 解析器 | `Tools\ConfigKit\src\ConfigKit.Sources.Delimited\DelimitedTableSource.cs:160-214` | 引号感知，`""` 表示字面引号，逗号分隔 |
| 服务端读表 | `Server/NBC.Server.Game/ServerTables.cs` | 启动时读 CSV ⇒ **改完必须重启服务端** |

## 三、最小可运行示例（导出链路）

```
DungeonConfig.asset (rows) → DungeonCsvBridge.BuildCsvText(rows)   // 保留前 4 行表头
  → UTF8(no BOM) + LF 写入 Configs/Design/Dungeon.csv
  → ConfigKit.Cli --source Configs\Design                          // 校验 + 重生成
  → 重启服务端                                                     // ServerTables 重读 CSV
```

## 四、方案对比

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A 现状（单向） | 只 CSV → SO | 零风险、已有 | 不能在客户端改完就生效 |
| **B SO 为编辑真值 + 导出（采用）** | SO 里改，按钮导出 CSV；另有 CSV → SO 覆盖 | 可视化、有类型校验、服务端仍单真值 | 需要「未导出」提示，忘记导出会跑旧数据 |
| C 双向实时同步 | 监听 CSV 改动自动回灌 SO | 两边随时一致 | 编辑器改动与磁盘改动互相触发，易覆盖 |

## 五、已知坑与版本兼容

1. **表头四行不能重写**：只替换数据行，重写会丢中文名/类型/规则。
2. **数字格式**：必须 `CultureInfo.InvariantCulture`，否则中文环境可能写 `3,000`。
3. **数组字段**：`monsters` 写成 `"6001,6001,6001"`（含逗号必须加引号）。
4. **校验与写盘**：导出前查主键唯一、`monsters`/`bossId` 存在于 `Monster` 表；写盘先临时文件再替换、留 `.bak`，失败不留半截。

## 六、结论

采用方案 B，先做 Dungeon 一张表：菜单 `Tools/NBC/配置表/副本表（SO ↔ CSV）`，列表编辑 + 校验 + 「导出到 CSV」/「从 CSV 导入」/「未导出改动」红字提示。「未导出」判据：用当前 SO 重拼 CSV 文本，与磁盘逐字比较。

导出 = 校验 → 写 CSV（保留表头）→ 跑 ConfigKit 生成 → 提示重启服务端；导入 = 解析 CSV → 校验 → 覆盖 `rows` → 保存资产。
代码量预估：窗口约 210 行、CSV 桥约 190 行、EditMode 测试约 60 行，合计约 460 行（<500）。
