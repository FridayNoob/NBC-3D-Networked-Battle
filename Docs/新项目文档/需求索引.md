# 需求索引

> 所有新工作都记在这里。**阶段沿用原计划 M0~M6**，每个阶段内部拆成一个个小需求；
> 一个需求一个文件夹、严格 8 篇（`01-技术预研` … `08-文档沉淀`），结构见 `Docs\00` §二之三。
> 维护方式：每开一个需求加一行，验收后回填状态；已验收的行只允许改错别字。

## 一、怎么用（三条规矩）

1. **命名**：`R三位序号-中文短语`，例 `R001-玩家移动`。序号只增不复用，删掉的需求留空号。
2. **状态**：只用五个词 —— `草稿` / `开发中` / `待验收` / `已验收` / `搁置`。
3. **轻量通道**：改 bug、整注释、修字符串、调参数 ⇒ 不建文件夹，去 `FIXES.md` 记一行。
   判据一句话：**做完之后用户会不会看到新东西？会 ⇒ 需求；不会 ⇒ 修复。**

## 二、编号按阶段分区（**2026-10-26 定**）

| 编号段 | 所属阶段 | 说明 |
| --- | --- | --- |
| R001~R099 | **M4** | 任务成就权威 + 帧同步 2v2 已闭合；剩下的是**客户端表现与收尾缺口** |

## 三、每篇文档的结构

与 `261026AI辅助开发` 的 8 篇对齐：固定 8 组小标题，一节都不许缺，没内容就写「（本步不涉及：原因）」；
每篇最后一节固定是「产出物检查清单」。模板在 `_模板\`，细则见 `Docs\00` §二之三。
