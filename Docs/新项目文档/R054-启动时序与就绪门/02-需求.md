# 02 需求

需求编号：R054
所属阶段：M4
作者：AI（DeepSeek）
状态：开发中

## 一、业务目标（一句话）

进副本时「装资源 → 设配置来源 → 等配置表 → 挂 HUD」四件事按固定顺序执行，任何一步没好就原地等、超时能说清卡在哪一步。

## 二、用户与场景

- 玩家：从 Login 点开始 → World → 按 E 进副本；或死亡复活、点「再来一次」再进副本。
- 玩家在屏幕上看到的是：HUD 出现在该出现的时候（不早于资源与配置就绪），不出现「表没加载」「资源层没初始化」这类红字。
- 开发/验收者：Console 里按 `[Boot]` 前缀能看出这次进副本卡在哪一步、耗时多久、因何失败。

## 三、功能列表

| 优先级 | 功能 | 说明 |
| --- | --- | --- |
| P0 | 统一就绪判断 | `BattleReadiness` 提供资源层/配置来源/表是否就绪的只读判断，消费者不再各写一套 |
| P0 | 幂等配置初始化 | `BattleConfigBootstrap.Ensure`：没来源就设来源、一张表都没有才预加载；重复调用无害 |
| P0 | 四步启动编排 | `BattleBootSequence`：等资源层 → 设配置来源 → 等 HUD 三张表 → 挂 HUD；第 4 步完成即触发 `Completed` |
| P0 | 单步超时与失败原因 | 每步 8 秒超时，失败原因写「第 N 步（中文名）超过 8 秒还没完成」 |
| P1 | 可取消 | 回 World / 切场景时 `Cancel`，之后不再触发任何回调 |
| P2 | 日志 | 每步进入、完成、失败各一条 `[Boot]` 前缀日志 |

## 四、边界（不做什么）

1. 不自己装资源层（仍由 `HpBarDemoBehaviour` 负责，编排只等）；
2. 不改服务端、不改协议、不改战斗逻辑；
3. 不做通用「生命周期框架」，只覆盖这一条启动链；
4. 不加 Boot 进度 UI（黑幕与进度条属 R046/R048 范围）。

## 五、优先级

P0 全部在本需求内完成；P1 的 `Cancel` 与 P2 的日志本次一起做（成本很低且直接服务排查）。

## 六、验收标准（当…时，应…）

1. 当玩家进副本且资源层还没装好时，HUD 不应请求面板，也不应刷「资源层尚未初始化」。
2. 当资源层就绪、但配置来源还没设时，`BattleConfigBootstrap.Ensure` 应把来源设成 `AssetConfigSource`。
3. 当一张配置表都没有时，`Ensure` 应发起一次 `PreloadAll`；已有任意表时不应重复发起。
4. 当三张 HUD 表都加载完成时，HUD 应在同一次 Tick 内挂上并立刻显示 BOSS/目标/任务信息。
5. 当某一步超过 8 秒未完成时，应输出 `[Boot] 失败：第 N 步（…）超过 8 秒还没完成`，并且不再继续后续步骤。
6. 当玩家返回 World 时，编排应被取消；再次进副本应从第 1 步重新开始。
7. 当连续两次进入副本时，HUD 只应 Bind 一次、`Completed` 只触发一次。
8. 当没有任何配置表且来源已设时，Console 不应出现 `[ConfigMgr] 表…还没加载` 的异常。
9. 当在 EditMode 跑全量测试时，新增 7 条编排用例应全绿，且原 805 条不受影响。
10. 当启动失败时，失败日志应能让验收者不打开代码就判断是「资源层慢」还是「配置表慢」。
