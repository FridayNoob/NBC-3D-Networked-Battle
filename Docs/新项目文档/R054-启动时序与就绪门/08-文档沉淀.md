## 一、文档范围

本需求治的是「进入战斗前，谁在什么时候把资源层、配置表、HUD 装好」。覆盖三块：就绪判断、幂等初始化、启动编排。任务系统、技能栏、打包流程不在范围内。

## 二、模块文档

### 2.1 `BattleReadiness`（就绪判断）

- 简介：只回答「现在能不能用」，不做任何装配动作。
- 接口：`AssetsReady`、`ConfigSourceReady`、`AllTablesReady`、`HudTablesReady`、`HudReady`、`DescribeMissing()`；常量 `HudTables = { Quest, QuestCondition, Monster }`。
- 示例：`if (!BattleReadiness.AssetsReady) { return; }` 放在任何「要用资源」的方法开头。
- 原理：就绪 = 若干个独立条件同时为真；每个条件只查一次状态，不改状态。
- 坑：`DescribeMissing()` 只用于日志，不要拿它做分支判断。
- 维护：新增一类依赖就往 `HudTables` 里加表名，并让 `DescribeMissing` 多一句。

### 2.2 `BattleConfigBootstrap`（幂等初始化）

- 简介：把「设配置来源 + 预加载全部表」收成一次调用，重复调用无害。
- 接口：`Ensure(Action<string> onFailed = null)`。
- 示例：`BattleConfigBootstrap.Ensure(reason => Debug.LogError("[HpBarDemo] 预加载配置表失败：" + reason));`
- 原理：`Source == null` 才 `SetSource`；`LoadedTableCount > 0` 就直接返回。
- 坑：它不等待加载完成——「表真的齐了吗」是 `BattleReadiness` 的事。
- 维护：新增配置来源类型时只改这里。

### 2.3 `BattleBootSequence`（启动编排）

- 简介：四步链「等资源层 → 设配置来源 → 等配置表 → 挂 HUD」，带单步超时，可重入。
- 接口：构造（四个 `Func<bool>` + 两个 `Action` + 日志 + 超时）、`Begin()`、`Tick(float)`、`Cancel()`、事件 `Completed`/`Failed`；枚举 `EBootStep`。
- 示例：
  - `m_boot = new BattleBootSequence(...); m_boot.Begin();`
  - 每帧 `m_boot.Tick(Time.deltaTime);`
  - 离开场景 `m_boot.Cancel(); m_boot = null;`
- 原理：状态机把「顺序」变成数据；每步只判断一个条件；满足即 `Enter(下一步)`；失败只报一次并停住。
- 坑：满足条件的当帧必须 `Finish()`，否则会差一帧（单测会抓到）。
- 维护：加步骤 = 加枚举值 + 加 `NameOf` 文案 + 在 `Tick` 里加一个分支，不改外部接口。

## 三、踩坑清单

1. **Unity 假绿**：新 `.cs` 没有 `.meta` 时，编译错误列表是旧的；必须先 `Assets/Refresh`。
2. **差一帧**：状态机「进入下一步」与「执行下一步」分在不同帧，测试要按同帧语义写。
3. **补丁式修顺序**：在两个调用点各加一个 `if` 只会让下一个调用点继续漏。
4. **失败要报步号与中文名**：只报「超时」无法定位是资源慢还是配置慢。
5. **测试工具超时**：`RunEditMode` 单次调用上限 30 秒，跑满时要重试并读结果文件。
