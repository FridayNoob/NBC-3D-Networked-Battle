# 03 方案设计

需求编号：R054
所属阶段：M4
作者：AI（DeepSeek）
状态：开发中

## 一、整体架构

```
进副本（RuntimeNetDriver.RefreshPresentation）
        │  第一次需要 HUD
        ▼
BattleBootSequence（每帧 Tick，四步）
   1 等资源层  ──► BattleReadiness.AssetsReady
   2 设来源    ──► BattleConfigBootstrap.Ensure（幂等）
   3 等配置表  ──► BattleReadiness.HudTablesReady（Quest/QuestCondition/Monster）
   4 挂 HUD    ──► RuntimeNetDriver.BindHud → RuntimeHudDriver.Bind
        │
        ▼
Completed（hudBound = true，不再 Tick）
```

回 World：`RuntimeNetDriver.CloseHud` → `BattleBootSequence.Cancel()` + `m_boot = null`；下次进副本重新 `Begin()`。

## 二、模块划分

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| `BattleReadiness` | 回答「资源层/来源/表 好了没」，给出缺项人话 | 加载、等待、重试 |
| `BattleConfigBootstrap` | 设来源、空表时预加载（幂等） | 等待加载完成、判断具体表 |
| `BattleBootSequence` | 四步推进、单步超时、日志、Completed/Failed | 具体判断实现（全部注入） |
| `RuntimeNetDriver` | 在需要时创建编排、每帧 Tick、完成时 BindHud、关 HUD 时取消 | 判断细节 |
| `RuntimeHudDriver` | 面板显示与数据刷新 | 启动顺序 |
| `HpBarDemoBehaviour` | 资源层安装（`await InstallAsync`）、进副本时也调一次 `Ensure` | 编排 |

## 三、接口（与最终代码逐字一致）

```csharp
public static class BattleReadiness
{
    public static bool AssetsReady { get; }
    public static bool ConfigSourceReady { get; }
    public static bool AllTablesReady { get; }
    public static bool HudTablesReady { get; }
    public static bool HudReady { get; }
    public static string DescribeMissing();
}

public static class BattleConfigBootstrap
{
    public static void Ensure(Action<string> onFailed = null);
}

public enum EBootStep { WaitAssets, PrepareConfigs, WaitTables, BindHud, Done }

public sealed class BattleBootSequence
{
    public const float DefaultStepTimeoutSeconds = 8f;

    public BattleBootSequence(
        Func<bool> assetsReady,
        Func<bool> configSourceReady,
        Func<bool> tablesReady,
        Action prepareConfigs,
        Action bindHud,
        Action<string> log = null,
        float stepTimeoutSeconds = DefaultStepTimeoutSeconds);

    public event Action Completed;
    public event Action<string> Failed;

    public EBootStep Step { get; }
    public bool IsRunning { get; }
    public bool IsFinished { get; }

    public void Begin();
    public void Tick(float deltaSeconds);
    public void Cancel();
    public static string NameOf(EBootStep step);
}
```

约定：`Tick` 内部不抛异常；`Completed` 在 `BindHud` 之后触发且只触发一次；`Cancel` 之后不再触发任何事件；`Begin` 可重入（重置到第一步）。

## 四、数据结构

| 数据 | 类型 | 含义 |
| --- | --- | --- |
| `m_step` | `EBootStep` | 当前步骤，同时是失败原因里的步号来源 |
| `m_stepElapsed` | `float`（秒） | 当前步已耗时，超 `m_stepTimeoutSeconds` 判失败 |
| `m_stepTimeoutSeconds` | `float`（秒） | 单步超时，默认 8，构造传 ≤0 时回落默认 |
| `HudTables` | `string[3]` | `Quest` / `QuestCondition` / `Monster`，HUD 真正依赖的表 |
| `m_boot` | `BattleBootSequence`（驱动字段） | 每局一条；回 World 置 null |

## 五、时序与流程

1. `RefreshPresentation` 发现需要 HUD 且未 Bind ⇒ `EnsureHud()`；
2. `EnsureHud` 第一次调用时构造编排（注入五个委托 + 日志），并 `Begin()`；
3. 每帧 `m_boot.Tick(Time.deltaTime)`：
   - 第 1 步：资源层好 ⇒ 进第 2 步；进第 2 步时执行一次 `Ensure`（设来源 + 可能预加载）；
   - 第 2 步：来源已设 ⇒ 进第 3 步；
   - 第 3 步：三张表齐 ⇒ 进第 4 步并**同帧完成**（避免一帧空窗）；
   - 第 4 步：执行 `BindHud`、打「表现层就绪」、触发 `Completed`；
4. 任一步 `m_stepElapsed > 8` ⇒ `Failed(reason)`，停跑，日志一条 `[Boot] 失败：…`；
5. `CloseHud` ⇒ `Cancel()` + `m_boot = null` + `m_hudBound = false`，下次进副本重新来。

## 六、选型与理由

1. **依赖注入而非单例直读**：编排要能在 EditMode 用假条件跑（本需求 7 条用例全靠这一点）；
2. **就绪判断与加载分离**：判断可随时问、加载只发生一次；避免「在判断里顺手加载」造成循环；
3. **超时在编排层**：单步超时 8 秒，比分散在各消费者更容易说清「卡在哪」；
4. **表齐后同帧完成**：少一帧空窗，玩家进副本不会先看到空 HUD；
5. **不引入协程**：`Tick` 显式推进，测试可以精确控帧。

## 八、风险与对策

| 风险 | 对策 |
| --- | --- |
| 资源层永远不就绪（安装失败） | 8 秒超时 + `[Boot] 失败：第 1 步（等资源层）…`，顺着 `HpBarDemo` 日志查 |
| 预加载失败后表永远不全 | 第 3 步超时，日志点名「等配置表」；`Ensure` 的失败回调另有 `[Boot] 预加载配置表失败：…` |
| 重复进副本导致重复 Bind | `m_hudBound` 短路 + `m_boot` 在 CloseHud 置 null；`Finish` 里 `m_finished` 再兜一次 |
| 编排与 HUD 各自判断不一致 | `RuntimeHudDriver.Bind` 仍保留 `BattleReadiness.AssetsReady` 门，双保险 |
| 新文件没被 Unity 导入导致「编译 0 错」假象 | 验收前必须 `Assets/Refresh` 并确认 `.meta` 生成 |
