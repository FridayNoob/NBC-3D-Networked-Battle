# 03 方案设计

需求编号：R046
所属阶段：M4
作者：AI（DeepSeek）
状态：开发中

## 一、整体架构

```
快照（ServerTick 30Hz）
   └─ PresentationFeed.View.Entities  ─┐
任务本 NetSession.Quests ───────────────┤
                                        ▼
                          RuntimeHudDriver（每帧，挂在 [DungeonSession] 上）
                                        │
              ┌─────────────────────────┼──────────────────────────┐
              ▼                         ▼                          ▼
   HudTargetPanel（prefab）    HudQuestPanel（prefab）    DeathScreenOverlay（prefab）
   BOSS 条 + 目标行             任务追踪 1~3 行            死亡黑幕（R041 行为不变）
```

## 二、模块划分

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| `HudTargetPanel` | 画 BOSS 条与目标行，按数值改填充/文字 | 不选目标、不读快照 |
| `HudQuestPanel` | 把任务本里进行中的行拼成 1~3 行文字 | 不做任务操作按钮（那是 QuestPanel） |
| `DeathScreenOverlay` | 黑幕显隐、标题、倒计时、状态行 | 不决定「什么时候死」（PlayerDeathFlow 决定） |
| `RuntimeHudDriver` | 每帧筛 BOSS/目标、算名字、喂三个面板 | 不画任何控件 |

## 三、接口

### 3.1 HudTargetPanel : BasePanel

| 方法 | 入参 | 出参 | 约定 |
| --- | --- | --- | --- |
| `SetBoss(bool visible, string label, int hp, int maxHp)` | 是否显示、标题、当前血、最大血 | 无 | `visible=false` 时整行隐藏；`maxHp<=0` 按 0 比例 |
| `SetTarget(bool visible, string label, int hp, int maxHp)` | 同上 | 无 | 无目标时隐藏目标行 |

控件名（prefab 里必须有）：`Root`、`BossRoot`、`BossLabel`、`BossValue`、`BossFill`、`TargetRoot`、`TargetLabel`、`TargetValue`、`TargetFill`。

### 3.2 HudQuestPanel : BasePanel

| 方法 | 入参 | 出参 | 约定 |
| --- | --- | --- | --- |
| `SetQuest(QuestPanelModel model)` | 任务本（可为 null） | 无 | 没有进行中的行 ⇒ 隐藏 `Root`；最多 3 行 |

控件名：`Root`、`Text_Tracker`。

### 3.3 DeathScreenOverlay : BasePanel（保留原类名与静态入口）

| 方法 | 入参 | 出参 | 约定 |
| --- | --- | --- | --- |
| `static DeathScreenOverlay Ensure()` | 无 | 面板实例 | 走 `UIManager.ShowPanel("DeathScreenOverlay", UILayer.Top)`，重复调用返回同一实例 |
| `Show(string title, string hint)` | 标题、提示 | 无 | 打开黑幕 |
| `SetCountdown(float remaining)` | 剩余秒 | 无 | 显示 `Mathf.CeilToInt` |
| `SetStatusText(string text)` | 状态行 | 无 | null 当空串 |
| `Hide()` | 无 | 无 | 只关 `Root`，面板实例保留 |

控件名：`Root`、`Img_Backdrop`、`Text_Title`、`Text_Countdown`、`Text_Status`。

### 3.4 RuntimeHudDriver : MonoBehaviour

| 方法 | 入参 | 出参 | 约定 |
| --- | --- | --- | --- |
| `Bind(PresentationFeed feed, NetSession session)` | 表现层、会话 | 无 | 由 `RuntimeNetDriver` 在进房成功后调用 |
| `Tick()`（内部 `Update`） | 无 | 无 | 每帧筛 BOSS 与最近目标并喂面板 |
| `CloseAll()` | 无 | 无 | 退出副本时关三个面板 |

目标选择规则：在 `Entities` 里取「`Alive && Kind != 0`」中离英雄最近的一个（`Kind==2` 视为 BOSS）。

## 四、数据结构

- BOSS/目标名字：`Kind==2` → `"BOSS（" + ConfigId + "）"`；`Kind==1` → `"怪物（" + ConfigId + "）"`；不引配置表。
- 距离：平方距离（毫米平方）比较，避免开方。
- 任务行：`QuestRow.Title + " · " + QuestRow.Detail`，最多 3 行，用 `\n` 拼接。

## 五、时序与流程

1. 进房成功 → `RuntimeNetDriver` 建 `RuntimeHudDriver` 并 `Bind`。
2. 每帧 `Update`：读 `feed.View.Entities` → 找 BOSS → 找最近怪 → `SetBoss/SetTarget`。
3. 每 0.2 秒（节流）读 `session.Quests` → `SetQuest`。
4. 玩家死亡 → `PlayerDeathFlow` 调 `DeathScreenOverlay.Ensure().Show(...)`（与现在一致）。
5. 退出副本 → `RuntimeNetDriver.ReturnToWorldRoutine` 调 `CloseAll()`，并 `HidePanel` 三个面板。

## 六、选型与理由

1. **用 prefab 而不是运行时 UGUI**：R045 的教训（锚点坐标写飞）；美术可拖布局。
2. **一个 `RuntimeHudDriver` 而不是让每个面板自己找数据**：数据源只有一处，面板保持「只画」。
3. **保留 `DeathScreenOverlay` 类名**：`PlayerDeathFlow` 与 `DungeonResultPanel` 有 9 处调用，改名会扩大影响面。
4. **名字用「种类 + 配置号」**：快照没有名字字段，引配置表会新增跨层依赖。
5. **任务追踪自己拼文字**：复用 `QuestPanelModel.CopyTrackingRows`，不重做行布局。

## 八、风险与对策

| 风险 | 对策 |
| --- | --- |
| `UIManager` 把 HUD 面板铺满并清零位置 | prefab 根上挂 `KeepPrefabTransform` |
| 面板名与 prefab 文件名不一致 ⇒ 打开失败 | 名字写常量，prefab 用同名文件 |
| 任务本为空导致空框 | `SetQuest` 里 0 行就隐藏 `Root` |
| BOSS 死亡瞬间血条残留 | 每帧按 `Alive` 判断，不做缓动 |
| 面板没人关，回 World 还在 | `CloseAll()` + `UIManager.HidePanel` |
