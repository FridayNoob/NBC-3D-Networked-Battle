# 01 技术预研

需求编号：R046
所属阶段：M4
作者：AI（DeepSeek）
状态：开发中

## 一、调研目标与约束

**目标**：把副本里的 HUD 补到「面试可演示」的程度——顶部 BOSS 大血条、当前目标的名字与血量、任务追踪行，并把 R041 的黑幕从运行时搭 UI 改成预制体面板。

**约束**：

1. 只改客户端表现层，服务端不动（数据已经在快照与任务消息里）。
2. 面板一律走既有 `BasePanel` + `UIManager.ShowPanel("面板名", 层)`，面板名就是 prefab 文件名（收集器 `AddressByFileName`）。
3. 不改 `SnapshotView.cs`（受保护文件），目标与 BOSS 的信息从 `PresentationFeed.View.Entities` 读。
4. 黑幕面板必须保留 `DeathScreenOverlay.Ensure()` 这类静态入口，避免改一堆调用点。
5. 代码量预算 500 行（§0.1），超了要拆。

## 四、方案对比

| 方案 | 做法 | 优点 | 缺点 | 适用 |
| --- | --- | --- | --- | --- |
| **A（采用）** | 新建 `HudTargetPanel`（BOSS 条 + 目标行）与 `HudQuestPanel`（任务追踪），黑幕改 `DeathScreenPanel`；三个 prefab，全部 `BasePanel` | 与现有 HpBarPanel 同构；预制体可拖布局；黑幕顺带还清技术债 | 要新建 3 个 prefab，需要一次编辑器操作 | 本需求 |

## 五、已知坑与版本兼容

1. **`UIManager` 挂载会清零 RectTransform**，除非 prefab 根上挂 `KeepPrefabTransform`（`UIManager.cs:850` 有注释）。HUD 小面板必须挂它，否则位置被清零跑到屏幕中央。
2. **`AddressByFileName`**：面板名只能等于 prefab 文件名（`HpBarDemoBehaviour.cs:95` 有记录），改名要同步改代码与收集器。
3. **`SnapshotView` 是受保护文件**，不能为了取 BOSS 便利而改它；用 `Entities` 自己筛。
4. **快照里没有名字字段**：怪物名只能按 `Kind` 显示「BOSS / 精英 / 小怪」，或从 `Monster.csv` 按 `ConfigId` 查（`EntitySnapshot` 有 `ConfigId`）。本需求先用「BOSS（1003）」这类「种类 + 配置号」的写法，不引表。
5. **任务本可能为空**（World 里没接任务就进副本）：任务追踪面板要能在 0 行时整块隐藏，不能显示空框。
6. **黑幕的静态入口**：`PlayerDeathFlow`、`DungeonResultPanel` 都在调 `DeathScreenOverlay.Ensure()`，改成 prefab 后必须保留同名静态方法，内部转调 `UIManager`。

## 六、结论

采用 **A**：三个新 prefab（`HudTargetPanel`、`HudQuestPanel`、`DeathScreenPanel`）+ 两个新脚本（`HudTargetPanel`、`HudQuestPanel`）+ 一个改写的 `DeathScreenPanel`，再由 `RuntimeHudDriver` 每帧把快照/任务本喂进去。预计 470 行左右，落在 500 行预算内。
