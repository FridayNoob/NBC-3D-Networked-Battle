## 三、根因分析

| # | 根因 |
| --- | --- |
| 1 | `BTNodeRegistry` 有 `s_loaded` 缓存；`BTNodeDefinitionAsset` 改动后没人让它失效，窗口也不重建左栏；属性面板/副标题用的是节点视图上缓存的旧 `BTNodeDefine` 对象 |
| 2 | `BTGraphView.RemoveNode` 只删了 `m_data.Nodes[id]`，**没把 id 从父节点的 `Children` 摘掉**，`RootNodeId` 也可能指向已删节点 |
| 3 | `CompleteConnection` 没有「这对节点已连过」的判断，删了再连会留下两条边；`ExportData` 逐条边写 `Children` 也不去重；`Validate` 把「同一 id 第二次访问」一律当环报 |
| 4 | 用 PowerShell「按行拼接数组再 `-join`」写文件，某次数组被当成单个元素写入。**能编译是因为重复语句语法合法** |
| 5 | 手写节点表时把 `Patrol/Idle` 合并计成一条、`Wait` 又单列，前后没核对 |

## 四、改进方案

| # | 改哪 | 怎么改 | 影响面 |
| --- | --- | --- | --- |
| 1 | 新增 `Data/BTNodeDefinitionsWatcher.cs`；改 `Window`（`RefreshAllWindows`）、`BTInspectorView.Bind`、`BTNodeView.UpdateSubtitle` | `AssetPostprocessor` 命中定义资产 → `Reload()` + 重建左栏 + 重绑面板；绑定/副标题每次从注册表取最新定义 | 仅编辑器 |
| 2 | `BTGraphData.RemoveDanglingReferences()`；`RemoveNode` 调用；`OnImport`、`BTPreviewRunner.Start` 兜底 | 删/导入/预览三处清脏引用；预览改为「克隆 → 清理 → 校验」顺序 | 仅编辑器 |
| 3 | `CompleteConnection`、`ExportData`、`Validate` | 拒绝重复边；导出时 `Contains` 去重；校验先判「重复引用 / 多个父节点」再判环 | 仅编辑器 |
| 4 | 工程习惯 | 改 C# 一律用**整段替换**而不是行拼数组；改完检查「最长行 < 200 字符」再提交 | 全项目 |
| 5 | 本文与 08 | 明确节点总数 = **16**（3 组合 + 6 条件 + 7 动作） | 文档 |
