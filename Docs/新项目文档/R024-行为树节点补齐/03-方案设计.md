# 03 方案设计

需求：R024-行为树节点补齐（客户端为准）
所属阶段：M4
作者：AI 起草　状态：已确认（2026-11-08）

## 一、整体架构

```
BTNodeDefinitions.asset（ScriptableObject，策划编辑）
         │ 每个条目：TypeName / 分类 / MaxChildren / 参数表 / **PreviewKind**
         ▼ 启动加载 + 校验
BTNodeRegistry（唯一权威：左栏分组、属性面板、端口规则都从这里取）
         │
    ┌────┴─────────────────────────────┐
    ▼                                  ▼
BTGraphView / BTInspectorView      BTPreviewRunner（200ms）
（按定义自动生成 UI，零节点代码）        │ 按 PreviewKind 找到预览求值器
                                        ▼
                                  BTPreviewRegistry（注册表，非 switch）
                                        ├─ 组合：Selector / Sequence / Parallel
                                        ├─ 通用求值器：IntCompare / FloatCompare / Flag / AlwaysSuccess / AlwaysRunning / Timed
                                        └─ 没有对应求值器 ⇒ 灰态「预览未实现」
```

**关键设计（按 AGENTS.md §0.2 SOLID）**：

1. **节点定义数据化**：14 个节点全部是 SO 里的数据；左栏/属性面板/连线规则都按定义生成 ⇒ **新增"纯参数"节点 0 行代码**。
2. **预览行为"配方化"**：SO 条目带 `PreviewKind` + 参数映射，绝大多数节点（比较血量/读开关/恒成功/恒运行/冷却）用**通用求值器**，不写新类。
3. **扩展点自注册**：预览求值器用 `[BtPreviewKind(...)]` 特性扫描注册；需要全新预览行为时**只新增 1 个文件**，`BTPreviewRunner` 一行不改。
4. **灰态**：没有求值器的节点返回 `NotPreviewed`（灰），不算 Failure。

## 三、接口（★ 先定死）

```csharp
// ---------------- 数据 ----------------
public enum BTPreviewKind
{
    None = 0,          // 没配 → 预览为灰
    AlwaysSuccess,
    AlwaysRunning,
    IntCompare,        // 读黑板 int 键，与阈值/参数比较
    FloatCompare,      // 读黑板 float 键
    Flag,              // 读黑板 bool 键
    Timed,             // 自己的计时器（Wait）
    CompositeSelector,
    CompositeSequence,
    CompositeParallel
}

public enum BTCompareOp { Less, LessOrEqual, Greater, GreaterOrEqual, Equal, NotEqual }

[Serializable] public sealed class BTParamEntry { public string Key; public string Label; public BTParamType Type; public string Default; }

[Serializable] public sealed class BTNodeEntry
{
    public string TypeName;
    public string DisplayName;
    public BTNodeCategory Category;
    public int MaxChildren;          // -1 不限 / 0 叶子
    public BTPreviewKind PreviewKind;
    public string PreviewKey;        // 黑板键，如 hp / targetId / skillCd / inRange / homeFar
    public BTCompareOp CompareOp;    // IntCompare/FloatCompare 用
    public string CompareParamKey;   // 阈值从哪个参数取（空=用常量）
    public int CompareConstInt;
    public float CompareConstFloat;
    public List<BTParamEntry> Params = new();
}

public sealed class BTNodeDefinitionAsset : ScriptableObject { public List<BTNodeEntry> Nodes = new(); }
```

```csharp
// ---------------- 预览扩展点 ----------------
public enum BTPreviewStatus { Success, Failure, Running, NotPreviewed }   // 新增第四态

public sealed class BTPreviewContext
{
    public BTBlackboard Blackboard;
    public float DeltaSeconds;
    public BTNodeData Data;            // 当前节点的数据（读 Params）
    public List<BTPreviewStatus> ChildStatuses;   // 组合节点用
    public Action<string> ChildrenTick;           // 组合节点驱动子节点
    public string Detail;              // 供状态栏显示
}

public interface IBtPreviewNode
{
    BTPreviewStatus Tick(BTPreviewContext ctx);
    void Reset();
}

[AttributeUsage(AttributeTargets.Class)]
public sealed class BtPreviewKindAttribute : Attribute
{
    public BTPreviewKind Kind { get; }
    public BtPreviewKindAttribute(BTPreviewKind kind);
}

public static class BTPreviewRegistry
{
    public static IBtPreviewNode Resolve(BTPreviewKind kind);   // 找不到 → null（⇒ 灰态）
    public static void EnsureRegistered();                       // 扫描一次（懒加载）
}
```

## 四、14 个节点的数据形态（全部在 SO 里，按 PreviewKind 配方）

| 节点 | 分类 | 参数 | PreviewKind | PreviewKey / 比较 |
| --- | --- | --- | --- | --- |
| `Selector` | Composite | — | CompositeSelector | — |
| `Sequence` | Composite | — | CompositeSequence | — |
| `Parallel` | Composite | — | CompositeParallel | — |
| `IsDead` | Condition | — | IntCompare | `hp` ≤ 0 |
| `InAttackRange` | Condition | `rangeMm`(int) | Flag | `inRange` |
| `AttackReady` | Condition | `skillId`(int) | FloatCompare | `skillCd` ≤ 0 |
| `HPBelow` | Condition | `hpThreshold`(int)、`percentOfMax`(bool) | IntCompare | `hp` < 参数 `hpThreshold` |
| `HasTarget` | Condition | — | IntCompare | `targetId` > 0 |
| `HomeFar` | Condition | — | Flag | `homeFar` |
| `Chase` | Action | — | AlwaysRunning | — |
| `BasicAttack` | Action | `hits`(int)、`intervalTicks`(int) | AlwaysSuccess | 预览日志标「多段×N」 |
| `CastSkill` | Action | `skillId`(int)、`cooldownSeconds`(float) | AlwaysSuccess | 置 `skillCd` = cooldownSeconds |
| `ReturnHome` | Action | — | AlwaysRunning | — |
| `Patrol` / `Idle` | Action | — | AlwaysSuccess | — |
| `Wait` | Action | `seconds`(float) | Timed | 用自己的计时器 |

> 说明：`BasicAttack` / `CastSkill` 需要「成功时写黑板」，用 `PreviewKind.AlwaysSuccess` + 一个可选 `WriteBackKey` 字段表达（同一套通用求值器，不为两个节点写类）。

## 五、时序（预览一次 Tick）

1. `BTPreviewRunner` 每 200ms 触发。
2. 从根节点递归：读该节点 `BTNodeData.NodeType` → `BTNodeRegistry.Find` 取定义 → 取 `PreviewKind`。
3. `BTPreviewRegistry.Resolve(kind)`；取不到 ⇒ **`NotPreviewed`（灰）**。
4. 求值器返回三态（组合节点通过 `ctx.ChildrenTick` 驱动子节点）。
5. Runner 把 `(nodeId → status)` 交给画布上色：绿/红/黄/灰。

## 六、技术选型与理由

| 选择 | 选定 | 理由（对齐 SOLID） | 被否方案 |
| --- | --- | --- | --- |
| 定义存哪 | **ScriptableObject 集合** | 策划可编辑、可校验、不需要 JSON 解析（D：编辑器侧不依赖序列化细节） | JSON（要自研解析、无类型安全） |
| 预览分派 | **PreviewKind + 注册表** | O：新增简单节点 0 行；新增新行为只加一个文件 | 按 NodeType 的 `switch`（每加节点改主流程） |
| 求值器怎么找 | **特性扫描 + 懒加载** | O/D：主流程不依赖具体实现 | 手写静态表（要改表） |
| 每节点是否一个文件 | **不需要**（同一求值器被多节点复用） | S/O：行为种类远少于节点数 | 一节点一文件（文件爆炸且重复） |
| 灰态 | `NotPreviewed` 第四态 | L：不破坏既有三态语义，只是多一个取值 | 复用 Failure（会误报红） |

## 八、SOLID 自检

| 原则 | 本设计怎么满足 |
| --- | --- |
| **S** | SO（数据）/ Registry（加载校验）/ PreviewApi（扩展点）/ PreviewKinds（行为）/ Runner（调度）/ View（显示）各自单一职责 |
| **O** | 新增纯参数节点 = 只改 SO（0 行）；新增新行为 = 新增一个 `[BtPreviewKind]` 类（新文件）⇒ 不改 Runner |
| **L** | `IBtPreviewNode` 契约写清：「返回 NotPreviewed 表示未实现，不得抛异常」；组合节点不改变子节点语义 |
| **I** | `IBtPreviewNode` 只有 `Tick` + `Reset`；节点读黑板/参数经 `BTPreviewContext`，不依赖 Runner 内部 |
| **D** | Registry 依赖 `BTNodeDefinitionAsset`（抽象数据），Runner 依赖 `IBtPreviewNode` 接口，都不 new 具体求值器 |

## 九、风险与对策

- **SO 被误改导致空节点库**：加载时校验（空列表、重名、空 TypeName、非法 `MaxChildren`）→ 抛异常并在状态栏提示资产路径。
- **`PreviewKind` 与参数映射配错**（如 `HPBelow` 指了不存在的参数键）：加载时校验 `CompareParamKey` 必须存在于 `Params`。
- **灰态误用**：`NotPreviewed` 只由「没有求值器」产生；求值器内部异常一律视为 Failure 并写日志（避免隐藏 bug）。
- **旧 JSON 导入**：`MoveTo` 不再注册 ⇒ 导入时报「类型未注册」，属预期（负责人确认不用管）。
- **注册扫描开销**：懒加载一次并缓存；编辑器域重载后自动失效重扫。
