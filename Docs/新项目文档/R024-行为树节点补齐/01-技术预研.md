# 01 技术预研

需求：R024-行为树节点补齐（客户端为准）
所属阶段：M4
作者：AI　状态：草稿（待负责人确认）

## 一、调研目标与约束

- 目标：把「怪物 AI 真正需要的节点」**先补进客户端编辑器**（`BTNodeRegistry` + 预览执行器 + 黑板项），
  让客户端成为节点定义的**唯一权威**；服务端随后照抄（R022 系列）。
- 约束：
  1. **只在编辑器**（`NBC.Editor`，不进包）；
  2. 节点名即 JSON 的 `NodeType`，一经发布**不许改名**；
  3. 不引外部插件，沿用 R023 的自研编辑；
  4. 代码量预估 **≈300 行**（见 §七），符合 AGENTS.md §0.1。

## 二、现状（已确认）

| 项 | 事实 |
| --- | --- |
| 客户端注册表（权威） | 8 种：`Selector` / `Sequence` / `Parallel` / `HPBelow` / `HasTarget` / `MoveTo` / `CastSkill` / `Wait` |
| 客户端预览执行器 | `BTPreviewNode.TickCore` 覆盖同上 8 种 |
| 黑板现有键 | `hp`（int）、`targetId`（int）、`skillCd`（float） |
| 服务端自创节点（**违规**） | `IsDead` / `InAttackRange` / `AttackReady` / `HomeFar` / `Chase` / `BasicAttack` / `ReturnHome` / `Patrol` / `Idle` |
| 服务端别名（**违规**） | `MoveTo→Chase`、`CastSkill→BasicAttack`、`Wait→Idle` |

## 三、要补的节点（9 个）

| # | 节点 | 分类 | 参数 | 语义 |
| --- | --- | --- | --- | --- |
| 1 | `IsDead` | 条件 | 无 | 自己死了 → 成功（放 Selector 最前，优先于一切） |
| 2 | `InAttackRange` | 条件 | 无 | 目标在普攻射程内 |
| 3 | `AttackReady` | 条件 | 无 | 普攻冷却已好 |
| 4 | `HomeFar` | 条件 | 无 | 离家超过回位半径 |
| 5 | `Chase` | 动作 | 无 | 朝目标移动一帧（运行中/成功） |
| 6 | `BasicAttack` | 动作 | 无 | 对目标发起一次普攻 |
| 7 | `ReturnHome` | 动作 | 无 | 朝出生点走，到家成功、途中运行中 |
| 8 | `Patrol` | 动作 | 无 | 允许巡逻（交给实体自身的巡逻位移） |
| 9 | `Idle` | 动作 | 无 | 站桩（不移动） |

补完后客户端共 **17 个**节点（8 旧 + 9 新）。

## 四、预览执行器怎么落（编辑器内自测用）

预览是简化模拟，不连服务端，所以新节点用**黑板开关**表达：

| 新黑板项 | 类型 | 默认 | 用途 |
| --- | --- | --- | --- |
| `inRange` | bool | false | 给 `InAttackRange` 读：是否在射程内 |
| `homeFar` | bool | false | 给 `HomeFar` 读：是否离家太远 |

| 节点 | 预览行为 |
| --- | --- |
| `IsDead` | `hp <= 0` → 成功；否则失败 |
| `InAttackRange` | 读 `inRange` |
| `AttackReady` | `skillCd <= 0` → 成功 |
| `HomeFar` | 读 `homeFar` |
| `Chase` / `ReturnHome` | 恒「运行中」（模拟持续移动） |
| `BasicAttack` | 成功，并把 `skillCd` 置为该节点冷却参数（暂用固定 2 秒，或复用 `CastSkill` 的参数字段） |
| `Patrol` / `Idle` | 恒成功 |

> 预览**不求拟真**，只求「条件能变红绿、动作不误判」；真正的行为以服务端为准。

## 五、必须先定的一个取舍：旧的 3 个节点怎么办

客户端现有 `MoveTo` / `CastSkill` / `Wait`，与新增的 `Chase` / `BasicAttack` / `Idle` **语义重叠**：

| 方案 | 做法 | 影响 |
| --- | --- | --- |
| **A（建议）** | **删掉** `MoveTo` / `CastSkill` / `Wait`，节点表收敛为 14 个（3 组合 + 6 条件 + 5 动作） | 名字唯一、无歧义；已导出的样例 `new_tree.json` 会失效（重新导出即可） |
| B | 保留旧的 3 个，服务端也实现它们（`Wait` 表示纯等待、`MoveTo` 与 `Chase` 并存） | 两个名字干同一件事，策划会困惑；服务端要维护双份 |
| C | 保旧名、不新增（用 `MoveTo` 当追击、`CastSkill` 当攻击、`Wait` 当站桩） | 名字与语义不符，行为树读起来像谜语 |

## 六、已知坑

1. **改名/删名 = 破坏已导出 JSON**：删 `MoveTo` 后，旧 JSON 导入会报「类型未注册」——这是**预期**，重新导出即可；但要在此需求里明确写出。
2. **预览三态语义**：`Chase` 恒 Running 会让外层 `Sequence` 一直 Running，属预期（它代表"这一帧没结束"）。
3. **黑板新增项要同步 UI**：`inRange` / `homeFar` 必须加进右侧黑板面板，否则策划没法测条件。
4. **服务端随后必须对齐**：本需求只改客户端；R022-1/2/3 要按新名字重写（删别名映射）。
