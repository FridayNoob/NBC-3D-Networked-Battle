# 02 需求

需求：R024-行为树节点补齐（客户端为准）
所属阶段：M4
作者：LYF（口述确认，AI 落稿）　状态：已确认（2026-11-08）

## 一、业务目标（一句话）

**让编辑器里的节点够用来配出「普通怪 + 带三技能和多段普攻的 BOSS」，并且节点定义放进 SO —— 策划自己加参数、加定义不用改代码。**

## 二、用户与使用场景

- 用户：策划（配怪物行为）、开发（实现行为）。
- 场景：策划打开行为树编辑器 → 左栏能看到「追/打/放技能/回位/巡逻/站桩 + 射程/冷却/血线条件」→ 拼出 BOSS 的三技能优先级 → 导出 JSON 交给服务端。

| # | 功能 | 优先级 | 说明 |

## 四、节点清单（本需求要交付的 14 个）

| 分类 | 节点 | 参数 |
| --- | --- | --- |
| 组合 | `Selector` / `Sequence` / `Parallel` | 无 |
| 条件 | `IsDead` | 无 |
| | `InAttackRange` | `rangeMm`（int，0=默认射程） |
| | `AttackReady` | `skillId`（int，0=普攻） |
| | `HPBelow` | `hpThreshold`（int）、`percentOfMax`（bool） |
| | `HasTarget` | 无 |
| | `HomeFar` | 无 |
| 动作 | `Chase` | 无 |
| | `BasicAttack` | `hits`（int，默认 1）、`intervalTicks`（int） |
| | `CastSkill` | `skillId`（int）、`cooldownSeconds`（float） |
| | `ReturnHome` | 无 |
| | `Patrol` / `Idle` | 无 |
| | `Wait` | `seconds`（float） |

## 五、边界（**本版明确不做**）

- **不改服务端**：三技能、多段结算、独立冷却的服务端能力是**另一个需求**（本需求只保证编辑器能"表达"，服务端后补）。
- 不做表达式 DSL、不做 Lua 脚本节点。
- 不做节点图标美术、不做 Undo/Redo。
- 预览只做「能变色」，**未实现的节点不追求拟真**（灰态 + 提示即可）。
- **禁止**在工厂/预览里按类型名堆 `switch`/`if-else`（违反 AGENTS.md §0.2 开闭原则）。
- 不兼容旧的 `MoveTo` 导出物（负责人确认已导出的 JSON 不用管）。
- 不改 `Selector/Sequence/Parallel` 的既有语义。

## 六、优先级

**P0**。依赖：R023（编辑器已验收）。被依赖：R022-1/2/3（服务端按新节点重建 AI）、服务端技能系统需求。

## 七、验收标准（「当…时，应…」）

- [ ] 当 打开编辑器时，左栏应出现 **14 个节点**，分「Composite / Condition / Action」三组
- [ ] 当 选中 `InAttackRange` 时，属性面板应有 `rangeMm` 且**能填 0（=默认射程）或 6000** 等值
- [ ] 当 选中 `AttackReady` / `CastSkill` 时，应能填 `skillId`，**不同技能可分别判断冷却**
- [ ] 当 选中 `HPBelow` 时，应能切 `percentOfMax`，切到 true 后阈值按百分比理解
- [ ] 当 选中 `BasicAttack` 时，应能填 `hits=3` 与 `intervalTicks`
- [ ] 当 用这套节点拼「三技能 + 多段普攻 + 分阶段」的 BOSS 树时，应**全部连通且导出成功**
- [ ] 当 点【预览】时：`IsDead`（hp≤0）绿、`InAttackRange`（inRange）按开关变色、`AttackReady`（skillCd≤0）绿、`Chase/ReturnHome` 黄、`Patrol/Idle` 绿
- [ ] 当 策划在 `BTNodeDefinitions.asset` 里给某节点**加一个参数**时，不改代码，属性面板应立刻出现该参数
- [ ] 当 删掉/移走该 SO 时，编辑器应**报错并给出期望路径**，而不是静默变成空节点库
- [ ] 当 新增一个**纯参数**节点（只多几个参数）时，应**不改任何 `.cs`**（只改 SO 资产）
- [ ] 当 新增一个**有行为**的节点时，应**只新增 1 个`.cs` 文件 + 注册**，`git diff` 里**不出现**对 `BtJsonLoader.CreateLeaf` / `BTPreviewNode.TickCore` 等既有业务文件的修改
- [ ] 当 策划在 SO 里加了定义、但该类型**还没有预览执行器**时，预览应把该节点显示为**灰色**，并在状态栏提示「预览未实现」，且**不因此让整棵树看起来全红**
- [ ] 当 导出 JSON 时，节点类型名与新定义一致（`IsDead`/`InAttackRange`/`CastSkill` …），**不含 `MoveTo`**
