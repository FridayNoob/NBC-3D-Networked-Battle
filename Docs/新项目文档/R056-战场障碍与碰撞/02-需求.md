## 业务目标（一句话）

在副本里摆上柱子/石头之后，玩家和怪物**都绕不过去而是被挡住**，而且这些障碍是策划在客户端摆好、写回配置的。

## 用户与场景

- **玩家**：进副本后想贴近柱子躲一下，结果角色被柱子挡住、沿着边缘滑开——说明碰撞在服务端生效；不会出现「穿墙」或「卡在柱子中间出不来」。
- **怪物**：追击玩家时被柱子挡住，会沿柱子边缘蹭过去，而不是直线穿过去。
- **策划/负责人**：在 Battle 场景里摆空物体（位置 = 中心、Scale = 尺寸），点一次菜单就把数据写回 CSV；不需要手改表格。

## 功能列表

| 优先级 | 功能 | 说明 |
| --- | --- | --- |
| P0 | 障碍数据表 `BattleObstacle.csv` | 每行一个障碍：所属副本、形状（圆/矩形）、中心、半径或半宽半高 |
| P0 | 服务端阻挡判定 | 位移后若进入障碍内部则不被采纳；支持分轴滑动（贴边走） |
| P0 | 客户端 Gizmos 显示 | 场景里画出每个障碍的轮廓，红色线框，一眼看出挡在哪 |
| P0 | 客户端写回菜单 | `Tools/NBC/战场/写回障碍到 CSV`：读场景里的障碍根节点 → 写 CSV + 提示行数 |
| P1 | 障碍与场地边界一致 | 出界与撞障碍用同一套「不可走」判定，避免两套规则打架 |
| P1 | 空表时行为不变 | CSV 只有表头时，移动表现与现在完全一致（回归基线） |
| P2 | 矩形旋转角度 | 本轮只支持轴对齐矩形，旋转留给以后 |
| P2 | 障碍高度/可跳越 | 本轮是 2D 平面判定，跳跃不能越过障碍（与现在服务端无高度一致） |

## 边界（不做什么）

- 不做寻路：怪物被挡住就沿边走，不绕远路（绕路属寻路需求，规则 12 用现成 A* 方案另议）。
- 不做客户端预测碰撞：客户端只显示快照位置，不做本地物理。
- 不做动态障碍（门、可破坏物）。
- 不做服务端热重载：改表要重启服务端（与 Monster 表一致）。

## 优先级

先做 P0 的四件事（数据、判定、显示、写回），P1 的两条随实现一并满足，P2 明确不做。

## 验收标准

1. 当 CSV 里有一条圆障碍位于 (2000, 0)、半径 800 时，玩家从 (0,0) 向 +X 走，应在 X≈1200 处停下（圆心减半径）。
2. 当障碍是矩形（中心 (0,3000)、半宽 1000、半高 500）时，从 (0,0) 向 +Z 走应停在 Z≈2500。
3. 当玩家贴着圆障碍斜向走时，应沿边缘滑开，不出现「卡住不动」。
4. 当怪物追击被障碍挡住时，应绕边缘继续靠近，不穿过去。
5. 当 CSV 只有表头（无障碍）时，移动与改动前一致。
6. 当在场景里移动障碍空物体并点「写回」后，CSV 对应行数值随之变化。
7. 当服务端启动时 CSV 有非法行（半径 0、矩形半宽 0）时，应跳过该行并在控制台报出行号。
8. 当同一副本有多条障碍时，全部生效（不只看第一条）。
