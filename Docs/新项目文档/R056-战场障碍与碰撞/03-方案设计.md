## 整体架构

```text
Battle 场景里的 BattleObstacleMarker（每个障碍一个空物体）
        │  菜单「Tools/NBC/战场/写回障碍到 CSV」
        ▼
Configs/Design/BattleObstacle.csv  ──（服务端启动直读）──►  ServerTables.Obstacles
                                                              │
                                                    BattleField.From(rows, dungeonId)
                                                              │
DungeonBattle.ApplyMove / MoveTowardsPoint ──► BattleEntity.ApplyMove(..., field)
                                                              │
                                                     快照里的位置（客户端只显示）
```

**一份真值**：CSV 是唯一数据源；场景里的 Marker 只是编辑入口；服务端只读 CSV。

## 模块划分

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| `BattleObstacleMarker`（客户端 MonoBehaviour） | 在场景里描述一个障碍（形状/尺寸），画 Gizmos | 不参与运行时判定，不上报服务端 |
| `BattleObstacleWriter`（Editor） | 扫场景里的 Marker，写 CSV，报行数与校验问题 | 不改场景、不调服务端 |
| `ServerTables`（改） | 读 `BattleObstacle` 表为 `ObstacleRow` 列表 | 不做几何判定 |
| `BattleField`（新，服务端） | 把行编译成判定结构；`IsBlocked(x, z)` | 不读文件、不写日志到控制台（只记计数） |
| `BattleEntity.ApplyMove`（改） | 求出位移后交给 `BattleField` 分轴尝试 | 不管数据来源 |

## 接口

### 服务端

```csharp
// Server/NBC.Server.Game/ServerTables.cs
public readonly struct ObstacleRow
{
    public ObstacleRow(int id, int dungeonId, int kind, int xMm, int zMm,
                       int radiusMm, int halfXMm, int halfZMm, string name);
    public int Id { get; }
    public int DungeonId { get; }
    public int Kind { get; }        // 0 = 圆，1 = 轴对齐矩形
    public int Xmm { get; }
    public int Zmm { get; }
    public int RadiusMm { get; }    // 圆用，毫米
    public int HalfXMm { get; }     // 矩形用，毫米
    public int HalfZMm { get; }
    public string Name { get; }
}

public IReadOnlyList<ObstacleRow> Obstacles { get; }
```

```csharp
// Server/NBC.Server.Game/BattleField.cs
public sealed class BattleField
{
    public static BattleField Empty { get; }
    public static BattleField From(System.Collections.Generic.IReadOnlyList<ObstacleRow> rows, int dungeonId);
    public bool IsEmpty { get; }
    public int Count { get; }        // 生效的障碍条数
    public int Skipped { get; }      // 因数值非法被跳过的条数
    public bool IsBlocked(int xMm, int zMm);
}
```

```csharp
// Server/NBC.Server.Game/DungeonBattle.cs（BattleEntity）
public void ApplyMove(int moveX, int moveY, int speedMmPerTick, int halfExtentMm,
                      BattleField? field = null);
```

约定：

1. `IsBlocked` 对边界返回 false（边界由既有 `Clamp` 管），只判障碍内部。
2. 圆判定 `dx*dx + dz*dz <= r*r`；矩形判定 `|dx| <= halfX && |dz| <= halfZ`（含边界）。
3. 分轴：先试 X，再试 Z；两轴都挡则不动，任一轴通过就只走那一轴（表现是「贴边滑」）。
4. `field == null` 或 `IsEmpty` 时行为与改动前逐位一致（回归基线）。

## 时序与流程

1. 策划在 Battle 场景摆放 Marker（位置对齐地面物体，尺寸填毫米）。
2. 点菜单「写回障碍到 CSV」→ 校验（副本号 1、尺寸 > 0、数量 > 0）→ 写 CSV → Console 报「写出 N 条」。
3. 重启服务端 → `ServerTables.TryLoad` 读到新表 → `RoomBattleService` 建世界时 `BattleField.From(rows, dungeonId)`。
4. 每帧 `DungeonBattle` 调 `ApplyMove(..., m_field)`；撞障碍的轴不生效。
5. 客户端从快照看到位置，不做本地物理。

## 选型与理由

| 选择 | 理由 | 放弃的方案 |
| --- | --- | --- |
| 圆 + 轴对齐矩形 | 判定两次整数乘法，数据可读；房间式副本够用 | 格子位图（编辑麻烦）、凸多边形（代码多） |
| 分轴滑动 | 十行代码即可获得「贴边走」手感 | 射线扫掠（复杂，且本项目速度 ≤ 90mm/帧，不会穿薄墙） |
| 服务端直读 CSV | 与 Monster 表一致，重启生效 | 生成二进制/嵌入资源（多一层构建） |
| 场景 Marker + 菜单写回 | 可视即可调（§0.4），不写自定义编辑器窗口 | 表格窗口手填（不直观）、运行时摆放（不能离线） |

## 风险与对策

| 风险 | 对策 |
| --- | --- |
| 斜向「穿角」 | 速度上限 90mm/帧远小于最小障碍尺寸，且分轴判定；文档写明是 AABB 近似 |
| 障碍把出生点围住 | 写回时警告「障碍与出生点 (-500, 0) 距离 < 半径」 |
| 服务端读表失败导致整局起不来 | 障碍表缺失/为空不影响启动（`BattleField.Empty`） |
| 手摆 Marker 的 Y 与地面不一致 | 判定只用 X/Z，Y 不参与；Gizmos 在 Y 处画 |
| 客户端改了 CSV 但服务端没重启 | 06 验收步骤明确要求「改完重启服务端」 |
