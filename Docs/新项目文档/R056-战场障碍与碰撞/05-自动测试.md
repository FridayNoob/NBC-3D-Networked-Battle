## 六、回归说明

- 本需求没改协议、没改快照字段，`WorldSnapshot` 与 AOI 不受影响。
- `ApplyMove` 多了一个可选参数 `BattleField? field = null`，不传时行为与改动前逐字一致（`null` 或空表都跳过障碍），所以老探针与锁步路径不受影响。
- 服务端全量探针 461/0；客户端 EditMode 812/0（本次无新增客户端用例）。

## 七、一个被测试抓出来的真 bug

第一版 `ApplyObstacles` 里，判「起点是不是已经在障碍里」写在了**挪动之后**：

```csharp
PosXmm = Clamp(PosXmm + dx, …);   // 已经挪进障碍
if (field.IsBlocked(PosXmm, PosZmm)) { return; }   // 于是每帧都认为「你本来就在里面」⇒ 直接穿墙
```

探针第 14 条报「停在 800mm 而不是 160mm」，一眼看出是整段没生效。修法：在 `ApplyMove` 里、挪动**之前**先记 `bool startBlocked = field.IsBlocked(PosXmm, PosZmm)`，挪完只在 `!startBlocked` 时做分轴判定。
