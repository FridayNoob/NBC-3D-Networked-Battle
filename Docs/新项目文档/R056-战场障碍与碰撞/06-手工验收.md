## 一、验收计划

| 类别 | 内容 | 判据 |
| --- | --- | --- |
| 正常 | 摆一个圆、写回、进副本撞它 | 人停在圆边，踩不到圆心 |
| 正常 | 斜着蹭圆边 | 贴着滑过去，不卡死 |
| 异常 | 表里有一行 `radiusMm = 0` | 服务端日志有跳过计数，进游戏不崩 |
| 边界 | 起点就在障碍里（把障碍摆在出生点） | 人能走出来，不被永久卡死 |
| 性能 | 摆 20 个障碍走一整圈 | 无卡顿（服务端每帧只做整数比较） |

## 二、走查步骤

1. 打开 `Client/Assets/_Project/Scenes/Battle.unity`，在 Hierarchy 里右键 → `Create Empty`，命名 `Obstacle_A`。
2. 选中它，`Add Component` → 搜 `BattleObstacleMarker` → 添加；Inspector 里设 `Kind = 0`、`Radius = 800`。
3. 把它摆到出生点正前方约 3 米（Scene 视图里能看到一个红色线框圆，勾选物体才是半透明填充）。
4. 再建一个 `Obstacle_B`，`Kind = 1`、`Half X = 1000`、`Half Z = 500`，摆在侧边。
5. 菜单 `Tools` → `NBC` → `战场` → `写回障碍到 CSV`。
6. Console 应出现：`[障碍] 已写回 2 条 → Configs/Design/BattleObstacle.csv`；弹出对话框显示条数。
7. 打开 `Configs/Design/BattleObstacle.csv`，应有 4 行表头 + 2 行数据，中文名不乱码。
8. 重新编译服务端并重启（`dotnet build Server\NBC.Server.Host\NBC.Server.Host.csproj -m:1`，再启动 Host）。
9. 客户端 Login → 开始游戏 → 走到 `[DungeonEntrance]` 按 E 进副本。
10. 朝 `Obstacle_A` 走：应停在圆边；斜着走：应沿边滑开；换 `Obstacle_B` 试矩形同理。

## 四、失败先看什么

| 现象 | 先看 | 判据 |
| --- | --- | --- |
| 撞不上去（直接穿过） | 服务端启动日志「配置表：… 障碍 N」 | N 是 0 ⇒ 表没读到（路径/编码） |
| 撞上去卡死不动 | 障碍是不是摆在出生点上 | 起点在障碍里应放行；若放行后仍卡，看是否被两面夹住 |
| 菜单点不动 | 菜单路径 `Tools/NBC/战场/写回障碍到 CSV` 是否存在 | 编辑器脚本编译错误会让菜单消失 |
| CSV 乱码 | 用记事本打开看是否 UTF-8 | 写回固定 `UTF8Encoding(false)`，不乱码 |
| 服务端没反应 | 是否重启过 | 表在 `AttachTables` 时读，改表必须重启 |
