## 二、模块文档

### 2.1 BattleObstacleMarker（客户端摆位）

- **简介**：挂在空物体上，用 Gizmos 画出障碍范围；它本身不参与运行逻辑，只负责"看得见地摆"。
- **接口**：`Kind`（0 圆 / 1 矩形）、`RadiusMm`、`HalfXMm`、`HalfZMm`，单位全部毫米；`Center => transform.position`。
- **示例**：`Create Empty` → `Add Component` → `BattleObstacleMarker` → `Kind=0`、`Radius=800`，Scene 视图出现红色线框圆。
- **原理**：`OnDrawGizmos` 用 `DrawWireSphere` / `DrawWireCube` 画线框；之所以不用 Mesh，是因为美术资产按 §0.5 不许程序化生成，调试线属"非美术"例外。
- **坑**：`DrawWireCube` 的尺寸是**全长**，所以传 `HalfXMm * 0.002f`（半轴 ×2 再转米）。
- **维护**：加新形状（旋转矩形/多边形）时在这里加 `Kind` 值与对应 Gizmos，同时改 `BattleField`。

### 2.2 BattleObstacleWriter（写回 CSV）

- **简介**：编辑器菜单，把场景里所有 Marker 写成 `Configs/Design/BattleObstacle.csv`，服务端下次启动才读。
- **接口**：`BattleObstacleWriter.WriteObstacles()`（`[MenuItem("Tools/NBC/战场/写回障碍到 CSV")]`）。
- **示例**：摆好两个障碍 → 菜单点一下 → Console 打出 `[障碍] 已写回 2 条到 <仓库根>\Configs\Design\BattleObstacle.csv`。
- **原理**：`FindObjectsOfType<BattleObstacleMarker>(true)` 连未激活的也收；按名字排序保证每次写出的行序稳定（便于 `git diff`）；`UTF8Encoding(false)` 写盘。
- **坑**：仓库根不能用"往上取 N 级"猜——本工程 Unity 在 `<仓库>\Client`，取一级会落到 `Client\Configs`。现在改成往上找含 `Configs\Design` 的目录。
- **维护**：新增列（例如旋转矩形要角度）时，同时改这里的表头字符串、`ObstacleRow`、`BattleField.From` 三处；表头即 schema，漏一处会在读取时回落成默认值而不报错。

### 2.3 ServerTables.ObstacleRow（读表）

- **简介**：服务端把 CSV 解析成 `ObstacleRow` 列表，按 `id` 排序后交给 `BattleField`。
- **接口**：`Obstacles`（`IReadOnlyList<ObstacleRow>`）、`ObstacleCount`；行结构 `ObstacleRow(Id, DungeonId, Kind, Xmm, Zmm, RadiusMm, HalfXMm, HalfZMm, Name)`。
- **示例**：`BattleField.From(tables.Obstacles, DungeonId)`。
- **原理**：表头即列名，`CsvSheet.Int/IntOr/StrOr` 按列名取值；缺列走 `WarnMissingColumn` 只告警一次，不抛异常（一张表坏了不能让整服起不来）。
- **坑**：CSV 可能被 Excel 存成 GBK，`ServerTables.ReadAllLinesAuto` 已做 BOM → UTF-8 严格 → GBK 回退；中文表头必须原样保留。
- **维护**：加副本时不需要改代码，`DungeonId` 列自己过滤。

### 2.4 BattleField + ApplyMove（服务端判定）

- **简介**：`BattleField` 是"一张地图的障碍集合"，只有 `IsBlocked(x, z)` 一个查询；`BattleEntity.ApplyMove` 在钳位之后调它。
- **接口**：`BattleField.From(rows, dungeonId)`、`IsBlocked(int xMm, int zMm)`、`Count` / `IsEmpty` / `Skipped`。
- **示例**：圆 `(2000,0) r=800`，人从 X=0 往 +X 走会停在 X≈1200（还要减半径余量）。
- **原理**：纯整数比较（`dx*dx + dz*dz <= r*r`、`|dx| <= halfX && |dz| <= halfZ`），没有浮点、没有 PhysX——因为服务端要确定性，且 Unity 物理在服务端根本不存在。
- **坑**：`ApplyObstacles` 必须先判"起点是否已经在障碍里"再挪动；挪完再判会导致每帧都判定"已在里面"而放行，直接穿墙（探针第 15 条就是抓这个）。
- **维护**：新增形状在 `From` 里解析、在 `IsBlocked` 里加分支；判定必须是纯函数（同样入参同样结果），否则帧同步会漂移。
