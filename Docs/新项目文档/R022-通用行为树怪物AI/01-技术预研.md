# 01 技术预研

需求：R022-通用行为树怪物 AI
所属阶段：M4
作者：AI　状态：草稿（待负责人确认）

## 一、调研目标与约束

- 目标：把「怪物 AI」做成**一份通用的行为树**，狼/蜘蛛/狼王都用同一套树，**只靠配置不同**；
  后续加怪或加 BOSS 只填表，不改代码。
- 约束：
  1. AI 必须在**服务端**（客户端只有位置与血量快照）⇒ 只能用**纯 C#**，不能用 Unity 插件；
  2. 确定性：只用整数运算 + 逻辑帧，不用 `float`/`Random`（沿用 DET 规则）；
  3. 不破坏现有探针（`StateName` / `HomeXmm` 等成员要被新大脑保留）。

## 二、现状（已确认）

| 项 | 事实 |
| --- | --- |
| 现有 AI | 只有 `BossBrain`：`StateMachine<EBossState>`，3 个状态（站桩/追击/攻击） |
| 状态机来源 | `NBC.Framework.Fsm`（纯 C#），服务端用 `<Compile Include>` 直接编进来 ✔ |
| 普通怪 | **没有任何 AI**：只执行巡逻 `PosXmm += PatrolSpeedMmPerTick * PatrolDir`，撞边界掉头 |
| 所以玩家靠近狼 | 狼照旧横着巡逻 ⇒ 你看到的「反方向走」 |
| Behavior Designer | **已装**（`Assets/Behavior Designer`），但它是 Unity 插件 ⇒ **服务端跑不了** |
| Monster 表列 | `id / name / hp / attack / skillIds` —— **没有仇恨半径、没有移速、没有 AI 类型** |
| 配置源头 | `Configs\Design\Monster.csv` → ConfigKit 生成 `Generated\Config_Monster.cs` 等 |
| 探针依赖 | `Brains[0].StateName`（"站桩"/"追击"/"攻击"）、`HomeXmm`、`TransitionCount`、类型 `BossBrain` |

## 三、关键取舍：行为树手写，不用插件

| 方案 | 能否在服务端跑 | 可视化 | 评价 |
| --- | --- | --- | --- |
| **手写纯 C# 轻量行为树（采用）** | ✔ | ✘ | 约 150 行框架 + 通用节点；与 `StateMachine` 同样被服务端编译进来 |
| Behavior Designer | ✘（Unity 插件） | ✔ | 只能做客户端非权威演示，位置会与快照打架 |
| 继续用 FSM | ✔ | ✘ | 加一个 BOSS 就要写一个状态类；行为树更适合"通用 + 配置化" |

结论：**手写行为树**，节点组合出「打最近的敌人 → 追 → 打 → 回家 → 巡逻」，靠参数区分怪种。

## 四、树的结构（通用近战）

```
Selector（按优先级从高到低）
├─ Sequence [自身死亡?]            → DoNothing
├─ Sequence [有目标 & 在攻击距离 & 冷却好] → 普攻
├─ Sequence [有目标 & 在仇恨范围]   → 朝目标移动（并保持朝向）
├─ Sequence [离家超过松弛量]        → 走回出生点
└─ Action 巡逻（无目标时的默认行为）
目标检测（每帧一次）：仇恨范围内最近的活英雄；超出范围 ⇒ 目标置空（leash）
```

## 五、通用性怎么落地（后续加怪只填表）

给 `Monster.csv` 加三列（**这是"通用"的关键**）：

| 新列 | 含义 | 例子 |
| --- | --- | --- |
| `aggroRangeMm` | 仇恨/追击半径 | 野狼 4000、狼王 4000 |
| `moveSpeedMmPerTick` | 每逻辑帧移动毫米数 | 野狼 40、狼王 30 |
| `aiKind` | AI 类型（`melee` = 近战追人；以后可加 `ranged`） | 全部先填 `melee` |

生成物由 ConfigKit 重新导出（`--no-build`，README 里写明本环境必须这么跑），**生成代码不手改**。

## 六、已知坑

1. **服务端没有 UnityEngine**：行为树只能用整数与自己实现的向量运算（已有 `DungeonBattle.DistanceMm` / `MoveTowardsPoint`）。
2. **探针会红**：`BossBrain` 若被替换，`_net-probe` 里 `BossBrain brain = battle.Brains[0]` 这类代码要跟着改类型；`StateName` 仍要返回"站桩/追击/攻击"以保住断言。
3. **BOSS 与普通怪共树**：BOSS 的差异只体现在参数（攻高血厚、移速慢），树本身不分支 —— 这样才算"通用"。
4. **`Monster.tsv` 是生成物**：源表是 `Configs\Design\Monster.csv`，改 tsv 会被下次导出覆盖。
5. **巡逻与追击会打架**：`BattleEntity.Step()` 里自带巡逻位移，必须让大脑在「追击/攻击」时把它关掉，否则一个往东一个往西。
6. **仇恨半径原本写死 4000**（R018 的 `BossAggroRangeMm`）：改成按表取之后，常量要保留为**默认值**，避免旧用例全红。

## 七、结论与改动清单

结论：**手写纯 C# 行为树 + `MonsterBrain`（替代 `BossBrain`）+ Monster 表加三列**，所有怪共用一棵树。

要改：
- 新增 `Server\NBC.Server.Game\Ai\` 下的行为树框架（节点基类、Selector、Sequence、条件、动作、树、黑板）
- 新增 `MonsterBrain`（持树 + 记忆 + 兼容成员 `HomeXmm` / `StateName` / `TransitionCount`）
- 删除 `BossBrain`（或改为薄封装）
- `DungeonBattle`：每只怪挂一个大脑；`BattleEntity.Step()` 在追击时跳过巡逻
- `Configs\Design\Monster.csv` 加三列 + ConfigKit 重新生成
- `_net-probe`：更新受影响的 BOSS 用例（类型与断言）
