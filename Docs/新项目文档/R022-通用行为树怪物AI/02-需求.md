# 02 需求

需求：R022-通用行为树怪物 AI
所属阶段：M4
作者：LYF（口述确认，AI 落稿）　状态：已确认（2026-11-06）

## 一、业务目标（一句话）

**每种怪/BOSS 有自己的行为树，但共用同一套通用节点**（巡逻、待机、侦测、追击、攻击、死亡…），
加新怪时只拼节点、不重写逻辑。

## 二、用户与使用场景

- 用户：开发期负责人；最终玩家。
- 场景：狼会巡逻、发现你就追、到身边就打；狼王有自己的一套（更慢更凶，可能带特殊行为）；以后加蜘蛛只需要组装「远程攻击」那一段。

## 三、功能列表（P0 / P1 / P2）

| # | 功能 | 优先级 | 说明 |
| --- | --- | --- | --- |
| 1 | 纯 C# 行为树框架（服务端） | P0 | NodeStatus / 组合节点（Selector、Sequence）/ 条件 / 动作 / 冷却装饰 |
| 2 | 黑板（上下文） | P0 | 世界、自己、出生点、当前目标、帧号、参数 |
| 3 | **通用节点库** | P0 | 侦测目标、有目标、在攻击距离、冷却好了、追击、普攻、回出生点、巡逻、待机、已死亡 |
| 4 | **野狼的树** | P0 | 巡逻 → 发现就追 → 到身边就打 |
| 5 | **狼王的树** | P0 | 待机/回位 + 追击 + 攻击（可加自己的特殊节点） |
| 6 | 每只怪按配置选树 | P0 | `Monster.csv` 加 `aiKind` 列（`wolf` / `boss`），工厂据此组装 |
| 7 | 参数来自配置 | P0 | `aggroRangeMm`、`moveSpeedMmPerTick` 两列 |
| 8 | 死亡/待机行为 | P1 | 已死亡 ⇒ 什么都不做（最短路） |
| 9 | 远程怪、召唤、多段技能 | P2 | 本次不做，但节点库要留出组合空间 |

## 四、边界（**本版明确不做**）

- 不用 Behavior Designer（Unity 插件，服务端跑不了），**手写纯 C#**。
- 不做行为树可视化编辑器（节点用代码组装）。
- 不做寻路绕障（直线朝目标走，场地是空的）。
- 不改客户端与协议（位置/血量仍走快照）。

## 五、优先级

**P0**。依赖：R018（BOSS 仇恨概念）、R019（攻击结算）、R020（伤害反馈）。

## 六、验收标准（「当…时，应…」）

- [ ] 当 玩家在野狼仇恨半径外时，狼应**继续巡逻**（左右走、撞边界掉头）
- [ ] 当 玩家进入狼的仇恨半径时，狼应**朝玩家移动**
- [ ] 当 狼进入攻击距离时，应**按冷却打玩家**（玩家掉血 + 飘字）
- [ ] 当 玩家跑出仇恨半径时，狼应**回到出生点附近继续巡逻**
- [ ] 当 狼王（BOSS）在场时，应使用**它自己的树**（行为与野狼不同：更慢、更凶、有回位）
- [ ] 当 某只怪死亡时，应立刻停止一切行动（不追、不打、不巡逻）
- [ ] 当 以后加新怪时，应只需**新增一棵树（拼通用节点）**，不改框架与已有怪
