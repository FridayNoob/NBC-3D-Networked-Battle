# 03 方案设计

需求：R022-通用行为树怪物 AI
所属阶段：M4
作者：AI 起草　状态：已确认（2026-11-06）

## 一、整体架构

```
DungeonBattle.Step()（每逻辑帧）
   ├─ 每单位 Step()（冷却 / 巡逻位移 —— 追击时由大脑禁用巡逻）
   └─ 每个大脑 Think(world) → MonsterBrain.Tick()
          └─ 行为树（每种怪一棵，由工厂按配置组装）
                └─ 通用节点库（侦测/追击/攻击/回位/巡逻/待机/死亡）
                      └─ 只调用 world 的既有能力（MoveTowardsPoint / TryBasicAttack / DistanceMm）
```

## 二、模块划分

| 模块 | 职责 | 不负责什么 |
| --- | --- | --- |
| `Ai/BtNode`（+ `BtStatus`） | 节点基类与三态（成功/失败/运行中） | 不碰战斗规则 |
| `Ai/BtComposite`（`BtSelector`、`BtSequence`） | 组合节点，按优先级/顺序跑子节点 | 不持有状态 |
| `Ai/BtCondition` / `Ai/BtAction` | 条件与动作的基类（`Tick` 返回三态） | 不存全局状态 |
| `Ai/BtCooldown` | 冷却装饰器（限流用，如「每隔 N 帧允许一次」） | — |
| `Ai/MonsterAiContext`（黑板） | 世界、自己、出生点、当前目标、帧号、参数 | 不做决策 |
| `Ai/CommonNodes` | **通用节点库**：`IsDead`、`DetectTarget`、`HasTarget`、`InAttackRange`、`AttackReady`、`Chase`、`BasicAttack`、`ReturnHome`、`Patrol`、`Idle` | 不写怪种差异 |
| `Ai/WolfAiTree` / `Ai/BossAiTree` | 每种怪**组装**自己的树（只挑节点、排优先级） | 不实现节点逻辑 |
| `Ai/MonsterAiFactory` | 按配置（`aiKind`）造树 | 不决定参数 |
| `MonsterBrain` | 持树 + 黑板 + 每帧 Tick；保留 `HomeXmm` / `StateName` / `TransitionCount` 供日志与探针 | 不实现具体行为 |
| `BossBrain` | **删除**（能力并入 `MonsterBrain` + `BossAiTree`） | — |

## 三、接口（★ 先定死）

```
enum BtStatus { Success, Failure, Running }

abstract class BtNode          { public abstract BtStatus Tick(MonsterAiContext ctx); public string Name { get; } }
abstract class BtComposite     : BtNode { protected readonly BtNode[] Children; }
sealed class BtSelector        : BtComposite   // 依次跑，第一个非 Failure 就返回
sealed class BtSequence        : BtComposite   // 依次跑，遇到 Failure 就返回
abstract class BtCondition     : BtNode        // 只判断，不产生副作用
abstract class BtAction        : BtNode        // 产生副作用（移动/攻击）
sealed class BtCooldown        : BtNode        // 包一个子节点 + 间隔帧数

sealed class MonsterAiContext
{
    public DungeonBattle World;
    public BattleEntity Self;
    public int HomeXmm, HomeZmm;
    public BattleEntity? Target;        // 由 DetectTarget 每帧刷新
    public int Tick;
    public int AggroRangeMm;
    public int MoveSpeedMmPerTick;
    public bool Chasing;                // 告诉 BattleEntity.Step() 别自己巡逻
}

sealed class MonsterBrain
{
    public int HomeXmm { get; }
    public int HomeZmm { get; }
    public string StateName { get; }        // 最近一个返回 Success 的叶子名（"站桩"/"追击"/"攻击"/"巡逻"/"回位"）
    public int TransitionCount { get; }
    public void Think(DungeonBattle world);
}
```

## 四、数据结构

- 每只怪一棵树（节点在构造时建好，运行期不 new）；每只怪一个黑板。
- 静态复用：`WolfAiTree.Build()` / `BossAiTree.Build()` 每次构造新树（节点无共享状态，简单安全）。

## 五、时序与流程

1. `DungeonBattle.Step()`：先 `Tick++`，再各单位 `Step()`（冷却；**`Chasing` 为 true 时跳过巡逻**）。
2. 再逐个 `MonsterBrain.Think(world)`：刷新黑板（目标、帧号）→ 树根 `Tick`。
3. 树内：`IsDead` 优先（死了一律 Failure 到底，什么都不做）→ 攻击 → 追击 → 回位 → 巡逻。
4. `Chase` 动作把 `Chasing=true` 并 `MoveTowardsPoint(self, target)`；`Patrol`/`ReturnHome` 把 `Chasing=false`。
5. `BasicAttack` 调 `world.TryBasicAttack(self, target.Id, out reason)`（服务端既有规则，含冷却与射程）。

## 六、技术选型与理由

| 选择 | 选定 | 理由 | 被否的方案 |
| --- | --- | --- | --- |
| 行为树实现 | **手写纯 C#** | 服务端无 UnityEngine，插件跑不了 | Behavior Designer（只能客户端、非权威） |
| 复用方式 | **通用节点库 + 每种怪一棵树** | 负责人明确要求：通用逻辑复用、特殊行为各写各的 | 所有怪共用一棵树（特殊行为挤不进去） |
| 参数来源 | `Monster.csv` 加 `aggroRangeMm` / `moveSpeedMmPerTick` / `aiKind` | 后续加怪只填表 | 代码常量（加怪要改代码） |
| 旧 AI | **删除 `BossBrain`** | 两套 AI 并存会重复逻辑 | 保留（后续合并成本更高） |

## 七、风险与对策

- **探针会红**：`BossBrain` 类型改名后，`_net-probe` 里 5 处引用要跟着改；`StateName` 保留"站桩/追击/攻击"语义，减少断言改动。
- **巡逻与追击打架**：黑板加 `Chasing` 标志，`BattleEntity.Step()` 见到就跳过巡逻（这是最容易出"一边追一边被巡逻拉回"的地方）。
- **配置重新生成**：`Monster.csv` 加列后必须跑 ConfigKit（`--no-build`）重新生成，否则字段读不到；生成物不手改。
- **确定性**：节点内只用整数与逻辑帧；不使用 `float` / `Random`。
- **BOSS 行为差异**：只通过参数与树的组装体现，框架不写 `if (isBoss)`。
- **死亡**：`IsDead` 放在 Selector 最前面，先于一切行为。
