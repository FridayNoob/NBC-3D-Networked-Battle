# 项目代码注释规范

状态：**待负责人确认**（2026-10-30 起草，确认后成为唯一入口）
适用范围：`Client/Assets/_Project/**/*.cs`
不适用：生成代码（`Protocol\NbcM3.cs`、`Config\Generated\*`）—— 重新生成会覆盖，手改无意义

> 本文是**本项目的唯一入口**。技能库 `csharp-code-comment` 是它的来源（通用原则），两边冲突时**以本文为准**。

## 一、三条原则

1. 注释只回答三件事：**这段干什么、数据长什么样、谁在调谁**。
2. 判断标准：**删掉这条注释会不会影响理解**；不影响就删。
3. 写「**为什么**」，不写「**是什么**」——「判断是否为空」这种复述代码的注释一律删。

## 二、文件头（每个 .cs 最上方）

列全本文件里的类型（接口 / 类 / 结构体 / 枚举），各一句功能：

```csharp
// 这个文件里有：
//   HpBarPanel（类）：屏幕 HUD 的血条面板，只负责按名字找控件 + 改长度与颜色
//   ERuntimeSyncMode（枚举）：运行时同步方式，状态同步或帧同步
```

要求：**不写作者、日期、版本号**（git 里有）；**不写长篇设计说明**（放 Docs）。

## 三、类头（类声明之前，四句）

```csharp
// 主要功能：每帧把输入压成四向之一，转身或倒退并位移，同时算出前后 / 左右分量。
// 主要数据成员：m_moveSpeed（米/秒）、m_forwardSpeed（前后分量，带符号）。
// 主要外部方法：ForwardSpeed / SideSpeed / MoveSpeed / CurrentSpeed（只读属性）。
// 谁在用它：挂在角色物体上；输入取自 InputManager.Current。
```

⚠️ 上下游只写**稳定的**调用点，不确定就写「内部调用」。**错的注释比没有注释更糟**。

## 四、字段（一行）

含义 + 单位或取值范围。**有单位必须写单位**。

```csharp
[SerializeField] private float m_moveSpeed = 5f;   // 每秒走多少米；场景 1 单位 = 1 米
private float m_sendAccumulator;                    // 上行节流累加器，秒
```

⚠️ 单位约定：**服务器协议与逻辑层用毫米 / tick**；**Unity 场景内的位移用米 / 秒**。跨层时在注释里点明换算。

## 五、方法（五段，顺序固定）

```csharp
// 功能：按「当前血 / 最大血」更新血条长度、颜色与数字。
// 入参：current 当前血（会被钳在 0..max）；max 最大血（<= 0 时按 0 比例处理）
// 返回：无
// 步骤：
//   1) 钳住 current 到 0..max
//   2) 算比例（max <= 0 时按 0）
//   3) 转给 SetRatio 统一处理显示
// 上游：战斗 HUD / 演示驱动
// 下游：SetRatio
```

规则：

1. **功能**（2026-10-30 新增）：一句话说清这个方法做什么；不是复述签名，也不是「处理 xxx」。
2. **返回**写真假分别代表什么，不写「返回 bool」。
3. **步骤**写顺序与原因，不翻译代码。
4. 有坑写一行「注意：」，说明不这么做会怎样 —— **这是最值得记的部分**。
5. 只有一行转发的，可以只写「功能」一段。

## 六、代码里禁止出现

| 禁止 | 原因 |
| --- | --- |
| Markdown 符号：`#`、`**`、反引号、竖线表格 | 编辑器里是噪音，复制到别处会变形；要强调用「」，编号用 `1) 2) 3)` |
| `====` 这类装饰分隔线 | 没有信息量，且让文件变长 |
| 工单编号（如 `M2-A2`、`§二十六`） | 属于文档，代码里写会过期 |
| **注释掉的代码** | 用版本控制；留着只会让人猜「能不能删」 |
| XML 文档注释（`///`）出现在**非公共 API** 上 | 见第六之二：`///` 只允许用于跨程序集的 public 契约 |

⚠️ `///` 不是全面禁止、也不是全面放开 —— 边界是「**会不会被别的程序集调用**」，规则见第六之二。

## 六之二、公共 API 的 XML 文档（2026-10-30 二次修订）

### 判定标准（只有一条）

> 这个 `public` 类型 / 成员，**会不会被本程序集之外的代码调用**？
> 会 ⇒ 写 `///` 三件套；不会 ⇒ 只用 `//` 五段。

理由：外部调用方只关心**契约**（干什么、参数含义、返回什么），这正是 `///` 擅长的；
维护者关心**步骤与坑**，那是五段式擅长的。Unity / Unreal 也是「公开接口写文档注释、实现写得精简」。

### 模板（只写契约摘要，1~2 句，不写步骤）

```csharp
/// <summary>取一次一致的全部统计，供 HUD 显示。</summary>
/// <returns>模式、累计与每秒字节、RTT、帧号的一次快照。</returns>
public static NetStatsSnapshot Snapshot()
{
    // 功能：先推进采样窗口，再把四个槽求和换算成带宽。
    // 步骤：
    //   1) Advance 让槽位与真实时间对齐
    //   2) 4 槽求和 ÷ 1 秒 = B/s
    // 上游：NetHudPanel 每 0.25 秒一次
    // 下游：无
}
```

⚠️ **不重复**：`<summary>` 是契约，五段是细节；允许轻微重叠，但不许互相抄一遍。

### 什么算「跨程序集」

程序集边界（asmdef）：`NBC.Framework`、`NBC.Framework.Net`、`NBC.Framework.UI`、`NBC.Framework.YooAsset`、`NBC.Game`、`NBC.Model`、`NBC.Protocol`、`NBC.Shared`、`NBC.Boot`、`NBC.Editor`、两个 Tests。

判据举例：
- `Framework*` 里给 `Game`/`Boot` 用的公开类型与方法 ⇒ **要 `///`**
- `Game` 里被 `Boot`（`HpBarDemoBehaviour`）或 `Editor`（`NetDebugWindow`）调用的公开成员 ⇒ **要 `///`**
- `Game` 内部互相调用（如 `HpBarPanel.SetHp`） ⇒ **不要 `///`**，用五段
- `internal` / `private` / `protected` ⇒ **一律 `//`**

### 兜底

- **不开 `CS1591`**（缺注释报警）：会把现有 0 警告基线一次打爆；靠自检清单与 review 卡。
- 存量文件：新代码必须写；旧文件改到时顺手补（与注释规范化同一节奏）。

## 七、TODO 格式（2026-10-30 新增）

```csharp
// TODO(LYF, 2026-11-15, R007)：断线后自动重连
// FIXME(LYF, 2026-11-01, R009)：闸门查不出跨程序集 using
```

要求：**必须带 名字 + 日期 + 需求号**，三者缺一不可。
好处：欠账可被脚本一把捞出，不用靠记忆。

```powershell
# 欠账看板（谁、什么时候、属于哪个需求）
Select-String -Path (Get-ChildItem Client\Assets\_Project -Recurse -Include *.cs).FullName -Pattern 'TODO\(|FIXME\('
```

## 八、必须删掉的注释

- 复述代码：「遍历数组」「判断是否为空」「赋值」。
- 和代码打架的旧注释（删掉或改对，**不许两说并存**）。
- 装饰性分隔线与历史变更（git 里有）。
- 已搬进 Docs 的长篇原理（代码里留一行指路，如「详见 Docs\27 §37」）。

## 九、商业项目通行要求对照（2026-10-30 新增）

| 通行要求 | 本项目做法 |
| --- | --- |
| 公共 API 必须有文档注释 | ✅ 做（**分层**）：跨程序集 public 用 `///` 三件套，其余用 `//` 五段 |
| 单位、坐标系、线程与生命周期必须写 | ✅ 做：字段与「注意：」都要写清 |
| 写「为什么」而不是「是什么」 | ✅ 做（本文第一条原则） |
| TODO/FIXME 可追踪 | ✅ 做（第七节的格式） |
| 禁止死代码、装饰线、表格 | ✅ 做（第六节） |
| 注释与实现同一次提交更新 | ✅ 做：改代码时必须同步改注释，否则视为缺陷 |
| 版权 / license 头 | ⏸ 暂不做（个人项目；开源或进公司代码库时再加） |
| 缺注释就报警（CS1591） | ⏸ 暂不开：会打爆 0 警告基线，靠自检与 review 卡 |
| 注释覆盖率当 KPI | ❌ **明确不做**：会催生复述代码的噪音 |

## 十、交付前自检（逐条答）

1. 只看文件头，能说出这个文件里有几个类型、各自干什么？
2. 只看类头，能说出它的主要数据、主要方法、谁在用它？
3. 随便挑一个方法，能只看注释就复述**它做什么**、步骤顺序、返回语义？
4. 编码检查：UTF-8 **无 BOM**、**LF**、注释里无 Markdown 符号、**「功能」条数 = 方法数**？
5. 新增的 TODO/FIXME 是否都带了名字 + 日期 + 需求号？
6. 跨程序集的 public 成员是否都有 `///` 契约摘要（且没有把五段抄进去）？
