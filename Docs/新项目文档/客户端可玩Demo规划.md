# 客户端可玩 DEMO 规划

> 目标：把现在"能用调试窗口进副本打几只怪"的状态，做成**可以完整游玩的单机演示**。
> 本文只做规划与需求拆分；每条需求仍按 8 步（01~08）独立交付，**只在 06 手工验收停**（AGENTS.md §0 加速模式）。

## 一、验收定义（"可玩 DEMO" 的 DoD）

**一条完整路径，全程不碰编辑器窗口**：

```
启动 → 主菜单（开始游戏 / 设置 / 退出）
     → 取名/选角（剑士）
     → 创建/进房（单人）
     → 进副本（加载过场）
     → 战斗（移动/普攻/技能/受击/死亡表现）
     → 死亡 → 复活倒计时 → 复活    或    击杀 BOSS → 通关
     → 结算面板（存活时间/击杀/伤害）→ 重开 或 返回主菜单
```

判定：上面每条都能手动走通，且**中途不需要打开任何 Editor 窗口**。

## 二、现状盘点

| 分类 | 已有 | 缺口 |
| --- | --- | --- |
| 移动/相机 | WASD、转身、跟随相机 | 相机可配置（距离/灵敏度） |
| 战斗 | J 键普攻（剑碰撞盒）、服务端裁决、冷却 | **无技能栏/多技能** |
| 怪物 | 服务端行为树（追/打/回位）、BOSS 守点、血条、飘字 | 技能型怪（BOSS 三技能） |
| 表现 | 受击/死亡动画、伤害飘字、受击闪白 | **无音效/无打击感（顿帧、震屏、命中特效）** |
| 流程 | 调试窗口可连接/进房 | **无主菜单/登录/进房 UI、无加载过场** |
| 死亡 | 有死亡动画 | **死后卡住：无复活、无惩罚、无回城** |
| 结算 | 服务端有 MatchResult | **无结算面板、无重开** |
| HUD | 血条（玩家/怪物）、网络 HUD | 技能冷却、任务指引、目标信息 |
| 其他 | 任务/成就面板、行为树编辑器 | 设置（音量/画质） |

## 五、明确不做（面试 demo 的取舍）

- 不做多人匹配/大厅列表（单人进副本即可；房间层已有，只是不出 UI）。
- 不做多副本/章节选择（一个副本走完即可）。
- 不做装备/背包/商店/成长（需求原文有，但 demo 不展示）。
- 不做移动端适配（只 PC）。
- 不做本地化/多语言。

## 六、风险与对策

| 风险 | 对策 |
| --- | --- |
| 服务端技能系统是大头（可能超 500 行） | 拆成 R033a/R033b，一次只做一端 |
| 复活与结算会改服务端规则（唯一入口） | 规则只写在 `DungeonBattle`，客户端只表现 |
| UI 依赖 YooAsset 面板加载（已有 HpBarPanel 先例） | 沿用 `UIManager.Open<TPanel>` 路径，先做 prefab 再接线 |
| 音效资源缺失 | 先用少量免费音效（或程序生成提示音），不占需求预算 |
