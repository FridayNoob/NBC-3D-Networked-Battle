# 01 技术预研

需求：R010-角色逻辑状态机
所属阶段：M4
作者：AI　状态：草稿（待负责人确认）

## 一、调研目标与约束

- 目标：用项目自带的 `Framework\Fsm` 管角色的**逻辑状态**（Idle / Move），并由它统一决定「能不能动」；以后加 Attack / Dead 只加状态类。
- 约束：
  1. 不改 `PlayerMove` 的移动算法（R013 定稿的四向转身）；
  2. 不引入第二套动画驱动（仍由 `PlayerAnimation` 喂 `Speed`/`Direction`）；
  3. `Framework\Fsm` 是 **.NET 无关** 的纯 C#，状态类放 `Game` 层（可以用 UnityEngine）。

## 二、框架 FSM 的真实 API（读代码确认）

`IState<S>`（`Framework\Fsm\IState.cs`）

| 成员 | 作用 |
| --- | --- |
| `string Name` | 状态名（日志与历史用） |
| `void OnEnter(S previous)` | 进入 |
| `void OnUpdate(in StateTick tick)` | 每 tick |
| `void OnExit(S next)` | 退出 |
| `bool OnEvent(EventId id)` | 事件（返回 true = 已消费） |
| `bool CanEnterFrom(S from)` | 准入校验（返回 false 会被拒并触发 `TransitionRejected`） |

`StateMachine<S>`（`StateMachine.cs`）

| 成员 | 作用 |
| --- | --- |
| `Register(S id, IState<S> state)` | 注册 |
| `Start(S initial)` | 启动（之后才能切） |
| `Tick(int frame)` | 推进；`StateTick(frame, deltaFrames)` 传给状态 |
| `TryChangeState(S next)` / `ForceChangeState(S next)` | 普通 / 强制切换 |
| `SendEvent(EventId id)` | 广播给当前状态 |
| `Current` / `CurrentName` / `History` / `StateChanged` / `TransitionRejected` | 观测 |

⚠️ **关键事实**：`StateTick` 只有 `Frame` 与 `DeltaFrames`，**没有 DeltaTime** —— 这套 FSM 是**帧驱动**、刻意不碰时间。
⇒ 它适合「逻辑状态」，**不适合**做位移积分（位移继续由 `PlayerMove` 用 `Time.deltaTime` 算）。

## 三、现状

| 文件 | 现状 |
| --- | --- |
| `PlayerMove` | 每帧读输入 → 四向转身 + 位移 → 出 `ForwardSpeed/SideSpeed/CurrentSpeed` |
| `PlayerAnimation` | `LateUpdate` 把分量归一化后写 `Speed`/`Direction`（Float，damping 0.1） |
| `Sword_Controller` | Idle ↔ Walk 由 `Speed > 0.1` / `< 0.1` 切换（R014 配好） |
| 逻辑状态 | **没有** —— 走到哪算哪，没有任何「此时不该动」的闸门 |

## 四、方案对比

| 方案 | 做法 | 评价 |
| --- | --- | --- |
| **A（采用）** | 新增 `PlayerBrain`（MonoBehaviour）持 `StateMachine<EPlayerState>`，注册 `Idle`/`Move` 两个状态；状态负责「允许不允许移动」与「上报状态变化」；`PlayerMove` 的启用由状态闸门控制 | 改动小、扩展点清晰；**本迭代可见变化 = Console 状态日志**（为 Attack 预留 `CanMove`） |
| B | 把 `PlayerAnimation` 的喂值逻辑拆进各状态 | 更「纯」，但会把已验证的动画链路拆散，风险大 |
| C | 用 `HierarchicalStateMachine`（分层） | 现在只有两态，分层是过度设计 |

## 五、已知坑

1. **帧号必须单调**：`Tick` 用 `Time.frameCount`（单调递增）；传 0 或倒退会抛异常。
2. **状态类不要碰时间**：`StateTick` 没有 deltaTime；谁要时间谁自己读（但状态里读 `Time` 会让逻辑难测，尽量别）。
3. **`TryChangeState` 会走 `CanEnterFrom`**：默认返回 true；以后加 Attack 时用它挡「死亡后还能攻击」。
4. **`PlayerMove` 的启用/停用**：禁用后 `PlayerMove` 不再写速度，`PlayerAnimation` 会读到 0 ⇒ 自动回 Idle，这是想要的行为；但**别忘了禁用时把 `CurrentSpeed` 清 0**（`PlayerMove` 的字段只在 `Update` 里清，禁用后保持旧值 —— 需要在 `OnDisable` 清）。
5. **两套「状态」的边界**：Animator 的状态（`S_Idle`/`S_Walk`）是**表现**，FSM 的状态是**逻辑**；不要让两边混成一个。

## 六、结论与要改的东西

结论：**加一个 `PlayerBrain` + `Idle`/`Move` 两个状态类**，用 `StateMachine<EPlayerState>` 管逻辑状态，并通过「允许移动」闸门控制 `PlayerMove`；本迭代不做 Attack/Dead，但把 `CanMove`、`SendEvent` 两个扩展点留好。

要改/新增：
- 新增 `Game\Player\EPlayerState.cs`（枚举）
- 新增 `Game\Player\PlayerIdleState.cs`、`PlayerMoveState.cs`
- 新增 `Game\Player\PlayerBrain.cs`（持 FSM、每帧 Tick、日志）
- 改 `PlayerMove.cs`：加 `OnDisable` 清速度（**唯一改动点**，其余不动）
