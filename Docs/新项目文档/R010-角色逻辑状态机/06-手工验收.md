## 一、测试计划（四类）

| 类别 | 本次要测什么 | 怎么做 |
| --- | --- | --- |
| 正常 | 状态是否随走/停切换且只打一条 | Play 走停 |
| 异常 | 有没有刷屏、有没有 FSM 异常 | 连续走 5 秒看 Console |
| 边界 | 站着不动时的行为变化（Idle 禁用 PlayerMove） | 站着按方向键立刻走 |

| 步 | 你做什么 | 应该看到什么 | 实际结果 |

## 三、异常场景

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| Inspector 里找不到 `Registered Count` | 它是 **C# 属性**，Unity 默认 Inspector 只显示序列化字段 | 加两个 `[SerializeField]` 调试字段（返修 #1） |
| 状态一直停在 Idle | 若 `m_move` 没自动找到 → Console 会报 `找不到 PlayerMove` | 未出现 |

## 四、性能表现

- 每帧一次 `Tick`（内部只是几个 if 与状态回调），开销可忽略；未观察到影响。
- 留一条观察项：以后状态数量增多（Attack/Dead/Stun）时，`CanEnterFrom` 的判断链会变长，届时可考虑用事件代替逐帧判断。

- [x] 当 Console 出现 FSM 异常（帧号倒退、状态未注册）时视为未通过 ⇒ 全程无异常
