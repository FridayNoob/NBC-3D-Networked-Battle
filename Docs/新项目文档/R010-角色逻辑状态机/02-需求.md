# 02 需求

需求：R010-角色逻辑状态机
所属阶段：M4
作者：LYF（口述确认，AI 落稿）　状态：已确认（2026-10-31）

## 一、业务目标（一句话）

**用项目自带的 `Framework\Fsm` 管角色的逻辑状态（Idle / Move）**，把「能不能动」收敛到一个闸门里，为后面的攻击/受击/死亡留位置。

## 二、用户与使用场景

- 用户：开发期负责人（本次）；最终玩家（间接，手感不变）。
- 场景：走动时 Console 打一条 `Idle → Move`；停下打 `Move → Idle`；连续走动不会刷屏。

## 三、功能列表（P0 / P1 / P2）

| 功能 | 优先级 | 说明 |
| --- | --- | --- |
| `PlayerBrain` + 框架 FSM | P0 | 注册状态、每帧 Tick、状态切换 |
| `Idle` / `Move` 两个状态 | P0 | 由「有没有方向输入」驱动切换 |
| 「允许移动」闸门 | P0 | 状态决定 `PlayerMove.enabled`，为 Attack 预留 |
| Console 状态日志 | P1 | 只在**切换时**打一条，不刷屏 |
| `Attack` / `Dead` 状态 | P2 | 以后接战斗需求再做 |

## 四、边界（**本版明确不做**）

- 不改 `PlayerMove` 的移动算法（R013 定死的四向转身）。
- 不改 `PlayerAnimation` 的喂参逻辑（仍喂 `Speed`/`Direction`）。
- 不做攻击/受击/死亡状态，不做技能输入。
- 不做 HUD 显示当前状态（以后有 HUD 需求再加）。
- 不把 FSM 用于位移计算（它是帧驱动，没有 deltaTime）。

## 五、优先级

**P0**。依赖：R012/R013（移动）、`Framework\Fsm`（已存在，注释已规范化）。

## 六、验收标准（「当…时，应…」）

- [ ] 当 停下不动时，Console 应只有一条 `[PlayerBrain] Idle → Move`（走起来时）和一条 `Move → Idle`（停下时），**不刷屏**
- [ ] 当 连续走动 5 秒时，Console 不应重复打印 `Idle → Move`
- [ ] 当 走/停/转身时，移动与动画手感应与 R014 完全一致（不能被状态机改坏）
- [ ] 当 打开 Inspector 时，`PlayerBrain` 应能看到当前状态与已注册状态数
- [ ] 当 Console 出现 FSM 的异常（帧号倒退、状态未注册）时，视为**未通过**
