- 改 3 个文件（`SnapshotSceneBinder` / `RuntimeNetDriver` / `HpBarDemoBehaviour`）+ 1 次资产操作（狼的 4 个材质）。
- 服务端、协议、动画控制器、R006 的位置平滑全部不动。

| 子任务 | 落点 |

## 二、功能概述

实体的槽位不再一律是胶囊：配了 `m_monsterPrefab` 就实例化那只狼，并按它的包围盒把脚底对到地面；本地英雄不建槽位（场景里已有真模型）。

## 三、接口与入参出参

| 成员 | 入参 | 出参 | 说明 |
| --- | --- | --- | --- |
| `m_monsterPrefab`（Inspector） | — | GameObject | 留空 = 胶囊 |
| `SnapshotSceneBinder.Ensure(view, playerId, prefab)` | 三个 | binder | 新增 3 参重载；旧 2 参重载保留（转调 null） |
| `RuntimeNetDriver.MonsterPrefab` | prefab | — | 装配者设置 |
| `MeasureGroundOffset(GameObject)` | 模型根部 | 抬升量（米） | 按包围盒算一次 |
| `Slot.GroundOffsetY` | — | float | 目标 y 用它 |

## 四、逐段讲解

1. **为什么 prefab 从 `HpBarDemoBehaviour` 传**：`SnapshotSceneBinder` 与 `RuntimeNetDriver` 都是**运行时创建**的，没有序列化宿主；场景里唯一能被 Inspector 配的就是 `HpBarDemo` 这个物体。
2. **为什么贴地要自动量**：狼的脚底在 y=−0.44，换一只龙又是别的数；写死必然错，量一次最省事。
3. **为什么跳过本地英雄**：R014 之后本地玩家是真模型（SwordGirl）且由 `PlayerMove` 驱动；再给它造一个槽位就是两个自己。
4. **为什么 `m_ownerPlayerId == 0` 时不跳过**：那时还不知道自己是谁，宁可多显示一个，也不能让敌人消失。

```csharp
        private Slot EnsureSlot(int entityId)
        {
            Slot slot;

            if (m_slots.TryGetValue(entityId, out slot))
            {
                return slot;
            }

            GameObject go;

            if (m_monsterPrefab != null)
            {
                // 有模型就用模型（R015）；局部位置先归零，位置随后由 MoveSlotTo 接管
                go = Instantiate(m_monsterPrefab, transform, false);
                go.name = "单位 " + entityId;
            }
            else
            {
                // 没配置模型就回落成胶囊 —— 这是可回退路径，不是错误
                go = GameObject.CreatePrimitive(PrimitiveType.Capsule);
                go.name = "单位 " + entityId;
                go.transform.SetParent(transform, false);
            }

            slot = new Slot(go);

            if (m_monsterPrefab != null)
            {
                slot.GroundOffsetY = MeasureGroundOffset(go);
            }

            m_slots.Add(entityId, slot);
            m_created++;
            return slot;
        }
```

```csharp
        // 功能：量出「脚底到轴心」的距离，让模型站在地面上而不是悬空或陷地。
        // 入参：go 刚实例化的模型根部
        // 返回：抬升量（米，正数表示要把物体抬高多少）；模型没有 Renderer 时返回 0.5（按胶囊处理）
        // 步骤：
        //   1) 扫一遍所有 Renderer（含隐藏子物体），把包围盒并起来
        //   2) 用「包围盒最低点 − 物体当前位置」得到局部空间的最低点
        //   3) 取相反数就是抬升量
        // 上游：EnsureSlot（只在建槽位时算一次）
        // 下游：LateUpdate 里作为目标 y
        // 注意：每个模型轴心不一样（狼的脚底在 y=−0.44），写死一个数必然对不上；量一次比手调可靠
        private static float MeasureGroundOffset(GameObject go)
        {
            Renderer[] renderers = go.GetComponentsInChildren<Renderer>(true);

            if (renderers == null || renderers.Length == 0)
            {
                return 0.5f;
            }

            Bounds bounds = renderers[0].bounds;

            for (int i = 1; i < renderers.Length; i++)
            {
                bounds.Encapsulate(renderers[i].bounds);
            }

            float lowestLocalY = bounds.min.y - go.transform.position.y;
            return -lowestLocalY;
        }
```

## 七、风险与幻觉自查

- 幻觉自查：只用了 `Instantiate`、`GetComponentsInChildren<Renderer>`、`Bounds.Encapsulate`、`AssetDatabase`，都是既有 API。
- 编码中踩到并修掉两处：
  1. 3 参 `Ensure` 写成 `private` ⇒ 驱动调不到（`CS1501`）→ 改 `public`；
  2. 新序列化字段没初始化 ⇒ 多出一条 `CS0649` 警告 → 加 `= null` 恢复 10 条基线。
- 行为变化：**本地玩家不再有槽位**（以前会有一个放大 1.4 倍的胶囊跟着自己）。
- 风险：`m_monsterPrefab` 为空时回落胶囊（这是设计好的回退路径）。
- 风险：模型朝向若与 +Z 相反，会「背对你走」；本次不处理，观察到再说。
