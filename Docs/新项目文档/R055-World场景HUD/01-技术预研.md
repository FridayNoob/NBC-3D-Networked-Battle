- 作者：AI（DeepSeek）
- 状态：开发中

## 一、调研目标与约束

目标：World（大厅/世界地图）里也显示「玩家血条 + 网络状态 + 任务追踪」三块 HUD，样式与副本里一致。

约束：

1. 面板复用现有三块 prefab（`HpBarPanel`/`NetHudPanel`/`HudQuestPanel`），不新画界面。
2. 资源层整局只能装一次（`AssetManager.Instance.IsInitialized` 之后重复装会抛异常）。
3. `UIManager.SetCanvasLocation` / `SetPanelLocationPrefix` 必须在第一次 `ShowPanel` 之前调用，之后调用会抛异常。
4. World 没有网络会话、没有任务数据：血条按满血显示，任务区显示一句提示。
5. 程序集方向：`NBC.Boot → NBC.Game`，资源层安装只能在 Boot 里做。

## 三、最小可运行示例

```csharp
// 装资源层（只装一次）
await AssetBootstrapper.InstallAsync(AssetRuntimeMode.EditorSimulate,
    AssetBootstrapper.DefaultPackageName, AssetPackageRoot.Resolve());
UIManager.Instance.SetCanvasLocation("Canvas");
UIManager.Instance.SetPanelLocationPrefix(string.Empty);

// 等就绪后开面板
UIManager.Instance.ShowPanel("HpBarPanel", UILayer.Bot, p => (p as HpBarPanel)?.SetHp(1200, 1200));
```

## 四、方案对比

| 方案 | 做法 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| A | Login 挂常驻 `AppBootstrap` 装资源层；World 的 `[Player_Hero]` 挂 `WorldHudDriver` | 一次装好整局可用；World 与 Battle 共用同一份资源 | 多一个常驻物体 | **采用** |
| B | World 自己再装一次资源层 | World 单独按 Play 也能跑 | 重复安装会抛异常，需要到处判重；两份初始化逻辑 | 不采用 |
| C | 把 HUD 画在 Canvas prefab 里，跟场景一起加载 | 不用代码 | Canvas 来自资源包，场景里本就没有；改 prefab 影响副本 | 不采用 |

## 五、已知坑与版本兼容

1. **Unity 未导入新文件会「假绿」**：新增 `.cs` 后没 `.meta` 时 `unity_get_compilation_errors` 还是旧结果，必须先 `Assets/Refresh`。
2. **`SetCanvasLocation` 只能调一次**：第二次抛 `InvalidOperationException`（R046 第二次重开副本踩过）。
3. **面板挂在 DontDestroyOnLoad 的 Canvas 下**：场景卸载不会自动关，必须 `OnDestroy` 里 `HidePanel`。
4. **`ShowPanel` 返回 void**：面板只能从 `onShown` 回调拿（第一次写 R046 时 `as` 转换直接 CS0039）。
5. **`Text_Tracker` 与 `Root` 不在同一父链也没关系**：显隐要按控件引用操作，不要 `transform.parent.SetActive`。
6. **World 场景里没有 Canvas**：`UIManager` 首次 `ShowPanel` 才会去加载 `Canvas` prefab，所以要等资源层就绪。

## 六、结论

采用方案 A：新增 Boot 侧 `AppBootstrap`（整局唯一、常驻）+ `AssetPackageRoot`（清单目录解析抽公共）+ Game 侧 `WorldHudDriver`（挂在 World 的 `[Player_Hero]`）。
预计新增 3 个文件约 300 行、改 2 个文件约 15 行，合计约 315 行，在 500 行预算内。
