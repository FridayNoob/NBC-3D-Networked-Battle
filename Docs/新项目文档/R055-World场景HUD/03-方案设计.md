# R055 World 场景 HUD —— 03 方案设计

- 需求编号：R055
- 所属阶段：M4
- 作者：AI（DeepSeek）
- 状态：开发中

## 一、整体架构

```
Login 场景                           World 场景                          Battle 场景
[AppBootstrap]（Boot，常驻）          [AppBootstrap]（自杀去重）            HpBarDemoBehaviour
   │ 装资源层（唯一一次）                [Player_Hero]                      （沿用同一份资源层）
   │ 设 Canvas 地址                      └ WorldHudDriver（Game）
   │ 预加载配置表                            │ 等 BattleReadiness.AssetsReady
   └─ DontDestroyOnLoad                      └ ShowPanel ×3（HpBar/NetHud/HudQuest）
```

## 二、模块划分

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| `AppBootstrap`（Boot） | 整局唯一的资源层安装、Canvas 地址对齐、配置表预加载、常驻 | 不画 HUD、不碰生命值 |
| `AssetPackageRoot`（Boot） | 找模拟清单最新目录 | 不装加载器 |
| `WorldHudDriver`（Game） | 等就绪、读英雄血上限、开三块面板、离开时关掉 | 不装资源层、不接管副本 HUD |
| `HudQuestPanel.SetHint` | 显示一句占位提示 | 不查任务表 |
| `HpBarDemoBehaviour`（改） | 复用 `AssetPackageRoot.Resolve` | 逻辑不变 |

## 三、接口（方法 + 入参 + 出参 + 约定）

```csharp
// AppBootstrap（MonoBehaviour）
public static bool Ready { get; }                // 资源层是否已就绪
public static string LastError { get; }          // 最近一次失败原因（空串 = 无）
// 私有生命周期：Awake（单例去重 + DDOL）、Start（装资源层 + 地址 + 预加载）

// AssetPackageRoot（静态）
public static string Resolve();                  // 返回目录全路径；找不到返回空串

// WorldHudDriver（MonoBehaviour，挂 [Player_Hero]）
public const string HpBarPanelName = "HpBarPanel";
public const string NetHudPanelName = "NetHudPanel";
public const string QuestPanelName = "HudQuestPanel";
public const int DefaultHeroId = 1001;
public const int FallbackMaxHp = 1200;
public const string QuestHint = "世界区域：暂无进行中的任务";
public const float AssetsWaitTimeoutSeconds = 15f;
// 私有：Start → BindRoutine（协程）；OnDestroy 关三块面板

// HudQuestPanel（新增）
public void SetHint(string text);                // 显示整块 + 一行提示
```

约定：

1. `AppBootstrap` 全流程幂等：`Ready || AssetManager.Instance.IsInitialized` 时直接跳过安装。
2. 面板地址 = prefab 文件名（收集器 `AddressByFileName`）。
3. `WorldHudDriver` 只在就绪后开面板；没就绪就每帧等，不重试安装。

## 四、数据结构

| 字段 | 类型 | 单位/取值 | 含义 |
| --- | --- | --- | --- |
| `m_heroId` | int | 1001 | 英雄编号（取血上限） |
| `m_maxHp` | int | 点，> 0 | 血上限（取表，取不到 1200） |
| `m_hp` | int | 点，0..m_maxHp | 当前显示血量（World 固定满血） |
| `m_mode` | `AssetRuntimeMode` | EditorSimulate / Offline | 资源模式 |
| `AssetsWaitTimeoutSeconds` | const float | 秒，15 | 等资源层告警阈值 |

## 五、时序与流程

1. Login 加载 → `AppBootstrap.Awake`（去重 + DDOL）→ `Start`：`AssetPackageRoot.Resolve()` → `InstallAsync` → `SetCanvasLocation("Canvas")` / `SetPanelLocationPrefix("")` → `BattleConfigBootstrap.Ensure`。
2. World 加载（Login 的那份还在）→ World 自带的 `[AppBootstrap]` 发现已有实例 ⇒ `Destroy` 自己。
3. World 的 `[Player_Hero]` 上的 `WorldHudDriver.Start` → 协程等 `BattleReadiness.AssetsReady` → `ResolveMaxHp()` → `ShowPanel` ×3 → 打 `[WorldHud] World HUD 已打开`。
4. 进副本：World 卸载 → `WorldHudDriver.OnDestroy` → `HidePanel` ×3；Battle 的 `HpBarDemoBehaviour` 复用资源层并显示副本 HUD。
5. 回 World：World 重新加载 → `WorldHudDriver` 重新开面板。

## 六、选型与理由

| 选择 | 理由 | 替代方案为什么不行 |
| --- | --- | --- |
| 资源层装在 Login | 整局只该装一次；Login 是固定入口 | 装在 Battle：World 就是没资源可用（就是这次的现象） |
| World 也挂 `AppBootstrap` + 单例去重 | 允许直接从 World 按 Play 调试 | 不挂：直接在 World 按 Play 会「没有加载器」 |
| 面板地址用文件名常量 | 与收集器规则一致 | 加 `UI/` 前缀：`Location is invalid` |
| World 任务区用 `SetHint` | World 没有任务数据，显示提示比空着强 | 强接 `LastQuestStates`：World 没有会话，拿不到 |

## 八、风险与对策

| 风险 | 对策 |
| --- | --- |
| 两处都挂 `AppBootstrap` 导致装两次 | 静态单例去重，后来者 `Destroy(gameObject)` |
| 面板挂常驻 Canvas 带到副本 | `WorldHudDriver.OnDestroy` 无条件 `HidePanel` |
| 资源层没就绪就 `ShowPanel` | 协程每帧等 `BattleReadiness.AssetsReady` |
| 场景 YAML 手改挂错脚本 | 用固定 guid（`f2bce4b8…` / `0686a35b…`），Refresh 后查编译与 Hierarchy |
| 血上限取不到 | 回落 1200 并照常显示 |
