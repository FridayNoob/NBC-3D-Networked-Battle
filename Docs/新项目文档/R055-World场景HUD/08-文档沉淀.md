## 一、文档范围

本需求做三件事：让 World 也有 HUD（血条 / 网络 / 任务占位）、把「装资源层」变成场景无关的常驻职责、把资源包目录解析抽成公共入口。技能栏、设置面板、任务系统不在范围内。

## 二、模块文档

### 2.1 `AppBootstrap`

- 简介：整个客户端唯一的「装资源层 + 设 UI 地址 + 预加载配置」入口，挂在 Login 与 World 两个场景上。
- 接口：静态 `Ready`、`LastError`；序列化字段 `m_mode`、`m_logDiagnostics`。
- 示例：Login/World 场景各放一个 `[AppBootstrap]` 物体即可，脚本自己保证只装一次。
- 原理：`Awake` 用 `s_instance` 去重并 `DontDestroyOnLoad`；`Start` 里「已就绪或加载器已装」就直接返回，否则安装。
- 坑：`UIManager.SetCanvasLocation` 只能在 Canvas 加载前设一次，重复设会抛异常——必须与「是否已安装」同条件。
- 维护：换成正式资源模式时只改 `m_mode` 与目录解析，其余不动。

### 2.2 `AssetPackageRoot`

- 简介：把「模拟清单目录在哪」从各处复制收敛成一处。
- 接口：`public static string Resolve()`（找不到返回空串）。
- 示例：`AssetBootstrapper.InstallAsync(mode, AssetBootstrapper.DefaultPackageName, AssetPackageRoot.Resolve())`。
- 原理：拼 `<工程根>/Bundles/StandaloneWindows64/DefaultPackage/`，只认含 `DefaultPackage*.bytes` 的子目录，按清单文件时间取最新。
- 坑：目录里可能有旧的构建结果，取「最新清单」而不是「字典序最后」。
- 维护：出正式包时这个入口不再被调用（由打包流程给地址），保留它不影响。

### 2.3 `WorldHudDriver`

- 简介：World 场景的三块 HUD 驱动，只做「开面板 + 填初始值」。
- 接口：序列化 `m_heroId`；内部协程 `BindRoutine`。
- 示例：挂在 `[Player_Hero]` 上，`m_heroId = 1001`。
- 原理：每帧等 `BattleReadiness.AssetsReady`（超 15 秒只告警一次）→ 读 `HeroConfig` 取满血 → 依次 `ShowPanel` 三块面板。
- 坑：`OnDestroy` 必须关掉自己开的三块面板，否则回 Login 还留着。
- 维护：World 新增 HUD 项时，在 `BindRoutine` 里追加一次 `ShowPanel`，并在 `OnDestroy` 对应关掉。

### 2.4 面板生命周期的通用规则（本需求的核心结论）

- 谁开谁关；关的时候连同「引用」一起清。
- 挂在 DDOL 上的面板不随场景卸载，必须由知道流程的代码显式关。
- 「空数据」与「不该占屏」是两种语义：前者用占位文案，后者才隐藏。

## 三、踩坑清单

1. `SetCanvasLocation` / `SetPanelLocationPrefix` 在 Canvas 已加载后调用会抛异常，必须与安装同条件。
2. 重复调用 `AssetBootstrapper.InstallAsync` 会报「已经装过加载器了」，入口必须先去重。
3. `CloseAll` 只 `HidePanel` 不清引用 ⇒ 下次懒加载不触发，面板永不出现。
4. `SetRows(0)` 会隐藏整块面板，空态要改用 `SetHint`。
5. 手写场景 YAML 时，新增根物体必须同时写 `SceneRoots`，否则打开场景看不到。
6. 手写 MonoBehaviour 需要 `.meta` 里已存在的脚本 guid；先 `Assets/Refresh` 再取。
7. 改动 `Client/Assets/_Project/UI/` 下的 prefab 后，必须重新构建 YooAsset 清单，否则运行时按地址找不到。
