# R055 World 场景 HUD —— 02 需求

- 需求编号：R055
- 所属阶段：M4
- 作者：AI（DeepSeek）+ 负责人决策
- 状态：开发中

## 一、业务目标（一句话）

玩家回到 World 后，屏幕上仍然有血条、网络状态与任务区，不会「一出副本就什么都没有」。

## 二、用户与场景

- 玩家从 Login 点「开始游戏」进入 World：看到自己的满血血条、右上角网络状态、任务区一句提示。
- 玩家从副本点「返回世界」：World 的 HUD 重新出现（副本那套 BOSS 条/目标条随场景卸载消失）。
- 玩家直接按 Play 从 World 场景开始调试：HUD 同样出现（场景里也挂了一份 `AppBootstrap`，靠单例去重）。

## 三、功能列表

| 优先级 | 功能 | 说明 |
| --- | --- | --- |
| P0 | World 显示玩家血条 | 读 `HeroConfig` 的血上限（1001 = 1200），按满血显示 |
| P0 | World 显示网络状态面板 | 复用 `NetHudPanel`（它自己每 0.25 秒读一次统计） |
| P0 | World 显示任务追踪 | 复用 `HudQuestPanel`，固定提示「世界区域：暂无进行中的任务」 |
| P0 | 离开 World 时关掉三块面板 | 场景卸载时 `HidePanel`，避免带到副本里叠两层 |
| P1 | 资源层整局只装一次 | Login 装好后 World/Battle 复用；World 自带的 `[AppBootstrap]` 自杀 |
| P1 | 就绪门 + 日志 | 等 `BattleReadiness.AssetsReady` 再开面板；超时 15 秒只告警一次 |
| P2 | 血条跟随真实血量 | World 没有网络会话，暂不接；留给以后的大厅玩法 |

## 四、边界（不做什么）

1. 不做新的 HUD 美术：三块面板都用现有 prefab。
2. 不做任务数据同步：World 里没有任务本，任务区只显示占位提示。
3. 不改服务端：本需求纯客户端。
4. 不动副本里的 `RuntimeHudDriver`：副本 HUD 仍由它负责。

## 五、优先级

P0 四条先做（缺一条 World 就是「空屏」）；P1 两条一起做（否则面板加载不出来）；P2 不做。

## 六、验收标准（当…时，应…）

1. 当玩家在 Login 点「开始游戏」进入 World 时，应在 2 秒内看到血条（1200 / 1200）。
2. 当 World 加载完成时，应看到右上角网络状态面板。
3. 当 World 加载完成时，任务区应显示「世界区域：暂无进行中的任务」。
4. 当玩家从 World 按 E 进入副本时，World 的三块面板应消失，副本的 BOSS 条/目标条正常出现。
5. 当玩家从副本点「返回世界」时，World 的 HUD 应重新出现。
6. 当连按两次从副本进出时，屏幕上不应出现两套血条。
7. 当资源层 15 秒还没就绪时，Console 应只出现一条 `[WorldHud] 资源层 15 秒还没就绪` 告警。
8. 当直接从 World 场景按 Play 时，HUD 也应出现（`[AppBootstrap]` 与 Login 那份去重）。
9. 当 Console 里查看启动日志时，应依次看到 `[AppBootstrap] 开始装资源层` → `[AppBootstrap] 资源层已就绪` → `[WorldHud] World HUD 已打开`。
10. 当离开 World 后回到 Login 再进 World 时，HUD 应重新加载且不报「已经装过加载器」。
