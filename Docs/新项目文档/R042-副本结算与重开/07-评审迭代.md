## 二、优先级

1→2→3 是「副本能不能玩」的主链路，先修；4→5 是「退出会不会炸」，次之；6~10 是「重开与返回世界」的观感与残留，最后成组修。

## 三、根因分析

- 1：网络攻击动作只绑 `J`，`PlayerBrain` 本机处理鼠标左键只播动画 ⇒ `ActionBits` 恒 0。
- 2：`SnapshotView.FindHero` 只返回活着的英雄，死后返回 null ⇒ `TrackHeroHealth(null)` 早退 ⇒ `HeroAlive` 恒 true。
- 3：找剑的锚点用了被关掉的 `PlayerAnimation`（`FindObjectOfType` 跳过禁用组件），且失败标志只置一次；冷却期的攻击位被周期发送带出去。
- 4/5：`SceneFlow` 加载失败后 `handle.Dispose()` 抛异常打断协程，兜底代码「存在但跑不到」；清理写在切场景之后。
- 6：退房再进房会删房重建；复用房又拿回同一局死光的怪；重载场景后新相机没人 `SetTarget`。
- 7：快照帧号取战斗世界 `Tick`，而新一局从 0 重数 ⇒ 客户端 `SnapshotView` 拒收所有新快照。
- 8：驱动跨场景常驻，清理在切场景之后，间隙里按旧快照在 World 重建了绑定器。
- 9：World 自带玩家 + DDOL 带来的玩家并存，直到加载完才销毁。
- 10：面板挂在 DDOL 的 `Canvas` 下，`HpBarDemo` 被销毁时没人关。

## 四、改进方案

| 改哪 | 怎么改 | 影响面 |
| --- | --- | --- |
| `InputMapping`/`LegacyInputSource` | 支持「主键 + 备用键」 | 只在输入层，Battle/World 共用 |
| `RuntimeNetDriver` | 自己扫快照找英雄（不看 `Alive`）；剑锚点按 `PlayerMove` 找并每秒重试；周期发送抹掉攻击位 | 副本链路 |
| `SceneFlow` | 失败不 `Dispose`、成功包 try/catch、失败场景记入集合；编辑器直接 SceneManager | 所有场景切换 |
| `RoomService`/`RoomBattleService` | 新增 `RestartDungeonRequest` 与 `ResetBattle`，房间常驻、不再退房重建 | 协议 + 服务端房间 |
| `RoomBattleService` | 快照帧号改**全局单调** `_serverTick` | 协议语义（帧号只增） |
| `RuntimeNetDriver` | 重开不重载场景（原地清槽位）；返回世界前关表现层、销毁带来的玩家；重开成功后重新 `BindCamera` | 副本表现层 |
| `HpBarDemoBehaviour` | `OnDestroy` 关 HUD 面板 | 副本 HUD |
