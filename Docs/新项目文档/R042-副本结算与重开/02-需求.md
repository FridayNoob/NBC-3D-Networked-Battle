# 02 需求

需求编号：R042
所属阶段：M4
作者：AI（DeepSeek）
状态：开发中

## 一、业务目标（一句话）

副本打完（怪清光或英雄全灭）时，玩家能看到一局的结果，并且能一键再开一局。

## 二、用户与场景

1) 单人刷 1001 副本，把最后一波怪清掉：屏幕上应该出现「胜利」，带上用时、击杀数、死亡数，下面两个按钮。
2) 玩家被怪打死：屏幕上应该出现「失败」，同样带数据，同样两个按钮；此时**不要**再弹 R041 的死亡倒计时（结算优先）。
3) 点「再来一次」：退回当前房间 → 立刻重新进同一副本 → 重载 Battle 场景，怪与英雄都是新一局的状态。
4) 点「返回世界」：退房 → 回 World 场景，角色回到出生点，副本进度不保留。

## 三、功能列表

**P0（必须）**

1. 服务端在副本结束时判定胜负（怪清光 = 胜；英雄全灭 = 负），并发一条 `DungeonResult`。
2. 结果带四个数字：用时（毫秒）、击杀数、死亡数、胜负。
3. 客户端收到后弹结算面板：大标题胜/负 + 一行数据 + 两个按钮。
4. 「再来一次」：退房 + 重新进同一 `dungeonId` + 重载 `Battle`。
5. 「返回世界」：退房 + `SceneFlow.LoadAsync(World)`。
6. 结算面板出现时，R041 的死亡倒计时与黑幕**不再接管屏幕**。

**P1**：服务端把 `room.Phase` 置 `Finished`（复用已有枚举，房间列表能看出这局结束了）。
**P2**：键盘快捷键（R = 再来一次，Esc = 返回世界），方便演示。

## 四、边界（不做什么）

1) 不做奖励、掉落结算、经验值、排行榜。
2) 不做 PVP 结算（`MatchResult` 保持原样，不复用）。
3) 不做结算数据持久化到数据库（本局结果只在内存里发一次）。
4) 不做多语言，文案中文字面量。
5) 不改 `CONTRACT_VERSION`（纯新增消息）。

## 五、优先级

先 P0 打通「打完 → 看到结果 → 再开一局」的闭环；P1/P2 顺手做，不影响验收。

## 六、验收标准（当…时，应…）

1) 当最后一只怪被打死时，应在 1 秒内弹出结算面板且标题为「胜利」。
2) 当英雄被怪打死时，应弹出面板且标题为「失败」，并且**不**出现 R041 的「你已倒下」黑幕。
3) 面板上的用时应在 0~副本时限之间，格式为 `mm:ss`。
4) 面板上的击杀数应等于本局实际击杀的怪数量（含 BOSS）。
5) 面板上的死亡数应为 0 或 1（单人副本）。
6) 当点「再来一次」时，应重新进房并重载 Battle，英雄满血、怪全部重生。
7) 当点「返回世界」时，应回到 World 场景并停在出生点。
8) 当按 R / Esc 时，应与点对应按钮等价。
9) 当服务端没有发结果（例如断线）时，客户端不应卡在结算态。
10) 当结果消息重复到达时，面板只处理第一次（不叠加、不重置倒计时）。
