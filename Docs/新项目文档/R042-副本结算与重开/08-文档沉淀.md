## 一、文档范围

## 二、模块文档

### 2.1 结算协议 `DungeonResult`

- 简介：服务端在副本结束（`IsFinished`）时广播一次结果，客户端据此弹结算面板。
- 接口：`ServerMessage.dungeon_result = 12`；字段 `outcome`（1 胜 / 2 负）、`duration_ms`、`monster_kills`、`hero_deaths`。
- 示例：`[战斗] 房间 r1 结束：胜，用时 83 秒，击杀 4，死亡 0`。
- 原理：`RoomBattleService.RecordIfFinished` 用 `_recorded` 去重，`room.Phase = Finished`，再 `SendToRoom`。
- 坑：`MatchResult` 是 PVP 语义，不能拿来当副本结果。
- 维护：加字段走 proto 兼容变更（新编号，不改旧号），重生成 `NbcM3.cs`。

### 2.2 结算面板 `DungeonResultPanel`

- 简介：运行时 UGUI 面板，标题（胜利/失败）+ 统计 + 两个按钮；R 重开、Esc 回世界。
- 接口：`Ensure()`、`IsShowing`、`Show(result, onRestart, onReturn)`、`Hide()`。
- 原理：Canvas sortingOrder 950（高于死亡黑幕 900），`Show` 时先关死亡黑幕并解锁鼠标。
- 坑：`Hide` 必须关整块 Canvas（只关背景会留下两行字）。
- 维护：R046 计划改成「预制体 + UIManager」。

### 2.3 重开与返回世界

- 简介：`RuntimeNetDriver.RestartDungeon()` 发 `RestartDungeonRequest`（不退房），`ReturnToWorld()` 退房并回 World。
- 原理：重开 = 服务端 `ResetBattle` 丢掉旧世界 + 客户端原地清槽位（不重载场景）；返回世界 = 先关表现层、销毁带来的玩家，再切场景。
- 坑：协程随组件销毁（切场景时 `yield` 之后不再执行）；DDOL 玩家与场景自带玩家并存。
- 维护：新场景跳转沿用「切之前清理、切之后只做接线」。

### 2.4 快照帧号 `_serverTick`

- 简介：`RoomBattleService` 为每次广播分配全局单调帧号，写进 `WorldSnapshot.ServerTick`。
- 原理：客户端 `SnapshotView.Apply` 拒收不比上一张新的快照（防画面倒退），所以服务端帧号必须跨「重开/换房」持续增大。
- 坑：曾用战斗世界 `Tick`、也曾用「按房号计数」，两者都会归零 ⇒ 客户端把新快照全丢掉，表现为「怪十几秒不出现」。
- 维护：任何「新世界」都不得重置该计数。

### 2.5 HUD 与表现层清理

- 简介：`HpBarDemoBehaviour.OnDestroy` 关两个面板；`RuntimeNetDriver` 在离开副本前清 `m_feed`/`m_binder`/槽位。
- 原理：面板挂 DDOL Canvas ⇒ 谁打开谁关；绑定器跨场景常驻 ⇒ 切之前先关闸。
- 坑：清理写在切场景之后 = 中间几帧会按旧快照重建。

## 三、踩坑清单

1. 动画在播 ≠ 请求发了（`ActionBits` 才是网络输入）。
2. `FindObjectOfType` 跳过禁用组件，别拿它当锚点。
3. 兜底代码存在 ≠ 会执行（异常打断协程）。
4. 单调序号必须放在会话层，不能放在「世界」层。
5. `DontDestroyOnLoad` 的对象要在切场景**之前**处理。
6. 面板挂在 DDOL Canvas 下，场景卸载不会带走。
