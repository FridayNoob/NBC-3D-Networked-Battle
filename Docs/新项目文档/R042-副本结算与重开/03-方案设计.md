# 03 方案设计

需求编号：R042
所属阶段：M4
作者：AI（DeepSeek）
状态：开发中

## 一、整体架构

```
服务端 Tick：DungeonBattle.IsFinished
   └─ RoomBattleService.RecordIfFinished（已有去重 _recorded）
        ├─ 新增：room.Phase = Finished
        ├─ 新增：DungeonResults.Build(battle) → DungeonResult
        └─ 新增：SendToRoom(DungeonResult) 一次性广播
客户端：
   NetSession 分发 switch → DungeonEnded 事件
   → RuntimeNetDriver.DungeonEnded 转发
   → DungeonResultPanel.Show(result, onRestart, onReturn)
        ├─ 再来一次：driver.RestartDungeon()
        └─ 返回世界：driver.ReturnToWorld()
```

## 二、模块划分

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| `DungeonBattle`（改） | 提供击杀数/死亡数/已用时三个只读数据 | 不判胜负、不发消息 |
| `DungeonResults`（新，服务端） | 把 `DungeonBattle` 的现状拼成 `DungeonResult` | 不发送、不改房间 |
| `RoomBattleService`（改） | 副本结束那一次调用：置相位 + 广播一次 | 不重复判定、不管客户端怎么显示 |
| `NetSession`（改） | 收到 `DungeonResult` 转成事件 | 不弹 UI、不切场景 |
| `RuntimeNetDriver`（改） | 转发事件 + 提供「重开」「回世界」两个动作 | 不画面板 |
| `DungeonResultPanel`（新） | 画面板、接两个按钮/快捷键 | 不判胜负、不连线 |
| `PlayerDeathFlow`（改） | 结算面板出现时让位（不抢屏） | 不读结算数据 |

## 四、数据结构

`DungeonResult`（`Protocol/nbc_m3.proto` 新增）：

```
message DungeonResult {
  int32 outcome = 1;       // 1 胜 / 2 负
  int32 duration_ms = 2;   // 本局用时
  int32 monster_kills = 3; // 击杀数（含 BOSS）
  int32 hero_deaths = 4;   // 死亡英雄数

```

挂到 `ServerMessage` 的新字段号（取当前最大值 +1，不改既有编号）。

## 五、时序与流程

1) 服务端 Tick 发现 `IsFinished` → `RecordIfFinished` 首次进入。
2) 置 `room.Phase = Finished`；`DungeonResults.Build` 拿四个数字；`SendToRoom` 广播一次。
3) 客户端 `NetSession` 收到 → `DungeonEnded` → 驱动转发 → 面板 `Show`。
4) 面板 `Show` 时先 `DeathScreenOverlay.Ensure().Hide()`，并置静态 `IsShowing = true`（死亡流程看到就让位）。
5) 点「再来一次」：`driver.RestartDungeon()` = `LeaveRoom()` → `m_joinRequested = false` → `SceneFlow.LoadAsync(Battle)`；Update 的自动进房逻辑下一帧重新 `JoinRoom`。
6) 点「返回世界」：`driver.ReturnToWorld()` = `LeaveRoom()` → `SceneFlow.LoadAsync(World)`。
7) 面板 `Hide()` 时置 `IsShowing = false`。

## 六、选型与理由

1) **结算数据用服务端新消息**，不复用 `MatchResult`（PVP 语义，队伍击杀数对不上）。
2) **`DungeonResults.Build` 单独成类**：纯函数、可被 `_net-probe` 直接测，不用起网络。
3) **面板运行时 UGUI**：与 R041 黑幕一致，先跑通；R046 统一迁预制体 + `UIManager`。
4) **重开用「退房 + 重新进房」**：服务端无需新增「重置战斗」接口，新房间天然是新世界。
5) **结算优先于死亡倒计时**：R041 的死亡流程是「死了等 5 秒」，结算已经给出下一步，不该再让玩家等。

## 八、风险与对策

1) 广播时机与 `_recorded` 去重绑在一起 ⇒ 每局只发一次；如果以后要「重发」，另开接口。
2) `LeaveRoom` 后立刻 `JoinRoom` 可能被服务端当成同一会话的第二次进房 ⇒ 用下一帧自动进房，不手动连发两条。
3) 重载 Battle 时玩家是 `DontDestroyOnLoad` 的，位置要由快照纠偏回出生点 ⇒ 由 `ReconcileHeroPosition` 处理，面板不放位置。
4) 面板按钮需要鼠标 ⇒ `Show` 时解锁并显示光标，`Hide` 时恢复由相机控制的光标状态。
5) 结算面板与死亡黑幕同时出现 ⇒ 面板优先，`Show` 里主动 `Hide()` 黑幕。
6) 断线收不到结果 ⇒ 面板不显示，玩家可 Esc 退出（R049 已有），不新增卡死路径。
