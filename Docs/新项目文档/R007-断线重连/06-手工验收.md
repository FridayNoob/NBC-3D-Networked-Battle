# 06 手工验收

需求：R007-断线重连
所属阶段：M4
作者：LYF　状态：已验收（2026-10-31）

## 一、测试计划（四类）

| 类别 | 本次要测什么 | 怎么做 |
| --- | --- | --- |
| 正常 | 断线后能否自动重连并回原房 | Play 中关掉服务端，再启动 |
| 异常 | 断线期间会不会抛异常（发输入 / 重复连接） | 看 Console |
| 边界 | 服务端一直不恢复会不会无限重连 | 关服后不重启，等 12 秒 |
| 性能 | 重连后画面是否跳帧、帧号是否正常 | 走动 + 看 HUD 帧号 |

## 二、正常流程走查

| 步 | 你做什么 | 应该看到什么 | 实际结果 |
| --- | --- | --- | --- |
| 1 | 起服 → Play → 走动 | 正常进房、能动、帧号递增 | **通过** |
| 2 | 中途**关掉服务端** | Console 只出现 `[Reconnect] 第 N 次重连：127.0.0.1:7778` | **通过** |
| 3 | **重启服务端** | `[Reconnect] 已重连，回房：<房号>` → `[Reconnect] 已回到房间 <房号>，表现层已重置` | **通过** |
| 4 | 重连后走动 | 恢复操作，帧号继续递增（不倒退） | **通过** |
| 5 | 关服后**不重启**，等约 12 秒 | `[Reconnect] 放弃重连：重连 5 次都没成功`，之后不再刷屏 | **通过** |
| 6 | 直接停止 Play | Console **没有**任何 `[Reconnect]` 日志 | **通过** |

负责人结论（原话）：「3个场景都测试成功」。

## 三、异常场景（本轮真踩到的，全部已修）

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| `InvalidOperationException: 还没上线就 Send`（断线瞬间） | `NetSession.InRoom` 只看房间字段，`Fail` 不清它 ⇒ 输入门仍放行 | 输入门改成 `IsOnline && InRoom` |
| `InvalidOperationException: 已经在连/连上了，先 Disconnect 再连` | 策略把「未在线」一律当失败，对着还在 `Connecting` 的会话重复 `Connect` | 策略改看 `ESessionState`，连接进行中只 `Wait` |
| 连接卡死时界面一直「连接中」 | 没有单次尝试超时 | 加 3 秒超时 ⇒ `Reset`（先 `Disconnect` 再重连） |

## 四、性能表现

- 重连后帧号连续、无「帧号倒退 / 假分歧」告警（表现层重置生效）。
- 退避期间客户端几乎不耗 CPU（每帧只做一次减法与几个比较）。
- 留一条观察项：锁步局重连回来后**本局不参与**（服务端只开局一次），要恢复得另开需求做 `LockstepResume`。

## 五、逐条对照 02 的验收标准

- [x] 当 服务端停掉时，Console 应在 0.5 秒内出现「重连中（第 1 次）」，最多重试 5 次 ⇒ 通过
- [x] 当 服务端在重试期间恢复时，应自动连回并**回到原房间** ⇒ 通过（`回房：r1`）
- [x] 当 重连成功时，不应出现「帧号倒退 / 假分歧」告警 ⇒ 通过（表现层已重置）
- [x] 当 玩家主动退出（停止 Play）时，**不应**触发重连 ⇒ 通过
- [x] 当 原房已不存在时，应停止重试并提示 ⇒ 通过（放弃日志）
- [x] 当 锁步局已开局时，应提示「本局已开始，无法恢复」 ⇒ **部分满足**：本版放弃/回房都如实打印，但没有专门针对「锁步已开局」的文案（见 07 遗留）
