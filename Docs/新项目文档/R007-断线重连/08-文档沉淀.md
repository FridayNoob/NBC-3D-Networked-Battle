## 二、模块文档

### 简介与使用场景

`NetReconnector`（`Game\Net\`，纯 C#）：断线后按退避表驱动「重连 → 回原房」，用完次数或房间没了就放弃。
`RuntimeNetDriver`（`Game\Bootstrap\`）：每帧把会话状态喂给它，并执行它给的下一步动作。

**一句话**：Brain 式的分工 —— **策略算「该做什么」，驱动做「真的做」**。

### 核心接口

| 成员 | 入参 | 出参 | 说明 |
| --- | --- | --- | --- |
| `Tick(ESessionState, bool inRoom, float dt, out string reason)` | 会话状态、是否在房、本帧秒数 | `EReconnectAction`：`None`/`Wait`/`Connect`/`JoinRoom`/`Reset`/`GiveUp` | 每帧调一次 |
| `NoteJoined(string roomId)` | 房号 | 无 | 每次成功进房都要调（重连要用它回原房） |
| `NoteIntentionalDisconnect()` | — | 无 | 主动断开时调，之后不再重连 |
| `NoteGiveUp(string reason)` | 原因 | 无 | 进房被拒时由调用方设置 |
| `Reset()` | — | 无 | 重新开始（开新局） |
| 只读属性 | — | `Phase` / `Attempt` / `LastReason` / `LastRoomId` / `DungeonId` | 日志与 HUD 用 |

退避表：**0.5s / 1s / 2s / 4s / 4s**（最多 5 次，约 11.5 秒）；**单次尝试超时 3 秒**（超时返回 `Reset`，由调用方先 `Disconnect`）。

### 使用示例（负责人亲手跑通，2026-10-31）

```text
Play（服务端开着）→ 进房成功
关掉服务端        → [Reconnect] 第 1 次重连：127.0.0.1:7778（0.5 秒后）
                    失败则 1s / 2s / 4s / 4s 继续
重启服务端        → [Reconnect] 已重连，回房：r1
                    [Reconnect] 已回到房间 r1，表现层已重置
关服不重启        → 约 11.5 秒后 [Reconnect] 放弃重连：重连 5 次都没成功
停止 Play         → 没有任何 [Reconnect]（主动断开不重连）
```

### 实现原理（简要）

`Update` 里 `Pump` 之后调 `DriveReconnect()`：取 `m_session.State` 与 `InRoom` 喂策略 → 按动作 `Connect` / `JoinRoom` / `Disconnect`（Reset）。
进房成功时 `NoteJoinedNow()` 记房号；若这次是重连回来的（阶段处于重连三态），清 `PresentationFeed` 缓存并重建绑定器。

### 已知限制与坑点

- **锁步局恢复不了本局**：服务端 `LockstepService.StartRoom` 有「只开一次」的闸，重进房间的座位拿不到 `LockstepStart`。
- **`InRoom` 断线后仍是 true**：它只看房间字段，`Fail` 不清。判断「能不能发输入」必须用 `IsOnline && InRoom`。
- **不能对着进行中的会话 `Connect`**：`NetSession.Connect` 在 `Connecting/Handshaking/Online` 时会抛异常；策略因此要区分「进行中」与「已失败」。
- **`Connect` 会清掉房间与锁步运行器**（注释原文：「重连前把上一次的残留清干净」）⇒ 重连后**必须**重新 `JoinRoom`。
- 主动断开（`Disconnect`）必须调 `NoteIntentionalDisconnect()`，否则会被当成断线去重连。

### 修改维护注意事项

- **改退避**：只改 `NetReconnector.BackoffSeconds` 表与 `m_maxAttempts`；别改 `Tick` 的阶段语义。
- **加动作**：在 `EReconnectAction` 加值 → `Tick` 里返回 → 驱动 `switch` 里实现；**每个动作都要有对应的日志**，否则排查时看不到进行到哪一步。
- **重连成功后要重置的东西**：表现层缓存（`m_feed.Clear()`）、绑定器（`m_binder = null`）；锁步运行器由 `NetSession.Connect` 自己清。
- **判据优先级**：谁能发数据（连接状态） > 业务在哪（房间/局号）。

## 三、踩坑清单（现象 / 原因 / 解决）

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `还没上线就 Send` | 输入门用 `InRoom` 判，断线后仍为 true | 改 `IsOnline && InRoom` |
| `已经在连/连上了，先 Disconnect 再连` | 对 `Connecting` 状态重复 `Connect` | 策略看状态，进行中只 `Wait` |
| 一直停在「连接中」 | 无超时 | 3 秒超时 ⇒ `Reset` |
| `Reset` 后立刻又连 | 阶段置成 `Waiting`，跳过了失败结算 | 阶段留 `Connecting` |
| 重连回来不重置表现层 | 用 `!InRoom` 清标记，永远不成立 | 用 `!online` 清标记 |
| 想给策略写单测却编不过 | `ESessionState` 嵌在 `NetSession.cs` 里，会拖进整个网络栈 | 抽成独立文件 |
