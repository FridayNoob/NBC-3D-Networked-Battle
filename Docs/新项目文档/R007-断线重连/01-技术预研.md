# 01 技术预研

需求：R007-断线重连
所属阶段：M4
作者：AI　状态：已确认（2026-10-31）

## 一、调研目标与约束

- 目标：网络断开后**自动恢复** —— 重新连上、重新登录、回到原来的房间，界面给出明确状态。
- 约束：
  1. **不改协议**（`Protocol\NbcM3.cs` 是生成代码，永不手改；新增消息要走重新生成，不在本次范围）；
  2. 不动 `RoomRegistry` / `RoomService` / `RoomBattleService` 等受保护文件；
  3. 主动断开（玩家自己下线）**不能**触发重连。

## 二、现状（读代码确认）

| # | 事实 | 出处 |
| --- | --- | --- |
| 1 | 传输层断开时只做一件事：`Fail("连接断开：" + reason)`，**没有任何重连尝试** | `NetSession.OnTransportClosed` |
| 2 | 会话状态只有 `Disconnected / Connecting / Handshaking / Online`（失败走 `Fail`） | `NetSession.ESessionState` |
| 3 | 协议里**没有**「恢复会话 / resume token」类消息；与进房相关的只有 `Handshake`、`JoinRoomRequest`、`RoomState` | `Protocol\NbcM3.cs` 消息清单 |
| 4 | 服务端座位按 `ClientSession` 存；断线会释放座位（有心跳超时释放的用例） | `RoomRegistry`、`_net-probe` 的 `RoomOverWire_DisconnectFreesTheSeat` / `HeartbeatTimeoutReleasesTheSeat` |
| 5 | **锁步局只开一次**：`LockstepService.StartRoom` 有「已开局就拒绝」的闸，`LockstepStart` 只发给**开局那一刻**房里的会话 | `LockstepService.cs:171-192`、`:239-256` |
| 6 | 状态同步链路是**每 tick 全量广播**给房里所有座位 ⇒ 新座位自然能收到快照 | `RoomBattleService` 的广播循环 |

## 三、由事实推出的两个结论

1. **客户端重连可做，且不需要改协议**：断线后重新 `Connect` → `Handshake`（同账号）→ `JoinRoom(上次的 roomId)`，服务端会当成一个新座位。
2. **「恢复正在进行中的锁步局」做不到**：重进房间的座位拿不到 `LockstepStart`（闸只让开一次），客户端锁步世界是空的，而服务端在继续推 —— 继续跑就是错的。
   - 但**状态同步**那条链路天然能恢复（快照是全量的）。

## 四、方案对比

| 方案 | 做法 | 结论 |
| --- | --- | --- |
| **A（本次采用）** | 客户端自动重连：`Fail`/`Closed` → 退避重试 → 重连 + 重登 + 回原房；界面显示「重连中…／重连成功／重连失败」；已开局的锁步局如实提示「本局已开始，无法恢复」 | **采用**：不改协议、不动服务端受保护文件，解决「网络抖动一下就得重开」这个真实痛点 |
| B | 协议加 `LockstepResume`（当前 tick + 世界哈希 + 实体 + 已确认帧），服务端在座位加入时补发 | 否（本期）：要改 `.proto` + 重新生成 + 服务端补发逻辑，工作量数倍；建议另开需求 |
| C | 只做「断线后回到登录界面，玩家手动重连」 | 否：等于没做，玩家仍要手动 |

## 五、A 方案的已知坑（必须处理）

1. **主动断开不能重连**：`NetSession` 已有 `m_closingIntentionally` 标记，重连逻辑必须尊重它。
2. **重连风暴**：断线后立刻重连会打满服务端。要有**指数退避 + 次数上限**（例如 0.5s / 1s / 2s / 4s，上限 5 次）。
3. **重连成功后必须重置表现层**：`PresentationFeed` / `PresentationSource` 里的计数与游标（帧号、换局计数）都以上一局为前提，不清会「跳到旧帧 / 假分歧」。
4. **锁步运行器要清**：R008 定的是「每局重建运行器」；重连也属于「新的一局」，必须重建（否则旧 `LastSteppedFrame` 会把新帧当成旧帧丢掉）。
5. **房间可能已经不存在**：所有人断线后房间会被删；这时重连应停在「重连成功但房间没了」，给出明确提示，不要无限重试。
6. **密码要从内存里复用**（本人再次登录需要），但**不能**写进日志。
7. **账号同名重进会不会顶掉自己**：服务端按会话管理，旧会话已断开，理论上不会；但要在实测里确认（否则会出现两个自己）。

## 六、结论与改动清单（A 方案）

结论：**在客户端做「自动重连 + 明确状态提示」**，不碰协议与服务端受保护文件；对锁步局如实提示「无法恢复本局」。

要改/新增（草案，02/03 再定死）：
- `NetSession`：记录「上次成功连接的 host/port/账号/房间」，暴露 `TryReconnect()` 或内部自动重连状态机
- 新增 `EReconnectState`（或复用会话状态 + 一个子状态）
- `RuntimeNetDriver`：断线后按退避策略驱动重连；重连成功时重建运行器与表现层
- `NetHudPanel`（或新的小面板）：显示「重连中（第 N 次）／已恢复／已放弃」
