# 03 方案设计

需求：R007-断线重连
所属阶段：M4
作者：AI 起草　状态：已确认（2026-10-31）

## 一、整体架构

```
NetSession（不改）                         NetReconnector（新，纯 C#）             RuntimeNetDriver（改）
  State: Disconnected ───────────────►  观察：状态 + 是否在房 + 是否主动断开
  StateChanged 事件 ─────────────────►  决策：等待？Connect？JoinRoom？放弃？
  Connect(host, port) ◄───────────────  动作：返回「下一步做什么」
  JoinRoom(roomId, dungeonId) ◄───────                    │
  CurrentRoom.RoomId（断线前记下）                         ▼
                                                    每帧调用并执行动作
```

**为什么不放在 `NetSession` 里**：`NetSession` 是「协议会话」，重连是**策略**（退避、上限、放弃条件）。
策略放外面，`NetSession` 保持「只负责一次连接的生死」，也便于 `_net-probe` 用假时钟直接测退避逻辑。

## 二、模块划分

| 模块 | 本次改动 | 不负责什么 |
| --- | --- | --- |
| `NetReconnector`（新，`Game\Net`） | 退避与决策：等待多久、要不要 `Connect`、要不要 `JoinRoom`、什么时候放弃 | 不发消息、不碰传输 |
| `RuntimeNetDriver`（改） | 每帧把会话状态喂给 `NetReconnector` 并执行它给的下一步；重连成功时重建运行器与表现层 | 不算退避、不管协议 |
| `NetSession` | **零改动**（账号/密码摘要在构造时就固定，再 `Connect` 一次即可） | — |
| `NetHudPanel`（改） | 显示「重连中（第 N 次）」/「已恢复」/「已放弃：原因」 | 不做决策 |

## 三、接口（★ 先定死）

```
NetReconnector（纯 C#，无 UnityEngine 依赖 —— 便于探针测试）
    enum EReconnectAction { None, Wait, Connect, JoinRoom, GiveUp }
    enum EReconnectPhase  { Idle, Waiting, Connecting, Joining, Recovered, GaveUp }

    构造(int maxAttempts = 5, int dungeonId = 1001)
    公开只读：Phase / Attempt / LastReason / SecondsUntilRetry

    void Reset()                                        // 主动断开时调用，回到 Idle 并清计数
    void NoteJoined(string roomId)                      // 每次成功进房记下房号（重连要用）
    void NoteIntentionalDisconnect()                    // 主动断开：从此不再重连，直到 Reset
    EReconnectAction Tick(bool isOnline, bool inRoom, float deltaSeconds, out string reason)

    退避表：第 1 次 0.5s，第 2 次 1s，第 3 次 2s，第 4 次 4s，第 5 次 4s（之后 GiveUp）
    lastRoomId 为空 ⇒ 走 Connect 后 JoinRoom(空房号, dungeonId)（让服务端重新安排）
    lastRoomId 非空但服务端回「房间不存在 / 已满」⇒ GiveUp 并带原因
```

```
RuntimeNetDriver（改）
    Update 里：
      EReconnectAction a = m_reconnector.Tick(m_session.State == ESessionState.Online, m_session.InRoom, Time.deltaTime, out string why);
      switch (a) {
        case Connect:  m_session.Connect(m_host, m_port); break;                 // 账号已在会话里
        case JoinRoom: m_session.JoinRoom(m_reconnector.LastRoomId, m_dungeonId); break;
        case GiveUp:   m_lastError = why; break;
      }
      进房成功（第一次或重连后）⇒ NoteJoined(roomId) + 重建运行器 + 重置表现层
```

## 四、数据结构

- `NetReconnector` 内部：`m_attempt`（0..5）、`m_wait`（剩余秒）、`m_phase`、`m_lastRoomId`、`m_intentional`。
- **不引入 UnityEngine 类型**（用 `float` 秒、`string` 房号），保证能在 `_net-probe` 里用假时钟跑。

## 五、时序与流程（断线 → 恢复）

1. 传输断开 → `NetSession.Fail` → `State = Disconnected`（`m_closingIntentionally` 为 false）。
2. 驱动下一帧把 `isOnline=false` 喂给 `NetReconnector` → `Phase = Waiting`，`m_attempt++`，`SecondsUntilRetry = 0.5`。
3. 等待到点 → 返回 `Connect` → 驱动调 `session.Connect(host, port)` → `Phase = Connecting`。
4. 连上 → `Handshaking` → `Online`；驱动看到 `Online && !InRoom` → 返回 `JoinRoom` → 调 `session.JoinRoom(lastRoomId, dungeonId)`。
5. 进房成功（`InRoom` 变 true）→ `NoteJoined` + 重建运行器 + 重置表现层游标 → `Phase = Recovered`。
6. 若第 4 步被拒（房间不存在/满）→ `GiveUp`，HUD 显示原因，停止重试。
7. 玩家主动 `Disconnect` → 驱动调 `NoteIntentionalDisconnect()` → 之后不再重连（直到 `Reset()`）。

## 六、技术选型与理由

| 选择 | 选定 | 理由 | 被否的方案 |
| --- | --- | --- | --- |
| 策略放哪 | **独立 `NetReconnector`（纯 C#）** | 可用假时钟在探针里测退避；`NetSession` 保持单一职责 | 塞进 `NetSession`（会话要同时管协议与策略） |
| 会话怎么重连 | **同一个 `NetSession` 再 `Connect`** | 账号与密码摘要在构造时固定，重建会话反而要重新存明文密码 | 新建 `NetSession`（要保管明文密码，风险更大） |
| 重连后回哪个房 | **断线前的 `CurrentRoom.RoomId`** | 玩家预期「回到我原来的队」；房没了就如实提示 | 让服务端重新安排（可能进到别的房） |
| 重试上限 | **5 次 + 退避到 4 秒** | 约 11.5 秒总窗口，覆盖常见抖动与短重启 | 无限重试（打满服务端、玩家无感） |

## 七、风险与对策

- **主动断开被误判成断线** ⇒ 驱动在主动 `Disconnect` 前先调 `NoteIntentionalDisconnect()`；`NetSession` 的 `m_closingIntentionally` 是会话层保险。
- **重连风暴** ⇒ 退避 + 上限；连接失败也计入次数。
- **表现层游标残留**（帧号倒退 / 假分歧）⇒ 重连成功时统一调「重置表现层 + 重建运行器」，这也是 R008 定下的「每局重建」原则。
- **同账号重进会不会出现两个自己** ⇒ 服务端按会话管座位、旧会话已断开；实测确认（06 里验）。
- **锁步局无法恢复** ⇒ 如实提示，不假装；`LockstepService.StartRoom` 的「只开一次」是硬限制。
- **重连期间玩家还能操作** ⇒ 重连中禁用输入发送（否则会往已断的传输里灌输入）。
