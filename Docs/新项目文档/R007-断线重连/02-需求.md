# 02 需求

需求：R007-断线重连
所属阶段：M4
作者：LYF（口述确认，AI 落稿）　状态：已确认（2026-10-31）

## 一、业务目标（一句话）

**网络断了自动连回去**（重连 + 重登 + 回原房），HUD 说清当前处于哪一步；**锁步局开过局就如实说「无法恢复」**，不假装恢复。

## 二、用户与使用场景

- 用户：开发期负责人；最终玩家。
- 场景：Play 中拔网线 / 停服 3 秒 / 服务端主动断开 → 客户端在 0.5~4 秒内自动重试 → 恢复后继续跑；若原房已没了或锁步局已开局，明确提示并停止重试。

## 三、功能列表（P0 / P1 / P2）

| 功能 | 优先级 | 说明 |
| --- | --- | --- |
| 断线检测与自动重连 | P0 | 被动断开才重连；主动断开不重连 |
| 退避重试 | P0 | 0.5s / 1s / 2s / 4s，最多 5 次，之后放弃并提示 |
| 重连后回原房 | P0 | 用断线前记下的房号 `JoinRoom(roomId, dungeonId)` |
| 重连后重置 | P0 | 重建锁步运行器、重置表现层游标（否则会跳到旧帧 / 假分歧） |
| 状态提示 | P1 | HUD / Console 显示「重连中（第 N 次）／已恢复／已放弃（原因）」 |
| 锁步局恢复本局 | P2 | **本期不做**（需协议加 `LockstepResume`，另开需求） |

## 四、边界（**本版明确不做**）

- 不改协议（`Protocol\NbcM3.cs` 是生成代码），不加 `LockstepResume`。
- 不动服务端受保护文件（`RoomRegistry` / `RoomService` / `RoomBattleService` / `ProgressBroadcaster` / `StateSync 相关`）。
- 不做「无缝续玩」：锁步局已开过局时，重连成功也只是「回到房间但本局不参与」。
- 不做手动重连按钮（自动重连已覆盖；按钮以后要再说）。
- 不保证跨进程/跨设备恢复（账号会话仍是内存态）。

## 五、优先级

**P0**。依赖：R008（运行时会话与自动开局）。

## 六、验收标准（「当…时，应…」）

- [ ] 当 服务端停掉（Play 中断开）时，Console 应在 0.5 秒内出现「重连中（第 1 次）」，最多重试 5 次
- [ ] 当 服务端在重试期间恢复时，应在下一次重试自动连回，并**回到原房间**（HUD 的房号与断线前一致）
- [ ] 当 重连成功时，表现层不应出现「帧号倒退」或「假分歧」告警（证明游标已重置）
- [ ] 当 玩家主动退出（停止 Play / 主动 Disconnect）时，**不应**触发任何重连重试
- [ ] 当 原房已不存在时，应停止重试并提示「房间已不存在」（不无限重连）
- [ ] 当 锁步局已开局时，应提示「本局已开始，无法恢复」（而不是静默无反应）
