## 3. 根因分析

| # | 根因 |
| --- | --- |
| 1 | 「参数快照」和「状态机内部字段」是两份数据。`BuildParams()` 读的是 `m_context.PoseIndex`，而 `NotifyPose()` 只改了状态机的 `m_poseIndex`，两份数据没有同步点，编译期完全看不出来。 |
| 2 | 美术把「收剑/出剑」做成了动画事件（第 0 帧 `SwitchSocket`），战斗动作收在右手（`To_Hand_R_Socket`）所以看不出来，姿势动作收在背后（`To_Put_Socket_Sword`）就露馅。 |
| 3 | 贴地射线用了 `m_groundMask = -1`，而玩家身上唯一的碰撞体是手里那把剑。剑被抬到射线下面时，射线把剑顶面当地面，角色被抬高；下一帧剑离开，又落回。 |
| 4 | 现象只被描述成「闪一下」，没区分「消失一帧」和「位移一下」。两种现象指向完全不同的根因（剔除 vs 改 y），我先按前一种改了。教训：**先问清现象，再动手**。 |
| 5 | `Object.Instantiate(clip)` + `AddObjectToAsset` 会把曲线数据整份序列化进 controller，七个表情直接把文件从 91 KB 撑到 22 MB。正确做法是运行期改（`AnimationClip.events` 不落盘）。 |
| 8 | 回移动层的两条过渡只判 `!ActionBusy && !Dead`，而格挡不占 `ActionBusy`，所以一进 `S_Block` 就被拉回。补 `ActionId < 7.5` 后解决。 |
