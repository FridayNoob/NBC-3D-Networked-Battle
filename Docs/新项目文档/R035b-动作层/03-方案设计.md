# 03 方案设计

需求：R035b-动作层（连击 / 技能 / 冲刺 / 格挡 / 姿势）
所属阶段：M4
作者：AI　状态：开发中（2026-11-13）

## 一、整体架构

```
输入（PlayerBrain）
  → PlayerStateMachine：决定进哪个动作（ActionId、帧数、连击排队）
  → PlayerStateContext：ActionBusy / ActionId / PoseIndex / StackSide
  → PlayerAnimatorPublisher：每帧幂等写 10 个参数
  → Animator：20 条 AnyState 过渡挑状态
位移：PlayerMove（实现 IPlayerMotion + IPlayerDash）
```

动作层只做「什么时候进、什么时候出」，不碰动画细节；动画细节全在控制器副本里。

## 二、模块划分

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| `PlayerStateMachine` | 连击窗口、动作帧数、格挡开关、姿势轮换 | 动画 clip、位移 |
| `PlayerTimings` | 每段动作帧数、连击窗口两个常量 | 播放速度（在控制器里） |
| `PlayerBrain` | 按键映射、每帧调 `SetBlocking` | 判定动作能不能进（交给状态机） |
| `PlayerMove` | 冲刺位移（`IPlayerDash`） | 冲刺时长与动画（状态机） |
| 控制器副本 | 13 条新过渡、`speed=1.4`、格挡 `offset=0.25` | 逻辑 |

## 三、接口

```csharp
// 状态机新增/扩展（R035b）
public bool NotifyAttack();          // 空闲→Attack1；窗口内→排队下一段；否则 false
public bool NotifySkill(int index);  // index 1..3，空闲且未格挡才生效
public bool NotifyDash();            // 进 Dash，帧数 DashFrames
public bool NotifyPose();            // PoseIndex 0→6 循环，进 Pose
public void SetBlocking(bool blocking); // 按住=ActionId 8，松开=清 0
public int PoseIndex { get; }        // 当前姿势序号 0..6

// 位移侧新增
public interface IPlayerDash
{
    void StartDash(float speedMetersPerSecond, float durationSeconds);
}
```

约定：`Notify*` 返回 true 表示「已进动作或已排队」；格挡不占 `ActionBusy`，但移动闸门额外判 `Blocking`。

## 四、数据结构

`PlayerTimings` 改为（单位：帧 @60fps）：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `AttackFrames` | 60 | 第 1 段（clip 84 帧 ÷ 1.4） |
| `Attack2Frames` | 60 | 第 2 段 |
| `Attack3Frames` | 93 | 第 3 段（130 ÷ 1.4） |
| `Skill1Frames` | 240 | 技能 1 |
| `Skill2Frames` | 144 | 技能 2 |
| `Skill3Frames` | 264 | 技能 3 |
| `DashFrames` | 60 | 冲刺 |
| `HitFrames` | 88 | 受击（R035a 原为 18，按 clip 修正） |
| `StunFrames` | 120 | 硬直 |
| `PoseFrames` | 90 | 姿势 |
| `ComboWindowStart` | 18 | 连击窗口开启帧 |
| `ComboEndBuffer` | 4 | 末尾缓冲帧 |

## 五、时序与流程（三段连击）

1. `Tick` 读输入，`ActionBusy=false` → `NotifyAttack()` → `BeginAction(Attack1, id=1, 60)`。
2. `ApplyPendingAction` 进 `Action` 上层，`ActionBusy=true`，移动闸门关闭。
3. 每帧 `AdvanceAction()`：`ActionFrame++`。
4. 第 18 帧起，再按左键 → `m_comboQueued = true`（不切状态，避免截断当前刀）。
5. 第 60 帧：`AdvanceAction` 发现排队且 `id<3` → `BeginAction(Attack2, id=2, 60)`，同帧被应用，动画直接进 `S_Attack_2`。
6. 第 3 段结束（或窗口外没按）→ `ResetAction()` → 回移动层（蹲着就回 `S_Crouch`）。

## 六、选型与理由

1. **排队而不是立即切段**：立即切会截断上一刀的后半段，看起来像掉帧；排队保证每段完整。
2. **格挡不占 `ActionBusy`**：格挡要能持续按住，用 `ActionBusy` 会被帧数计时自动结束；独立 `Blocking` 标志更简单。
3. **冲刺位移放 `PlayerMove`**：状态机不该知道米/秒；`IPlayerDash` 让 `PlayerMove` 自己按时间推进。
4. **控制器的 13 条过渡全部 AnyState + 参数条件**：不依赖状态内过渡，避免「从某个状态出发忘了接」。
5. **格挡用 `offset=0.25` + `speed=0` 定格**：不新增美术资源，也不改 clip。

## 八、风险与对策

| 风险 | 对策 |
| --- | --- |
| 技能 4 秒太长，玩家以为卡死 | 动作期间 Console 打日志；HUD 提示留 R046 |
| `S_Stun` clip 循环 | 用帧数退出，不加 `hasExitTime` |
| 格挡被「回移动层」拉出 | 两条回移动层过渡都加 `ActionId NotEqual 8` |
| 连击排队在受击后仍生效 | `NotifyHit`/`NotifyDead` 里清 `m_comboQueued` |
| 冲刺时 `MovementEnabled=false` 把位移吃掉 | `PlayerMove.Update` 先处理冲刺分支，再走闸门 |
