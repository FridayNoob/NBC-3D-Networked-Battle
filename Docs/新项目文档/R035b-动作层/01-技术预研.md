# 01 技术预研

需求：R035b-动作层（连击 / 技能 / 冲刺 / 格挡 / 姿势）
所属阶段：M4
作者：AI　状态：开发中（2026-11-13）

> 本步承接 R035a 的骨架：动作层已有 9 个状态位（`Attack1..3`、`Skill1..3`、`Dash`、`Block`、`Pose`），
> 状态机已有 `ActionBusy` + `ActionId` 两条通道。本步只补「动作怎么开始、怎么连、怎么结束」。

## 一、调研目标与约束

目标：让玩家在 World 里能打出「三段普攻连击、三个技能、一段冲刺、按住格挡、摆姿势」，全部由现有 bool/float 参数驱动，不新增 Trigger。

约束：

1. 动画参数只有 R035a 建的 10 个，动作靠 `ActionBusy` + `ActionId`（0=无、1-3 攻击、4-6 技能、7 冲刺、8 格挡、9 姿势、10 受击、11 硬直）。
2. 控制器只改副本 `Client/Assets/_Project/Animator/Player_Sword_Controller.controller`，美术包原件不动。
3. World 是单机表现（服务端没有技能系统）⇒ 技能只播动画、不产生伤害判定；伤害仍留给服务端技能需求。
4. 动作期间禁移动（R035a 已实现闸门），动作结束回移动层。
5. 不新增输入框架，键位沿用 `PlayerBrain` 的 Inspector 字段。

## 二、核心 API 清单

| API | 用途 | 关键点 |
| --- | --- | --- |
| `PlayerStateMachine.NotifyAttack()` | 起手/连击 | 内部按连击窗口决定 1/2/3 段 |
| `PlayerStateMachine.NotifySkill(int)` | 技能 1-3 | `ActionId = 3 + index` |
| `PlayerStateMachine.NotifyDash()` | 冲刺 | 位移由 `PlayerMove` 推一小段 |
| `PlayerStateMachine.NotifyPose()` | 姿势轮换 | `PoseIndex 0..6` |
| `PlayerStateMachine.SetBlocking(bool)` | 格挡按住/松开 | 只改 `ActionId=8`，不占 `ActionBusy` |
| `AnimatorState.speed` | 动作播放速度 | 用来把 84 帧的 clip 压到 60 帧 |
| `AnimatorStateTransition.hasExitTime` | 按归一化时间退出 | 动作播完自动回流，比手写帧数稳 |

## 三、最小可运行示例

```csharp
// 攻击键：忙时若还在连击窗口内，就排下一段；否则忽略
if (Input.GetMouseButtonDown(0))
{
    m_machine.NotifyAttack();   // 内部：空闲→Attack1；窗口内→Attack2/3；窗口外→忽略
}

// 格挡：按住/松开
m_machine.SetBlocking(Input.GetMouseButton(1));
```

控制器侧不需要新过渡：`ActionBusy && ActionId==2` → `S_Attack_2`、`==3` → `S_Attack_3`、`==4..6` → 三个技能、`==7` → `S_QuickShift_F`、`==9` → `CBG_*`。格挡 `ActionId==8` 常驻 `S_Block`。

## 四、方案对比

### 4.1 动作时长：clip 实测 vs 手写帧数

控制器实测（`Sword_Controller` 副本，2026-11-13 读回）：

| 状态 | clip | 原始长度 | 60fps 帧数 | 循环 |
| --- | --- | --- | --- | --- |
| `S_Attack_1` | `S_Attack1` | 1.4 s | 84 | 否 |
| `S_Attack_2` | `S_Attack2` | 1.4 s | 84 | 否 |
| `S_Attack_3` | `S_Attack3` | 2.167 s | 130 | 否 |
| `S_Sp_Skill_1` | `S_Sp_Skill1` | 4.0 s | 240 | 否 |
| `S_Sp_Skill_2` | `S_Sp_Skill2` | 2.4 s | 144 | 否 |
| `S_Sp_Skill_3` | `S_Sp_Skill3` | 4.4 s | 264 | 否 |
| `S_QuickShift_F` | `S_Quickshift_F` | 1.0 s | 60 | 否 |
| `S_Evade` | `S_Evade` | 1.467 s | 88 | 否 |
| `S_Hit_L` / `S_Hit_R` | 同名 | 1.467 s | 88 | 否 |
| `S_Stun` | `S_Stun` | 2.0 s | 120 | **是** |
| `S_Die` | `S_Die` | 2.167 s | 130 | 否 |

R035a 的 `PlayerTimings` 默认值（攻击 36 / 技能 48 / 冲刺 18 / 受击 18 / 硬直 45）是**按手感拍的**，和 clip 对不上：36 帧就退出会在挥到一半时被拉回移动层，出现「砍一刀人突然站好」。

三个选项：

| 选项 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A 原始时长 | 帧数改成 84/84/130、技能 240/144/264 | 动作完整、不截断 | 普攻 1.4 秒偏慢，连击手感发沉 |
| B 加速播放 | `state.speed=1.4`，帧数 60/60/93；技能 1.3x | 手感利落、连击快 | 动作略快，脚滑更明显；需要同时改资产与帧数 |
| C 折中 | 普攻 1.2x（70 帧）+ 技能 1x（完整播） | 普攻不拖、技能有分量 | 两套速度，记忆成本略高 |

**负责人已定（2026-11-13）**：选 **B**——三个攻击状态 `speed = 1.4`，帧数按 **60 / 60 / 93**；技能、冲刺、闪避保持原速（1x），帧数 240 / 144 / 264、60、88。

### 4.2 连击窗口

- 60 帧一段，窗口开在「进入 + 18 帧」（约 0.3 秒，起手结束），关在「进入 + 帧数 − 4」（末尾留 4 帧缓冲）。
- 窗口内再按 → 记下「排队」，当前段播完立刻切下一段（不回到移动层）；这样不会把当前刀截断。
- 窗口外按 → 忽略（不缓存），避免「乱按攒三段」。

### 4.3 格挡姿态

`S_Block` 现在复用 `S_Evade` 的 clip（1.467 秒、不循环）。按住右键会停在最后一帧（收招姿势），不像举盾。三个选项：

| 选项 | 做法 | 结果 |
| --- | --- | --- |
| A 借用闪避前半段 | `state.speed = 0`，进入时 `normalizedTime` 停在 0.25 | 定格成一个侧身姿态，能看，但不是举盾 |
| B 借 CBG 姿势 | 用 `CBG_Greeting` 之类当格挡姿态 | 姿势不对，语义错 |
| C 先不做姿态、只做逻辑 | 格挡期间保持当前移动动画，只把 `ActionId=8` 打开 | 最省事，但看不到「在格挡」 |

**负责人已定（2026-11-13）**：选 **A**——`S_Block` 的 `state.speed = 0`，进格挡的那条过渡 `offset = 0.25`，进门就定格在闪避动作 1/4 处（侧身），像一个临时防守姿态。

### 4.4 技能与冲刺

- 技能 1-3：只播动画（World 无结算），播完回移动；服务端技能系统另开需求。
- 冲刺：按 `V` 播 `S_QuickShift_F`，同时给 `PlayerMove` 一个 0.18 秒的初速度（8 米/秒），结束回移动（`Space` 留给 R035d 的跳跃）。
- 姿势：`F` 轮换 `PoseIndex 0..6`，对应 `CBG_*` 七个状态，90 帧后自动回移动；再按 F 换下一个。

## 五、已知坑与版本兼容

1. `S_Stun` 的 clip 是**循环**的，靠 `ActionBusy` 帧数退出；如果只加 `hasExitTime` 过渡会一直循环。
2. 技能 clip 4 秒，期间玩家会觉得「卡住」——需要在 HUD 上给个动作提示（R046 再做），本期只在 Console 打日志。
3. `S_QuickShift_F` 只有前向，没有左右后；本期只做前冲，其余方向留到后续。
4. `ActionId` 是 float，等值判断用 `Greater(id-0.5) + Less(id+0.5)` 窗口（R035a 已定），别用 `Equals`。
5. 格挡如果走 `ActionBusy`，会被「回移动层」过渡拉出；R035a 的 07 已记录：必须让回移动层的条件排除 `ActionId==8`。

## 六、结论

- 采用 **B 加速播放** 还是 **A 原始时长** 需要负责人拍板（见弹窗）；它与 02 的验收数字直接相关。
- 连击窗口、技能只播动画、姿势轮换三项按 4.2~4.4 的默认方案走。
- 格挡姿态三选项也需拍板，否则 `S_Block` 会停在收招帧。
- 代码量预估：状态机动作分支 +140、`PlayerBrain` 输入/计时 +120、`PlayerMove` 冲刺 +60、控制器过渡 4 条（资产不计行），合计约 **320 行**，在 500 行预算内。
