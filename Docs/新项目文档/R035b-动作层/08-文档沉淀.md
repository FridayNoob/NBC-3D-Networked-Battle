## 1. 文档范围

本需求沉淀四类内容：

1. **动作层的用法**：怎么让角色打三段、放技能、冲刺、格挡、摆姿势。

4. **维护入口**：改时长、改键位、加动作分别动哪里。

## 2. 模块文档

### 2.1 动作层状态（`PlayerStateMachine`）

- **简介**：在 R035a 的分层骨架上加了动作层：三段普攻（带连击排队）、三技能、前冲、格挡、七姿势。动作期间角色不能移动，动作播完按当前输入回移动层。
- **接口**：
  - `bool NotifyAttack()`：空闲时起手 Attack1；动作层且 `ActionId` 是 1/2 且在连击窗口内时只排队；其它情况返回 false。
  - `bool NotifySkill(int index)`：`index` 取 1~3，越界返回 false。
  - `bool NotifyDash()` / `bool NotifyPose()`。
  - `void SetBlocking(bool blocking)`：右键按住为 true。不占 `ActionBusy`，但会禁移动。
  - 只读：`PoseIndex`（下一次要播的表情序号 0~6）、`Blocking`。
- **示例**：`PlayerBrain` 里按 J / 左键调 `NotifyAttack()`；状态机返回 true 且是冲刺时，再调 `(m_motion as IPlayerDash).StartDash(8f, 0.18f)`。
- **原理**：动作通过 `BeginAction(state, actionId, frames)` 排队，`Tick` 里先推进计时再消费排队；到点优先接下一段连击，否则清空回移动层。连击窗口是「进入 +18 帧」到「结束前 4 帧」，窗口内只置一个 `m_comboQueued` 布尔，不做输入缓冲队列。
- **坑**：`PoseIndex` 必须同时写进 `PlayerStateContext`，否则发布出去永远是 0（见 3.1）。
- **维护**：改时长改 `PlayerTimings`（12 个字段）；加动作要同时加 `EPlayerState`、`PlayerActionId`、控制器过渡、`PlayerInput` 键位。

### 2.2 控制器副本的过渡（`Player_Sword_Controller`）

- **简介**：美术包控制器只读，我们在 `Client/Assets/_Project/Animator/Player_Sword_Controller.controller` 有一份副本，World 的剑士实例指向它。
- **接口**（参数）：`Speed`、`Direction` 沿用；新增 `Crouch`、`Grounded`、`VerticalSpeed`、`ActionBusy`、`ActionId`、`StackSide`、`PoseIndex`、`Dead`。
- **结构**：41 个状态、61 条过渡（41 条旧过渡全部 Mute，20 条 Active）。7 条是移动/移动层切换，13 条是动作（三段、三技能、冲刺、格挡、七姿势中的 8 条 AnyState），其余是受击/死亡。
- **原理**：AnyState 过渡按顺序投票，先命中先走。所以顺序是「死亡 → 受击 → 攻击 → 格挡 → 移动」，保证死亡永远优先。
- **坑**：格挡不占 `ActionBusy`，回移动层的两条过渡必须带 `ActionId < 7.5`，否则一进 `S_Block` 就被拉回（见 3.2）。
- **维护**：`S_Attack_1..3` 的 `speed=1.4`（60/60/93 帧的来源）；`S_Block.speed=0`、进入过渡 `offset=0.25`。

### 2.3 贴地（`WorldPlayerSetup`）

- **简介**：World 里没有 CharacterController，角色靠「向下打射线、把 y 设成命中点」贴地。
- **接口**：`m_probeHeight`（起点高度 5 米）、`m_probeDistance`（50 米）、`m_groundMask`、`m_logGroundSnap`（诊断开关）。
- **原理**：`RaycastNonAlloc` 收集全部命中，跳过玩家自己和子物体，取最近的外部命中点。
- **坑**：玩家身上唯一碰撞体是手里的剑；不跳过自己，剑一抬手就被当成地面（见 3.3）。
- **维护**：`m_logGroundSnap` 默认开，y 变化超过 1 厘米打一行 `[贴地] ...`，验收完可以关。

### 2.4 蒙皮网格守卫（`PlayerSkinnedMeshGuard`）

- **简介**：把玩家身上 15 个 `SkinnedMeshRenderer` 的 `updateWhenOffscreen` 打开，避免大动作时剑/衣摆跑出烘焙包围盒被整块剔除。
- **接口**：`Apply()`；`PlayerBrain.Awake` 自动挂。
- **原理**：Unity 默认用绑定姿势烘焙的包围盒做视锥剔除，姿势超出盒子就整块不画。
- **坑**：这不是本轮「角色跳一下」的根因（改完仍跳），别把它当成万能药。
- **维护**：新增挂件（披风、尾巴）时确认它也在 `GetComponentsInChildren` 覆盖范围内。

## 3. 踩坑清单

### 3.1 参数快照与内部字段是两份数据

状态机里 `m_poseIndex` 是「下一次播第几个」，`PlayerStateContext.PoseIndex` 是「这一帧发给 Animator 的值」。只改前者，动画永远停在第一个。判据：**任何要影响表现的状态变化，都要在同一帧写进 context**；单测断言 `Parameters`，不要断言内部字段。

### 3.2 动画事件会改武器挂点，且不区分「战斗」和「姿势」

`CBG_*` 第 0 帧的 `SwitchSocket` 把剑收到背后，退出时战斗动作又切回右手。修法是运行期清掉 `CBG_*` 的事件：`AnimationClip.events` 的修改只在本次 Play 有效，不改美术资产、不落盘。

### 3.3 贴地射线要排除自己

`m_groundMask = -1` + 玩家身上有武器碰撞体 = 武器一抬手就被当地面。判据：**任何「以世界为参照」的射线/重叠查询，都要先问「会不会打到自己」**。

### 3.4 不要为了改一个事件去复制 AnimationClip

`Object.Instantiate(clip)` 会把曲线整份序列化进 controller（七个表情 → 22 MB）。运行期能改的（events、参数、速度）就在运行期改；必须落盘的才动资产。

### 3.5 先问清现象，再决定查什么

「闪一下」可能是「网格消失一帧」（剔除）、「角色位移一下」（改 y）、「武器换挂点」（事件）。三种根因三条链路。这一轮先按剔除改，白改一轮。判据：**现象描述里必须包含「谁在动、动了几帧、动完回不回来」**。

### 3.6 动作过渡要写「什么时候不能出去」

只写「什么时候能进」不够。`S_Block` 的进入条件满足后，如果回移动层的过渡没有排除它，就会一帧进一帧出。判据：**每条常驻状态都要有一条显式的「退出条件」**。
