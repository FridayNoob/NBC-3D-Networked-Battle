# R057 技能无敌帧 —— 01 技术预研

> 需求编号：R057　所属阶段：M4　作者：AI（DeepSeek Harness）　状态：开发中

## 一、调研目标与约束

玩家按 Q/E/R 放技能时，希望「技能期间打不动」：既不掉血、也不被打断。要弄清三件事：

1. 现在的伤害是从哪一条路进来的，能不能只改**一个**地方就让所有伤害都被拦下。
2. 无敌的**时长**该由谁说了算（客户端动画 / 服务端表 / 硬编码）。
3. 拦下之后客户端要不要做什么（飘字、受击动画、状态机）。

约束：

- 服务端权威：伤害只能由 `DungeonBattle.ApplyDamage` 结算，客户端不做免伤判断。
- 一份真值：时长进 `Configs/Design/Skill.csv`，两端读同一张表（AGENTS.md §0.4）。
- 只做玩家英雄：负责人 2026-11-20 定，怪物放技能照旧会掉血。
- 不改协议：免伤不产生新事件（负责人选的「什么都不显示」）。
- 预算：≤ 500 行 `.cs`。

    if (IsInvulnerable(targetId))
    {
        return DamageResult.Blocked();   // 不掉血、不记事件、不记账
    }

## 四、方案对比

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A 服务端窗口（采用） | 施法成功时记「无敌到第 N 帧」，`ApplyDamage` 早退 | 只改一处；客户端零改动；天然不飘字 | 时长必须由表给，动画改了要跟着改表 |
| B 客户端免伤 | 客户端收到伤害先丢 | 快 | 服务端血照掉，两端对不上，等于没做 |
| C 加「护盾值」 | 给英雄加护盾，伤害先扣盾 | 以后能扩成真护盾 | 本次只要「不受伤害」，多一层状态没必要 |

## 五、已知坑与版本兼容

1. **时长来源**：动画 4.0/2.4/4.4 秒、控制器 1.5 倍速 ⇒ 实际 2.67/1.6/2.93 秒；客户端动作帧 160/96/176（60fps）。表里存毫秒 `invulnMs`，服务端换算 `ceil(ms / 33)` 帧，避免两边各写一份帧数。
2. **窗口起点**：施法**被服务端接受**的那一刻开始算，不是客户端按下时——否则网络延迟会让「已经掉血了才进无敌」。
3. **重复施法**：冷却内放不出来，所以不会叠加；万一以后加长按连放，取「结束帧更大者」，不要相加。
4. **0 = 不无敌**：表里填 0 时整套逻辑等于不存在，方便以后给某些技能关掉。
5. **计分口径**：被免掉的伤害**不能**记进「承受伤害」，否则战绩里的承伤会虚高。
6. **怪物豁免**：只有 `Kind == 0 && PlayerId != 0` 的英雄才记录，狼王放技能照旧会掉血。

## 六、结论

采用方案 A：`Skill.csv` 加 `invulnMs` 一列 → `SkillSystem` 施法成功时记窗口 → `DungeonBattle.ApplyDamage` 早退并返回 `Blocked`。客户端一行不改，靠「没有伤害事件」自然实现不掉血、不飘字、不打断。预计：服务端 +80 行、表 +1 列、探针 +4 条、客户端 0 行，**在 500 行预算内**。
