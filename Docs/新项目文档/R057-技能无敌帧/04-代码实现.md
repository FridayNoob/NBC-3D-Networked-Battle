## 2. 功能概述

玩家英雄按下 Q/E/R 释放技能后，从服务端**接受施法的那一刻**起进入无敌窗口，
窗口长度等于这个技能的无敌时长（默认就是整个技能动画的时长）。
窗口内任何来源的伤害（普攻、技能、掉落伤害）都不结算：不掉血、不弹飘字、
不加承伤、也不会被打死。窗口结束后立刻恢复正常。

## 3. 接口与入参出参

```csharp
// 表行（ServerTables.cs）
public readonly struct SkillRow
{
    public readonly int Id;
    public readonly string Name;
    public readonly int Damage;
    public readonly int CooldownTicks;
    public readonly int RangeMm;
    public readonly int HitFrame;
    public readonly int InvulnTicks;   // 新增：无敌时长（逻辑帧，0 = 不无敌）
}

// 规则（SkillSystem.cs）
public bool IsInvulnerable(int entityId, int tick);
private void GrantInvulnerability(DungeonBattle battle, BattleEntity caster, SkillRow skill);

// 世界门面（DungeonBattle.cs）
public bool IsInvulnerable(int entityId);
public static DamageResult Blocked();   // Ok = false，调用方自然当成"没打中"
```

约定：
- `invulnMs` 是**毫秒**，`InvulnTicks` 是**逻辑帧**（30Hz，一帧 33ms），换算向上取整。
- `invulnMs = 0` 或表里没有这一列 ⇒ 这个技能不无敌（老表不用改也能跑）。
- 只有 `Kind == 0`（英雄）且 `PlayerId != 0`（有主）才会获得窗口；怪物放技能不无敌。

## 4. 逐段讲解

### 4.1 表：加一列，跟着动画走

```csv
id,name,damage,damageType,hitFrames,cooldownMs,rangeMm,invulnMs
2001,旋风斩,500,Physical,40,6000,2500,2667
2002,上挑斩,80,Physical,22,8000,2500,1600
2003,突进斩,120,Physical,48,12000,3000,2933
```

2667 / 1600 / 2933 毫秒正好是 1.5 倍速之后的三段技能动画时长
（4.0 / 2.4 / 4.4 秒 ÷ 1.5）。动画改速度时这一列要跟着改，
否则会出现"人已经能动、却还在免伤"或"动画没放完就被打死"。

### 4.2 解析：毫秒换成帧，和冷却同一套算法

```csharp
int cooldownMs = sheet.IntOr(r, "cooldownMs", 0);
int tickMs = 1000 / NetContract.TickRate;
int cooldownTicks = cooldownMs <= 0 ? 0 : ((cooldownMs + tickMs - 1) / tickMs);

// 无敌时长同一套换算：2667ms ⇒ 81 帧。填 0（或没这一列）= 这个技能不无敌
int invulnMs = sheet.IntOr(r, "invulnMs", 0);
int invulnTicks = invulnMs <= 0 ? 0 : ((invulnMs + tickMs - 1) / tickMs);
```

### 4.3 记账：施法成功才给窗口，取更晚的那个

```csharp
public bool IsInvulnerable(int entityId, int tick)
{
    if (!m_invulnUntil.TryGetValue(entityId, out int untilTick))
    {
        return false;
    }

    return tick <= untilTick;
}

private void GrantInvulnerability(DungeonBattle battle, BattleEntity caster, SkillRow skill)
{
    if (skill.InvulnTicks <= 0)
    {
        return;
    }

    if (caster.Kind != 0 || caster.PlayerId == 0)
    {
        return;
    }

    int untilTick = (int)battle.Tick + skill.InvulnTicks;

    if (m_invulnUntil.TryGetValue(caster.Id, out int existing) && existing > untilTick)
    {
        return;
    }

    m_invulnUntil[caster.Id] = untilTick;
}
```

### 4.4 闸门：在 `ApplyDamage` 最前面早退

```csharp
public DamageResult ApplyDamage(int targetId, int damage, int attackerId = 0)
{
    BattleEntity? target = Find(targetId);

    if (target == null)
    {
        return DamageResult.Missing();
    }

    if (IsInvulnerable(targetId))
    {
        return DamageResult.Blocked();
    }

    bool wasAlive = target.Alive;
    // ……以下原样不变：扣血、记伤害事件、记账、判死、掷掉落
}
```

为什么不放在调用点：普攻、技能、掉落伤害三条路都会走到 `ApplyDamage`，
放在这里只写一次；放在调用点就要写三份，漏一处就能被打死。

## 6. 风险与幻觉自查

| 风险 | 自查结论 |
| --- | --- |
| 以为"免伤 = 扣 0 血" | 不是。`Blocked` 直接返回，连伤害事件都不记，所以飘字也不会弹 |
| 以为要客户端也判一次 | 不用。客户端 `NotifyHit` 在技能动作期间本来就拒绝受击；服务端才是权威 |
| 担心旧表读不了 | `IntOr(r, "invulnMs", 0)` ⇒ 没有这一列就是 0，等于不无敌 |
| 担心连放叠加 | `GrantInvulnerability` 取 max，不累加 |
| 担心怪物也变无敌 | 判了 `caster.Kind != 0 || caster.PlayerId == 0` 直接返回，探针有对应用例 |
| 担心技能自己打不到人 | 免伤只拦"受到的伤害"，`Tick` 里的 `ApplyDamage` 打的是目标，不受影响 |
