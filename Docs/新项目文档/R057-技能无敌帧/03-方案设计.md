# R057 技能无敌帧 —— 03 方案设计

> 需求编号：R057　所属阶段：M4　作者：AI（DeepSeek Harness）　状态：开发中

## 一、整体架构

```
Skill.csv(invulnMs) ──► ServerTables.SkillRow.InvulnTicks
                              │
玩家按 Q/E/R ──► 协议 skill_cast ──► SkillSystem.TryCast ──► 记「无敌到第 N 帧」
                                                          │
狼的普攻 ─────────────────────► DungeonBattle.ApplyDamage ─┤
狼的技能 ─────────────────────►（同上，唯一闸门）          │
                                                          ▼
                                          在窗口内 ⇒ DamageResult.Blocked（不掉血/不记事件/不记账）
```

免伤**只有一个入口**：`ApplyDamage`。普攻、技能、以后的任何伤害来源都从这里过。

## 二、模块划分

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| `Configs/Design/Skill.csv` | 每个技能的无敌时长（毫秒） | 谁享有无敌（那是规则） |
| `ServerTables.SkillRow` | 把毫秒换算成逻辑帧 | 什么时候生效 |
| `SkillSystem` | 记录/查询每个施法者的无敌窗口 | 结算伤害（仍交给 `DungeonBattle`） |
| `DungeonBattle.ApplyDamage` | 窗口内直接返回 `Blocked` | 判断该不该给窗口 |
| 客户端 | 什么都不做 | — |

## 三、接口（与最终代码逐字一致）

```csharp
// Server/NBC.Server.Game/ServerTables.cs
public readonly struct SkillRow
{
    public readonly int Id;
    public readonly string Name;
    public readonly int Damage;
    public readonly int CooldownTicks;
    public readonly int RangeMm;
    public readonly int HitFrame;
    public readonly int InvulnTicks;   // 新增：无敌时长（逻辑帧，0 = 不无敌）
    public SkillRow(int id, string name, int damage, int cooldownTicks, int rangeMm, int hitFrame, int invulnTicks);
}

// Server/NBC.Server.Game/SkillSystem.cs
public bool IsInvulnerable(int entityId, int tick);            // 只读查询
private void GrantInvulnerability(DungeonBattle battle, BattleEntity caster, SkillRow skill);

// Server/NBC.Server.Game/DungeonBattle.cs
public DamageResult ApplyDamage(int targetId, int damage, int attackerId = 0);  // 内部加早退
public bool IsInvulnerable(int entityId) => m_skills != null && m_skills.IsInvulnerable(entityId, Tick);

// DamageResult
public static DamageResult Blocked() => new(null, default, 0, false);
```

约定：

- `InvulnTicks = 0` ⇒ 永不无敌。
- 窗口区间是 **闭区间** `[施法帧, 施法帧 + InvulnTicks]`。
- 只有 `Kind == 0 && PlayerId != 0`（玩家英雄）会获得窗口；怪物放技能不获得。
- 重复施法取 `Math.Max(旧结束帧, 新结束帧)`，不做累加。

## 四、数据结构

| 字段 | 类型 | 单位 | 说明 |
| --- | --- | --- | --- |
| `invulnMs` | int | 毫秒 | CSV 列；0~10000 |
| `InvulnTicks` | int | 逻辑帧（33ms） | `ceil(ms / 33)`；0 表示不无敌 |
| `m_invulnUntil` | `Dictionary<int,int>` | 逻辑帧 | 施法者实体编号 → 无敌结束帧 |

`Skill.csv` 三行取值（与 1.5 倍速后的动作时长一致）：2001 = 2667、2002 = 1600、2003 = 2933。

## 五、时序与流程

1. 客户端按 Q → 状态机接受 → 发 `skill_cast`。
2. 服务端 `RoomBattleService.HandleSkillCast` → `DungeonBattle.TryCastSkill` → `SkillSystem.TryCast`：通过后写冷却、入队命中、**写无敌窗口**。
3. 同一帧或后续帧，狼的普攻/技能 → `ApplyDamage` → 命中窗口 ⇒ `Blocked`，血量不变、`_pendingHits` 不增加。
4. `m_skills.Tick` 每帧推进冷却与命中；窗口用帧号比较，过期自然失效（不需要清理回调）。

## 六、选型与理由

| 选择 | 理由 | 替代方案为什么不行 |
| --- | --- | --- |
| 拦截放在 `ApplyDamage` | 所有伤害都从这里过，一处覆盖全部来源 | 在每个攻击入口各判一次，漏一个就出「技能期间仍掉血」 |
| 时长进 CSV | AGENTS.md §0.4：表现/手感数据在客户端调、写回 CSV、两端同源 | 服务端硬编码 1.5 秒，和动画对不上，改动画要改代码 |
| 表里存毫秒而不是帧 | 人看动画是秒；帧数由服务端换算，避免两处各写帧数漂移 | 存帧（80/48/88）改动动画后要手算 |
| 不加协议事件 | 负责人选「什么都不显示」 | 加事件要动 proto、重生成、两端同步，收益为零 |
| 只给玩家 | 负责人明确 | 怪物也无敌会让「狼王放技能时打不动」显得像 bug |

## 八、风险与对策

| 风险 | 对策 |
| --- | --- |
| 窗口起点算错（晚一帧）⇒ 起手被打 | 在 `TryCast` 通过的同一帧写入，探针断言「施法当帧打不动」 |
| 免伤仍记「承受伤害」 | 早退在记账之前；探针断言 `DamageTaken` 不变 |
| 表里忘填 `invulnMs` | `IntOr` 回落 0 = 不无敌，不会崩；06 里验一次「填 0 就没免伤」 |
| 以后怪物也要无敌 | 只有 `GrantInvulnerability` 一个判断点，改一行即可 |
| 和冷却逻辑打架 | 冷却在窗口之前判；放不出来就没有窗口（验收第 7 条） |
