# 01 技术预研：配置表通用桥（10 张表）

## 一、调研目标与约束
- 目标：把 R050 只服务 Dungeon 的「SO ↔ CSV」桥抽成**一张表都不用改代码**的通用桥，10 张表共用。
- 约束 1：CSV 前 4 行（字段名/中文名/类型/规则）就是 schema，**类型行已写明 `int/string/float/int[]/enum:Type/ref:Type[]`**，不再另写一套元数据。
- 约束 2：服务端只读 CSV，所以「导出即跑 ConfigKit」的链路不能变。
- 约束 3：不引入反射缓存之外的新依赖；Unity 2022.3 的 `System.Reflection` 够用。
- 约束 4：每张小表（< 50 行）导出要 < 2 秒（含 ConfigKit 进程）。
- 约束 5：不动生成物 `Config_*.cs` 的字段定义。

## 二、核心 API 清单
| API | 用途 |
| --- | --- |
| `FieldInfo[] type.GetFields(BindingFlags.Public \| Instance)` | 拿 SO 行的字段顺序与类型 |
| `Convert.ChangeType(value, field.FieldType, CultureInfo.InvariantCulture)` | int/float 解析（避免本地化小数点） |
| `Enum.Parse(type, text, true)` / `Enum.GetName` | `enum:` 列 |
| `string.Split(',')` + `int.TryParse` | `int[]` 列 |
| `AssetDatabase.LoadAssetAtPath<T>` | 按路径加载 SO |
| `ScriptableObject.rows`（`List<Config_X>`） | 反射拿 `rows` 字段再按行读 |

## 三、最小可运行示例
```csharp
// 1) 读表头：第 3 行是类型行
string[] types = SplitLine(lines[2]);          // int,string,int,int[],enum:EDamageType
// 2) 反射拿 SO 行类型
Type rowType = asset.GetType().GetField("rows").FieldType.GetGenericArguments()[0];
FieldInfo field = rowType.GetField(types.Length > 0 ? names[i] : "");
// 3) 解析：int[] 先切再转；enum 用 Enum.Parse；其余 Convert.ChangeType
field.SetValue(row, Convert.ChangeType(cell, field.FieldType, CultureInfo.InvariantCulture));
```
关键点：**字段名来自 CSV 第 1 行**，不靠顺序，所以列顺序调整不会错位。

## 四、方案对比
| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A 每表一个桥 | 复制 R050 的 `DungeonCsvBridge` 9 次 | 简单直白 | 9 份重复代码，改一处要改十处 |
| **B 通用桥 + 注册表（采用）** | 一份桥 + `ConfigTableRegistry` 登记「表名/CSV 路径/SO 路径/行类型」 | 新增表 = 登记一行 | 反射读字段，调试时看不到强类型 |
| C 代码生成器 | 用 T4/脚本按 CSV 生成强类型桥 | 零反射 | 生成器本身要维护，且会与 ConfigKit 职责重叠 |

## 五、已知坑与版本兼容
1. **float 本地化**：`float.Parse` 在中文本地化下会把 `8.5` 解析成 85（小数点被当千位分隔）。必须 `CultureInfo.InvariantCulture`。
2. **enum 两种写法**：CSV 里是名字（`KillMonster`），也可能有人填数字；解析要两者都支持。
3. **`ref:Type?` 与 `ref:Type[]`**：前者是 int 且 0 表示空，后者是 int[]；不能按 `ref:` 前缀统一处理，要看 `[]`。
4. **string 含逗号/引号**：写回必须加引号并把 `"` 变 `""`（R050 已实现，直接复用）。
5. **SO 里 `rows` 是 `List<T>`**：反射要 `IList` 接口操作，不能直接 `List<object>`。
6. **枚举程序集**：`NBC.Shared.Condition.EConditionEvent` 在 `NBC.Shared`，Editor 程序集已引用，无需新增依赖。

## 六、结论
- 采用 **方案 B**：`ConfigTableRegistry`（10 行登记）+ `ConfigTableBridge`（读/写/校验）。
- 拆分：**R051 = 通用桥 + 注册表 + 测试**（预估 470 行）；**R052 = 通用窗口 + 菜单整理 + 删旧类**（预估 430 行）。
- 迁移分两批：第一批 Skill/Reward/DropTable（只有 int/int[]/enum），第二批 Monster/Level/Hero/Quest/QuestCondition/Achievement（含 float、ref、string）。
