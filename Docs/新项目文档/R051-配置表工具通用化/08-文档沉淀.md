## 一、文档范围

沉淀「注册表 + 通用桥」这两个可复用模块，供以后加新表、排查「SO 与 CSV 不一致」时查阅。

## 二、模块文档

### 2.1 `ConfigTableRegistry`

- 简介：10 张配置表的「名字 → CSV 路径 / SO 路径 / 行类型」登记处。
- 接口：`All`（10 条 `ConfigTableEntry`）、`Find(string name)`（大小写不敏感，找不到返回 null）。
- 示例：`var entry = ConfigTableRegistry.Find("Monster");`
- 原理：纯静态数据，没有 IO；新表 = 加一条 `Entry(...)`，不改其他代码。
- 坑：`RowType` 必须与 `Config_<表>` 类名一致，写错时桥会在 `GetRows` 处报「行列类型对不上」。
- 维护：新增 CSV 时同时加 SO（`Client/Assets/_Project/Configs/`），否则 `Find` 能返回、`LoadAssetAtPath` 为 null。

### 2.2 `ConfigTableBridge`

- 简介：任意一张已登记表在「SO ↔ CSV 文本」之间互转，含编码识别、校验、写盘与 ConfigKit 重生成。
- 接口：`ReadColumns` / `BuildCsvText` / `FormatCell` / `IsDirty` / `DescribeFirstDifference` / `Validate` / `Export` / `Import` / `TryParseCell` / `RunConfigKit` / `GetRows` / `CreateRow` / `GetCellText` / `TrySetCell` / `SplitLine`。
- 示例：`Export(entry, asset, out msg)`；`IsDirty(entry, asset, out detail)`。
- 原理：**表头 4 行就是 schema**（字段名 / 中文名 / 类型 / 规则），导出只重写数据行；写盘顺序是「读原文件 → 备份 → 临时文件 → 替换 → 跑 ConfigKit → 失败回滚」。
- 坑：
  1. `IsDirty` 必须两侧都 `Normalize`（去尾部换行），否则导出后永远显示「不一致」。
  2. Excel 会把 `6001,6001` 写成 `600,160,016,001`，解析时要能按 4 位一组还原。
  3. CSV 可能是 UTF-8（带/不带 BOM）、GBK 或 UTF-16，读的时候必须看 BOM 再严格解。
  4. 文件可能正被 Excel 独占，读要用 `FileShare.ReadWrite` 并重试。
- 维护：改 `FormatCell` 前先跑 10 表往返比较（`tests` 与 MCP 脚本各一次），一张表不一致就说明规则改错了。

## 三、踩坑清单

1. **单元素数组别加引号**：Excel 对 `"2003"` 与 `2003` 的处理不同，ConfigKit 也按裸值读。
2. **float 要保底一位小数**：`9` 与 `9.0` 对 Excel 是两种显示，往返比较会永远不等。
3. **可空引用 0 写空**：`ref:Skill?` 的 0 表示「没有」，写成 `0` 会被当成不存在的技能编号。
4. **全角逗号也要加引号**：中文名里出现 `，` 时 Excel 会把它当分隔符。
5. **BOM 保持原样**：无 BOM 的老文件加 BOM 会造成整文件 diff，掩盖真正的改动。
6. **加列后要重导 SO**：ConfigKit 只生成 C#/tsv/json，「导入 TSV → SO」是另一条链路。
