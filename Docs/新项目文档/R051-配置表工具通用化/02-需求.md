# 02 需求：配置表通用桥

## 一、业务目标（一句话）
让策划/负责人只学一套「改 SO → 导出 CSV → 重生成」的动作，10 张配置表都能用。

## 二、用户与场景
- 负责人：在 Unity 里改数值（例如狼的 `hp`、副本的 `spawnRadiusMm`），点导出，重启服务端生效。
- AI：新增一张表时只登记一行，不再复制 400 行桥代码。

## 三、功能列表
| 优先级 | 功能 |
| --- | --- |
| P0 | 按表名解析 CSV 路径、SO 路径与行类型（`ConfigTableRegistry`） |
| P0 | 通用读：读表头 → 列名/中文名/类型/规则 |
| P0 | 通用导出：SO 行 → CSV 数据行（引号、`int[]`、enum 名称、float 不变文化） |
| P0 | 通用导入：CSV 数据行 → SO 行（类型转换失败要报「第 N 行 列名 值」） |
| P0 | 校验：主键唯一且 > 0、字符串长度、`range()` 规则、引用列必须存在 |
| P1 | 导出后自动跑 ConfigKit；失败回滚 |
| P1 | 全部 10 张表都能导出/导入往返（用真实 CSV 验） |
| P2 | `IsDirty` 比较（SO 重拼 vs 磁盘），供窗口红字用 |

## 四、边界（不做什么）
1. 不做「新建表」向导（新增表仍要手写 CSV 与生成器配置）。
2. 不做多人协同/版本控制冲突解决。
3. 不校验业务语义（例如「Boss 必须比小怪强」）。
4. 不改服务端读表方式（仍读 CSV）。
5. 本需求**不含窗口 UI**（窗口在 R052）。

## 五、优先级
R051（桥）是 R052（窗口）的前置；桥不通过不写窗口。

## 六、验收标准（当…时，应…）
1. 当调用 `ConfigTableRegistry.All` 时，应返回 10 张表且每张都有 CSV 路径、SO 路径、行类型。
2. 当读取 `Monster.csv` 时，应得到 10 列，中文名依次为「编号/名称/生命值/攻击力/技能列表/仇恨范围…」。
3. 当导出 Monster 时，`skillIds` 为 `"2001,2003"`（带引号），`hp` 为整数，float 列为 `8.5` 而不是 `85`。
4. 当导入 `QuestCondition.csv` 时，`eventType` 应解析成 `EConditionEvent.KillMonster`。
5. 当导入 `Level.csv` 时，空的 `bossSkillId` 应为 0 而不是抛异常。
6. 当某行 id 重复时，校验应报「第 N 行（id=X）：主键重复」并拒绝写入。
7. 当某列填了非数字时，应报「第 N 行 列 hp：值 abc 不是 int」。
8. 当引用列写了 Monster 表里没有的编号时，应报「怪物 9999 不在 Monster 表里」。
9. 当 10 张表各跑一次「导出 → 导入」时，CSV 与 SO 都应逐字不变（幂等）。
10. 当导出成功时，应自动调用 ConfigKit 且退出码为 0；失败时应回滚 CSV。
