# 03 方案设计：配置表通用桥

## 一、整体架构
```
ConfigTableRegistry（10 行登记：表名 / CSV / SO / 行类型）
        │
ConfigTableBridge（读表头 / 写数据行 / 校验 / 导入 / 导出 / 跑 ConfigKit）
        │
Configs/Design/*.csv  ←→  Client/Assets/_Project/Configs/*Config.asset
        │
NBC.ConfigKit.Cli → Generated（两端共用）
```
窗口（R052）只调桥，不碰文件。

## 二、模块划分
| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| `ConfigTableRegistry` | 表清单、按名查找、路径解析 | 读写 |
| `ConfigTableBridge` | 表头解析、行↔单元格、校验、导出/导入、跑 ConfigKit | UI、Undo |
| `ConfigCsvFormat`（静态工具） | 单元格转义、`int[]`/enum/float 的格式化与解析 | 文件 IO |

## 三、接口（与 04 代码逐字一致）
```csharp
public sealed class ConfigTableEntry
{
    public string Name;        // 表名，如 "Monster"
    public string CsvPath;     // 仓库相对路径，如 "Configs/Design/Monster.csv"
    public string AssetPath;   // Unity 路径，如 "Assets/_Project/Configs/MonsterConfig.asset"
    public Type RowType;       // typeof(Config_Monster)
}

public static class ConfigTableRegistry
{
    public static IReadOnlyList<ConfigTableEntry> All { get; }
    public static ConfigTableEntry Find(string name);
}

public static class ConfigTableBridge
{
    public static string ResolveRepoRoot();
    public static string ReadCsvText(string path, out string encodingNote);
    public static List<ConfigColumn> ReadColumns(ConfigTableEntry entry, out string error);
    public static string BuildCsvText(ConfigTableEntry entry, IList rows, string headerBlock);
    public static bool IsDirty(ConfigTableEntry entry, ScriptableObject asset, out string detail);
    public static bool Validate(ConfigTableEntry entry, IList rows, List<string> errors);
    public static bool Export(ConfigTableEntry entry, ScriptableObject asset, out string message);
    public static bool Import(ConfigTableEntry entry, ScriptableObject asset, out string message);
    public static bool RunConfigKit(out string message);
}

public struct ConfigColumn
{
    public string Name;   // 字段名
    public string Label;  // 中文名
    public string Type;   // int/string/float/int[]/enum:.../ref:...
    public string Rule;   // key/len(1,16)/range(2,4)/min(0)
}
```

## 四、数据结构
- 行对象：直接用生成的 `Config_X`（字段名 == CSV 第 1 行）。
- SO：`rows` 字段是 `List<Config_X>`，反射取 `IList` 后按索引增删。
- 编码：读用 BOM → 严格 UTF-8 → GBK 兜底；写统一 UTF-8 带 BOM。

## 五、时序与流程
1. **读**：`ReadCsvText` → 切 4 行表头 → `ReadColumns`。
2. **导出**：`Validate` → 保留磁盘表头 → 逐行 `FormatCell` → 备份 → 临时文件 → 替换 → `RunConfigKit`（失败回滚）。
3. **导入**：读 → 逐行 `ParseCell`（失败报「第 N 行 列 X」）→ 整体 `Validate` → 通过才替换 `rows`。
4. **脏检查**：用 SO 重拼 CSV 与磁盘逐字比较（不含表头差异则视为不脏）。

## 六、选型与理由
| 选择 | 理由 |
| --- | --- |
| 反射 + CSV 类型行作为 schema | 不新增元数据文件，CSV 本身就是唯一真源 |
| enum 写名字、读名字或数字 | 与现有 CSV 一致，手改也友好 |
| float 用 `InvariantCulture` | 避免中文本地化把 8.5 变 85 |
| 校验失败整表回滚 | 与 R050 行为一致，避免半张表被写坏 |

**偏差说明（2026-11-16）**：桥实测 1086 行，是预估的 2.9 倍。原因是通用桥要同时处理四件预估时低估的事：① 表头/类型/规则的解析与校验；② 编码兼容（BOM/UTF-8/GBK）与 Excel 占用时的共享读 + 重试；③ 导出事务（备份 → 临时文件 → 替换 → ConfigKit → 回滚）；④ 反射读写 + 引用完整性校验。负责人已在弹窗中选「特批一次做完」，按 §0.1 记录偏差；不拆分是因为注册表、桥、测试是一套东西，拆开会让桥留半截。

## 八、风险与对策
| 风险 | 对策 |
| --- | --- |
| 反射字段名与 CSV 不一致 | `Validate` 先检查「CSV 列名都能在行类型上找到字段」，否则直接报错 |
| 枚举类型跨程序集找不到 | 用 `Type.GetType` + 已加载程序集扫描兜底 |
| 大表（100+ 行）导出慢 | 实测 >2 秒再优化，不提前做批量 API |
| 误改生成物 | 不写 `Generated/`，只跑 ConfigKit |
