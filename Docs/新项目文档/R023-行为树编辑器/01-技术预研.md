# 01 技术预研

需求：R023-行为树编辑器（EditorWindow + UIElements）
所属阶段：M4
作者：AI　状态：草稿（待负责人确认）

## 一、调研目标与约束

- 目标：一套**只在编辑器里跑**的简易行为树编辑器：左侧节点库、中间画布拖拽连线、右侧属性面板、本地预览 Tick、JSON 导入导出。
- 约束：
  1. **只在编辑器**：代码放 `NBC.Editor`（`includePlatforms: ["Editor"]`），绝不进包、不进服务端；
  2. Unity **2022.3**，用 **UI Toolkit（UXML/USS + C#）**；
  3. **全部自研**，不引 Behavior Designer 或任何外部 BT 插件；
  4. 导出的 JSON **只含纯数据**（无 Unity 对象），字段结构固定，后续服务端按 `NodeType` 字符串匹配节点工厂。

## 三、两条实现路线（关键决策点）

| | A. 用 GraphView（Unity 内置） | B. 纯手写画布 |
| --- | --- | --- |
| 拖拽/缩放/框选 | **内置** | 自己实现（指针事件 + 变换） |
| 节点与端口 | `Node` / `Port` 现成 | 自己画端口 + 命中测试 |
| 连线 | `Edge` + `Port.Connect` 现成 | 自己算曲线（`Painter2D`）+ 命中测试 |
| 代码量 | 约 600~900 行 | 约 1500~2000 行 |
| 风险 | 命名空间是 **Experimental**（多年稳定但名义上非正式） | 全靠自己，bug 面大 |
| 与需求契合 | ✔ 仍是 UI Toolkit / UXML，只是复用内置图控件 | ✔ 更"纯"但性价比低 |

**建议 A（GraphView）**：它本身就是 UI Toolkit 实现，符合"UIElements + UXML"；省下的代码量可以投到属性面板、预览、JSON 这些真正的业务点上。

## 五、JSON Schema（按负责人给定，字段大小写照抄）

```json
{
  "TreeId": "wolf_default",
  "RootNodeId": "n1",
  "Nodes": {
    "n1": {
      "NodeType": "Selector",
      "Pos": { "x": 0, "y": 0 },
      "Params": { "hpThreshold": 30, "name": "低血" },
      "Children": ["n2", "n3"]
    }
  }
}
```

关键约束：
- `Nodes` 是**字典**（id → 节点），不是数组 ⇒ 便于服务端按 id 引用；
- `Children` 是**有序** id 列表（Selector/Sequence 的顺序有意义）；
- `Params` 只放基础类型（float/int/bool/string），JSON 里就是数字/布尔/字符串；
- 导出时**不写 Unity 对象**（无 `instanceID`、无路径）。

## 六、已知坑

1. **GraphView 是 Experimental 命名空间**：升级 Unity 大版本时可能改名；把用到的 API 收在 `BTGraphView` 一处，便于以后替换。
2. **UXML 里的自定义元素**：GraphView 是 C# 创建的 VisualElement，只能通过 UXML 里的**占位容器**（`<ui:VisualElement name="canvas-slot"/>`）挂进去，不能直接在 UXML 里声明 GraphView。
3. **拖拽连线的一对多约束**：需求是「一条输出只能连一个子节点」⇒ 连新线前先断开该端口已有连线（GraphView 默认允许多连）。
4. **根节点唯一**：新建/导入后要校验只有一个根（无输入线的节点既是根，也是树入口）；删除根要阻止。
5. **循环引用**：连线前做「目标是否可以是自己的祖先」判断（DFS）。
6. **预览与画布分离**：预览运行时的节点是**另一套对象**，只读画布数据的快照；预览状态（三色）只写进节点视图的样式类，绝不回写 `Params`。
7. **参数实时生效**：属性面板改值 ⇒ 直接改 `BTNodeData.Params` ⇒ 若正在预览，需重建运行时（或标记 dirty 让下一 Tick 重建）。
8. **`Wait` 这类有跨帧状态的节点**：预览时每个运行时节点要能保存自己的计时器；重建树即重置。
9. **资源路径**：UXML/USS 放 `Editor/BehaviorTree/Resources/`，用 `AssetDatabase.LoadAssetAtPath` 读，避免 `Resources.Load` 把编辑器资源带进包的风险（编辑器程序集本身不打包，但路径写死更稳）。

## 七、结论与改动清单

结论：用 **GraphView（Unity 内置 UI Toolkit 图控件）+ UXML 三栏布局** 实现；数据模型与 UI 完全分离；预览运行时独立且仅编辑器。

要新增（全部在 `Editor/BehaviorTree/` 下）：
- 数据：`BTGraphData` / `BTNodeData` / `BTNodeDefine`（含节点注册表）
- 视图：`BehaviorTreeEditorWindow` / `BTGraphView` / `BTNodeView` / `BTInspectorView` + UXML/USS
- 预览：`BTPreviewRunner` / `BTPreviewNode`
- IO：`BTJsonUtil`
- 菜单入口：`AI工具/BehaviorTree Editor`
