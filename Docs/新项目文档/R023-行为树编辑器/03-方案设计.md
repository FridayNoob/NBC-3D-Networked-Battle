# 03 方案设计

需求：R023-行为树编辑器（EditorWindow + UIElements）
所属阶段：M4
作者：AI 起草　状态：已确认（2026-11-06）

## 一、整体架构

```
BehaviorTreeEditorWindow（EditorWindow，UXML 三栏）
├─ 左：节点库（BTNodePalette，按注册表自动生成，支持拖拽）
├─ 中：画布 BTGraphView : GraphView（节点 / 连线 / 缩放 / 拖拽，全部 UI Toolkit）
├─ 右：BTInspectorView（按节点定义动态生成字段） + 黑板面板（预览用）
├─ 工具栏：TreeId / 导入JSON / 导出JSON / 预览 / 停止预览
├─ IO：BTJsonUtil（自研 JSON 读写，纯数据）
├─ 数据：BTGraphData（与 UI 无关，序列化模型）
└─ 预览：BTPreviewRunner（200ms，编辑器 only）→ 回传状态 → 节点三色
```

## 二、模块划分

| 模块 | 职责 | 不负责什么 |
| --- | --- | --- |
| `Data/BTNodeData` | 一个节点的纯数据：类型、位置、参数、子节点 id | 不涉及 UI |
| `Data/BTGraphData` | 整棵树：`TreeId` / `RootNodeId` / `Nodes` 字典 | 不做校验以外的逻辑 |
| `Data/BTNodeDefine` | 节点**定义**：类型名、分类、参数表、子节点上限；`BTNodeRegistry` 注册表 | 不执行行为 |
| `Data/BTParamValue` | 参数值（Float/Int/Bool/String 四型） | — |
| `View/BehaviorTreeEditorWindow` | 窗口装配、工具栏、导入导出、预览启停 | 不画节点、不算树 |
| `View/BTNodePalette` | 左栏节点库（按分类分组、可拖拽） | — |
| `View/BTGraphView` | 画布：增删节点、连线、环检测、唯一根、导入导出快照 | 不做参数编辑 UI |
| `View/BTNodeView` | 单个节点的可视元素（端口、标题、状态色） | — |
| `View/BTInspectorView` | 右侧属性面板（按定义动态建控件） | 不执行预览 |
| `View/BTBlackboardView` | 预览用黑板（Hp / TargetId / SkillCd / 自定义键值） | — |
| `Preview/BTPreviewRunner` | 固定 200ms Tick；构建运行时树、回传状态 | 不改画布数据 |
| `Preview/BTPreviewNode` | 简化运行时节点（执行器） | 不做序列化 |
| `IO/BTJsonUtil` | 导出/导入（自研 JSON 解析与输出，严格 Schema） | 不碰 UI |

## 三、接口（★ 先定死）

```
// ---- 数据 ----
sealed class BTNodeData
{
    public string NodeType;
    public float PosX, PosY;
    public Dictionary<string, BTParamValue> Params;
    public List<string> Children;      // 有序；叶子为空
}

sealed class BTGraphData
{
    public string TreeId;
    public string RootNodeId;          // 空 = 还没有根
    public Dictionary<string, BTNodeData> Nodes;
    public string FindRoot();          // 没有任何父节点引用的那个
    public bool Validate(out string error);   // 唯一根 / 环 / 悬空引用
}

// ---- 节点定义 ----
enum BTNodeCategory { Composite, Condition, Action }
struct BTParamDefine { string Key; string Label; BTParamType Type; string Default; }
sealed class BTNodeDefine
{
    public string TypeName;            // JSON 里的 NodeType 字符串
    public string DisplayName;
    public BTNodeCategory Category;
    public int MaxChildren;            // -1 = 不限（组合节点）；0 = 叶子
    public BTParamDefine[] Params;
}
static class BTNodeRegistry
{
    public static IReadOnlyList<BTNodeDefine> All;
    public static BTNodeDefine Find(string typeName);
    public static void Register(BTNodeDefine define);      // 新增自定义节点唯一入口
}

// ---- 画布 ----
sealed class BTGraphView : GraphView
{
    public event Action<BTNodeData> SelectionChangedData;
    public BTGraphData ExportData(string treeId);
    public void ImportData(BTGraphData data);
    public void ApplyStatus(string nodeId, BTPreviewStatus status);   // 预览三色
    public void ClearStatus();
}

// ---- JSON ----
static class BTJsonUtil
{
    public static string Export(BTGraphData data);     // 严格按 Schema 输出（缩进 2）
    public static BTGraphData Import(string json);     // 抛 BtJsonException（带行列）
}
```

## 四、数据结构与 JSON 映射

| 内部 | JSON |
| --- | --- |
| `BTGraphData.TreeId` | `"TreeId"` |
| `BTGraphData.RootNodeId` | `"RootNodeId"` |
| `BTGraphData.Nodes`（字典） | `"Nodes": { "<id>": {…} }` |
| `BTNodeData.NodeType` | `"NodeType"` |
| `PosX/PosY` | `"Pos": {"x":…, "y":…}` |
| `Params`（四型） | `"Params": {"hpThreshold": 30, "name": "低血", "boss": true}`（**保持 JSON 原生类型**） |
| `Children` | `"Children": ["n2","n3"]`（有序） |

> 参数值必须按类型写成 JSON 原生值（数字/布尔/字符串），不能统一写成字符串 —— 否则服务端要用字符串再解析一次。

## 五、关键流程

1. **新建节点**：从左栏拖 `TypeName` 到画布 → `BTGraphView` 生成 id（`n1`、`n2`…递增）→ 建 `BTNodeData`（参数取定义里的默认值）→ 建 `BTNodeView`。
2. **连线**：从输出端口拖到目标节点的输入端口 → 校验（不能自连、不能成环、目标没有父亲）→ 断开该输出原有连线 → 连接 → 写 `Children`。
3. **删节点**：断掉相关连线 → 从 `Nodes` 移除 → 若删的是根 ⇒ 阻止并提示。
4. **唯一根**：根 = 没有任何父节点引用的节点；若出现 0 个或多个 ⇒ 导出前报错。
5. **属性编辑**：选中 → `BTInspectorView` 按定义建控件 → 改动写回 `BTNodeData.Params` → 若在预览中则标记"需要重建运行时"。
6. **预览**：点【预览】→ 快照当前数据 → 构建运行时树 → `EditorApplication.update` 里按 200ms Tick → 每个运行时节点返回状态 → 画布三色。
7. **导入导出**：导出 = `ExportData(treeId)` → `BTJsonUtil.Export` → 写文件（`SaveFilePanel`，默认 `Assets/BehaviorTrees/<treeId>.json`）；导入反之。

## 六、技术选型与理由

| 选择 | 选定 | 理由 | 被否的方案 |
| --- | --- | --- | --- |
| 画布 | **GraphView（内置）** | 连线/拖拽/缩放现成，代码量少一半 | 手写 Painter2D（代码翻倍、bug 面大） |
| JSON | **自研读写** | 工程没有 Newtonsoft；`JsonUtility` 不支持字典与动态类型 | 引 Newtonsoft（要装包，改依赖） |
| 参数存储 | 四型联合 `BTParamValue` | 导出能保持原生类型；属性面板按类型出控件 | 统一 string（服务端要再解析） |
| 节点扩展 | **注册表**（`BTNodeRegistry.Register`） | 新增节点只加一个定义 + 一个运行时执行器 | 硬编码 switch（每处都要改） |
| 预览 | `EditorApplication.update` + 200ms 计时 | 不依赖运行时脚本，停止即停 | 协程（EditorWindow 里不好控生命周期） |

## 七、风险与对策

- **GraphView 是 Experimental 命名空间**：所有调用收在 `BTGraphView` 一处；升级 Unity 只改这一个文件。
- **UXML 不能直接声明 GraphView**：UXML 里放 `<ui:VisualElement name="canvas-slot"/>` 占位，C# 里 `Add()` 进去。
- **一输出一连**：GraphView 默认允许多连 ⇒ 连接前先删该端口已有 edge。
- **成环检测**：从目标节点向下 DFS，若遇到源节点 ⇒ 拒绝。
- **预览污染数据**：预览只读快照；三色只写 USS class，绝不回写 `Params`。
- **参数实时生效**：预览中改参数 ⇒ 置 `dirty`，下一 Tick 重建运行时树。
- **导入非法 JSON**：`BTJsonUtil` 抛带行列的异常，窗口提示并保持原画布不变。
- **资源路径**：UXML/USS 用 `AssetDatabase.LoadAssetAtPath`（编辑器程序集不打包，但路径写死比 `Resources.Load` 稳）。
