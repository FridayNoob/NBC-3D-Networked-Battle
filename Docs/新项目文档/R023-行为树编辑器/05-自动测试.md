## 三、测试代码

不新增测试工程：编辑器工具的行为全靠 `execute_code` 直接调 API（一次性，不落仓库）。典型片段：

```csharp
// JSON 往返
var data = new BTGraphData { TreeId = "wolf_test" };
data.Nodes["n1"] = new BTNodeData { NodeType = "Selector", PosX = 10, PosY = 20 };
data.Nodes["n1"].Children.Add("n2");
string json  = BTJsonUtil.Export(data);
string json2 = BTJsonUtil.Export(BTJsonUtil.Import(json));
// 断言 json == json2

// 预览三态
var runner = new BTPreviewRunner();
runner.Start(data, out _);
runner.Blackboard.Set("hp", BTParamValue.FromInt(10));
runner.Tick(0.2f);
runner.Status["n2"];   // Success
```

## 五、自动化测不到的部分

- 拖拽手感（鼠标从端口拖出、黄线跟随、松开落点判定）
- 属性面板控件是否实时生效的观感
- 布局是否美观（三栏比例、字号）
- 导出/导入对话框（Unity 原生面板）

## 六、回归说明

- 改 `NBC.Editor`：跑 asmdef 闸门即可（编辑器程序集不进包，不影响运行时）。
- 回归点：菜单仍能打开窗口；已有 Editor 工具（`MonsterColliderTool` / `NetDebugWindow` / `ConfigImporter`）不受影响。
- 闸门曾经缺 `UnityEngine.UIElementsModule` 等引擎模块引用 ⇒ 已补进 `Tools\Check-AsmdefBoundaries.ps1` 的模块列表。
