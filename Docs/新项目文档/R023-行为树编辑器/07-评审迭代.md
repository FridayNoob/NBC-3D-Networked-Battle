## 一、问题清单（描述 + 类型 + 严重度）

| # | 现象 | 类型 | 严重度 |
| --- | --- | --- | --- |
| 1 | 窗口一打开就是竖排、**看不到画布** | 缺陷（样式挂错节点） | **高**（不可用） |
| 2 | 节点上没有圆点，**连不上线** | 缺陷（把「根」实现成删端口） | **高** |
| 3 | 能拖出线，松手**连不上** | 缺陷（GraphView 连接器不认目标端口） | **高** |

| 5 | 画布只有 1 个可见节点，预览却报 2 个根 | 缺陷（幽灵节点：内建删除绕过回调） | 高 |
| 6 | hp=100 时条件节点却显示成功 | 缺陷（`Stop()` 清空黑板） | 中 |
| 7 | 导入后 `seconds` 从 Float 变 Int | 缺陷（按小数点猜类型） | 中 |
| 8 | 新建节点完全重叠，看不见 | 缺陷（无避让） | 中 |
| 9 | 预览报错只说「根数量不是 1」，不说哪个 | 体验（报错不可操作） | 中 |

## 二、优先级

1~5 是「用不了」，必须修；6~9 是「用起来困惑」，一起修掉（成本都很低）。

## 三、根因分析

- **#1**：USS 只加到了 `BTGraphView`，窗口根节点没有样式 ⇒ 所有 `flex-direction: row` / `flex-grow` 不生效，界面塌成竖排、画布高度 0。
  教训：**UI Toolkit 的样式表要挂在「用到这些 class 的最近公共祖先」上**。
- **#2**：把「根节点不能有输入端口」实现成「没有父节点就删端口」，而新拖进来的节点本来就没有父节点 ⇒ 永远连不上。
  教训：**约束要表达成可观察的状态（徽标/校验），不要破坏可操作性**。
- **#3**：GraphView 自带 `EdgeConnector` 在「自定义 Node 子类 + 自建 Port」组合下不认目标端口（拖出线但落点无效）。
  教训：**实验性命名空间的控件出问题，果断换自实现，不要耗在猜它的内部契约**。
- **#4**：把「一条输出只能连一个子节点」对所有节点执行，而行为树的组合节点天生多子。
  教训：**规则要挂在「节点定义」上（MaxChildren），不要挂成全局策略**。
- **#5**：GraphView 的 Delete 键/内建右键删除走 `DeleteElements`，**不触发** `graphViewChanged` ⇒ 我的字典没清理，留下「看不见但还在」的幽灵节点。
  教训：**接管删除必须重写 `DeleteSelection`**，并在导出前做一次「视图还在不在」的兜底剪枝。
- **#6**：`Stop()` 里清了黑板；而【清空画布】会先 Stop ⇒ 面板显示 100、运行时读 0。
  教训：**"运行时状态"与"用户输入"要分开清**（黑板属于用户输入）。
- **#7**：导入按 JSON 文本有无小数点判断 Int/Float，而导出整数值的 float 会写成 `1`。
  教训：**有 schema（节点定义）就用 schema 决定类型，不要从文本猜**。
- **#8**：新建节点不做位置避让 ⇒ 与已有节点重叠，用户以为只有一个。
  教训：**可视化工具必须保证"新建的东西看得见"**。
- **#9**：校验失败只给数量。
  教训：**报错要能直接指导操作** —— 列出 id + 自动选中/框选。

## 八、教训（最值钱的五条）

1. **UI Toolkit 的样式表要挂在用到这些 class 的祖先上** —— 挂错地方的表现是"布局全塌"，不是报错。
2. **约束用"状态/校验"表达，不要用"破坏可操作性"表达**（根节点删输入端口 = 自断手脚）。
3. **实验性控件出问题就换自实现** —— 自研拖拽 80 行就稳了，比猜 GraphView 内部契约划算。
4. **接管删除必须重写 `DeleteSelection`**；`DeleteElements` 不触发 `graphViewChanged`。
5. **有 schema 就别从文本猜类型**；**"用户输入"和"运行时状态"要分开清**。

## 九、遗留（如实）

- 预览的节点状态颜色会被**选中蓝框**盖住（看状态前要先点空白取消选中）。
- 不做 Undo/Redo（删除后不能撤销）；不做多棵树管理（靠导入导出切换）。
- 不支持子树（需求里明确本版不做）。
- 导出的 JSON 与服务端 BT 的**节点执行器尚未对接**（R022 搁置）；目前 JSON 只保证结构与字段对齐。
- 新增节点除了注册定义，还要在 `BTPreviewNode` 加一个执行分支才能预览（已在 08 文档里写明）。
