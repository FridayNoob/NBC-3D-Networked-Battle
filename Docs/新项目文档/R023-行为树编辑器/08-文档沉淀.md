## 二、模块文档

### 简介与使用场景

`AI工具 / BehaviorTree Editor` 是一个**只跑在编辑器里**的可视化行为树编辑器：
左栏节点库 → 中间画布拖拽连线 → 右栏属性 + 预览黑板 → 导出/导入 JSON（给服务端 BT 用）。

- 程序集：`NBC.Editor`（`includePlatforms: ["Editor"]`）⇒ **绝不进包、不进服务端**。
- 技术栈：UI Toolkit（UXML/USS + `UnityEditor.Experimental.GraphView`）+ 自研 JSON。

### 代码分层（四个目录）

| 目录 | 职责 | 关键类型 |
| --- | --- | --- |
| `Data/` | **纯数据模型**（与 UI 无关，可直接序列化） | `BTGraphData`、`BTNodeData`、`BTParamValue`、`BTNodeDefine`、`BTNodeRegistry` |
| `IO/` | 导入导出（自研 JSON 解析/输出） | `BTJsonUtil`、`BtJsonParser` |
| `View/` | **编辑器 UI**（画布/节点/属性/窗口） | `BehaviorTreeEditorWindow`、`BTGraphView`、`BTNodeView`、`BTInspectorView` |
| `Preview/` | **仅编辑器的预览运行时**（200ms Tick，**不用于正式游戏**） | `BTPreviewRunner`、`BTPreviewNode`、`BTBlackboard` |

> 注释里统一标注：【编辑器 UI 代码】/【预览模拟运行时代码】/【数据模型】，并要求只在 Editor 下执行。

### 怎么新增一个自定义节点（需求第 9 条）

以新增「`TimerAbove`（计时超过 X 秒）条件节点」为例，**两步**：

**第 1 步：注册节点类型与参数**（文件 `Data/BTNodeDefine.cs` 的 `RegisterDefaults()` 末尾加一段）

```csharp
Register(new BTNodeDefine
{
    TypeName = "TimerAbove",                       // 就是 JSON 里的 NodeType，命名后别改
    DisplayName = "TimerAbove（计时超过）",
    Category = BTNodeCategory.Condition,           // 决定左栏分组
    MaxChildren = 0,                               // 条件节点是叶子
    Params = new[]
    {
        new BTParamDefine
        {
            Key = "seconds",                       // JSON 里 Params 的键
            Label = "秒数",
            Type = BTParamType.Float,              // 决定属性面板控件与 JSON 类型
            DefaultValue = "1.5"
        }
    }
});
```

**第 2 步（只有要能预览才需要）：加执行分支**（文件 `Preview/BTPreviewRunner.cs` 的 `BTPreviewNode.TickCore()` 里加一个 `case`）

```csharp
case "TimerAbove":
    float need = GetFloat("seconds");
    m_elapsed += deltaSeconds;
    if (m_elapsed >= need)
    {
        m_elapsed = 0f;
        return BTPreviewStatus.Success;
    }
    return BTPreviewStatus.Running;
```

> 加了第 1 步，节点就能**拖出来、能连线、能改参数、能导出 JSON**；加了第 2 步才能在**预览**里看到状态。
> 不用改任何界面代码 —— 左栏与属性面板都是按注册表自动生成的。

### JSON 契约（服务端要按这个读）

```json
{
  "TreeId": "wolf_melee",
  "RootNodeId": "n1",
  "Nodes": {
    "n1": {
      "NodeType": "Selector",
      "Pos": { "x": 360, "y": 120 },
      "Params": { },
      "Children": ["n2", "n3"]
    },
    "n2": {
      "NodeType": "HPBelow",
      "Pos": { "x": 300, "y": 300 },
      "Params": { "hpThreshold": 30 },
      "Children": []
    }
  }
}
```

| 字段 | 约定 |
| --- | --- |
| `Nodes` | 字典（id → 节点），便于按 id 引用 |
| `Children` | **有序**列表（Selector/Sequence 顺序有意义） |
| `Params` | 值保持 **JSON 原生类型**（数字/布尔/字符串），不要统一写成字符串 |
| `NodeType` | 服务端按字符串匹配节点工厂；**改名会破坏已导出的树** |

### 常用操作与快捷键

| 操作 | 方式 |
| --- | --- |
| 打开窗口 | 菜单 `AI工具 / BehaviorTree Editor` |
| 新建节点 | 左栏拖到画布；或点左栏条目（在画布中心新建）；或画布空白处右键 |
| 连线 | 按住所选节点的 `out` 圆点拖到目标节点 `in` 圆点（或目标节点方框上松手） |
| 删除节点 | 选中后工具栏【删除节点】/ Delete 键 / 右键【删除此节点】 |
| 复制节点 | 工具栏【复制节点】或右键【复制此节点】 |
| 设为根 | 节点上右键【设为根（断开父连线）】 |
| 预览 | 【▶ 预览】/【■ 停止预览】；200ms 一帧，绿=成功/红=失败/黄=运行中 |
| 清空 | 【清空画布】（先停预览再清） |

### 已知限制与坑点

- **预览三色会被选中蓝框盖住**：看状态前先点空白取消选中。
- **根节点 = 没有父节点的那个**；出现 2 个根就无法预览（会列出 id 并自动选中/框选）。
- **一个节点只能有一个父节点**；把 `Wait` 连到新父节点会自动从旧父节点上摘下来。
- **组合节点可多子**（`MaxChildren = -1`）；`MaxChildren = 1` 的节点才会「一输出一连」。
- **不做 Undo**：删除不可撤销。
- **JSON 里的 NodeType 改名 = 破坏兼容**。

### 排查「哪里不对」四步

1. **看不到画布** ⇒ USS 是否挂在 `rootVisualElement`（不是 GraphView）。
2. **节点没有圆点** ⇒ 是不是又把「根」实现成删端口了（应保留端口 + 用徽标）。
3. **预览报多个根** ⇒ 用【清空画布】重来；或看 Console 里「清理幽灵节点」的警告。
4. **条件结果反直觉** ⇒ 先看黑板值（面板 vs 运行时是否一致），再确认比较语义（`HPBelow` 是**严格小于**）。

## 三、踩坑清单（现象 / 原因 / 解决）

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 界面竖排、画布高度 0 | USS 只加给 GraphView | 样式表加到窗口根节点 |
| 节点无圆点、连不上 | 输入端口按「根」被删 | 端口常驻 + 根徽标 |
| 拖出线但连不上 | GraphView 连接器不认目标端口 | 自研拖拽（TrickleDown + Painter2D） |
| 连第二个子节点时前一条消失 | 单子规则对所有节点生效 | 按 `MaxChildren` 区分 |
| 看不见的节点仍算根 | 内建 Delete 绕过 `graphViewChanged` | 重写 `DeleteSelection` + 导出前剪枝 |
| hp=100 却成功 | `Stop()` 清空黑板 | Stop 不清；预览前同步面板值 |
| 导入后 Float 变 Int | 按小数点猜类型 | 按节点定义强转 |
| 新建节点看不见 | 与已有节点重叠 | `AvoidOverlap` |
