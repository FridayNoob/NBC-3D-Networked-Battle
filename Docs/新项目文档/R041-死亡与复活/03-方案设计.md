# R041 死亡与复活 —— 03 方案设计

需求编号：R041
所属阶段：M4
作者：AI 辅助
状态：开发中

## 1. 整体架构

```
死亡来源                流程组件                     去向
PlayerBrain.IsDead ─┐
                     ├→ PlayerDeathFlow（客户端） ─┬→ World：回出生点 + NotifyRevive
RuntimeNetDriver     │   ├ 判定场景与人数           ├→ Battle 单人：LeaveRoom + 切 World
  .HeroAlive=false ──┘   ├ 5 秒倒计时（DeathScreen） └→ Battle 多人：旁观（隐藏 + 禁用输入 + Esc 退出）
                         └ 结束时只执行一次
```

服务端**不加新协议、不加新表**：单人退出房间后房间空了，`RoomBattleService.DropBattlesOfDeadRooms` 会回收战斗世界，下次进副本就是新局（满足「副本重置」）。

## 2. 模块划分

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| `PlayerDeathFlow`（新，`Game/Player/`） | 侦测死亡、判定场景/人数、跑倒计时、分发三种去向、防重复触发 | 画黑幕（交给 `DeathScreenOverlay`）、切场景细节（交给 `SceneFlow`） |
| `DeathScreenOverlay`（新，`Game/UI/`） | 运行时建 UGUI 黑幕 + 倒计时文字 + 提示，`Show(seconds, text)` / `Tick(remaining)` / `Hide()` | 决定什么时候死、什么时候活 |
| `PlayerBrain.NotifyRevive()`（改） | 把状态机拉回 `Locomotion/Idle`、清 `Dead`、恢复输入 | 挪位置（交给流程组件） |
| `RuntimeNetDriver`（改） | 暴露 `HeroAlive`、`LeaveRoom()` 两个小接口 | 死亡表现 |
| `SceneFlow`（不改） | 已有的 `LoadAsync(GameScene.World)` | — |
| 服务端（不改或极小改） | 死亡英雄不能移动（`ApplyMove` 已有 `!Alive` 守卫） | 复活计时、退出逻辑 |

## 3. 接口

```csharp
// 死亡流程（挂在 [Player_Hero] 上，World 与 Battle 都能用）
public sealed class PlayerDeathFlow : MonoBehaviour
{
    public bool IsRunning { get; }                 // 是否正在死亡流程（外部可查，用于禁用别的输入）
    public void BeginDeath();                      // 供调试/外部强制触发（测试用）
}

// 死亡遮罩（运行时 UGUI，不依赖 YooAsset 预制体）
public sealed class DeathScreenOverlay : MonoBehaviour
{
    public void Show(float seconds, string title, string hint);
    public void Tick(float remainingSeconds);
    public void Hide();
}
```

约定：
1. `PlayerDeathFlow.Update` 每帧最多推进一次倒计时；`IsRunning` 为真时不再触发第二次。
2. 倒计时秒数取 `Level` 表 `deathCountdownSeconds`（默认 5）；表读不到时用序列化字段 `m_fallbackSeconds = 5f`。
3. `RuntimeNetDriver.HeroAlive` 返回「自己的英雄快照是否存在且 `Alive`」；没有快照时返回 `true`（避免开场误判死亡）。

## 4. 数据结构

| 数据 | 位置 | 说明 |
| --- | --- | --- |
| `m_worldSpawn`（Vector3） | `PlayerDeathFlow` | 主世界出生点，默认 `(280.799, 1.450, 425.014)` |
| `m_fallbackSeconds`（float） | 同上 | 配置读不到时的兜底 5 秒 |
| `deathCountdownSeconds`（int） | `Configs/Design/Level.csv` 新列 | 1~15，默认 5；客户端经 `LevelConfig` 读 |
| `EPlayerState` / `PlayerStateMachine` | 已有 | 复活时 `ForceChange(Locomotion, Idle)` |

## 5. 时序与流程

**主世界**

1. `PlayerBrain` 进入 `Die`（调试键 `L` 或将来服务端同步）→ `PlayerDeathFlow` 发现 `IsDead`。
2. `BeginDeath`：`overlay.Show(5, "已阵亡", "5 秒后回到出生点")`，`IsRunning = true`。
3. 每帧 `Tick` 更新数字；期间 `PlayerBrain` 的输入分支因 `Dead` 已全拒。
4. 到 0：`overlay.Hide()` → `transform.position = m_worldSpawn` → `brain.NotifyRevive()` → `IsRunning = false`。

**副本单人**

1. 快照里自己的英雄 `Alive=false` → `BeginDeath`，文案「即将退出副本」。
2. 到 0：`driver.LeaveRoom()` → `SceneFlow.Instance.LoadAsync(GameScene.World)`。
3. 切场景完成后 `IsRunning = false`（流程组件随场景销毁，下一次进副本重新开始）。

**副本多人**

1. 同上进入倒计时；到 0 后不切场景，改为：隐藏自己角色（关所有 Renderer + 停下动画）、`PlayerMove.MovementEnabled = false`。
2. 显示「旁观中，按 Esc 退出」；`Esc` → `LeaveRoom()` + 切 `World`。
3. 其他人不受影响（服务端世界继续推进）。

## 6. 选型与理由

| 选择 | 理由 | 被否方案 |
| --- | --- | --- |
| 客户端驱动流程 | 服务端已有权威 `Alive`，退出/切场景本来就是客户端行为；不新增协议 | 服务端加 `ReviveAtTick` 字段（要动 `NBC.Protocol` 生成代码） |
| 运行时 UGUI 黑幕 | YooAsset 的 UI 收集器还没配（`scene_*` 组为空），做 prefab 反而卡住；AGENTS §0.5 允许 UI 布局程序化 | 新建 prefab + UIManager（要配 YooAsset 收集器与构建） |
| 倒计时读 `Level` 表 | 与 §0.4 一致（客户端可调、写回 CSV、两端同源）；`Level` 已在 `GameTables` 预加载清单里 | 写死在代码里（改一次要重编译） |
| 旁观用「隐藏自己」 | 不改服务端、不影响别人；`Alive=false` 的尸体本来就该消失 | 服务端加观战者列表（超出 demo 范围） |

## 8. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 开场第一帧还没有快照，`HeroAlive` 误判成死亡 | 没快照时返回 `true`；只在 `HasWorld` 后才参与判定 |
| 死亡瞬间重复触发（快照重复/调试键连按） | `IsRunning` 门闩 + 结束后 0.5 秒冷却 |
| 切场景时流程组件被销毁，倒计时状态丢失 | 流程状态本来就跟场景走；切完由新场景重新开始 |
| 旁观时自己角色仍被相机跟随/仍能输入 | 隐藏 Renderer + 关闭 `PlayerMove.MovementEnabled` + 屏蔽 `PlayerBrain.enabled` |
| `Level.csv` 加列后 Unity 资产要重导入 | 生成后提示负责人跑一次「导入 TSV→ScriptableObject」（与 `Monster.csv` 同流程） |
| 主世界复活后 HUD 血量不刷新 | 复活时把 `HeroHp = HeroMaxHp`（World 无服务端血量）并触发一次 HUD 刷新 |
