# R041 死亡与复活 —— 08 文档沉淀

## 1. 文档范围

本需求只做客户端：死亡检测、黑幕倒计时、World 复活、副本单人退出、副本多人旁观。服务端零改动。涉及三个模块与一处驱动扩充。

## 2. 模块文档

### 2.1 PlayerDeathFlow

- 简介：挂在 World 的 `[Player_Hero]` 上，负责「检测死亡 → 黑幕倒计时 → 按场景分流处理」。
- 接口：Inspector 字段 `m_countdownSeconds`、`m_worldSpawn`、`m_levelId`、`m_hideWhenDead`、`m_logDiagnostics`；无公开方法。
- 示例：把组件挂在玩家根节点即可，倒计时秒数默认读 `LevelConfig.deathCountdownSeconds`，读不到用 Inspector 值。
- 原理：`Update` 里用 `PlayerBrain.IsDead` 或 `RuntimeNetDriver.HeroAlive == false` 判死；倒计时结束按 `SceneFlow` 当前场景分流（World 复活 / 副本单人退出 / 副本多人旁观）。
- 坑：`Hide()` 必须放在复活流程第一步，否则中间异常会一直黑。
- 维护：新增死亡表现改 `DeathScreenOverlay`；新增分流场景改 `ResolveDeath()`。

### 2.2 DeathScreenOverlay

- 简介：运行时构建的全屏黑幕（Canvas + 黑图 + 标题 + 倒计时 + 提示），零资产依赖。
- 接口：`Ensure()`、`Show(title, hint)`、`SetCountdown(seconds)`、`SetStatusText(text)`、`Hide()`、`IsShowing`。
- 示例：`DeathScreenOverlay.Ensure().Show("你已倒下", "5 秒后回到出生点");`
- 原理：首次 `Ensure()` 建 Canvas（sortingOrder 900）与三行 `Text`，字体用 `LegacyRuntime.ttf`，之后只切 `SetActive`。
- 坑：`Show`/`Hide` 必须对称——只关背景会把两行字留在屏幕上。
- 维护：R046 会整体换成预制体 + `UIManager`，届时本类删除。

### 2.3 状态机复活入口

- 简介：`PlayerStateMachine.NotifyRevive()` 与 `PlayerBrain.NotifyRevive()`，把死亡态清干净并回到 `Locomotion/Idle`。
- 接口：`bool NotifyRevive()`，没死返回 false。
- 示例：复活流程里先传送位置、再 `m_brain.NotifyRevive()`。
- 原理：清 `Dead`、`ActionBusy`、`ActionId`、连击、格挡、落地缓冲，`Grounded = true`、`VerticalSpeed = 0`、`SetMoveSpeed(0)`、`MovementEnabled = true`，最后 `ForceChange(Locomotion, Idle)`。
- 坑：只清 `Dead` 不清动作标志，复活后会卡在 `Action/Pose`。
- 维护：新增死亡时写入的状态，复活这里也要清。

### 2.4 RuntimeNetDriver 扩充

- 简介：给客户端死亡流程补三个只读事实与一个动作：`HeroAlive`、`HeroEntityCount`、`PlayerBrain` 懒查找、`LeaveRoom()`。
- 接口：`bool HeroAlive { get; }`、`int HeroEntityCount { get; }`、`void LeaveRoom()`。
- 示例：`if (!driver.HeroAlive) flow.BeginDeath();`（实际由 `PlayerDeathFlow` 内部轮询）。
- 原理：`TrackHeroHealth` 每帧拿到英雄快照后同步 `m_heroAlive`，人数按 `Kind == 0` 统计；首次拿到快照时把 `PlayerDeathFlow` 挂到驱动自身（Battle 的英雄是运行时生成的）。
- 坑：`ReconcileHeroPosition` 在英雄死亡时直接 return，位置纠偏不会把尸体拉走。
- 维护：多英雄玩法改动时同步 `CountHeroEntities()`。

## 3. 踩坑清单

1. `Show` / `Hide` 必须操作同一层节点，否则会留下「幽灵文字」。
2. 「关黑幕」要放在复活流程的最前面，异常兜底优先于流程完整。
3. Unity 编辑器失焦时不继续编译；触发重编必须留下实质内容变化，删空行会取消编译。
4. 编辑器 AppDomain 可能加载旧程序集，此时改场景 YAML 是可行的绕过手段，之后让 Unity 重新保存一次。
5. `readonly struct` 不能用对象初始化器，必须走构造函数。
6. Play 模式下启动 Test Runner 会因保存场景而抛异常，跑测试前先退出 Play。
7. 日志节流要按「值是否异常」而不是只按时间。
