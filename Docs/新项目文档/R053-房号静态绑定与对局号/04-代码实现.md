# 04 代码实现

需求编号：R053
所属阶段：M4
作者：AI（DeepSeek）

## 一、子任务与约束

| # | 子任务 | 约束 |
| --- | --- | --- |
| 1 | 协议加 `match_id` 并重生成 | 只新增字段，旧编号不动 |
| 2 | 房号静态绑定副本 | 已存在的房直接复用 |
| 3 | 空房保留、世界回收 | 房间在、世界不在 |
| 4 | 开打/重开时对局号 +1 | 放 `EnsureBattle`，只数「建世界」 |
| 5 | 客户端显示对局号 | 只改日志，不改判定 |

## 二、功能概述

房号从「第几次开房」变成「哪个副本」（`d1001`）；「第几局」由 `Room.MatchId` 表达，每建一次战斗世界 +1，并随 `RoomState` 下发。空房不再删除，但战斗世界照旧回收。

## 三、接口与入参出参

| 成员 | 入参 | 出参 | 说明 |
| --- | --- | --- | --- |
| `RoomRegistry.Create` | `int dungeonId` | `Room` | 房号 `"d"+dungeonId`；已存在返回同一个 |
| `Room.MatchId` | — | `int` | 从 0 起，开打 +1 |
| `Room.ToState` | — | `RoomState` | 带 `MatchId` |
| `RoomBattleService.EnsureBattle` | `Room` | `DungeonBattle?` | 成功后 `room.MatchId++` |
| `DropBattlesOfDeadRooms` | — | — | 房间不存在或 `IsEmpty` 都回收 |

## 四、逐段讲解

1. **房号生成**：`"d" + dungeonId` 一眼能看出是哪个副本；`TryGetValue` 先查，保证「同副本只有一间」。
2. **空房保留**：把 `Phase` 拨回 `Waiting` 而不是删对象——席位表是空数组，后来者加入即可；不拨回的话下一局会被误认为「正在打」。
3. **世界回收**：房间还在但没人，世界就是垃圾；连 `_recorded` 一起清，否则「这一间的第二局」会被判成「已经结算过」而不再广播结果。
4. **对局号递增**：只放在「建世界成功」这一处，`ResetBattle` 只负责丢世界，不重复 +1。
5. **客户端显示**：只改日志文本，判定完全不动。

## 五、完整代码（改动单元）

`Server/NBC.Server.Core/RoomRegistry.cs`：

```csharp
public Room Create(int dungeonId)
{
    // 房号 = "d" + 副本号：一个副本一间房，房号跟着配置走，不再每次开房 +1。
    // 「第几局」由 Room.MatchId 表达（谁开打谁 +1），房号本身不随对局变化。
    string roomId = "d" + dungeonId;

    if (_rooms.TryGetValue(roomId, out Room? existing))
    {
        return existing;
    }

    var room = new Room(roomId, dungeonId, _capacity);
    _rooms.Add(roomId, room);
    return room;
}

public int MatchId { get; set; }
```

`Room.ToState()` 增加一行 `MatchId = MatchId,`。

`RoomRegistry.Leave`：

```csharp
room.Remove(session);

if (room.IsEmpty)
{
    // R053：空房**不再删除** —— 房号静态绑定副本（`d1001`），房间作为「副本的常驻实例」
    // 一直存在，随时可以再加入。只把阶段拨回等待：否则下次有人进房会以为这一局还在打。
    room.Phase = RoomPhase.Waiting;
}

return room;
```

`Server/NBC.Server.Game/RoomBattleService.cs`（建世界成功之后）：

```csharp
DungeonBattle battle = built;
_battles.Add(room.RoomId, battle);

// 新的一局：对局号 +1（房号不变，客户端靠它区分「第几局」）。
room.MatchId++;
Note?.Invoke($"房间 {room.RoomId} 开打：副本 {room.DungeonId}（第 {room.MatchId} 局，" +
             $"{battle.BossCount} 个 BOSS、{battle.Entities.Count - battle.BossCount} 个普通怪）");
```

`DropBattlesOfDeadRooms` 的判定：

```csharp
Room? room = _registry.Find(pair.Key);

// 房间被删（旧语义）或房间还在但**没人了**（R053：空房常驻）都算「没人看这一局」。
// 房间对象保留、战斗世界回收：下次进房 `EnsureBattle` 会重新开一局（对局号 +1）。
if (room == null || room.IsEmpty)
{
    dead ??= new List<string>();
    dead.Add(pair.Key);
}
```

## 七、风险与幻觉自查

- 对局号只在一处 +1（`EnsureBattle`），没有在 `ResetBattle` 里重复加。
- 空房保留后，`DropBattlesOfDeadRooms` 必须能识别「房间在、人没了」，否则世界泄漏。
- `_recorded` 与房间生命周期解耦：房号静态复用后，**不清理会让第二局静默不结算**。
- 探针里三条旧断言（空房删除、房间数 0、世界回收）已同步改成新语义。
