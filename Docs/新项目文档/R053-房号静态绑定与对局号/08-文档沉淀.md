## 一、文档范围

本需求涉及：房间编号语义、对局号、空房常驻、战斗世界回收、快照帧号单调。代码落点：`Server/NBC.Server.Core/RoomRegistry.cs`、`RoomService.cs`、`Server/NBC.Server.Game/RoomBattleService.cs`、`Protocol/nbc_m3.proto`、`Client/Assets/_Project/Game/Net/NetSession.cs`。

## 二、模块文档

### 1. 房间编号（RoomRegistry）

- **简介**：一个副本只对应一间房，房号 = `d` + 副本号（`d1001`）。
- **接口**：`Create(int dungeonId)`、`Join(...)`、`Leave(session)`、`Find(string roomId)`。
- **示例**：两个客户端先后进 1001，拿到同一个 `d1001`。
- **原理**：房号从「运行时实例号」变成「配置的标识」，因此可以稳定复用。
- **坑**：空房不能删，但 `Phase` 必须拨回 `Waiting`，否则下次有人进房会被当成「这一局还在打」。
- **维护**：新增副本不需要改代码，`Dungeon.csv` 加行即可。

### 2. 对局号（Room.MatchId + RoomState.match_id）

- **简介**：表达「这一间房的第几局」，从 1 开始，每建一次战斗世界 +1。
- **接口**：`Room.MatchId`、`RoomState.MatchId`（协议字段 `match_id = 6`）。
- **示例**：同一间 `d1001` 连打三局，客户端日志分别显示第 1/2/3 局。
- **原理**：把「房间」（长期）与「一局」（短期）分开表达。
- **坑**：只在 `EnsureBattle` 建世界成功后 +1，不能在 `ResetBattle` 里重复加。
- **维护**：将来做赛季/战绩时，`(roomId, matchId)` 就是唯一对局键。

### 3. 空房与战斗世界（RoomService + RoomBattleService）

- **简介**：房间常驻、世界回收。
- **接口**：`RestartRequested` 事件（`RoomService`）→ `ResetBattle(Room)`（`RoomBattleService`）。
- **示例**：最后一人离开 → 立刻作废这一局；再进 → 新一局、怪满血。
- **原理**：状态一出现就处理，tick 只做兜底。
- **坑**：房间空的时长可能短于一个 tick（实测 16ms），**不能**只靠 `Tick` 里的清理。
- **维护**：`ResetBattle` 同时清 `_recorded`，否则新一局不广播结算。

### 4. 快照帧号（`_serverTick`）

- **简介**：服务端快照帧号全局单调，客户端只接受「比上一张新」的快照。
- **接口**：`NextServerTick()`、`WorldSnapshot.ServerTick`。
- **示例**：重开、换房、换副本都不会让帧号倒带。
- **原理**：单调是客户端丢弃乱序/旧包的判据，任何「重数」都会导致整段画面被丢弃。
- **坑**：曾经按房号计数，新房间从 1 开始 ⇒ 客户端十几秒不刷怪。
- **维护**：新增任何「重开」路径时，确认帧号来源仍是这一个计数器。

## 三、踩坑清单

1. tick 兜底清理有延迟窗口，状态一变就处理才是主力。
2. 空房保留后，`Phase` 必须拨回 `Waiting`。
3. `_recorded` 必须跟「世界」同寿命。
4. 帧号不能重数（重开/换房都不行）。
5. 日志文案要跟着行为改（「已删除」 vs 「房间本身保留」）。
6. 单人环境下多人验收要如实标「未构造」。
