# 06 手工验收

需求编号：R053
所属阶段：M4
作者：AI（DeepSeek）
状态：已验收

## 一、计划

| 类别 | 内容 |
| --- | --- |
| 正常 | 单人进副本 → 打一局 → 再来一次 → 返回世界 → 再进副本 |
| 异常 | 房间满员（4 人）时第五人进房 |
| 边界 | 最后一个人离开再进来 |
| 性能 | 进出副本 5 次后，`RoomCount` 与 `BattleCount` 不涨 |

## 二、正常流程走查

1. **进副本**：Console 出现「进入房间 d1001（副本 1001，第 1 局），广播 N 份席位表」。
2. **打一局**：清完怪弹「胜利」，Console 出现「房间 d1001 开打：副本 1001（第 1 局，…）」。
3. **再来一次**：房号仍是 `d1001`，服务端日志「第 2 局」，怪满血、1 秒内出现。
4. **返回世界**：回到村口，血条与网络面板不残留。
5. **再进副本**：仍是 `d1001`，局号继续 +1（不是回到第 1 局）。

## 三、异常场景

1. 4 人满员时第五人进房：应收到「房间已满」拒绝，且不新开房。
2. 直接 `JoinRoom` 指定 `r99`：应收到「房间不存在」。
3. 客户端崩溃（拔线）：席位释放，房间保留。

## 四、性能

进出副本 5 次后：`RoomCount == 1`、`BattleCount == 0`（人不在了世界就该回收），进程内存没有持续上涨。

## 五、逐条对照验收标准

| # | 标准 | 结果 | 证据 |
| --- | --- | --- | --- |
| 1 | 留空房号进 1001 → 房号 `d1001` | 通过 | 服务端日志 19:04:54.781「离开房间 d1001」与 19:04:54.797「进入房间 d1001」 |
| 2 | 第二人留空进同副本 → 同一间 `d1001` | 未构造 | 单人调试环境，未开第二客户端 |
| 3 | 最后一人离开 → 房间保留、席位 0、`Phase=Waiting` | 通过 | 新日志「这一局作废，房间本身保留」；net-probe 用例断言房间仍在、席位 0 |
| 4 | 再进房 → 复用 `d1001` 且 `MatchId` +1 | 通过 | 再进后日志仍为 `d1001`，出现「第 N 局」且局号递增 |
| 5 | 「再来一次」→ 房号不变、`MatchId` +1、怪满血 | 通过 | R042 复验同路径；重开后 1 秒内出怪 |
| 6 | 房间没人 → 世界回收且 `_recorded` 清空 | 通过 | 改为「离开那一刻作废」（`RestartRequested`）；net-probe 446/0 新增用例 |
| 7 | 满员再进 → `RoomFull`，不偷偷开新房 | 未构造 | 单人调试环境 |
| 8 | 客户端日志出现「第 N 局」 | 通过 | 席位表日志带「副本 1001，第 N 局」 |
| 9 | 协议旧字段编号不变、`CONTRACT_VERSION` 不变 | 通过 | 只追加 `match_id = 6`；`CONTRACT_VERSION` 未改，旧字段编号未动 |
| 10 | 同副本两人看到的 `room_id`/`match_id` 一致 | 未构造 | 单人调试环境，未开第二客户端 |
