## 五、测不到的部分

1. 客户端日志里的「第 N 局」没有自动化断言（只改文本）。
2. 多人同房间时的 `match_id` 一致性只靠协议字段，未单独构造两人对账用例。
3. 空房常驻导致的内存增长没有度量（本项目副本数个位数）。
4. `MatchId` 溢出（int 上限）未测。
5. 机器人占位与空房回收的组合只靠逻辑推断。

## 六、回归说明

- 三条旧断言（空房删除、`RoomCount==0`、世界回收）**语义已变**，本次同步改为「房间保留、世界回收」，不是放宽。
- 其余 442 条 net-probe 用例全绿，说明房号语义变更没有波及战斗、同步、任务、成就链路。
- EditMode 798 条全绿（本次未改客户端判定逻辑）。
