# 02 需求

需求：R003-血条HUD
所属阶段：M4
作者：LYF（口述确认，AI 落稿）　状态：已确认（2026-10-26，负责人「2、3没问题」）

## 一、业务目标（一句话）

**让玩家在屏幕上看见自己的血量**，并且血少了能一眼看出来 —— 后面所有战斗反馈都从这条血条开始。

## 二、用户与使用场景

- 用户：开发期负责人验证；最终玩家在战斗时随时可见。
- 场景：进战斗/演示场景后，血条常驻屏幕角落；受伤时变短、颜色从绿转红；血空时归零。

## 三、功能列表（P0 / P1 / P2）

| 功能 | 优先级 | 说明 |
| --- | --- | --- |
| 屏幕 HUD 常驻血条 | P0 | 满血显示为满格 |
| 掉血时变短 | P0 | 比例 = 当前/最大 |
| 颜色随比例变化 | P0 | 绿 → 黄 → 红 |
| 数字（如 80 / 100） | P1 | prefab 里放了 `Text_Value` 才显示 |
| 敌人血条、受伤飘字 | P2 | 本版不做 |
| 血量平滑过渡动画 | P2 | 本版不做（要就后加，用插值） |

## 四、边界（**本版明确不做**）

- 不做敌人血条、不做飘字、不做数值跳动动画。
- 不接服务端：血量用本地假数据（按空格扣血），真数据接快照另开需求。
- 不自己生成 UI 物体：**一切外观由 prefab 决定**（负责人明确要求），代码只改 `fillAmount` 与颜色。
- 不做血条的多语言/描边/图片替换（这些都属于 prefab 调整，不用改代码）。

## 五、优先级

**P0**。依赖：R001（已有可操作角色）、`UIManager` + `BasePanel`（项目已有）。

## 六、验收标准（「当…时，应…」）

- [ ] 当 进入 Play 时，屏幕角落应出现一条满格血条
- [ ] 当 按一次空格时，血条应立刻变短一段，数字同步（若放了 `Text_Value`）
- [ ] 当 血量降到 30% 以下时，血条颜色应明显偏红
- [ ] 当 血量打到 0 时，血条应为空、不再继续缩短
- [ ] 当 我在 prefab 里改位置/图片/大小后重新进 Play，应直接生效，且不需要改代码
