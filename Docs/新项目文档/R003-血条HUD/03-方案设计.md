# 03 方案设计

需求：R003-血条HUD
所属阶段：M4
作者：AI 起草　状态：已确认（2026-10-26，负责人「2、3没问题」）

## 一、整体架构

分三层，各管一段：**资源层**（你做的 `Canvas` / `HpBarPanel` prefab）→ **管理层**（项目已有 `UIManager` 按地址加载、挂到 `Bot` 层）→ **表现层**（`HpBarPanel` 改 `fillAmount` 与颜色）。演示数据由 `HpBarDemoBehaviour` 提供，将来换成战斗 HUD 即可，`HpBarPanel` 不用改。

## 二、模块划分

| 模块（类） | 负责什么 | **不负责**什么 |
| --- | --- | --- |
| `HpBarPanel`（继承 `BasePanel`） | 按控件名取 `Image`；把比例写进 `fillAmount`；按比例改颜色 | 不建物体、不设坐标、不做伤害计算 |
| `HpBarDemoBehaviour`（MonoBehaviour，住 **NBC.Boot**） | 装资源层、打开面板、按空格扣血 | 不代表正式战斗逻辑（演示完可删）；不负责画血条 |
| `UIManager`（已有） | 加载 prefab、挂层、面板池 | 不管血条怎么画 |

## 三、接口（★ 先定死，代码必须与此逐字一致）

```
HpBarPanel : BasePanel
    常量 FillControl  = "Img_Fill"     必需，Image 且 Image Type = Filled
    常量 BgControl    = "Img_Bg"       可选
    常量 ValueControl = "Text_Value"   可选，TMP 或 UGUI Text 都认
    属性 Ratio        -> float         0..1，只读
    SetHp(int current, int max) -> void   钳 0..max，算比例，顺带更新数字
    SetRatio(float ratio)       -> void   钳 0..1，改 fillAmount 与颜色
    重写 OnInit()                -> void   由 BasePanel.Initialize 调，负责取控件

HpBarDemoBehaviour : MonoBehaviour   // 住 NBC.Boot（asmdef 方向：Boot -> Game 单向）
    字段 m_maxHp           -> int   默认 100
    字段 m_damagePerPress  -> int   默认 10
```

## 四、数据结构

| 数据 | 类型 | 含义 / 单位 | 谁改它 |
| --- | --- | --- | --- |
| `Ratio` | float | 血量比例，0..1（无单位） | `HpBarPanel.SetRatio` |
| `Image.fillAmount` | float | 填充比例，0..1 | `HpBarPanel.SetRatio` |
| `m_hp` | int | 当前血（演示用） | `HpBarDemoBehaviour.Update` |
| prefab 里的 RectTransform | — | 位置/锚点/大小，**全部由负责人定** | 负责人（编辑器） |

## 五、时序与流程

1. 进 Play → `HpBarDemoBehaviour.Start` 调 `UIManager.Instance.ShowPanel("HpBarPanel", UILayer.Bot, onShown, onFailed)`。
2. `UIManager` 按地址 `UI/HpBarPanel` 加载 prefab → 实例化 → 挂到 `Canvas/Bot` 下。
3. 面板 `Initialize()` → `CollectControls()` 按名字收集控件 → 调 `OnInit()` 取 `Img_Fill` 等。
4. `onShown` 回调里拿到 `HpBarPanel` → `SetHp(100, 100)` ⇒ 满格。
5. 按空格 → `m_hp -= 10` → `SetHp(m_hp, 100)` ⇒ `fillAmount` 与颜色变化。

## 六、技术选型与理由

| 选择 | 选定 | 理由 | 被否的方案 |
| --- | --- | --- | --- |
| UI 进场景方式 | prefab + `UIManager` 按地址加载 | 沿用项目 UI 架构：层级、面板池、资源加载都复用 | 代码运行时建 Canvas（绕框架）、prefab 直接拖场景（以后要迁） |
| 血条画法 | 单个 `Image` + `fillAmount` | 一张图就能做，且**外观改 prefab 即可**（换图/换色不用改代码） | 两个 RectTransform 拉伸（要算宽度）、Sprite 切片 |
| 颜色 | `Color.Lerp(red, green, ratio)` | 一行搞定，够用 | 三色分段（更精确但要配阈值） |
| 数字 | 先试 `TMP_Text`，没有再用 `Text` | 两种 prefab 都能接，负责人不必被我绑死 | 只支持其中一种 |

## 七、风险与对策

- `ui` 组收集器为空 / prefab 没进清单 ⇒ 报 `Location is invalid`。对策：配收集器 + 重建一次 YooAsset。
- `Img_Fill` 的 `Image Type` 不是 Filled ⇒ `fillAmount` 无效。对策：prefab 里必须设 Filled；代码取不到控件会抛异常点名。
- 控件名写错 ⇒ 不报错、只是没效果。对策：`Img_Fill` 用 `RequireControl`（抛带指引的异常），其余可选控件静默跳过。
- `ShowPanel` 是异步的，`onShown` 之前面板为 null。对策：演示驱动只在回调里用 `m_panel`。
- **跨程序集不能用上层**：`AssetBootstrapper` 在 `NBC.Boot`，`HpBarPanel` 在 `NBC.Game`，引用方向是 Boot→Game 单向 ⇒ 演示驱动只能住 Boot（否则 CS0234）。
- 血条被别的层盖住 ⇒ 挂 `Bot` 层（最底层）可能被后续面板遮挡。对策：HUD 就该在最底，若被盖住调 `UILayer.Mid`。
