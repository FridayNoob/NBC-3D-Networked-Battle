## 三、根因分析

- #1：演示驱动要用 `AssetBootstrapper`，它在 `NBC.Boot`；而 asmdef 是 `NBC.Boot -> NBC.Game` **单向**，`NBC.Game` 看不见 Boot。
  我把文件放进了 `Game/UI`，等于反向引用。判据：**报 `CS0234` 且命名空间是项目自己的 ⇒ 先查 asmdef 引用方向**。
- #2：`UIManager` 的默认地址是 `UI/Canvas` 与 `UI/<面板名>`（`DefaultCanvasLocation` / `DefaultPanelLocationPrefix`），
  而收集器规则 `AddressByFileName` 产出的地址只有 `Canvas` / `HpBarPanel`。我默认「地址 = 文件名」，没读那两个常量。
- #3：`UIManager.AttachToLayer` 在挂载时会把面板根 `offsetMin/offsetMax = 0`（铺满整层）。
  我读框架时只看到「挂到层」，没读到后面 4 行；血条直接挂在根上 ⇒ 根铺满 ⇒ 血条跟着铺满。
- #4：`_api-probe` 把 `Game\**`、`Boot\**` 全编进**同一个程序集**，所以看不见 asmdef 边界；
  `Check-AsmdefBoundaries` 只校验 asmdef 的 json 声明与生成结果，不做「using 是否越界」的语义检查。

## 八、教训（可复用判据）

1. **新增一条 `using` 之前，先看两个 asmdef 的 `references` 方向。** 单向引用（Boot→Game）下，下层永远看不见上层。
2. **本地编译闸不能代替 Unity 编译**：`_api-probe` 是单程序集，asmdef 越界它一定看不见 —— 「我这儿 0 错」不等于「Unity 能编过」。
3. **用别人框架的常量之前，先 grep 它的 `Default*`**（本例 `DefaultCanvasLocation`）；别假设「地址就是文件名」。
4. **框架把一个物体挂到父节点时改了哪些 RectTransform 字段，必须读那几行**（本例铺满 ⇒ HUD 全屏）。
