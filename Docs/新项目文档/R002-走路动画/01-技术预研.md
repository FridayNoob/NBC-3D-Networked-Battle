## 二、核心 API 清单（含出处）

| API / 概念 | 用途 | 出处 |
| --- | --- | --- |
| `Animator.SetFloat("Speed", v)` | 把「当前速度」喂给状态机 | Unity Scripting API: Animator |
| `Animator.Play(name)` / `CrossFade(name, 0.1f)` | 直接切状态（本需求用状态机，不直接调） | 同上 |
| `Animator StringToHash` | 参数名不写字符串（避免拼错静默失败） | 同上 |
| `Animator.applyRootMotion` | **必须关**：否则动画自带位移会和 `PlayerMove` 的位移**叠加** | Unity 手册：Root Motion |
| `Animator Controller`（`.controller`） | 状态机资产：Idle ↔ Walk 两条 + `Speed` 参数 | Unity 手册：Animator Controller |
| `Avatar`（Humanoid） | 人形骨骼映射，只有它才能做动画重定向 | Unity 手册：Avatar |
| FBX 导入设置 | `Rig = Humanoid` 才会生成 Avatar；`Animation Type` 选错就没有重定向 | Unity 手册：Model Import |

## 五、已知坑与版本兼容

1. **必须关 `Apply Root Motion`**：`PlayerMove` 是直接改 `transform.position`，动画若带位移会**叠加**（角色跑得飞快或漂移）。
2. **FBX 的 `Rig` 必须是 Humanoid**，否则没有 Avatar、动画无法重定向到别的模型。
3. **走路速度要匹配**：我们移动是 **5 米/秒**，而 Walk 动画通常约 1.3 米/秒 ⇒ 会「脚打滑」。两种修法：把 `m_moveSpeed` 调小，或让动画 `State.speed` 随速度缩放（本需求先用调速度，最省事）。
4. **模型原点/身高**：Unity-chan 通常按 **1 单位 = 1 米**、脚底在 y=0；我们此前用 Capsule 时放在 y=1（胶囊中心）。换模型后要按**脚底对齐**重新摆。
5. **动画参数名写错不报错**：`SetFloat("speed")` 与 `SetFloat("Speed")` 是两个参数；用 `StringToHash` 或在 Controller 里核对。
6. **模型文件不进仓库**：Unity-chan 许可**不得单独再分发模型数据**，公开仓库等于再分发。用 `.gitignore` 挡掉目录，README 写明来源与放置路径。
7. **Unity-chan 的 Controller 可能自带 Run/跳跃**：本需求只用 Idle/Walk 两个状态，其余状态不用但可以留着。
