# 03 方案设计

需求：R002-走路动画
所属阶段：M4
作者：AI 起草　状态：已确认（2026-10-27；2026-10-28 补充 m_speedScale 与三条风险）

## 一、整体架构

三块，各管一段：**算位移**（`PlayerMove`，已有）→ **报速度**（`PlayerMove.CurrentSpeed`，新增只读属性）→
**喂动画**（`PlayerAnimation`，新增，只调 `Animator.SetFloat`）。**状态机本身在 Animator Controller 里**，代码不写「该播哪个动画」。

## 二、模块划分

| 模块（类） | 负责什么 | **不负责**什么 |
| --- | --- | --- |
| `PlayerMove`（改） | 照旧算方向/转身/位移；**新增**把「本帧实际速度」暴露出来 | 不碰 Animator |
| `PlayerAnimation`（新增） | 每帧读 `PlayerMove.CurrentSpeed`，写进 `Animator` 的 `Speed` 参数 | 不判断状态、不做过渡（都在 Controller 里） |
| Animator Controller（负责人配） | Idle ↔ Walk 两状态、`Speed` 浮点参数、0.15 秒过渡 | 不写代码 |

## 三、接口（★ 先定死，代码必须与此逐字一致）

```
PlayerMove（在 R001 的基础上新增一个只读属性，行为不变）
    属性 CurrentSpeed -> float      本帧实际速度，米/秒（= 位移长度 / deltaTime）
    字段 m_moveSpeed / m_turnSpeed  保持不变

PlayerAnimation : MonoBehaviour
    常量 SpeedParameter = "Speed"   与 Controller 里的参数名一致
    常量 WalkThreshold  = 0.1f      低于它算静止（米/秒）
    字段 m_animator -> Animator     可留空，留空时自动 GetComponentInChildren
    字段 m_damping  -> float        默认 0.1，SetFloat 的平滑时间（0 = 不平滑）
    LateUpdate() -> void            每帧读速度并写参数
```

## 四、数据结构

| 数据 | 类型 | 含义 / 单位 | 谁改它 |
| --- | --- | --- | --- |
| `CurrentSpeed` | float | 实际速度，米/秒 | `PlayerMove.Update`（每帧重算） |
| `Speed`（Animator 参数） | float | 喂给状态机的速度值，米/秒 | `PlayerAnimation.LateUpdate` |
| `lastPosition` | Vector3 | 上一帧位置，用来算位移 | `PlayerMove`（每帧更新） |

## 五、时序与流程（**顺序是本节的重点**）

1. `PlayerMove.Update`：读输入 → 转向 → 位移 → **用「这一帧的位移 / deltaTime」算出 `CurrentSpeed`**。
2. `PlayerAnimation.LateUpdate`：读 `CurrentSpeed` → `SetFloat(SpeedParameter, speed, m_damping, Time.deltaTime)`。
3. Controller 里：`Speed > 0.1` → Walk；`Speed < 0.1` → Idle；过渡 0.15 秒。
4. 停下（或方向相消、或被挡住）⇒ 位移为 0 ⇒ `CurrentSpeed = 0` ⇒ 回 Idle。

⚠️ **为什么 `PlayerAnimation` 用 `LateUpdate`**：同一个物体上两个 `Update` 的调用顺序**不保证**。
如果动画先跑，它拿到的是**上一帧**的速度 —— 表现是「按下按键后要慢一帧才播 Walk」，很难查。
放 `LateUpdate` 就一定在 `PlayerMove.Update` 之后。

## 六、技术选型与理由

| 选择 | 选定 | 理由 | 被否的方案 |
| --- | --- | --- | --- |
| 「在走」的判据 | **实际位移速度** | 被挡住/卡住时会自动回 Idle；不需要额外写「碰撞检测」 | 看有没按键（方向相消时会误播） |
| 动画驱动 | 两个状态 + `Speed` 浮点参数 | 配置全在 Animator 窗口，代码只有一行 | 代码 `CrossFade`（状态一多就乱） |
| 组件拆分 | `PlayerMove` 算、`PlayerAnimation` 喂 | 单一职责：以后换模型/换动画只动动画组件 | 全塞进 `PlayerMove` |
| 过渡 | Controller 里 0.15 秒 | 改时长不用改代码 | 代码里写死 CrossFade 时间 |
| Root Motion | **代码强制关**（`applyRootMotion = false`） | 位移由 `PlayerMove` 管，动画再带位移就叠加 | 依赖 prefab 勾选（容易漏） |

## 六之二、为什么不走框架状态机（**2026-10-27 负责人问过，记在这里**）

项目里有两套状态机，管的东西不一样：

| | Unity `Animator` | `Framework\Fsm`（`StateMachine` / `HierarchicalStateMachine`） |
| --- | --- | --- |
| 管什么 | 动画片段与过渡混合 | 逻辑状态（`OnEnter/OnUpdate/OnExit/OnEvent/CanEnterFrom`） |
| 过渡/混合/动画事件/重定向 | 内置 | 要自己写 |
| 可单测 | 否（只能 Play 看） | 是（纯 C#，EditMode 可驱动） |
| 项目里生产使用 | 本需求起接入 | **0 处**（只有框架注释与 EditMode 测试用过） |

结论：**动画归 Animator**（不然就是把它的过渡混合重写一遍），
**逻辑状态归框架 FSM**，且框架 FSM 应该**驱动** Animator（`OnEnter` 里 `CrossFade`）。
那件事单独开 **R010「角色逻辑状态机」**（Idle / Move / Attack / Dead），本需求不做。
## 七、风险与对策

- **顺序**：两个 `Update` 顺序不定 ⇒ 动画用 `LateUpdate`（见第五节）。
- **参数名写错**：`SetFloat("speed")` 不报错、只是不动 ⇒ 常量集中一处，且 `PlayerAnimation` 启动时**校验参数存在**（`Animator.parameters` 里找一遍，没有就 `Debug.LogError` 点名）。
- **Root Motion**：即使 prefab 勾了 `Apply Root Motion`，代码也强制关掉。
- **Animator 在子物体**（换模型后常见）：`m_animator` 留空时用 `GetComponentInChildren<Animator>()`。
- **脚滑**：需求已确认本版不解决（移动 5 米/秒 vs 动画约 1.3 米/秒），记 07 遗留。
- **模型原点**：Unity-chan 脚底在 y=0；原来的 Capsule 是中心在 y=1，换模型时别沿用 y=1。
