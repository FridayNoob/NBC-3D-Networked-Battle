## 二、模块文档

### 简介与使用场景

`PlayerAnimation`（NBC.Game，`Game\Player\`）：把 `PlayerMove` 的**实测速度**换算后写进 `Animator` 的 `Speed` 参数；
Idle/Walk 的切换与过渡全在 Controller 里，代码不判断状态。

### 核心接口

| 接口 / 字段 | 入参 | 出参 | 说明 |
| --- | --- | --- | --- |
| `PlayerMove.CurrentSpeed` | — | float（米/秒） | 本帧实测：位移长度 ÷ `deltaTime` |
| `PlayerAnimation.SpeedParameter` | — | `"Speed"` | 与 Controller 里的 Float 参数同名 |
| `PlayerAnimation.WalkThreshold` | — | `0.1f` | 低于它算静止 |
| `m_speedScale`（Inspector） | — | float，默认 `0.2` | 米/秒 → 0~1；换直接吃米/秒的 Controller 时设 1 |
| `m_damping`（Inspector） | — | float，默认 `0.1` | `SetFloat` 平滑时间 |

### 使用示例（负责人亲手跑通，2026-10-28）

```text
1) 角色：unitychan（Animator + PlayerMove + PlayerAnimation；Rigidbody/Collider 可留）
2) Controller：UnityChanLocomotions（Float 参数 Speed；BlendTree 阈值 0 / 0.8）
3) Animator：Apply Root Motion 不勾（代码也会强制关）
4) Play → 按 W 走、松开站、A/S/D 转向
```

### 实现原理（简要）

`PlayerMove.Update` 记下移动前后位置差，算 `CurrentSpeed`；`PlayerAnimation.LateUpdate` 读它、按阈值归零、乘 `m_speedScale` 钳到 0~1，写进 `Animator`。
用 `LateUpdate` 是为了保证在 `PlayerMove.Update` 之后（同物体两个 `Update` 顺序不保证）。

### 已知限制与坑点

- **脚打滑**：移动 5 米/秒 vs Walk 动画约 1.3 米/秒（遗留）。
- 只支持 Idle/Walk；Run 会在速度更高时由 Controller 自己切（当前归一化到 1.0 可能触到 Run 档）。
- 依赖 Controller 里存在 **Float** 参数 `Speed`；缺失会在 `Awake` 报错并停用。

### 修改维护注意事项

- 换 Controller：先确认参数名与量纲，再决定 `m_speedScale`（0~1 用 0.2，米/秒用 1）。
- 换模型：确认 `Rig = Humanoid`、`Apply Root Motion` 不勾、身上**没有**自带移动脚本。
- 不要把喂参数改回 `Update`。

## 三、踩坑清单（现象 / 原因 / 解决）

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 模型粉色 | 材质引用的 shader 资产不存在（GUID 0 命中） | 材质改 URP/Lit 并接 Base Map |
| 角色乱跑/速度翻倍 | 预制体自带 `UnityChanControlScriptWithRgidBody` | 移除该组件（`FaceUpdate` 可留） |
| 位移漂移 | `Apply Root Motion = true` | 关掉（代码也强制关） |
| 一直播跑步 | 我们喂米/秒，Controller 期望 0~1 | `m_speedScale = 0.2` 换算并钳 1 |
| 动画不切换且 Console 无红字 | 参数名/类型不对（`SetFloat` 静默无效） | `Awake` 里校验参数并点名报错 |
| 按住 W 却播上一帧的速度 | 喂参数写在 `Update` 里 | 改 `LateUpdate` |
| 仓库突然多出 192 MB | 第三方模型未忽略 | 导入前先补 `.gitignore`（按实际路径） |
