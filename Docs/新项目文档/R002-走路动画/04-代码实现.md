需求：R002-走路动画
所属阶段：M4
作者：AI（代码量很小，核心是「谁算速度、谁喂参数」两个决定）　状态：已确认（2026-10-28 验收通过，含 m_speedScale 修订）

## 一、子任务与设计约束

- 本单元：`PlayerMove`（**加一个只读属性**）+ 新增 `PlayerAnimation`（喂 Animator）。
- 约束：状态与过渡全在 Controller 里；代码只写 `Speed` 参数；同一物体上两个脚本；`LateUpdate` 读速度；**强制关 Root Motion**。

## 二、功能概述

`PlayerMove` 每帧照旧算位移，并顺手算出**本帧实测速度**（位移长度 ÷ `deltaTime`）暴露成 `CurrentSpeed`；
`PlayerAnimation` 在 `LateUpdate` 里把它写进 `Animator` 的 `Speed` 参数，Controller 据此在 Idle / Walk 之间切。

## 三、接口与入参出参

| 单元 | 入参 | 出参 | 异常 |
| --- | --- | --- | --- |
| `PlayerMove.CurrentSpeed` | 无 | float，米/秒（0 = 本帧没动） | 不抛 |
| `PlayerAnimation.Awake` | 无 | 无 | 缺 `PlayerMove`/`Animator`/`Speed` 参数时 `LogError` 并停用自己 |
| `PlayerAnimation.LateUpdate` | 无 | 无（写 Animator 参数） | 不抛 |

## 四、逐段讲解

1. **为什么用实测位移算速度**：需求要的是「真的在动」。有碰撞以后被墙挡住时位移为 0，速度自然归零、动画回站姿 —— 不用再写一套「有没有碰撞」的判断。
2. **为什么先清零**：`Update` 里「没输入」会提前 `return`，先把 `m_currentSpeed` 置 0，那些分支就不会残留上一帧的速度。
3. **为什么 `PlayerAnimation` 用 `LateUpdate`**：同物体两个 `Update` 顺序不保证，反了就会喂上一帧速度（表现为慢一帧）。
4. **为什么强制 `applyRootMotion = false`**：位移由 `PlayerMove` 管，动画若也带位移就是叠加（角色会飞或漂）。
5. **为什么要校验参数存在**：`Animator.SetFloat` 对不存在的参数**不报错**，只是什么都不发生 —— 校验一次并点名，比以后猜半小时强。
6. **为什么阈值 0.1**：浮点抖动会让速度在 0 附近跳，直接比较 `> 0` 会导致状态来回切。
7. **为什么 `speed < WalkThreshold` 时喂 0**：让 Controller 的条件永远只有两个档（0 或真实速度），过渡更干净。

`Client/Assets/_Project/Game/Player/PlayerMove.cs`（**在 R001 基础上新增 `CurrentSpeed`，移动行为不变**）

```csharp
// 这个文件里有：
//   PlayerMove（类）：把 InputManager 产出的输入命令变成角色的移动与转身

using NBC.Framework.Input;
using UnityEngine;

namespace NBC.Game.Player
{
    // 主要功能：每帧读 InputManager 的当前命令，把量化轴还原成方向，转身并位移；并把本帧实际速度暴露给动画。
    // 主要数据成员：m_moveSpeed（米/秒）、m_turnSpeed（度/秒）、m_currentSpeed（本帧实测速度，米/秒）。
    // 主要外部方法：CurrentSpeed（只读属性，给 PlayerAnimation 用）。
    // 谁在用它：挂在角色物体上；输入取自 InputManager.Instance.Current，键位在 InputMapping 里可改。
    public sealed class PlayerMove : MonoBehaviour
    {
        // 每秒走多少米。场景里 1 单位 = 1 米，5 就是每秒 5 米
        [SerializeField] private float m_moveSpeed = 5f;

        // 转身速度，度/秒。720 约等于 0.2 秒转半圈，手感不拖
        [SerializeField] private float m_turnSpeed = 720f;

        // 本帧实测速度（米/秒）：位移长度 / deltaTime；没动就是 0
        private float m_currentSpeed;

        // 入参：无
        // 返回：本帧实测速度，米/秒（0 = 这一帧没动）
        // 上游：PlayerAnimation.LateUpdate
        // 下游：无
        public float CurrentSpeed
        {
            get { return m_currentSpeed; }
        }

        // 入参：无（引擎每帧调用）
        // 返回：无
        // 步骤：
        //   1) 取 InputManager 单例；播放模式下它已经把 LegacyInputSource 装好，并每帧自己 Tick 一次
        //   2) 读 Current 的 MoveX / MoveY（已是 -1000..1000 的量化轴），除以 MoveScale 还原成 -1..1
        //   3) 方向是零就返回（本帧速度为 0）；不返回会把朝向强行转到默认方向
        //   4) 归一化；斜着走（W+D）不归一化会比直走快 1.41 倍
        //   5) 由方向求朝向，按 m_turnSpeed 限速转过去
        //   6) 位移 = 方向 乘 速度 乘 deltaTime
        //   7) 用「这一帧实际移动了多远 / deltaTime」算出 CurrentSpeed（给动画用）
        // 上游：Unity 引擎每帧调用
        // 下游：InputManager.Current、Transform.rotation、Transform.position
        // 注意：这里不要再调 InputManager.Tick。它每帧已经自己 Tick 过一次，再调一次会打乱「刚按下/刚松开」的边沿判定
        private void Update()
        {
            // 本帧没动就是 0（下面提前 return 的分支也走这里，所以先清掉）
            m_currentSpeed = 0f;

            InputManager input = InputManager.Instance;

            if (input == null || !input.IsEnabled)
            {
                return;
            }

            InputCommand command = input.Current;

            float x = (float)command.MoveX / InputCommand.MoveScale;
            float z = (float)command.MoveY / InputCommand.MoveScale;

            Vector3 direction = new Vector3(x, 0f, z);

            if (direction.sqrMagnitude < 0.0001f)
            {
                return;
            }

            direction.Normalize();

            Quaternion target = Quaternion.LookRotation(direction, Vector3.up);
            transform.rotation = Quaternion.RotateTowards(
                transform.rotation, target, m_turnSpeed * Time.deltaTime);

            Vector3 before = transform.position;
            transform.position += direction * (m_moveSpeed * Time.deltaTime);

            // 实测位移（不是「我想要走多快」）：被挡住时它自然变成 0，动画就会回站姿
            if (Time.deltaTime > 0f)
            {
                m_currentSpeed = (transform.position - before).magnitude / Time.deltaTime;
            }
        }
    }
}
```

`Client/Assets/_Project/Game/Player/PlayerAnimation.cs`（新增）

```csharp
// 这个文件里有：
//   PlayerAnimation（类）：把角色的实际速度喂给 Animator 的 Speed 参数

using UnityEngine;

namespace NBC.Game.Player
{
    // 主要功能：每帧读 PlayerMove 的 CurrentSpeed，写进 Animator 的 Speed 参数，由 Controller 决定播 Idle 还是 Walk。
    // 主要数据成员：m_animator（目标 Animator）、m_damping（SetFloat 平滑时间）、m_move（同物体上的 PlayerMove）。
    // 主要外部方法：无，只有 Unity 的 LateUpdate 回调。
    // 谁在用它：和 PlayerMove 一起挂在角色物体上；状态与过渡全在 Animator Controller 里配。
    [RequireComponent(typeof(PlayerMove))]
    public sealed class PlayerAnimation : MonoBehaviour
    {
        // 与 Controller 里的浮点参数同名（写错不会报错，只会不动，所以下面会校验）
        public const string SpeedParameter = "Speed";

        // 低于这个速度算静止，米/秒（0.1 足够滤掉浮点抖动）
        public const float WalkThreshold = 0.1f;

        // 目标 Animator：留空时自动在本物体及其子物体里找
        [SerializeField] private Animator m_animator = null;

        // SetFloat 的平滑时间（秒）。0 = 不平滑；0.1 让切换不生硬
        [SerializeField] private float m_damping = 0.1f;

        // 同物体上的位移组件（速度来源）
        private PlayerMove m_move;

        // 参数名的哈希值（每帧用整数查参数，不拼字符串）
        private int m_speedHash;

        // 入参：无（引擎在开始帧调一次）
        // 返回：无
        // 步骤：
        //   1) 取同物体的 PlayerMove；没装就报错（本类不自己算速度）
        //   2) 找 Animator：没手填就 GetComponentInChildren，找不到就报错并停用自己
        //   3) 强制关掉 Root Motion（位移由 PlayerMove 管，动画再带位移会叠加）
        //   4) 校验 Controller 里确实有 Speed 参数，没有就点名报错
        // 上游：Unity 引擎
        // 下游：Animator.applyRootMotion / Animator.parameters
        private void Awake()
        {
            m_move = GetComponent<PlayerMove>();

            if (m_move == null)
            {
                Debug.LogError("[PlayerAnimation] 同一个物体上没有 PlayerMove，动画拿不到速度。", this);
                enabled = false;
                return;
            }

            if (m_animator == null)
            {
                m_animator = GetComponentInChildren<Animator>();
            }

            if (m_animator == null)
            {
                Debug.LogError("[PlayerAnimation] 没有 Animator（本物体和子物体都没找到）。", this);
                enabled = false;
                return;
            }

            m_animator.applyRootMotion = false;
            m_speedHash = Animator.StringToHash(SpeedParameter);
            ValidateParameter();
        }

        // 入参：无（引擎每帧在 Update 之后调）
        // 返回：无
        // 步骤：
        //   1) 读本帧实测速度
        //   2) 低于阈值就按 0 喂（避免浮点抖动让状态来回切）
        //   3) SetFloat 写到 Speed 参数，带 damping 平滑
        // 上游：Unity 引擎（LateUpdate，保证在 PlayerMove.Update 之后）
        // 下游：Animator.SetFloat
        // 注意：不要改成 Update。同一物体上两个 Update 的先后不保证，顺序反了会喂上一帧的速度
        private void LateUpdate()
        {
            float speed = m_move.CurrentSpeed;

            if (speed < WalkThreshold)
            {
                speed = 0f;
            }

            m_animator.SetFloat(m_speedHash, speed, m_damping, Time.deltaTime);
        }

        // 入参：无
        // 返回：无
        // 步骤：
        //   1) 遍历 Controller 的参数表
        //   2) 找到同名 float 参数就通过
        //   3) 找不到就报错并停用（否则每帧 SetFloat 都是无效调用，且不报错）
        // 上游：Awake
        // 下游：无
        private void ValidateParameter()
        {
            AnimatorControllerParameter[] parameters = m_animator.parameters;

            for (int i = 0; i < parameters.Length; i++)
            {
                if (parameters[i].name == SpeedParameter &&
                    parameters[i].type == AnimatorControllerParameterType.Float)
                {
                    return;
                }
            }

            Debug.LogError(
                "[PlayerAnimation] Animator Controller 里没有 Float 参数 " + SpeedParameter +
                "（现有参数：" + parameters.Length + " 个）。动画不会切换。", this);

            enabled = false;
        }
    }
}
```

## 六、调用示例


## 七、风险与幻觉自查

- 幻觉自查：`Animator.SetFloat(int,float,float,float)`、`Animator.StringToHash`、`Animator.parameters`、`AnimatorControllerParameterType.Float`、`Animator.applyRootMotion` 均存在；`PlayerMove.CurrentSpeed` 为本需求新增。
- **本轮踩到的工具坑（两个闸都要补模块引用）**：`Animator` 不在 `UnityEngine.CoreModule`，而在 `UnityEngine.AnimationModule`。
  · `_api-probe` 报 `CS1069` ⇒ 在 `ApiProbe.csproj` 加该模块引用；
  · `Check-AsmdefBoundaries.ps1` 生成的 csproj 也报同样错 ⇒ 把 `UnityEngine.AnimationModule` 加进脚本的 `$engineModules` 列表。
  · 这已是同一族第三次（Input→InputLegacyModule、Audio→AudioModule、Animator→AnimationModule）。
- 风险：`m_animator` 留空时用 `GetComponentInChildren`，若模型层级里有多个 Animator 会取第一个。
- 已知缺陷（本版不修）：移动 5 米/秒 vs Walk 动画约 1.3 米/秒 ⇒ **脚会滑**（02 已确认为遗留）。
