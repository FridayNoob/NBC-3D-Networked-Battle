## 三、根因分析

- #1：材质引用的 shader GUID 在**全项目 0 命中** ⇒ 不是 URP 不兼容，而是**卡通 shader 资产根本没随包进来**。
  判据：粉色 + 材质 shader 显示 Missing ⇒ 换 URP 内置 shader 并重连贴图，别去查管线配置。
- #2：用的是 `Prefabs/for Locomotion/unitychan.prefab`，它自带**示例玩法脚本**（自己读键盘、自己用 Rigidbody 移动）。
  我们只看了「有没有 Animator」，没看「还挂了什么」。
- #3：预制体把 `Apply Root Motion` 勾着；位移已经由 `PlayerMove` 每帧写，动画再写就叠加。
- #4：`.gitignore` 只挡住了我自己预设的 `Art/Characters/`，而模型实际导入在 `Assets/UnityChan/`。
- #5：`UnityChanLocomotions` 的 BlendTree 阈值是 `0` 与 `0.8`（0~1 归一化），我们喂的是实测米/秒（最大 5）。

## 八、教训（可复用判据）

1. **用别人的预制体当角色，先把它身上的组件全看一遍** —— 示例玩法脚本会抢移动权。
2. **粉色先查「材质引用的 shader 资产在不在」**，再查管线；`Missing` 和「不兼容」是两回事。
3. **导入第三方资产前先写 `.gitignore`**，并且**按实际导入路径**写，不是按你以为的路径。
4. **喂 Animator 的参数先看它期望的量纲**（0~1 还是米/秒），差一个量纲就永远播最高档。
5. **能读实时状态就别靠猜**：本轮用 MCP 桥读到 `Apply Root Motion=true`、组件清单、控制台 0 error，省了三轮来回。
