## 一、整体架构

```
怪物预制体（Forest Wolf - Grey）
 ├─ MonsterAiDebugView（新，运行期 + 编辑期都活）
 │    ├─ Attack （子 Transform）→ 红圈
 │    ├─ Aggro  （子 Transform）→ 白圈
 │    └─ Ground （子 Transform）→ 蓝竖线
 │    ├─ Gizmos（编辑期，OnDrawGizmos）
 │    └─ LineRenderer ×3（运行期，懒创建在三个子物体上）
 └─ [SerializeField] MonsterConfig m_config → Client/Assets/_Project/Configs/MonsterConfig.asset

Inspector（MonsterAiDebugViewEditor）
 ├─ 表值 vs 显示值对比 + 「显示值 ≠ 服务端值」红字
 └─ 按钮「写回 Monster.csv」→ MonsterAiCsvWriter.TryWrite(...)
```

## 二、模块划分

| 文件 | 负责 | 不负责 |
| --- | --- | --- |
| `Game/View/MonsterAiDebugView.cs`（新） | 三个子 Transform、三色 Gizmos、三色 LineRenderer、覆盖值 | 读写 CSV、重生成 |
| `Editor/MonsterAiDebugViewEditor.cs`（新） | Inspector 对比与按钮、写回后提示 | 画圈、写 CSV |
| `Editor/MonsterAiCsvWriter.cs`（新） | 按 `MonsterConfigId` 改 CSV 三列（保留其余列与原换行） | 生成配置、重启服务端 |
| `Game/View/SnapshotSceneBinder.cs`（改） | 实例化后 `Bind(e.ConfigId)` | 显示逻辑 |
| `Configs/Design/Monster.csv`（数据） | 新增 `groundLineMm` 列 + 三只怪取值（接地 300/300/500） | — |

## 三、接口（★ 先定死）

```csharp
public sealed class MonsterAiDebugView : MonoBehaviour
{
    public int MonsterConfigId { get; set; }        // 写回哪一行（默认 6001）
    public int AttackRangeMmOverride { get; set; }   // 0 = 用表值
    public int AggroRangeMmOverride { get; set; }
    public int GroundLineMmOverride { get; set; }

    public int DisplayAttackRangeMm { get; }         // 覆盖 > 0 ? 覆盖 : 表值
    public int DisplayAggroRangeMm { get; }
    public int DisplayGroundLineMm { get; }

    public bool IsOverriding { get; }                // 三个覆盖值是否与表值不同
    public void Bind(int monsterConfigId);           // 运行时由 Binder 调用
}

public static class MonsterAiCsvWriter
{
    public const string CsvRelativePath = "Configs/Design/Monster.csv";

    // 成功返回 true 并给出"下一步要做什么"的提示；失败给出原因
    public static bool TryWrite(int monsterId, int attackMm, int aggroMm, int groundMm, out string message);
}
```

参数/取值：

| 字段 | 单位 | 含义 | 非法值 |
| --- | --- | --- | --- |
| `AttackRangeMmOverride` | 毫米 | 攻击判定半径（红） | ≤ 0 视为"用表值" |
| `AggroRangeMmOverride` | 毫米 | 玩家检测半径（白） | 同上 |
| `GroundLineMmOverride` | 毫米 | 接地线长度（蓝） | 同上 |

## 四、时序

**编辑期**：选中预制体 → `OnDrawGizmos` 按三个子 Transform 画三色 → 改 Inspector 数值 → Gizmos 立即变。

**运行期**：`EnsureSlot` 实例化 → `Bind(configId)` → `LateUpdate` 更新三条 LineRenderer 的顶点 → 玩家看到圈跟着狼走。

**写回**：Inspector 点按钮 → 校验（>0）→ `MonsterAiCsvWriter` 改 CSV 三列 → 提示：
`重生成命令 + 重启服务端`（不自动跑 CLI，遵守 AGENTS.md §3 禁止一键脚本）。

## 五、CSV 变更

```
id,name,hp,attack,skillIds,aggroRangeMm,attackRangeMm,moveSpeedMmPerTick,leashRadiusMm,groundLineMm
                                                                                             ↑ 新增（int, range(0,999999)）
6001 野狼：4000 / 2000 / 40 / 100000 / 300
6002 蜘蛛：4000 / 2000 / 40 / 100000 / 300
6003 狼王：4000 / 2000 / 90 / 200    / 500
```

- 服务端 `MonsterRow` **不读** `groundLineMm`（无代码改动）。
- 客户端 `Config_Monster` 会多一个 `groundLineMm` 字段（重生成后可用）。

## 六、选型与理由

| 选择 | 理由 | 被否方案 |
| --- | --- | --- |
| LineRenderer 画运行期圈 | Game 视图可见、无需美术资源 | 只用 Gizmos（Game 视图看不到） |
| 三个子 Transform 承载圆心 | 判定位置可拖、与"三种判定"一一对应 | 用偏移向量（不够直观） |
| 组件引用 `MonsterConfig` SO | 读表值与服务端同源；不用硬编码路径 | 读 TSV 文本（多一处解析） |
| 写回只改 CSV、不跑生成 | 遵守"禁止一键脚本"；生成由人执行 | 按钮一键写回+生成+重启 |
| 接地也入表 | AGENTS.md §0.4：一份真值、不在预制体里另存 | 接地只放组件字段 |

## 八、SOLID 自检

| 原则 | 怎么满足 |
| --- | --- |
| **S** | 显示（View）/ 编辑面板（Editor）/ CSV 写回（Writer）三件事分三个文件 |
| **O** | 以后加"扇形判定"只需新增一个画法分支或子类，不动写回与面板 |
| **L** | `MonsterAiDebugView` 不修改 `MonsterConfig` 资产（只读），写回只走 CSV |
| **I** | Writer 只有一个 `TryWrite`，不把生成/重启塞进同一个方法 |
| **D** | 组件依赖 `MonsterConfig` 抽象数据，不直接读文件路径 |

## 九、风险与对策

| 风险 | 对策 |
| --- | --- |
| 运行期 LineRenderer 无材质显粉线 | 显式用 `Sprites/Default` 并设颜色 |
| 覆盖值与表值不一致被忽略 | Inspector 红字 + `IsOverriding` 提示；写回后自动清空覆盖 |
| 写回改坏 CSV（逗号/引号） | Writer 只改目标列的数值单元格（纯数字），不碰其它列与引号 |
| 每帧 new 数组导致 GC | 顶点/位置数组按需扩容并复用 |
| 预制体上没挂组件 | `SnapshotSceneBinder` 里 `GetComponent` 为空则跳过（不报错） |
