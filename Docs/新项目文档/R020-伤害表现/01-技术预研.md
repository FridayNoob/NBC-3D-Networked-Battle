# 01 技术预研

需求：R020-伤害表现（飘字 + 受击动画）
所属阶段：M4
作者：AI　状态：草稿（待负责人确认）

## 一、调研目标与约束

- 目标：**打中之后屏幕上有反馈** —— 伤害数字飘出来、被打的怪抖一下（受击动画）、怪死掉。
- 约束：
  1. 不改服务端、不改协议（伤害数字**从快照的 HP 差值**算）；
  2. 简单优先：不做怪物血条、不做暴击/闪避等花活；
  3. 复用素材自带的动画参数，不新建状态机。

## 二、数据从哪来（已确认）

| 项 | 结论 | 出处 |
| --- | --- | --- |
| 快照是否带血量 | **有**：`EntitySnapshot.Hp` / `MaxHp` | 协议 pbr 生成代码 |
| 刷新频率 | 30Hz（每条快照都带全量实体） | `NetContract.TickRate` |
| 表现层是否已有实体列表 | 有：`PresentationFeed.View.Entities` | R006/R015 |
| 因此伤害数字 | = **上一帧 Hp − 这一帧 Hp**，纯客户端算 | 无需协议改动 |

## 三、素材侧（已确认）

| 对象 | 可用的触发参数 |
| --- | --- |
| 狼（`Forest Wolf - Controller`） | **`Take Damage`**(Trigger)、**`Die`**(Trigger)、`Walk`(Bool) |
| 本地玩家（`Sword_Controller`） | `TAKE`、**`HIT L`**、`HIT R`、`STUN`、`DIE`、`ATTACK 1~3` |

## 四、飘字用什么做（已确认可行）

| 项 | 结论 |
| --- | --- |

| 现有 HUD | 只有屏幕 HUD 血条（`HpBarPanel`，本地玩家） |

## 五、方案

| 部分 | 做法 |
| --- | --- |
| 伤害数字 | 新组件 `DamagePopup`（静态 `Show(worldPos, amount)`）：创建 world-space TMP 文本「-N」，1.2 秒内上浮 + 淡出后销毁 |
| 受伤者动画 | 槽位比较 HP 差值：掉血 ⇒ `SetTrigger("Take Damage")`；`Alive` 转 false ⇒ `SetTrigger("Die")` |
| 参数兼容 | 每个槽位缓存「有没有 Take Damage / Die」（不同怪参数名可能不同），缺了就跳过（只飘字） |
| 死亡 | 槽位隐藏是现有逻辑（R015），本次只补一个 Die 触发 |

## 六、已知坑

1. **HP 差值会被快照乱序/丢帧干扰**：只处理「这一帧 Hp < 上一帧」，负数忽略；新出现的实体先记基线再比较（否则第一次见到会飘一个满血值）。
2. **治疗**（Hp 变大）不飘字：本版只做伤害。
3. **一次多段伤害**：差值合并成一个数字（够用；分段显示要服务端事件，不做）。
4. **死亡瞬间**：`Alive=false` 当帧槽位会被隐藏，`Die` 触发要**先播再隐藏**，否则看不见。
5. **TMP 默认字体**：如果以后把默认字体改掉且新字体没有数字字形，会显示空白 —— 飘字用默认字体资产即可。
6. **性能**：每刀一个 TMP 对象，1.2 秒后销毁；同一时刻数量个位数，不做池化。

## 七、结论与改动清单

结论：**在 `SnapshotSceneBinder` 里按 HP 差值触发「飘字 + 受击/死亡动画」**，新增一个 80 行左右的 `DamagePopup`；服务端与协议零改动。

要改：
- 新增 `Game\UI\DamagePopup.cs`
- 改 `Game\View\SnapshotSceneBinder.cs`（槽位记上一帧 HP；掉血飘字 + 触发 `Take Damage`；死亡触发 `Die`）
