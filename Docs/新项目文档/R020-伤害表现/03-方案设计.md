## 一、整体架构

```
服务端快照（Hp / MaxHp / Alive）→ PresentationFeed.View
        │                              │
        │                              ├─ SnapshotSceneBinder（怪物侧）
        │                              │    ├─ 血条：SetRatio(hp/max)
        │                              │    ├─ 掉血：飘字 + Take Damage
        │                              │    └─ 死亡：Die → 隐藏
        │                              └─ RuntimeNetDriver（玩家侧）
        │                                   ├─ 掉血：飘字 + PlayHit()
        │                                   └─ HeroHp/HeroMaxHp → HUD
        └────────────────────────────────────────────→ HpBarDemoBehaviour 每帧刷 HUD
```

## 三、接口（★ 先定死）

```
DamagePopup（静态）
    public static void Show(Vector3 worldPosition, int amount)
    常量：LifetimeSeconds=1.2、RiseMetersPerSecond=1.2、BaseFontSize=36
    颜色/字号分档（绝对值，伤害单位=点）：
        1..19   → 白 (#FFF6D5)，字号 30
        20..49  → 橙 (#FFB347)，字号 38
        50..    → 红 (#FF4D4D)，字号 48
    偏移：每次随机 ±0.25 米（X/Z），避免完全重叠

MonsterHealthBar（组件）
    public void Bind(int maxHp)                 // 建两个 SpriteRenderer（底黑 + 填充红）
    public void SetRatio(float ratio)           // 0..1，改填充的 localScale.x
    （Update 里朝向 Camera.main）

SnapshotSceneBinder.Slot 新增：
    int LastHp; bool HpKnown; bool AliveKnown;
    bool HasTakeDamage; bool HasDie;            // controller 参数存在性
    MonsterHealthBar HealthBar;

RuntimeNetDriver 新增：
    public int HeroHp { get; private set; }         // 0 = 未知
    public int HeroMaxHp { get; private set; }

PlayerAnimation 新增：
    public void PlayHit()                       // HIT L / HIT R 交替；缺参数只告警一次
```

## 四、数据结构

- 槽位多 3 个值类型 + 2 布尔 + 1 引用；无集合。
- 血条：每个槽位 2 个 SpriteRenderer（共享一张运行时生成的 1×1 白 Sprite）。
- 飘字：每次 Instantiate 一个小物体（TMP + 驱动脚本），1.2 秒后销毁。

## 五、时序与流程

1. 槽位创建：`HealthBar.Bind(maxHp)`、缓存 `HasTakeDamage/HasDie`、`HpKnown = false`。
2. 每帧：`if (!HpKnown) { 记基线 } else if (Hp < LastHp) { 飘字 + Take Damage }`；更新血条比例。
3. `Alive` 由 true→false ⇒ `Die` 触发一次；槽位隐藏沿用现有逻辑。
4. 玩家侧：driver 每帧读自己英雄的 Hp，掉血就飘字 + `PlayHit()`；并把 `HeroHp/HeroMaxHp` 留给 HUD。
5. HUD：`HpBarDemoBehaviour.Update` 读 `driver.HeroHp` 刷 `HpBarPanel`。

## 六、技术选型与理由

| 选择 | 选定 | 理由 | 被否的方案 |
| --- | --- | --- | --- |
| 数字来源 | 快照 HP 差值 | 协议零改动 | 加事件消息（改协议） |
| 飘字 | TMP world-space | 已引用、默认字体覆盖数字 | 世界→屏幕坐标 UI（要管遮挡/相机） |
| 血条 | **两个 SpriteRenderer** | 零 UI 依赖、便宜、好调 | world-space Canvas + Image（重、要 Canvas 组件） |
| 玩家侧归属 | 放在 driver | driver 已持有玩家引用与快照入口 | 放进 binder（binder 只认槽位） |
| HUD 刷法 | 每帧轮询 | 一个属性读值，最简单 | 事件订阅（多一层解绑风险） |
| 暴击 | **不做** | 服务端没有暴击数据，编一个等于骗人 | 客户端随机放大（假数据） |

## 七、风险与对策

- **新怪飘满血 / 血条从 0 开始**：`HpKnown=false` 时只记基线并把血条设为满。
- **死亡动画看不到**：先 `SetTrigger("Die")`，槽位隐藏仍由 `HideGone` 处理（下一帧才消失）。
- **参数缺失**：`HasTakeDamage/HasDie` 在建槽位时查好；缺了只飘字。
- **血条朝向**：`Update` 里 `transform.rotation = Camera.main.transform.rotation`（billboard）；相机为空就跳过。
- **Sprite 生成**：运行时建一张 1×1 白纹理并缓存为静态 Sprite，避免每个槽位建一张。
- **玩家侧误飘**：玩家 `PlayerId` 未绑定时 `FindHero` 返回 null ⇒ 跳过，不飘字。
- **HUD 抖动**：服务端 30Hz，HUD 每帧读同一个值，不会抖；血条只在数值变化时 SetHp。
