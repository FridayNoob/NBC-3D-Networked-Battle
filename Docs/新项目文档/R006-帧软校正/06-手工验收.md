## 三、瞬移兜底的实测数据（MCP 直接操作场景）

| 步骤 | 结果 |
| --- | --- |
| 记录槽位 1 原位 | `x=2.740, z=-1.500` |
| 把它瞬时扔到 | `x=502.740`（+500 米） |
| 2 秒后读回 | `x=2.74, z=-1.50`（**已归位**） |

判据：若走「匀速追」分支，500 米 ÷ 60 米/秒上限 = **至少 8.3 秒**；实测 2 秒内归位 ⇒ 走的是**瞬移分支**。

## 四、异常场景

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| 新实体从地图中心滑过来 | 首帧没归位 | 用 `Slot.Positioned` 标记（04 已实现） |
| 实体会「飞出去再飞回来」 | 无速度上限 | `MaxChaseSpeed = 60` 钳住 |
| 平滑后位置不精确等于快照 | 方案 A 的定义（在「路上」） | 属预期；要精确就把 `m_snapshotIntervalSeconds` 调极小退化 |

## 五、性能表现

- 每帧每实体多一次 `Vector3.Distance` + 一次 `MoveTowards`，开销可忽略。
- 未观察到掉帧。
- 留一条观察项：实体数上百时（PVP 多人），可以改成「只在移动的槽位上算」以省掉静止实体的计算。
