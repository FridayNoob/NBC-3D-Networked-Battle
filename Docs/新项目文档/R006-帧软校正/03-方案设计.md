# 03 方案设计

需求：R006-帧软校正（快照插值）
所属阶段：M4
作者：AI 起草　状态：已确认（2026-10-31）

## 一、整体架构

只改**表现层写位置的那一处**，不动任何数据流：

```
服务端 30Hz 快照 → NetSession → PresentationFeed → SnapshotSceneBinder.LateUpdate
                                                        │
                                        原来：localPosition = 目标       ← 一跳一跳
                                        现在：localPosition = 朝目标匀速追 ← 连续
```

## 二、模块划分

| 模块 | 本次改动 | 不负责什么 |
| --- | --- | --- |
| `SnapshotSceneBinder`（改） | 位置赋值 → 匀速追踪；加瞬移兜底、速度钳位、两个 Inspector 参数 | 不改快照数据、不改相机、不改池 |
| `Slot`（同一个文件里的私有类） | 加一个 `Positioned` 标记：首次出现直接归位 | — |
| 服务端 / 协议 / 锁步链路 | **零改动** | — |

## 三、接口（★ 先定死）

```
SnapshotSceneBinder 新增序列化字段（Inspector 可调）：
    m_snapshotIntervalSeconds = 0.0333f   快照间隔（秒），默认 1/30；注入后用于算追踪速度
    m_teleportDistanceMeters  = 10f       瞬移阈值（米），超过就归位不追

新增常量：
    MaxChaseSpeed = 60f                   追踪速度上限（米/秒）

新增私有方法：
    void MoveSlotTo(Slot slot, Vector3 target)
        1) 首次出现（!slot.Positioned）⇒ 直接归位并置标记
        2) 距离 >= m_teleportDistanceMeters ⇒ 直接归位
        3) 否则 speed = min(距离 / m_snapshotIntervalSeconds, MaxChaseSpeed)
           localPosition = MoveTowards(当前, target, speed * Time.deltaTime)

Slot 新增字段：
    bool Positioned                       是否已经落过位（首次要瞬移，不能从原点滑进来）
```

## 四、数据结构

- `Slot` 只多一个 `bool`；位置本身直接用 `Transform.localPosition` 当「当前显示位置」，不另存一份（避免两份状态不一致）。

## 五、时序与流程

1. 新实体第一次出现：`EnsureSlot` 建出槽位（在原点）→ 本帧 `MoveSlotTo` 检测 `!Positioned` ⇒ **直接归位**（否则会从原点滑过去）。
2. 之后每帧：目标来自本帧快照（`PosXMm * 0.001`），按 `距离 / 快照间隔` 匀速追。
3. 到点即停（`MoveTowards` 自然停住），不会抖动。
4. 距离超阈值 ⇒ 归位（换局/复活/传送）。
5. 本地玩家（`OwnerPlayerId == m_ownerPlayerId`）也走同一套 —— 但本地玩家实际由 `PlayerMove` 驱动，服务端快照对它是「参考」；若两者差得远会触发瞬移兜底，这是预期（防漂移）。

## 六、技术选型与理由

| 选择 | 选定 | 理由 | 被否的方案 |
| --- | --- | --- | --- |
| 平滑方式 | **匀速追踪（MoveTowards）** | 零延迟、无历史缓存、实现小 | 缓冲插值（+33ms）、指数平滑（追不上） |
| 速度 | 距离 / 快照间隔，钳 60 米/秒 | 正常情况刚好在下一条快照到达时追上 | 固定速度（快慢都不对） |
| 瞬移 | 距离阈值 10 米 | 换局/复活必然远超阈值；正常移动 33ms 最多 0.2 米 | 比 tick 变化（要知道服务端 tick） |

## 七、风险与对策

- **横穿地图**（最典型）：靠瞬移阈值 + 首帧归位兜住。
- **快照卡顿后一次性追很远**：速度被钳在 60 米/秒；超过阈值的直接归位。
- **错误地在世界坐标与局部坐标间混用**：`MoveSlotTo` 全程用 `localPosition`，与原来一致。
- **暂停时角色还在动**：用 `Time.deltaTime`（暂停时为 0）⇒ 自然停住。
- **本地玩家被服务端快照拉走**：本地由 `PlayerMove` 每帧覆盖位置，快照只是参考；若真出现打架，说明服务端与本地预测差太多，属另一个问题（软校正不负责）。
