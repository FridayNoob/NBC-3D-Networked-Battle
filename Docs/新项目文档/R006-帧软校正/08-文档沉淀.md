## 二、模块文档

### 简介与使用场景

`SnapshotSceneBinder`（`Game\View\`）：把服务端 30Hz 快照搬到场景几何体上，并驱动相机跟随。
**R006 之后**：位置不再直接赋值，而是**朝目标匀速追**（60fps 连续），所以敌人/怪物看起来是平滑移动而不是每 33ms 跳一格。

### 核心接口

| 成员 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `m_snapshotIntervalSeconds` | Inspector float（秒） | `1/30` | 快照间隔。追踪速度 = 距离 ÷ 这个值 ⇒ 刚好在下一条快照到达时追上 |
| `m_teleportDistanceMeters` | Inspector float（米） | `10` | 瞬移阈值。距离超过它直接归位（换局/复活/传送） |
| `MaxChaseSpeed`（常量） | 60 米/秒 | — | 追踪速度上限，防飞出画面 |
| `Slot.Positioned`（私有） | bool | false | 首帧归位标记 |

### 使用示例（负责人亲手跑通，2026-10-31）

```text
Play（服务端开着）→ 看敌人胶囊走动：连续移动 ✔
换局 / 复活        → 瞬间出现在新位置，不滑过去 ✔
想更「软」一点      → 把 m_snapshotIntervalSeconds 调大（会落后于服务端）
想退回旧行为        → 把它调到极小（速度被钳位，等价于一跳一格）
```

### 实现原理（简要）

```
目标 = (PosXMm * 0.001, scale*0.5, PosZMm * 0.001)   // 局部坐标
if (!slot.Positioned)                → 直接归位（首帧）
else if (距离 >= 10)                  → 直接归位（瞬移）
else → speed = min(距离 / 快照间隔, 60)
       localPosition = MoveTowards(当前, 目标, speed * dt)
```

### 已知限制与坑点

- **位置不再精确等于快照**：这是平滑的代价。回放/对账请用**数据层快照**，不要用表现层位置。
- **本地玩家也走这条链**：它每帧被 `PlayerMove` 覆盖，快照只是参考；差超过 10 米会触发归位（防漂移，属预期）。
- 未做朝向插值、未做外推，网络延迟大时会「慢半拍」。
- 实体很多时每帧都算一次 `Distance`，可以优化成只算移动中的槽位。
- 胶囊仍然是**占位代理**（不是怪物模型），换模型是另一个需求。

### 修改维护注意事项

- **改阈值要成对想**：`m_teleportDistanceMeters` 太小 ⇒ 正常移动也被判瞬移（又变回跳）；太大 ⇒ 换局时会横穿地图。
- **别把 `localPosition` 换成 `position`**：槽位挂在池根下，坐标系必须一致。
- **别用固定速度**：固定速度在远近距离下都错，必须按「距离 / 快照间隔」算。
- **新加实体类型时**：仍然复用 `m_slots`，`Positioned` 会自动让新槽位首帧归位。

## 三、踩坑清单（现象 / 原因 / 解决）

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 每 33ms 跳一格 | 快照位置直接赋值 | `MoveTowards` 追踪 |
| 换局时横穿地图 | 目标在几十米外还在「追」 | 距离 ≥ 10 米直接归位 |
| 新实体从地图中心滑过来 | 槽位新建在原点 | `Positioned` 首帧归位 |
| 想逐帧采样却采不到 | MCP 的执行回调不跨帧 | 改用「时长 → 距离」二值实验 |
