- 约束：
  1. 纯 .NET、确定性（整数 + 逻辑帧，无随机）；
  2. 只消费 R022-1 的内核与条件，**不改它们**；
  3. **`CastSkill` 暂时恒失败**（服务端技能系统未做，负责人已确认先接线）；
  4. 不改玩家侧、不改协议、不改快照字段；
  5. 代码量预估 **≈460 行**（见 §七），符合 AGENTS.md §0.1。

## 三、方案

```
Ai/Bt/Actions.cs        7 个动作节点（Chase / BasicAttack / CastSkill / ReturnHome / Patrol / Idle / Wait）
Ai/Bt/BtTreeBuilder.cs  用代码搭三套默认树：wolf / boss（R022-3 再改成读 JSON）
Ai/Bt/MonsterBrain.cs   新大脑：每帧刷新目标 → Tick 树 → 记录 StateName/LastAction
DungeonBattle           普通怪与 BOSS 改用新大脑（旧文件暂时保留，R022-3 删）
```

**动作语义**：

| 节点 | 行为 | 返回 |
| --- | --- | --- |
| `Chase` | 设 `Chasing=true`，朝目标移动一帧 | Running（还没到）/ Success（已贴脸） |
| `BasicAttack` | 射程内且冷却好才打；`hits>1` 时按帧分段 | Success（打出去了）/ Failure |
| `CastSkill` | **恒 Failure** + 首次告警 | Failure |
| `ReturnHome` | 朝出生点走 | Running / Success（到家） |
| `Patrol` | 清除 `Chasing`，让实体自身巡逻 | Success |
| `Idle` | 清除 `Chasing`，站住 | Success |
| `Wait` | 按逻辑帧计时 | Running / Success |

## 四、关键技术判断

| 判断 | 理由 |
| --- | --- |
| 目标检测放大脑、不做成节点 | R022 的老坑：检测做成节点会在 Selector 里返回 Success 吃掉整帧 |
| `Chasing` 由动作节点写、`Step` 读 | 巡逻位移与追击位移必须二选一，否则"一边追一边被拉回" |
| 三套树用代码搭（暂不读 JSON） | R022-3 才做 JSON；先让行为跑起来，少一个变量 |
| 旧文件先保留 | 删掉会同时牵动 `DungeonBattle` 与探针；等 R022-3 一次替换干净 |
| 多段普攻用 `intervalTicks` 分帧 | 同一帧连打会跳过冷却语义；分段更接近"多段" |

## 五、已知坑

1. **Selector 短路**：`Chase` 若在"没贴脸"时返回 Success，后面的攻击分支永远不执行 → 必须返回 Running。
2. **`Chasing` 泄漏**：动作换了（如从 Chase 切到 Idle）必须清 `Chasing`，否则实体还在往目标走。
3. **探针耦合**：`Brains` 列表元素类型会从旧 `MonsterBrain` 换成新的，探针里 `BrainOf(...)` 的返回类型与 `StateName` 读法要同步改。
4. **BOSS 回位语义**：`MonsterAiProfile.Boss.LeashRadiusMm = 200`，回位到 200mm 内即成功，别写成 0。

## 六、结论与改动清单

- 新增：`Ai/Bt/Actions.cs`、`Ai/Bt/BtTreeBuilder.cs`、`Ai/Bt/MonsterBrain.cs`
- 修改：`DungeonBattle.cs`（建怪处改 new 新大脑；`Brains` 类型）、`_net-probe/Program.cs`（类型与状态读取）
- 不改：R022-1 内核与条件、玩家侧、协议、快照
