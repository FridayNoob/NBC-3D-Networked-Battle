# R043b 需求：技能结算与 BOSS 技能

需求编号：R043b　所属阶段：M4　作者：AI　状态：开发中

## 一、业务目标（一句话）

让服务端真正认识「技能」这件事：玩家按 Q/E 能打掉怪的血，BOSS 会用自己的三个技能打玩家，冷却与射程都由服务端说了算。

## 二、用户与场景

- 玩家：在副本里按 Q（火球）/ E（冰箭）对着狼王放，期望看到约 0.1~0.2 秒后怪掉血、飘字出现、技能进入冷却。
- 玩家：站着不动对远处放技能，期望被告知「够不着」，而不是打空气也掉血。
- BOSS：进入仇恨范围后，除了普攻，还会放火球与冰箭；技能没冷却好就继续普攻，不会站着发呆。

## 三、功能列表

| 优先级 | 功能 | 判据 |
| --- | --- | --- |
| P0 | `Skill.csv` 增加 `cooldownMs`、`rangeMm` 两列并生成到两端 | ConfigKit 0 错误；`Config_Skill` 多两个字段 |
| P0 | 服务端技能判定：施法者/目标/阵营/射程/冷却五道关 | 五条拒绝理由都能在日志里看到 |
| P0 | 命中延迟：按 `hitFrames[0]` 帧后扣血 | 探针里等 N 帧才掉血 |
| P0 | 协议 `SkillCast` 上行，服务端按 `player_id` 找英雄 | 单人副本按 Q 掉血 |
| P0 | BOSS 行为树插入 `CastSkill`，失败落回普攻 | 狼王对玩家造成 2001/2002 的伤害 |
| P1 | 冷却查询 `CooldownTicksLeft`（给 R043a 的界面用） | 探针读到的剩余帧数与表一致 |

## 四、边界（不做什么）

1. 不做蓝耗、能量、施法条、技能打断与升级。
2. 不做客户端预测伤害（等服务端 `ServerEvent.damage` 回来才飘字）。
3. 不做 BOSS 专属技能动画（先用普攻动画 + 飘字 + 日志）。
4. 不改锁步技能（`PVP_Room` 仍只跑普攻与移动）。
5. 不做范围伤害（AoE）、多段命中与位移技能。

## 五、优先级

先 P0 全部打通（能按 Q 掉血 + BOSS 会放技能），P1 的冷却查询在 R043a 之前必须能读到，否则技能栏只能猜。

## 六、验收标准（当…时，应…）

1. 当玩家按 Q 瞄准 2000mm 内的狼王时，应在 `hitFrames[0]` 帧后掉 500 血，并排出伤害飘字。
2. 当玩家在冷却内再次按 Q 时，应被拒（日志「技能还在冷却，还剩 N 帧」），血量不变。
3. 当玩家对 7000mm 外的目标按 Q 时，应被拒（日志「超出技能射程」）。
4. 当玩家按 E 时，应造成 80 点冰箭伤害，与 2001 各自独立冷却。
5. 当玩家按 R 时，因英雄只配了两个技能，应被客户端忽略且不报错。
6. 当狼王进入仇恨并冷却就绪时，应能对玩家造成伤害，且伤害值来自 2001/2002 表。
7. 当 BOSS 技能全部在冷却时，应继续用普攻，不站桩。
8. 当技能未配置（`skillIds` 为空）的怪尝试 `CastSkill` 时，应返回失败并落回普攻。
9. 当服务端收到不存在的技能编号时，应拒绝并记录理由。
10. 当服务端重启后，冷却从头开始（内存态，不落库）。
