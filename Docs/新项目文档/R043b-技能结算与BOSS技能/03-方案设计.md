# R043b 方案设计：技能结算与 BOSS 技能

需求编号：R043b　所属阶段：M4　作者：AI　状态：开发中

## 一、整体架构

```
客户端 PlayerBrain(Q/E) ──SkillCast(player_id, skill_id, target_id, tick)──▶
   NetSession.SendSkillCast
                                   RoomBattleService.HandleSkillCast
                                          │ 按 session.PlayerId 找英雄
                                          ▼
                                   DungeonBattle.TryCastSkill ──▶ SkillSystem.TryCast
                                                                   │ 五道关
                                                                   ├ 冷却表 caster+skill
                                                                   └ 待结算队列 PendingCast
                                   DungeonBattle.Step ──▶ SkillSystem.Tick
                                                                   │ 帧数减到 0
                                                                   ▼
                                                            ApplyDamage → 伤害事件 → 飘字
服务端 BOSS 树 CastSkill ──▶ DungeonBattle.TryCastSkill（同一入口）
```

## 三、接口（与最终代码逐字一致）

```csharp
// Server/NBC.Server.Game/SkillSystem.cs
public sealed class SkillSystem
{
    public SkillSystem(ServerTables tables);
    public bool TryCast(DungeonBattle battle, BattleEntity caster, int skillId, int targetId, out string reason);
    public void Tick(DungeonBattle battle);
    public int CooldownTicksLeft(int casterId, int skillId);
    public int PendingCount { get; }
    public long CastCount { get; }
}

// Server/NBC.Server.Game/DungeonBattle.cs（新增）
public bool TryCastSkill(BattleEntity caster, int skillId, int targetId, out string reason);
public int SkillCooldownTicksLeft(int casterId, int skillId);

// Client/Assets/_Project/Shared/Battle/BattleRules.cs（新增）
public static bool WithinRange(int axMm, int azMm, int bxMm, int bzMm, int rangeMm);

// Server/NBC.Server.Game/ServerTables.cs（扩行）
public readonly struct SkillRow   // (Id, Name, Damage, CooldownTicks, RangeMm, HitFrames, InvulnTicks)
public readonly struct MonsterRow // 增加 int[] SkillIds
```

约定：

1. `TryCast` 拒绝一律写人话 `reason`，**不**回 `ErrorResponse`（由世界状态决定，见 `RoomBattleService` 文件头第三节）。
2. `rangeMm` 指圆心到目标的直线距离；判定用平方和，边界算射中。
3. `CooldownTicksLeft` 返回剩余逻辑帧；0 表示可用。

## 四、数据结构

| 结构 | 字段 | 单位 / 取值 |
| --- | --- | --- |
| `SkillRow` | `CooldownTicks` | 逻辑帧（30Hz），`cooldownMs / 33` 向上取整 |
| `SkillRow` | `RangeMm` | 毫米，100~20000 |
| `SkillRow` | `HitFrames` | 逻辑帧数组（升序），一行可写多个命中帧；每段伤害 = 总伤害均分，余数补给最后一段 |
| `PendingCast` | `CasterId / TargetId / Damage / TicksLeft` | 实例编号 / 实例编号 / 点 / 帧 |
| 冷却表 | `Dictionary<(int caster, int skill), int ticks>` | 帧，每帧递减到 0 移除 |
| `MonsterAiProfile` | 新增 `SkillIds` | 配置编号数组，空数组表示不会技能 |
| `BtContext` | 新增 `SkillCursor` | 轮转下标，跨帧保留 |

## 五、时序与流程

1. 客户端按下 Q → `PlayerBrain` 找到 `RuntimeNetDriver` → `NetSession.SendSkillCast(2001, targetId)`。
2. 服务端 `HandleSkillCast`：`session.PlayerId` 找英雄 → `battle.TryCastSkill(hero, 2001, target, out reason)`。
3. `SkillSystem.TryCast` 依次检查：施法者活着 → 表里有该技能 → 施法者配了该技能 → 目标存在/活着/不同阵营 → 射程 → 冷却。
4. 通过：写冷却（`CooldownTicks`）、按 `HitFrames` 逐段入队（`TicksLeft = 该段帧`、伤害 = `SplitDamage` 均分）、`CastCount++`，返回 true。
5. 每帧 `Step` 末尾 `SkillSystem.Tick`：所有待结算 `TicksLeft--`，到 0 的调 `battle.ApplyDamage` 并移出队列。
6. BOSS 树：`Seq[HasTarget, InAttackRange, CastSkill]` 放在普攻之前；`CastSkill` 失败（冷却/无技能）就落到普攻分支。

## 六、选型与理由

1. **延迟结算队列** vs 立即扣血：选队列，技能才有「飞过去」的时间感，且帧号可复现。
2. **独立 `SkillSystem`** vs 塞进 `DungeonBattle`：选独立，`DungeonBattle` 已经 1400+ 行，规则再塞进去会破 SOLID 且难测。
3. **共享层加 `WithinRange`** vs 各写一份：选共享层，避免出现第二把「尺子」。
4. **`MonsterRow` 加 `SkillIds`** vs 在树里写死技能号：选表驱动，符合 §0.4 与「数值归负责人」。
5. **客户端临时转发** vs 等 R043a：选临时转发，否则 R043b 无法在单人副本里验「按 Q 掉血」。

## 八、风险与对策

| 风险 | 后果 | 对策 |
| --- | --- | --- |
| 动画帧与逻辑帧不同步 | 掉血比动画早/晚 | 用 `hitFrames` 里的帧号，日志打印实际帧差 |
| `hitFrames` 数组为空 | 进队列却永不出队 | `NormalizeHitFrames` 兜底为 1 帧 |
| 协议编号冲突 | 客户端解析错位 | 只在末尾加 `=9`，重生成后核对 |
| BOSS 技能卡住树 | BOSS 不普攻 | `CastSkill` 失败即 Failure，落到普攻分支 |
| 数值过强 | 火球秒狼 | 数值全在 CSV，负责人调 |
