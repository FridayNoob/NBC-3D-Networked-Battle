## 二、模块文档

### 简介与使用场景

`PlayerMove` + `FollowCamera`：让一个角色用键盘走动、相机第三人称跟随。
适用于任何「单人 + 键盘 + 第三人称」场景；联机版把输入换成网络下发即可（`InputCommand` 同构，可直接复用）。

### 核心接口

| 接口 / 字段 | 入参 | 出参 | 说明 |
| --- | --- | --- | --- |
| `PlayerMove.Update` | 无 | 无（改自身 Transform） | 引擎每帧调；读 `InputManager.Current` |
| `PlayerMove.m_moveSpeed` | float | — | 米/秒，默认 5 |
| `PlayerMove.m_turnSpeed` | float | — | 度/秒，默认 720 |
| `FollowCamera.LateUpdate` | 无 | 无（改相机 Transform） | 引擎在 Update 之后调 |
| `FollowCamera.m_target` | Transform | — | 跟谁，Inspector 拖入 |
| `FollowCamera.m_offset` | Vector3 | — | 相对偏移，默认 (0,4,-6) 米 |
| `FollowCamera.m_smooth` | float | — | 跟随顺滑倍率，默认 8 |

### 使用示例（负责人亲手跑通，2026-10-26）

```text
1) 场景里放 Plane（Scale 10,1,10）与 Capsule（改名 Player，Position 0,1,0）
2) Player 挂 PlayerMove
3) Main Camera 挂 FollowCamera，Target 拖成 Player
4) 点 Play，先点一下 Game 视图，按 W/A/S/D
```

### 实现原理（简要）

`InputManager` 每帧采集一次并产出 `InputCommand`（轴已量化成 -1000..1000）；
`PlayerMove` 只读 `Current`，除以 `MoveScale` 还原方向，归一化后转身并位移；
`FollowCamera` 用「角色位置 + 朝向 × 偏移」算机位，再 `Lerp` 追过去。

### 已知限制与坑点

- 无碰撞、无边界：会穿墙、会掉出地面。
- 依赖旧输入系统（`LegacyInputSource`）：切 New Input System 要换一个 `IInputSource` 实现。
- 相机 `Lerp` 系数在极低帧率（<10fps）下会一顿一顿。

### 修改维护注意事项

- 改手感只动 `m_moveSpeed` / `m_turnSpeed`，不要改算法。
- 改键位改 `InputMapping`，不要改 `PlayerMove`。
- 加第二个角色就再挂一份；要做「一个驱动者控多个」需回 03 重新设计。

## 三、踩坑清单（现象 / 原因 / 解决）

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 按键完全没反应 | Game 视图没有焦点；或 `InputManager` 没拿到采集源 | 先点一下 Game 视图；播放模式会自动装 `LegacyInputSource` |
| 角色一半埋在地里 | 胶囊原点在中心，y=0 | Position.y 设 1 |
| 松手后还在滑 | 用了 `Input.GetAxis`（自带平滑，本工程 gravity 3 / sensitivity 3） | 走 `InputCommand` 二值轴，或 `GetAxisRaw` |
| 斜着走更快 | 方向没归一化（W+D 长度 1.41） | `direction.Normalize()` |
| 技能「刚按下」偶尔丢 | 在 `Update` 里又调了一次 `InputManager.Tick` | **只读 `Current`**，Tick 由框架每帧做一次 |
| 想改键却发现写死 | 直读 `Input.GetKey` 绕过 A7 输入框架 | 读 `InputManager.Current`，键位在 `InputMapping` 里 |
