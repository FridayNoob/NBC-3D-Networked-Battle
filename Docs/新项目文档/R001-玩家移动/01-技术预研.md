# 01 技术预研

需求：R001-玩家移动
所属阶段：M4
作者：AI　状态：已确认（2026-10-26，负责人认可「为什么不用物理」）

## 一、调研目标与约束

- 目标：Unity 2022.3 下，让一个角色在地面按键盘移动并能转身，相机第三人称跟随。
- 约束：只做 PC；不许加新依赖；不引物理；本版只有一个角色；手感要「灵活」。

## 二、核心 API 清单（含官方文档）

| API | 用途 | 文档 |
| --- | --- | --- |
| `Transform.position` / `rotation` | 改角色与相机的位置朝向 | Unity Scripting API: Transform |
| `Input.GetKey(KeyCode)` | 读按键（旧输入系统） | Scripting API: Input |
| `Quaternion.LookRotation` | 由方向求朝向 | Scripting API: Quaternion |
| `Quaternion.RotateTowards` | 限速平滑转身 | Scripting API: Quaternion |
| `Vector3.Lerp` / `Mathf.Clamp01` | 相机平滑跟随 | Scripting API: Vector3 / Mathf |
| `Time.deltaTime` | 把「每秒」换算成「本帧」 | Scripting API: Time |

## 四、方案对比

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 改 `Transform` | 最简单、行为可预测 | 无碰撞，会穿墙 | 采用 |
| `Rigidbody` | 真实物理、能推箱子 | 惯性/摩擦/质量都要调，第一版难控 | 否 |
| `CharacterController` | 自带碰撞、能上斜坡 | 要配胶囊尺寸、处理台阶 | 以后再做 |

## 五、已知坑与版本兼容

- 编辑器里 `Input.GetKey` 需要 **Game 视图有焦点**（先点一下 Game 视图），否则像按键失灵。
- Unity 胶囊默认高 2 米、原点在中心 ⇒ 摆地面时 y 必须是 1。
- `Input.GetAxis` 有平滑（本工程 `gravity 3 / sensitivity 3`），松开后会滑一段；本需求要「松手即停」，所以用 `GetKey`。
- 若日后切 New Input System，`Input.GetKey` 会失效，需换 `Keyboard.current`。

## 六、结论

- 推荐：`Transform` 直接位移 + `Input.GetKey`，参数放 `[SerializeField]`。
- 不推荐：第一版就上物理（手感调不准，且本需求没碰撞）。
- 必须注意：`Time.deltaTime` 必乘；方向必归一化；相机必放 `LateUpdate`。
