# 03 方案设计

需求：R018-怪物仇恨半径调到 4 米
所属阶段：M4
作者：AI 起草　状态：已确认（2026-11-05）

## 一、整体架构

只改一个常量，链路完全不变：

```
BossBrain.Think → NearestAliveHero → 距离 > 半径 ? target=null : target
                                      ↑
                          只改这里（2200 → 4000）
```

## 二、模块划分

| 模块 | 本次改动 | 不负责什么 |
| --- | --- | --- |
| `DungeonBattle`（服务端） | 常量 `BossAggroRangeMm` 2200 → 4000，注释更新 | 不改移速、不改刷怪、不改场地 |
| `BossBrain` | **零改动**（读常量） | — |
| `_net-probe`（本地） | 守卫用例断言改写 | 不进仓库 |
| 客户端 / 协议 | **零改动** | — |

## 三、接口（★ 先定死）

```
DungeonBattle.BossAggroRangeMm : const int
    2200 → 4000（毫米；4 米）
    依据：副本 1001 的 spawnRadiusMm = 3000（场地半径 3 米），略大于场地 ⇒ 一进场就会被追
    保留：超出后 target = null（leash 回出生点）

守卫用例（_net-probe，本地）：
    原来：assert 最近出生距离 > 半径（2.5 米 > 2.2 米）
    改成：assert 半径 <= 场地半径 × 1.5（4.0 <= 4.5）—— 保留「别跨图追」的设计本意
```

## 四、数据结构

无（常量）。

## 五、时序与流程

1. 服务端每逻辑帧调 `BossBrain.Think`。
2. 取最近活英雄；距离 > 4000mm ⇒ 视为没有目标。
3. 状态机：有目标 ⇒ Chase/Attack；没目标 ⇒ Idle/ReturnHome。
4. 其余全不变。

## 六、技术选型与理由

| 选择 | 选定 | 理由 | 被否的方案 |
| --- | --- | --- | --- |
| 取值 | **4000mm（4 米）** | 场地半径 3 米，4 米 = 一进场就会被追；10 米在此图等价但会误导注释 | 10 米（数值无意义）、放大场地（关卡改动） |
| 范围 | **统一半径** | 负责人选定；改动最小 | 按怪种区分（要加配置列） |
| 守卫用例 | **改成「半径 ≤ 场地 × 1.5」** | 保住设计本意（别跨图追），又允许「全场可见即追」 | 直接删用例（失去回归保护） |

## 七、风险与对策

- **BOSS 太凶**（60 点/0.5 秒，1200 血约 10 秒死）：4 米下 BOSS 会主动压上来。对策：先看 Play 效果；太凶就另开需求做「BOSS 单独小半径」。
- **小怪一起压上来**：三只狼 + BOSS 同时接近，观感可能拥挤。对策：观察；必要时给怪加「分散/包抄」另开需求。
- **守卫用例红**：已规划改写。
- **改常量后忘记重编服务端**：启动时日志会打 tick 率与配置核对，注意看；必要时重编 Host。
