## 2026-11-12 方向调整：从"副本 demo"到"开放世界切片"

**负责人原话要点**：

> 调研原神，做一个开放世界：登录后进入大世界；采集资源进背包；打野怪；与 NPC 对话接任务；
> 与好友联机（进入好友世界 / 好友进自己的世界）；单人副本或多人联机副本 —— 这些用**状态同步**；
> 还可以开启 PVP 决斗（多个玩家被传入另一个副本战斗）—— 这里用**帧同步**。
> 状态同步和帧同步的大部分逻辑**优先放客户端**，但有些逻辑需要放服务器。

**已确认的解读（我复述、他认可）**：

| 项 | 结论 |
| --- | --- |
| 范围 | **方案 A：开放世界切片**（1 区域 + AOI + 采集/背包 + 野怪 + NPC 任务 + 1 副本 + 好友进世界） |
| 施工顺序 | 先 **AOI + 世界/场景**，再玩法（采集/NPC/任务），最后 PVP 帧同步 |
| 逻辑归属 | 移动/表现/预测在客户端；**伤害、掉落、背包、任务进度、PVP 胜负必须服务端** |
| 同步模式 | 大世界/副本 = 状态同步；PVP = 帧同步（单独场景，不混用） |

**沿用/新增的全局规则**：

1. **配置客户端调、写回 CSV**（AGENTS.md §0.4）：界面/表现/手感参数一律客户端可视化配置 → 写回 `Configs/Design/*.csv` → 生成 → 服务端权威。
2. **资产策略**（AGENTS.md §0.5）：**不要程序化生成美术资产**（不用代码批量造树/石/房子）；**优先用外部下载的现成素材**（CC0/免费包），并记录来源与许可证。
3. **上下文策略**：方向性决策随时写进本文件或对应需求 md，不只留在对话里。
