## 二、模块文档

### 2.1 内核与契约（`Ai/Bt/BtCore.cs`）

- **简介**：三态 + 参数接口 + 特性 + 抽象基类；每帧只调 `Tick`。
- **接口**：`BtNode.Tick(BtContext) → BtStatus`；`BtNode.Configure(IBtParamSource)`；`[BtNode("TypeName")]`。
- **示例（新增一个条件，只加文件）**：
  ```csharp
  [BtNode("HpAbove")]
  public sealed class HpAboveCondition : BtNode
  {
      public override string TypeName => "HpAbove";
      public override BtStatus Tick(BtContext ctx) => ctx.Self.Hp > 0 ? BtStatus.Success : BtStatus.Failure;
  }
  ```
- **原理**：参数在 `Configure` 一次性读进字段，`Tick` 不再分配、不再读参数；条件只读、不返回 Running。
- **坑**：条件若修改 `ctx` 或世界，`Selector` 的短路就会被破坏（本章第 1 条铁律）。
- **维护**：加节点只需新增一个类 + 特性；内核、组合、上下文都不用改（工厂在 R022-3 扫描注册）。

### 2.2 组合语义（`Ai/Bt/BtComposites.cs`）

- **简介**：`Selector` / `Sequence` / `Parallel`。
- **接口**：`AddChild(BtNode)`；`Tick` 返回三态。
- **示例**：`Sequence[HasTarget, InAttackRange, BasicAttack]` = 「有目标且够得着才打」。
- **原理**：Selector 第一个非 Failure 即赢；Sequence 遇 Failure/Running 短路；Parallel 全跑再聚合。
- **坑**：`Running` 在 Sequence 里也会短路 —— 这是"追到一半别顺手打"的正确行为。
- **维护**：只改遍历/聚合规则时动这一处，别在节点里各写一套。

### 2.3 6 个条件的边界（`Ai/Bt/Conditions.cs`）

| 节点 | 判定 | 边界（改数值前先看） |
| --- | --- | --- |
| `IsDead` | `Self.Alive` 取反 | HP=0 → Success |
| `HasTarget` | 目标非空且 `Alive` | 目标死 → Failure |
| `InAttackRange` | `DistanceTo <= rangeMm`（0→2000） | 2000 → Success；2001 → Failure |
| `AttackReady` | `skillId=0` 看冷却；`>0` 恒 Failure | 剩 1 帧 → Failure；0 → Success |
| `HPBelow` | 绝对值 `hp < t`；百分比 `hp*100 < t*maxHp` | 30/30 → Failure；29/30 → Success |
| `HomeFar` | `DistanceToHome > Profile.LeashRadiusMm` | 等于 → Failure；+1mm → Success |
