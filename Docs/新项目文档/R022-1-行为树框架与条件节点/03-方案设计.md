# 03 方案设计

需求：R022-1-行为树框架与条件节点
所属阶段：M4
作者：AI　状态：待确认（2026-11-09）

## 一、整体架构

```
R022-3 解析 JSON ──→ 按 [BtNode("TypeName")] 扫描注册的工厂创建节点 ──→ 挂 Children
                                    │
                                    ▼
                    MonsterBrain（R022-2）每个逻辑帧 Tick 根节点
                                    │
                    ┌───────────────┴───────────────┐
                    ▼                               ▼
              BtComposites（3）              BtLeafConditions（6）
              只做"遍历 + 短路聚合"           只读 BtContext，无副作用
                                    │
                                    ▼
                            BtContext / BtOps（世界能力薄封装）
```

## 二、模块划分

| 文件（`Server/NBC.Server.Game/Ai/Bt/`） | 负责 | 不负责 |
| --- | --- | --- |
| `BtCore.cs` | 三态枚举、`[BtNode]` 特性、抽象基类、`IBtParamSource` 参数接口 | 具体节点、工厂、JSON |
| `BtComposites.cs` | `Selector` / `Sequence` / `Parallel` 的遍历与聚合、`AddChild` | 叶子行为 |
| `BtContext.cs` | `MonsterAiProfile`、`BtContext`、`BtOps`（查敌/距离/移动/攻击/回位） | 树结构 |
| `BtLeafConditions.cs` | 6 个条件节点（含参数解析到字段） | 动作、修改世界 |

> 每个条件节点**一个类一个文件**？—— 不：6 个条件都很短且同类（只读判断），放一个文件更易读；
> 与 AGENTS.md §0.2 的关系：新增**第 7 个**条件时新增文件即可，不改本文件（见 §六 说明）。

## 三、接口（★ 先定死）

```csharp
public enum BtStatus { Success = 0, Failure = 1, Running = 2 }

// 参数来源：R022-3 从 JSON 的 Params 提供；本需求只依赖这个接口（DIP）
public interface IBtParamSource
{
    bool TryGetInt(string key, out int value);
    bool TryGetBool(string key, out bool value);
    bool TryGetFloat(string key, out float value);
}

[AttributeUsage(AttributeTargets.Class, Inherited = false, AllowMultiple = false)]
public sealed class BtNodeAttribute : Attribute
{
    public string TypeName { get; }
    public BtNodeAttribute(string typeName);   // 必须与客户端 BTNodeDefinitions 里的 TypeName 完全一致
}

public abstract class BtNode
{
    public abstract string TypeName { get; }                 // 与 [BtNode] 一致，便于日志
    public virtual void Configure(IBtParamSource p) { }      // 只在这里读参数（构造后不再读）
    public abstract BtStatus Tick(BtContext ctx);
}

public readonly struct MonsterAiProfile
{
    public int AggroRangeMm;
    public int MoveSpeedMmPerTick;
    public int LeashRadiusMm;
    public bool PatrolWhenIdle;
    public static MonsterAiProfile Melee { get; }    // (4000, 40, 100000, true)
    public static MonsterAiProfile Boss { get; }     // (4000, 40, 200, false)
}

public sealed class BtContext
{
    public DungeonBattle World;
    public BattleEntity Self;
    public int HomeXmm, HomeZmm;
    public BattleEntity Target;      // 由 MonsterBrain 每帧刷新（不是树节点）
    public int Tick;
    public MonsterAiProfile Profile;
    public bool Chasing;             // 动作节点写；Step 据此让位
    public string LastAction;        // 动作节点写（R022-2）
}

public static class BtOps
{
    public static BattleEntity FindNearestHero(DungeonBattle world, BattleEntity self, int rangeMm);
    public static int DistanceTo(BtContext ctx);                  // 到目标的距离（mm），无目标返回 int.MaxValue
    public static int DistanceToHome(BtContext ctx);
    public static void MoveTowards(BtContext ctx, int speedMmPerTick);
    public static void MoveHome(BtContext ctx, int speedMmPerTick);
    public static bool TryAttack(BtContext ctx);
}
```

条件节点构造约定（R022-3 要用）：
**无参构造 + `Configure(IBtParamSource)` 读全部参数**，`Tick` 内不再分配、不再读参数。

## 四、六个条件的判定规则（含边界）

| 节点 | 判定 | 边界 |
| --- | --- | --- |
| `IsDead` | `Self.Hp <= 0` | HP=0 → Success；HP=1 → Failure |
| `HasTarget` | `Target != null && Target.Alive` | 目标死 → Failure |
| `InAttackRange` | `DistanceTo <= 射程` | `rangeMm=0` → 用 2000；2000 → Success，2001 → Failure |
| `AttackReady` | `skillId=0` 看 `Self.AttackCooldownTicksLeft <= 0` | 剩 1 帧 → Failure，0 → Success |
| `HPBelow` | `percentOfMax` ? `hp*100 < threshold*maxHp` : `hp < threshold` | 严格小于 |
| `HomeFar` | `DistanceToHome > Profile.LeashRadiusMm` | 等于 → Failure，+1mm → Success |

> `AttackReady(skillId>0)`：服务端目前只有普攻冷却（技能系统未做）。
> 本需求约定：**skillId > 0 一律返回 Failure**，并在首次遇到时打一条 warning；技能系统落地后改这里。

## 五、数值与确定性

- 全部整数（mm / tick / hp）；**不用 float 时间、不用 Random**。
- `Configure` 阶段才读参数（float 参数只用于 `Wait`，本需求没有）。
- `BtContext` 每只怪一个、跨帧复用；节点类每棵树构造一次，`Tick` 不 new。

## 六、SOLID 自检

| 原则 | 本设计怎么满足 |
| --- | --- |
| **S** | 内核（BtNode）/ 组合 / 上下文 / 条件各自独立；组合只管遍历，条件只管判断 |
| **O** | 新增条件 = 新增一个类 + `[BtNode]`，内核、组合、工厂都不改（工厂扫描注册在 R022-3） |
| **L** | 契约写明：**条件节点不得修改 ctx 或世界**；`Tick` 只返回三态 |
| **I** | 参数只依赖 `IBtParamSource`（4 个方法），不依赖 JSON/文件/字典实现 |
| **D** | 节点依赖 `BtContext`/`BtOps` 抽象，不直接碰 `DungeonBattle` 内部字段 |
