## 一、一句话总结

> **在不依赖网络的前提下，做出了"接任务 → 打怪 → 任务完成 → 交付 → 奖励到账"的可演示闭环，

核对 `Docs\20` §三 的 M2 定义：**复用 M1 的框架/配置/日志看板，新增条件系统 + 任务运行时 + 任务 UI** —— 全部落地。

## 四、这一轮**真正的成本**在哪（如实记）

代码不是难点。**难点是把演示跑起来**——中间卡了四道坎，每一道都改成了机制：

| # | 坎 | 形状 | 改成了什么机制 |
| --- | --- | --- | --- |
| 1 | 模拟清单目录空 | 字段默认空串 + **提示说 A 代码做 B**（"留空=用默认"却 `return ""`） | 留空 → **自动挑最新的一份清单**，并打印用的是哪份 |
| 2 | **读源码读错了代码路径** | 窗口入口（`EditorSimulateBuildPipelineViewer`）输出 `<构建版本>/`；运行时反射入口（`BundleSimulateBuilder`）输出 `Simulate/` —— 我只读了一条 | 同上（**别让人填路径**）+ `Docs\16` 按两条源码改准 |
| 3 | 配置资产是**旧快照** | 两步流水线第二步要人手点，**忘了不报错** | 编辑器侧**过期检查菜单** + 运行时侧**数据预检**（缺 id 就启动时说清 + 给两步办法） |
| 4 | 导入菜单**随机挑错类型** | 工程里有两个同名 `HeroConfig`（生成物 + 测试假类型），判据是"任意程序集里第一个同名类型" | 判据收紧为"同名 **且** 真的有 `LoadFromTsv`"，有歧义**报出来不猜** |

> 📌 沉淀出的两条**新母题**（已写进 `Docs\00` v1.9.4）：
> ① **"读了源码"还不够，要读对代码路径**；
> ② **"手工步骤 + 没有提示" = 一定会在某天以别的 bug 的面目出现**（坎 1/3 都是"快照"）。

另有一类"红"值得单独记：**测试自己写错**占了 M2 期间红的大半
（阳性对照大小写、伤害算错、夹具造不出场景、断言持有了已销毁对象……）。
**报错信息指向的位置，和它真正想验的东西常常不是一回事** ——
遇到这种红，先问"我这个场景真的构造出来了吗"。

## 五、方法论沉淀（M2 期间**新学到的**）

| # | 教训 | 出处 |
| --- | --- | --- |
| 1 | **一个走不到的分支比没有分支更糟** —— 判据："**当你写不出某个状态的测试时，先怀疑那个状态是否真的存在**" | M2-B（"目标已经死了"的分支） |
| 2 | **注释写着 A、代码做的是 B，比没有注释更危险** | M2-B（`Bind` 说"装配时就报错"却只查一半）、M2-C（"留空=用默认"却返回空） |
| 3 | **规则一处实现、两个调用点 = fail early + fail loud**（不是"两套规则"） | M2-B（技能归属：装配期 + 结算期） |
| 4 | **"读了源码"还要读对代码路径** | M2-C（模拟清单两个入口） |
| 5 | **"手工步骤 + 没有提示" = 某天会以别的 bug 的面目出现** | M2-C（配置资产/清单都是快照） |
| 6 | **通用层不许认识业务词**（认识一次，复用就结束了） | M2-A（条件系统不认识"任务/成就"，有机械检查） |
| 7 | **"全有或全无"**：要么整个动作生效，要么一点都不生效 | M2-A（`Accept` 先校验后登记 / `Submit` 先查奖励再改状态） |
| 8 | **能测的界面**：模型与摆放分开，逻辑就全在 EditMode 里 | M2-D（视图模型 12 条，不需要预制体） |
| 9 | **闸门绿不等于 Unity 绿**：单程序集闸门抓不到 **asmdef 级**的程序集边界错误 | M2-D（CS0012，Boot 缺 `NBC.Framework.UI`） |

> 其中 **1/2/3/6/7** 是"设计层面"的收获，**4/5/9** 是"工具与流程层面"的收获。
> 后者更难得 —— 它们说明**我的验证手段本身也有边界，而边界要说清楚**。

## 六、遗留与下一步（不藏）

| # | 遗留 | 影响 | 计划 |
| --- | --- | --- | --- |
| 1 | **任务面板预制体没搭** | V6 的"看得见"这一半待验证（面板本身的 22 条用例已绿） | 你按 `Docs\22` D 组清单搭一次（5 个控件）；**不搭也能跑**（左上角有 OnGUI） |
| 2 | **"抵达区域"是瞬时事件** | 先走进区域、再接"抵达区域"任务 → 条件永远不推进 | 接取时做一次**状态回填**；M4 做成就时会撞上同一个问题（成就进度可持久化，登录要按已有进度回填） |
| 3 | **条件行不能跨任务复用** | 两条任务共用同一行会撞"重复登记"（有意设计） | 已写进 `Docs\17` §十三；加任务时给它**自己的**条件行 |
| 4 | **"测试里用到的技能必须属于那个单位"** 未做成机械检查 | M2-B 期间我在测试里错了两次（人眼扫必漏） | M3 顺手做（扫测试源码里的 `CastSkill`/`Bind` 调用对配置） |
| 5 | **配置热重载 / 增量导出（CFG-06/07）** | 每次改表都要"跑 CLI + 点导入" | M5（现在有**过期检查**兜底，不再是静默的坑） |
| 6 | **表现层完全没有** | 打怪只有 Console + OnGUI，没有模型/动画/飘字 | M3（副本与 BOSS 时一起做） |
| 7 | **客户端预测 / 回滚、网络模拟器（NET-07）** | M2 还没碰网络 | **M3**（需求 §6.1 的 P0） |
