| 项 | 内容 |
| --- | --- |

## 一、为什么会"乱码"（先把概念说清）

TextMeshPro **不用系统字体**。它用的是**预先生成好的 SDF 字体资产**：
一张装了字形"距离场"的图集 + 一张"哪个字符对应图集哪一块"的表。

而 TMP 默认给的那个 `LiberationSans SDF` **只包含拉丁字形**——
中文的字形**在它里面根本不存在**。所以中文渲染出来是一排方框（俗称"豆腐块"）。

> 📌 所以这件事**既不是编码问题、也不是乱码**，而是"**字体里没有这个字**"。
> 换成 UGUI 的老 `Text` 也是同一个道理（它会去找系统字体兜底，所以看起来"能用"，
> 但换台机器/打包到别的平台就未必）。

---

## 二、两条路，以及本项目为什么选 Dynamic

| | Static（预烘焙） | **Dynamic（动态）** ✅ |
| --- | --- | --- |
| 做法 | 在 Font Asset Creator 里**把用到的字全选出来**烤进图集 | 给一个源字体文件，TMP **按需把字形加进图集** |
| 优点 | 图集小、包体小、运行时零开销 | **任何字都能显示**（包括配置表里后加的字） |
| 缺点 | **字表之外的字照样是方框** | 需要**源字体进包**（本例 14.9 MB）；首次显示某字有一瞬间的生成延迟；图集会随运行增长 |

**本项目选 Dynamic。** 决定性理由：

> **任务的名称与描述来自配置表**（`Quest.name` / `desc`），**策划会改**。
> Static 的话，策划加一个带生僻字的任务名，界面上就是方框 ——
> 而这正是本项目一直在防的那类"**看起来正常、其实缺东西**"的问题。

📌 旁证：负责人的另一个工程 RPG2 里那份同名字体资产实测是
`m_AtlasPopulationMode: 1`（= Dynamic），1024×1024 —— **同一套做法**。

## 三、怎么接（两个菜单，**第二步最容易被漏**）

```
Tools/NBC/UI/① 生成中文字体资产（TMP，Dynamic）      ← 已有可用资产时**不重建**
Tools/NBC/UI/② 设为 TMP 默认字体 + 加为兜底字体
```

### ⚠️⚠️ 实测记录：这条路上我踩了三个坑（都写下来，别重复）

| # | 现象 | 真因 | 处置 |
| --- | --- | --- | --- |
| 1 | 面板中文**方框**，日志说"字体找到了并用上了" | 那是 **IMGUI** 的坑：`GUI.skin.font` 被每个 `GUIStyle` 自带的字体盖掉 | 字体要挂在 **`GUIStyle`** 上（见 §五） |
| 2 | 面板仍**方框**，资产里 `m_UsedGlyphRects` 一直空 | 源字体用了 **`.otf`**（CFF 轮廓）—— TMP 动态加载取不到字形 | 换 **`.ttf`**（旁证：RPG2 那份可用的资产指的是 `.ttf`） |
| 3 | 换 `.ttf` 后**一个字都不显示** | 用 `TMP_FontAsset.CreateFontAsset` 脚本生成的资产**图集是空的**（`Texture2D.m_CompleteImageSize: 0`、宽高 0） | **不再脚本生成**：改用一份**经验证可用**的资产（从 RPG2 整份搬，连 `.meta` 一起搬以保住 GUID） |

> 📌 第 3 条尤其值得记：**"资产建出来了"不等于"资产可用"** ——
> 我一开始只查了"文件在不在、GUID 对不对、模式是不是 Dynamic"，这些都是**表面**指标；
> 真正决定它能不能画出字的是**图集里有没有数据**（`m_CompleteImageSize`）与
> **有没有真的加进字形**（`m_UsedGlyphRects`）。
> 这和本项目一直在防的"看起来正常的假成功"是同一族 —— 只不过这次的"假成功"信号是**文件名和字段名**。

### 现在的资产（仓库里就这一份）

| 文件 | 大小 | 说明 |
| --- | --- | --- |
| `Art/Fonts/AlibabaPuHuiTi-3-55-Regular.ttf` | 8.5 MB | 源字体（Dynamic 模式要它进包） |
| `Art/Fonts/AlibabaPuHuiTi-3-55-Regular SDF.asset` | 2.1 MB | TMP 字体资产：**Dynamic** / 1024² 图集 / **图集有数据**（`m_CompleteImageSize: 1048576`）/ 71 个已烘焙字形 / 已开多图集 |

两份都是**从 RPG2 整份搬过来的**（连 `.meta`），GUID 不变，所以资产里的源字体引用不会断。
**仓库比原来小了 13 MB**（原来那份 `.otf` 14.9 MB + 21.7 MB 的 `.ttf` 都删了）。

### ① 生成字体资产（**备用路径**）

⚠️ 菜单 ① 现在的行为是：**资产已存在就只报告、不重建**（因为脚本生成那条路实测会产出"图集为空"的资产）。
只有你手动删掉资产之后，它才会用 `.ttf` 走 `CreateFontAsset` 重新生成 —— 那条路**不保证可用**，
真要走请用下面的官方窗口。

### ② 设为默认 + 加为兜底 + 项目级兜底（**三件事都要做**）

| 做什么 | 影响谁 |
| --- | --- |
| 设为 **TMP 默认字体**（写进 `TMP Settings.asset`） | **以后新建**的 TMP 文字默认用它 |
| 加进 `LiberationSans SDF` 的**兜底列表** | **已经摆好**的文字（TMP 组件上存着各自的字体引用，遇缺字形会去兜底列表找） |
| 加进 `TMP Settings` 的**项目级兜底列表** | 任何 TMP 文字找不到字形时的**最后一道网** |

> 📌 更省事的做法（**推荐**）：面板组件上有个 **Panel Font** 字段
> （`QuestPanel.m_panelFont`）—— 把这份字体资产拖上去，
> 面板就会**把字体直接写给每个文字**（含运行时克隆出来的行），**完全不依赖兜底链**。

### 走不通时的退路（官方窗口）

`Window → TextMeshPro → Font Asset Creator`：

| 字段 | 填什么 |
| --- | --- |
| Source Font File | 那份 `.ttf` |
| Sampling Point Size | 64（或 Custom 也行） |
| Padding | 5 |
| Atlas Resolution | 2048 × 2048 |
| Character Set | **Custom Range**（随便填几个字先出图集即可） |
| Render Mode | SDFAA |
| → | 点 **Generate Font Atlas** → **Save as...** 存到同目录 |

存完在资产的 Inspector 上把 **Atlas Population Mode 改成 `Dynamic`**，
然后再跑上面的菜单 ②。（Creator 只出静态图集，动态是资产的属性。）

## 五、追加：**IMGUI（`OnGUI`）的中文是另一套系统**（2026-09-23 实测踩到）

M2 的演示壳子用 `OnGUI` 画状态。**它完全不经过 TMP** ——
IMGUI 用的是**系统动态字体**，所以"TMP 字体资产配好了"对左上角那块 HUD **没有任何帮助**。

✅ 处理（`M2DemoBehaviour.EnsureGuiFont`，一次）：

1. Inspector 上拖了 **Gui Font** → 用它（最稳、跨平台）
2. 没拖 → **自动从操作系统里找一个中文字体**兜底
   （`Font.CreateDynamicFontFromOSFont`，按 `Microsoft YaHei` → `SimHei` → `SimSun` … 顺序试）
3. 都失败 → 打一条**说清怎么修**的警告（而不是静默显示方框）

### ⚠️⚠️ 关键坑：**光设 `GUI.skin.font` 没用，字体必须挂在 `GUIStyle` 上**

2026-09-23 实测踩到，现象很值得记：

```
日志：  [M2演示] HUD 字体：系统里找到了「Microsoft YaHei」并用上了
屏幕：  还是方框
```

原因：默认皮肤里 `label` / `box` 这些样式**各自带着内置 Arial 字体**，
它们**不会**去继承 `GUI.skin.font`。
所以"我设了皮肤字体"这件事**在引擎里是成功的、在屏幕上是无效的** ——
典型的"**日志说成功 ≠ 真的生效**"。

✅ 正解：把字体挂到**样式**上，全程只用这些样式：

```csharp
s_labelStyle = new GUIStyle(GUI.skin.label);
s_labelStyle.font = font;      // ← 关键在这一行
m_boxStyle = new GUIStyle(GUI.skin.box);
m_boxStyle.font = font;        // ← 外框样式也要挂，否则框里的内置字体照样方框
```

📌 **这也是本项目第 N 次撞上"看起来正常的假成功"** —— 只不过这次的假成功信号是
**我自己写的那条日志**（"找到了并用上了"）。教训：**日志要打在"确实生效"那一步之后**，
而不是"拿到了想做事的材料"那一刻。

> ⚠️ 路径 2 只在**开发机**上有效（打包到没装那个字体的机器就不行）。
> 但这块 HUD 本来就是开发期临时显示，正式界面（M3）会换成 TMP —— 这条路会自然退场。

### 实测记录：怎么判断"方框"来自哪一套

| 观察 | 含义 |
| --- | --- |
| 我们那份 `AlibabaPuHuiTi SDF.asset` 的 **`m_UsedGlyphRects: []`（0 个字）** | TMP **一次都没**向它要过字形 |

这条**有两解**，必须结合现场判断：

- 若方框在**任务面板（TMP）**上 → 说明 TMP 没走到兜底（或面板根本没绑上/没渲染中文）
- 若方框只在**左上角 HUD** 上 → 那是 IMGUI，和 TMP 无关（本篇 §五 的处理就是治它）

📌 **教训**：排查"中文方框"的第一件事是**先分清是哪一套字体系统** ——
TMP（字体资产）与 IMGUI（系统字体）互不相干，混在一起查会一直查错方向。
