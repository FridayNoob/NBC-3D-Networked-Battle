| 项 | 内容 |
| --- | --- |
| 日期 | 2026-09-23 |
| 起因 | 负责人：**"中文字体显示乱码"**（任务面板上的中文变成方框） |
| 结论 | **不是编码问题，是字体里没有那个字形** —— TMP 默认字体只有拉丁字形 |
| 做法 | 阿里普惠体 3.0（Regular）+ **Dynamic 模式**的 TMP 字体资产 |

## 一、为什么会"乱码"（先把概念说清）

TextMeshPro **不用系统字体**。它用的是**预先生成好的 SDF 字体资产**：
一张装了字形"距离场"的图集 + 一张"哪个字符对应图集哪一块"的表。

而 TMP 默认给的那个 `LiberationSans SDF` **只包含拉丁字形**——
中文的字形**在它里面根本不存在**。所以中文渲染出来是一排方框（俗称"豆腐块"）。

> 📌 所以这件事**既不是编码问题、也不是乱码**，而是"**字体里没有这个字**"。
> 换成 UGUI 的老 `Text` 也是同一个道理（它会去找系统字体兜底，所以看起来"能用"，
> 但换台机器/打包到别的平台就未必）。

---

## 二、两条路，以及本项目为什么选 Dynamic

| | Static（预烘焙） | **Dynamic（动态）** ✅ |
| --- | --- | --- |
| 做法 | 在 Font Asset Creator 里**把用到的字全选出来**烤进图集 | 给一个源字体文件，TMP **按需把字形加进图集** |
| 优点 | 图集小、包体小、运行时零开销 | **任何字都能显示**（包括配置表里后加的字） |
| 缺点 | **字表之外的字照样是方框** | 需要**源字体进包**（本例 14.9 MB）；首次显示某字有一瞬间的生成延迟；图集会随运行增长 |

**本项目选 Dynamic。** 决定性理由：

> **任务的名称与描述来自配置表**（`Quest.name` / `desc`），**策划会改**。
> Static 的话，策划加一个带生僻字的任务名，界面上就是方框 ——
> 而这正是本项目一直在防的那类"**看起来正常、其实缺东西**"的问题。

📌 旁证：负责人的另一个工程 RPG2 里那份同名字体资产实测是
`m_AtlasPopulationMode: 1`（= Dynamic），1024×1024 —— **同一套做法**。

## 三、怎么接（两个菜单，**第二步最容易被漏**）

```
Tools/NBC/UI/① 生成中文字体资产（TMP，Dynamic）
Tools/NBC/UI/② 设为 TMP 默认字体 + 加为兜底字体
```

### ① 生成字体资产

- 源：`Assets/_Project/Art/Fonts/AlibabaPuHuiTi-3-55-RegularL3.otf`
- 输出：`Assets/_Project/Art/Fonts/AlibabaPuHuiTi SDF.asset`
- 参数：**Dynamic**、图集 **2048×2048**、采样 **64px**、间距 **5**、**允许多图集**
- ⚠️ 图集与材质必须**作为子资产存进同一个 .asset**，否则重开工程后引用会丢
  （现象是"字体资产在，但一个字都不出"）

### ② 设为默认 + 加为兜底（**两件事都要做**）

| 做什么 | 影响谁 |
| --- | --- |
| 设为 **TMP 默认字体**（写进 `TMP Settings.asset`） | **以后新建**的 TMP 文字默认用它 |
| 加进 `LiberationSans SDF` 的**兜底列表** | **已经摆好**的文字（TMP 组件上存着各自的字体引用，遇缺字形会去兜底列表找） |

> 📌 **为什么必须做兜底那一步**：TMP 的文字组件上**序列化着一份字体资产引用**。
> 只设"默认字体"**只影响新建的组件** —— 你面板上那三个字仍然是 LiberationSans，
> 照样是方框。加进兜底列表之后，**已有预制体一个字都不用改**。

### 走不通时的退路（官方窗口）

`Window → TextMeshPro → Font Asset Creator`：

| 字段 | 填什么 |
| --- | --- |
| Source Font File | 那份 .otf |
| Sampling Point Size | 64（或 Custom 也行） |
| Padding | 5 |
| Atlas Resolution | 2048 × 2048 |
| Character Set | **Custom Range**（随便填几个字先出图集即可） |
| Render Mode | SDFAA |
| → | 点 **Generate Font Atlas** → **Save as...** 存到同目录 |

存完在资产的 Inspector 上把 **Atlas Population Mode 改成 `Dynamic`**，
然后再跑上面的菜单 ②。（Creator 只出静态图集，动态是资产的属性。）

## 四、已知局限（如实记）

| # | 局限 | 什么时候处理 |
| --- | --- | --- |
| 1 | **源字体进包**（.otf 14.9 MB） | M5 打包优化：按用到的字符**子集化**（`fonttools` 之类），能把这份压到几百 KB |
| 2 | 动态图集**随运行增长**（中文常用字约 3500 个） | 图集满时 TMP 会再开一张（多图集），不丢字但显存涨；M5 观察实测值再定 |
| 3 | 我**没法在 EditMode 里验证**这两个菜单（调的是 TMP 编辑器侧 API） | 由负责人在 Unity 里跑一次确认（Console 每步都有日志） |
| 4 | 只放了一份 **Regular** | 要加粗/其它字重就再拷一份文件（别在本文件上手改） |

## 五、追加：**IMGUI（`OnGUI`）的中文**

M2 的演示壳子用 `OnGUI` 画状态。IMGUI 用的是系统**动态字体**（Arial），
Windows 上缺字形时会**回退到系统字体**，所以中文**通常能显示**。

如果它也是方框，那就不是 TMP 的问题，而是 IMGUI 的默认字体不兜底 ——
两条路：① 给 `GUI.skin.font` 指定一个动态 `Font`；② **把 HUD 换成 TMP**。
M2 的 HUD 只是开发期临时显示，**优先级低**；M3 做正式 UI 时它会自然退场。
