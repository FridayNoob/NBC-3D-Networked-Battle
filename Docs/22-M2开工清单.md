## 一、M2 要达成什么

**一句话**：在**完全不需要网络**的前提下，做出"**接到一个任务 → 打一局 PVE → 任务完成 → 交付 → 奖励真的发下来**"的可演示闭环。

### 1.1 验收标准（源自 `Docs\20` §三 M2 行）

| # | 完成标准 | 对应任务 | 验证方式（可测） |
| --- | --- | --- | --- |
| V1 | **条件系统**落地：事件 → 进度 → 达成回调，且**不认识"任务/成就"这两个词** | **A1** | EditMode 测试；`Shared\Quest\` 里搜不到 "Quest" 字样（机械检查） |
| V2 | 任务运行时：接取 → 进度 → 完成 → 交付 → 发奖 | **A2** | EditMode 端到端用例（假表 + 假发奖口） |
| V3 | 新增配置表 `Quest` / `QuestCondition` / `Reward`（+ `Monster`，PVE 要用） | **A3** | ConfigKit 校验通过、三份产物一致、报错定位照旧 |
| V4 | 单机 PVE 最小战斗：属性 + 伤害结算 + 死亡事件 | **B** | EditMode 战斗结算用例 + PlayMode 冒烟 |
| V5 | 用**真实战斗事件**驱动任务条件（不是测试里手搓 `Notify`） | **C** | 端到端用例：打够怪 → 任务自动完成 |
| V6 | 任务 UI：接取 / 追踪 / 交付 | **D** | 面板 EditMode 用例（逻辑）+ 你点击验证（预制体） |

### 1.2 M2 的红线（**明确不做**，来自 `Docs\20` §二）

任务链、多分支、日常/周常、自动寻路引导；多阶段 BOSS、难度分级、随机词缀；成就、PVP、好友、聊天（M4/M5）。
