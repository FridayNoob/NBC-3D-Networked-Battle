## 三、⚠️ 三条"闸门"的关系（**这是本项目最反直觉的一点**）

```
_api-probe        把所有源码编进【一个】程序集  → 验语法/API，**没有程序集边界这回事**
_asmdef-probe     按 asmdef 边界【分别】编      → 验程序集引用（CS0012/CS0246）
Unity Test Runner EditMode 测试                 → 验行为（并且**只有它认得 Unity 的 asmdef**）
```

> 📌 **`_api-probe` 绿 ≠ Unity 绿。** 这是本项目记了 4 次以上的教训（`Docs\00` 里标为 W10）。
> **真实案例**：给 `BattleSession.FromConfigMgr` 加了一个**可选参数**（类型在 `NBC.Shared`），
> 单程序集闸门**绿**，Unity 报 `CS0012`，而调用方源码里**一个字都没提那个类型**。
> ⇒ 所以第 ③ 条命令不是可选项。
> ⚠️ 更细的一层：`_asmdef-probe` 第一版**自己也有 bug**（MSBuild 的 `ProjectReference`
> **会传递**，Unity 的 asmdef 引用**不会**）—— 它是靠"变异测试"才被证明有效的，
> 详见 `Docs\27-M4开工清单.md` §十一。

## 五、跑起来看（三个进程）

```powershell
# 服务端（⚠️ 先 build 再启动 —— 双击 bin 里的 exe **不会**编译）
dotnet build Server\NBC.Server.Host\NBC.Server.Host.csproj -m:1
Server\NBC.Server.Host\bin\Debug\net8.0\NBC.Server.Host.exe
```

启动横幅里会打 `Built :`（**四个 dll 里最新的时间戳**）——
⚠️ **它和你源码的时间对不上就说明你跑的是旧 exe**（`Docs\14` 那次事故就是这个）。

客户端：**Unity 里进 Play**；调试用 **`Tools/NBC/网络/网络调试窗口`**（连接 → 加入房间 → 打怪）。
⚠️ 窗口是**编辑器程序集**，EditMode 测试引用不到它 —— 所以它的正确性靠**你手点**验。

## 六、第一天**不要**做的事（省你两天）

| 别做 | 因为 |
| --- | --- |
| 别升 Unity 版本 / 换插件版本 | 决策已冻结（`Docs\00` §五），换版本会动 `.meta` 与包解析 |
| 别用 `float` 做**战斗数值** | 帧同步要**位级别确定**；`float` 的 `Sin`/`Sqrt` 在不同运行时可以不同，一次不同之后**每一步都放大** |
| 别把 `Shared\` 当成"想放啥就放啥" | 它要能在**没有 Unity** 的 .NET 8 上编译（`noEngineReferences: true` 是机械保证的） |
| 别在客户端算伤害/血量 | 服务端权威。客户端只做两件事：**只发意图、只显示快照**（完整理由见 `Docs\教学\M3-B`） |
| 别手工同步两份代码 | `Shared\` 是**唯一源码**，服务端 `<Compile Include>` 引它 —— 拷贝两份必然漂移且**不报错** |
| 别直接跑 `Docs\08-数据库脚本.sql` | 它第 38 行是 `DROP DATABASE`（**会清库**）。加表用幂等的 `Docs\08b-...` |
