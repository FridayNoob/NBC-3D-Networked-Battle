# 08 · 怎么自己验（所有闸门与探针清单）

> **目的**：让"**我这边验过了**"变成**你能自己重跑**。
> 每个都写明：**它验什么 / 一条命令 / 成功判据 / 它抓不到什么**。
> ⚠️ 最后那一列最重要 —— 不知道一个闸门抓不到什么，就会误以为它绿了就等于没问题。

---

## 一、⚠️ 先记住这张表：四道闸门各自认得什么

| 闸门 | 它认得 | 它**不**认得 | 要开 Unity？ | 在仓库里？ |
| --- | --- | --- | --- | --- |
| `_api-probe` | 语法 / Unity API 存不存在 / **C# 9** | **程序集边界**（它把源码编进**一个**程序集） | 用本机 Unity 程序集，**不用开 Unity** | ❌ 不进（15 处本机路径） |
| `_asmdef-probe`（生成器） | **程序集引用**（`CS0012` / `CS0246` 的跨程序集形态） | 行为 | 否（但要本机 Unity 程序集） | 生成器 ✅ / 生成物 ❌ |
| EditMode（Unity） | **行为** + **真正的 asmdef 规则** | —— | ✅ 要 | ✅（源码在 `Tests\EditMode\`） |
| 三个 `.NET` 探针 | **真跑的逻辑/网络/数据库** | Unity 侧行为 | 否 | ✅ |

> 📌 **本项目最贵的一条教训（记了 4 次以上）**：
> **`_api-probe` 绿 ≠ Unity 绿。** 真实案例：给一个方法加了个**可选参数**
> （类型在另一个程序集），单程序集闸门绿、Unity 报 `CS0012`，
> 而调用方源码里**一个字都没提那个类型**。
> ⇒ 所以下面 §二 的三条**不是可选项**。

## 二、四条命令（日常自检，约 1~2 分钟）

```powershell
cd "E:\U3D Projects\0_MyFile\3D联网战斗Demo"

# ① 服务端 + 全部工程能编（⚠️ -m:1 必须加，见下）
dotnet build Server\NBC.sln -m:1

# ② ⚠️ 程序集边界（唯一能抓 CS0012 的）
powershell -ExecutionPolicy Bypass -File Tools\Check-AsmdefBoundaries.ps1

# ③ 双端共享逻辑（条件系统，47 条；不需要 Unity / 不需要数据库）
dotnet build Server\_condition-probe\ConditionProbe.csproj -m:1
Server\_condition-probe\bin\Debug\net8.0\NBC.ConditionProbe.exe

# ④ Unity 侧：Window > General > Test Runner > EditMode > Run All（当前 691 全绿）
```

**成功判据**：① `0 个错误` ② `12 个程序集全绿` ③ `通过 47，失败 0` ④ `691 全绿`

⚠️ **①的"1 个警告"如果是 `MSB3027/MSB3021 文件被 NBC.Server.Host (PID) 锁定`** ——
那是**你的服务端正在跑**锁住了 `bin`，**不是代码错**。
要么关掉服务端再编，要么先用 `dotnet build Server\NBC.sln -m:1 -t:Compile` 做语法体检。

## 三、三个 `.NET` 探针（**都在仓库里**，克隆下来就能重跑）

> 📌 **它们为什么在仓库里**（判据见 `Server\.gitignore` 文件头）：
> **它们只引用仓库内的工程 + 公开 NuGet 包，没有任何"本机才有的路径"** ⇒
> 别人 clone 下来就能跑。而"实测数字"只有能被别人重跑才算**证据**，否则只是"我说过"。
>
> 对照：`_api-probe` 有 **15 处** `HintPath` 指向本机 Unity 安装目录，
> 所以它进不了仓库 —— 那类闸门只能由**你这台机器**跑。

### 3.1 `_condition-probe` —— 双端共享层的纯逻辑（**47 全绿**）

```powershell
dotnet build Server\_condition-probe\ConditionProbe.csproj -m:1
Server\_condition-probe\bin\Debug\net8.0\NBC.ConditionProbe.exe
```

| | |
| --- | --- |
| **验什么** | `Shared\Condition\`（条件系统）、`Shared\Battle\`（伤害结算）、`Shared\Net\`（分帧）、**真 socket**（`Framework.Net` 的 `TcpTransport`） |
| **为什么值得单开** | 共享层的卖点是"**双端同一份源码**"，而"能在 .NET 8 上真跑"这件事，**只有跑一遍才算数**（Unity 侧跑的是 Mono/IL2CPP） |
| **成功判据** | `通过 47，失败 0。结果：✅ 全绿` |
| **它抓不到** | Unity 侧行为；`#nullable` 与 C# 版本的差异（那由 ② 和 `_api-probe` 管） |

**几条值得看的用例**（它们各自钉住一条语义）：
`不清零且已达成 -> 注册时立刻通知`、`订阅晚了 -> 收不到那次『注册即达成』的通知`、
`归属表要在 Register 之前就绪`、`重复登记要报错`、`TCP：端口没人听 → 报人话原因而不是卡住`。

### 3.2 `_net-probe` —— 端到端**真 socket**（**93 全绿**）

```powershell
dotnet build Server\_net-probe\NetProbe.csproj -m:1
Server\_net-probe\bin\Debug\net8.0\NBC.NetProbe.exe
```

| | |
| --- | --- |
| **验什么** | 服务端用**生产代码**（`TcpServerTransport` / `ServerMessagePump`），客户端用 Unity 侧那份 `TcpTransport` 源码 ⇒ 验的是"**两个进程真的能说话**" |
| **为什么** | 这一点只有**真跑**才算数；权威用例仍在 Unity 侧 NUnit |
| **成功判据** | `通过 93，失败 0` |
| **它抓不到** | Unity 客户端的表现层（`SnapshotView` → 场景物体）；它只到"字节与语义"这一层 |

### 3.3 `_db-probe` —— 真 MySQL 往返（**51 全绿**）

```powershell
# ⚠️ 需要数据库密码（不进仓库，走环境变量）
$env:NBC_DB_PASSWORD = [Environment]::GetEnvironmentVariable("NBC_DB_PASSWORD","User")
dotnet build Server\_db-probe\DbProbe.csproj -m:1
Server\_db-probe\bin\Debug\net8.0\NBC.DbProbe.exe
```

| 块 | 条数 | 验什么 | 需要密码？ |
| --- | --- | --- | --- |
| 一 写回缓存逻辑 | 24 | 脏集合并 / 幂等 / `Remove` 写 0 / **单飞** / **`MarkUnflushed` 不覆盖新值** | 否（假 DAO） |
| 二 **真 MySQL：进度往返** | 6 | **重启后进度还在** / 绝对值覆盖（10 覆盖 4 而非 14）/ 收尾干净 | ✅ |
| 三 **DB-10 报错形状** | 5 | 密码错→「密码不对」；端口没人听→「连不上」+ 三条排查；**不互相误报**；**不打印密码** | 否（**故意连不上**） |
| 四 台账逻辑 | 8 | 单调性 / 两个编号空间 / **落库失败那一批要回到脏集** | 否（假 DAO） |
| 五 **真 MySQL：台账往返** | 5 | **重启后还记得发过**（防重复发奖的全部依据）/ 主键去重生效 | ✅ |

**成功判据**：`通过 51，失败 0`

⚠️ **第二/五块没有密码时会明确打印「跳过 + 怎么给密码」** ——
而不是安静少跑一半。**"探针全绿"可能其实是"那两块一条都没跑"**，那正是本项目一直在防的假绿。
⇒ 看到 `⏭️ 跳过` 时，**不要**把它当成通过。

⚠️ **探针会往真库里写测试数据、并在收尾删掉**（用 `player_id = 1`）。
如果你要跑它，**别在那个库上同时做别的实验**。

## 四、两个"不进仓库"的闸门（只有本机能跑）

### 4.1 `_api-probe` —— 语法 / Unity API / C# 9

```powershell
dotnet build Server\_api-probe\ApiProbe.csproj -m:1
```

| | |
| --- | --- |
| **为什么值得有** | 它用**本机那份 Unity 程序集**编译，所以能回答"我写的这个 API 在这个 Unity 版本里到底存不存在"；`LangVersion` 钉成 **9.0** 与 Unity 2022.3 一致，于是"闸门绿"就代表"语法上 Unity 也能编" |
| **为什么不进仓库** | **15 处 `HintPath` 指向 `D:\SOFT\Unity\...` 与 `Client\Library\...`** —— 换台机器就失效，放进去只会让人以为能用 |
| **成功判据** | `0 个错误` |
| ⚠️ **它抓不到什么** | **程序集边界**（它把所有源码编进**一个**程序集）。这就是 §4.2 存在的唯一理由 |

📌 它历史上抓到的两类真错（判据是"编译器说的"，不是猜的）：
**`UnityEngine.Input` 其实在 `InputLegacyModule`**、**`UnityEditor` 转发到门面 `UnityEngine.dll`**。
⇒ 报 `CS0246/CS0012` 时**先读它原文**，它常常直接告诉你该加哪个引用。

### 4.2 `Tools\Check-AsmdefBoundaries.ps1` —— 程序集边界（生成器**在仓库里**）

```powershell
powershell -ExecutionPolicy Bypass -File Tools\Check-AsmdefBoundaries.ps1
# 只生成不编译（排查生成物时用）：
powershell -ExecutionPolicy Bypass -File Tools\Check-AsmdefBoundaries.ps1 -GenerateOnly
```

**做法**：把每个 `asmdef` 的**文件集合**与**引用集合**照抄成 csproj，一个个真编。
`Server\_asmdef-probe\gen\` 是生成物（**不进仓库**，因为里面是本机 Unity 路径）；
**生成器 `Tools\Check-AsmdefBoundaries.ps1` 在仓库里** ⇒ 你能重建。

**成功判据**：`asmdef 边界检查：12 个程序集全绿 ✅`

⚠️ **它的命门是 `<DisableTransitiveProjectReferences>true</DisableTransitiveProjectReferences>`**：
MSBuild 的 `ProjectReference` **默认把引用传递下去**，而 **Unity 的 asmdef 引用绝不传递**。
少了那一行，这个闸门**抓不到它要抓的那个错** —— 我就是这么发现的（`Docs\27` §十三）：

| 变异测试 | 结果 |
| --- | --- |
| 基线（已修） | 12 个程序集全绿 ✅ |
| 变异（把那个坏参数加回去） | 单程序集闸门 **0 错**（盲区坐实）／本闸门 **[红] NBC.Boot**，复现出与 Unity **同一个文件同一个列号**的 `CS0012` |
| 还原 | 12 全绿 ✅ |

> 📌 **一个新加的检查，必须先用变异证明它会红。** 否则你只是多了一个"看起来像检查"的东西。

⚠️ **`Check-ScriptEncoding.ps1` 的存在理由**：Windows PowerShell 5.1 读**没有 BOM** 的中文 `.ps1`

⇒ 所以它必须是**机械检查**，不能靠自觉。

## 七、⚠️ 跑之前最容易踩的四条（都会让你得到**假结果**）

| 坑 | 表现 | 怎么办 |
| --- | --- | --- |
| **没加 `-m:1`** | 报 `0 个错误` 但**退出码 1**（本机并行 MSBuild 静默失败） | 一律加 `-m:1`（你自己终端里不受此限，但加上无害） |
| **跑的是旧产物** | 改了代码、重启服务端、**什么都没变** | ⚠️ **双击 `bin` 里的 exe 永远不会编译**。用"先 build 再启动"；服务端启动横幅的 `Built :` 就是四个 dll 里最新的时间戳，**对不上就是旧 exe** |
| **`--no-build` / `-t:Compile` 被当成"验过了"** | `-t:Compile` **只编译、不写输出目录**；`--no-build` 明确表示"跑现成的" | 它们只算**语法体检**；要看行为必须真构建 + 真跑 |
| **看到探针打「跳过」却当成通过** | 比如 `_db-probe` 第二/五块没密码时**只跳过** | 判据是看**块数**，不是只看最后那行"全绿" |
