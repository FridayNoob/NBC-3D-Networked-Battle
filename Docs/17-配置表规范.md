## 一、为什么"先写规范再写代码"

`Docs\16` 给 C2 定的验收是：

> **故意写错一格 → 报错定位到「文件 + 表 + 行 + 列」**

这句话只有在**"什么算错"已经被事先定义清楚**之后才有意义。
否则写工具的过程就变成"一边写解析器、一边定义规则"——
而规则会在**实现方便**的地方悄悄变形（例如"空单元格就当 0 吧，省事"），
最后交付的是一份**只有实现者知道**的隐性规范。

**所以这份文档是工具与策划之间的契约**：契约先冻结，然后工具去实现它。
下面每一条都写成**可判定**的形式（"对/错"没有歧义），因为工具要拿它做判断。

## 二、文件、工作表与命名

| 对象 | 规则 | 例子 |
| --- | --- | --- |
| **Excel 文件** | 放 `Client\Assets\_Project\Configs\Design\` 下，名字随意（仅供人看） | `Hero.xlsx` |
| **工作表（sheet）** | ⚠️ **一个 sheet = 一张表**，且 **sheet 名必须等于表名** | sheet 名必须是 `Hero` |
| **表名** | **大驼峰、单数**，只允许 `A-Z a-z 0-9` | `Hero` ✅ / `heroes` ❌ / `Hero_Table` ❌ |
| **行数据类型** | `Config_<表名>`（由工具生成） | `Config_Hero` |
| **SO 类型** | `<表名>Config`（由工具生成） | `HeroConfig` |
| **SO 资产** | `Client\Assets\_Project\Configs\<表名>Config.asset` | `HeroConfig.asset` |
| **字段名（第 1 行）** | **小驼峰英文**，与生成的 C# 字段**同名**；禁止中文、空格、`-` | `moveSpeed` ✅ / `MoveSpeed` ❌ / `移动速度` ❌ |
| **主键字段名** | **必须叫 `id`**（不接受 `Id` / `ID` / `key` / `uid`） | `id` |
| **枚举** | **在 C# 里手写定义**，Excel 只写成员名 + 类型写 `enum:类型名` | `enum:EDamageType` |

> **为什么强制 sheet 名 == 表名**：报错定位的第一个要素是"**文件 + 表**"。
> 如果一个文件里塞十张 sheet、sheet 名还和文件名对不上，
> 策划看到 `Hero.xlsx` 的报错会以为在找 `Hero` 表，实际上错在 `Monster` sheet 里 ——
> **定位信息本身就变成了误导**。

> **为什么主键必须叫 `id`**：工具要能**不看第 4 行就知道哪列是主键**（给个 typos 兜底），
> 也因为外键写的是 `ref:Hero` —— 如果每张表的主键叫法都不一样，外键就没法统一。

## 三、表头结构：五行，精确到格子

| Excel 行 | 内容 | 必填 | 例 |
| --- | --- | --- | --- |
| **第 1 行** | **字段名** | ✅ | `id` `name` `hp` `moveSpeed` |
| **第 2 行** | **中文注释**（给策划 / review 用） | ✅ | `编号` `名称` `生命值` `移动速度（毫米/秒）` |
| **第 3 行** | **类型** | ✅ | `int` `string` `int` `int` |
| **第 4 行** | **校验规则**（可留空） | ⭕ | `key` `` `range(1,999999)` `` |
| **第 5 行起** | **数据** | ✅ | |

**几条钉死的细节**（每一条背后都是一个"静默出错"）：

| # | 规则 | 不这么定会怎样 |
| --- | --- | --- |
| 1 | **第 1 行不得有空列**：字段名一旦中断，右边再有内容就报错 | 策划在中间空一列做视觉分隔 → 工具猜"这列不要了" → **某列数据被静默丢弃** |
| 2 | **第 1 行以 `#` 开头 = 整列忽略** | 策划想临时停用一列，只能删掉再手抄回来；给了 `#` 就不用删 |
| 3 | **第 2 行（注释）必须填** | 没有注释的配置表，半年后没人知道 `moveSpeed = 1500` 是"米/秒"还是"毫米/秒" |
| 4 | **行首整行以 `#` 开头 = 忽略该行** | 策划写备注不会被当成数据 |
| 5 | **整行为空 = 表结束**；若空行之后**又有数据行** → **报错** | 这是经典陷阱：表中间空一行，后面几十行数据**静默消失**，而且看上去"导出成功" |
| 6 | **不允许合并单元格**（表头区与数据区都不允许）→ 一律报错 | 合并单元格会让"这一格的值"变成"哪一格？"，解析结果取决于读取方式 |
| 7 | **不允许公式**（`=SUM(...)`）→ 一律报错 | 工具读到的是**公式缓存值**，Excel 一改就变，导出的 SO 不可复现 |

## 四、类型系统（完整清单）

| 类型写法 | 生成的 C# 字段类型 | Excel 里怎么写 | 可空写法 |
| --- | --- | --- | --- |
| `int` | `int` | `100` | 见 §六 |
| `long` | `long` | `10000000000` | 见 §六 |
| `float` | `float` | `1.5` | ⚠️ **仅表现层**，见下 |
| `bool` | `bool` | `true` / `false` / `1` / `0` | 见 §六 |
| `string` | `string` | 任意文本 | 见 §六 |
| `enum:类型名` | 该枚举类型 | **成员名**（`Fire`），不是数字 | 见 §六 |
| `int[]` | `int[]` | 逗号分隔：`1,2,3` | 见 §六 |
| `ref:表名` | `int` | 对方表的主键值：`1001` | `ref:表名?` |
| `ref:表名[]` | `int[]` | 逗号分隔：`1001,1002` | `ref:表名[]?` |
| 任意类型加 `?` | 可空 | 留空 | —— |

### ⚠️ 4.1 最重要的一条决策：**战斗数值禁止用 `float`**

这条直接来自 M1-D2（确定性定点数学）：

> 帧同步要求**双端算出位级别相同**的结果。
> `float` 的 `Sin` / `Sqrt` / 甚至 `a * b + c` 的**舍入方式**在不同运行时、不同 CPU 上**可以不一样**，
> 而且**一次不一样之后，之后每一步都在放大**。

所以：

| 用途 | 允许的类型 | 单位约定 |
| --- | --- | --- |
| **参与战斗结算** | `int` / `long` | **单位必须写在中文注释里** |
| 比例 / 百分比 | `int` | **万分比**：`1500` = **15.00%** |
| 距离 / 坐标 / 速度 | `int` | **毫米**（`1500` = 1.5 米） |
| 时间 | `int` | **毫秒**（帧号另算） |
| **纯表现层**（相机距离、UI 动画时长） | `float` **可以** | 但**第 4 行必须写 `view`**（见下） |

**工具据此强制检查**：类型是 `float` 而第 4 行没有 `view` 标记 → **报错**。

> **为什么用"万分比"而不是百分比**：百分比只有两位整数精度，
> "暴击率 12.34%" 就写不出来了；万分比留了两位小数，且**仍然是整数**，定点运算里不丢精度。
>
> **代码里怎么用**：
> ```csharp
> // 配置里写 1500（万分比），结算时转成定点数
> Fix64 ratio = (Fix64)cfg.CritRatePerTenThousand / (Fix64)10000;
> ```
> ⚠️ **工具绝不允许把 Excel 里的小数自动转成 `Fix64`**
> —— `Fix64` 从 `float` 的转换是 `explicit`（必须显式写出 `(Fix64)`），
> 那是 D2 故意设的**路障**：让你每次转换都必须**说出口**。
> 自动转换会把"我用了浮点"这件事埋进流水线里，而它**不会报错**。

### 4.2 `bool` 的写法

只接受 `true` / `false` / `1` / `0`（大小写不敏感）。

⚠️ **不接受** `是` / `否` / `Y` / `N` / `✓` —— 这些会让"空值"和"假"混在一起，
而**"没填"和"填了假"是两件事**（见 §六）。

## 五、主键与外键

### 主键

| 规则 | 值 |
| --- | --- |
| 数量 | **恰好一列**（写 `key` 规则；若不写 `key`，工具按"字段名是 `id`"推断，但**报一条警告**） |
| 类型 | **只能是 `int`**（M1 不支持字符串主键 / 复合主键） |
| 取值范围 | **`1 .. 2147483647`**（`0` 与负数**报错**） |
| 唯一性 | 全表唯一，重复 → 报错（指出**两条**的行号） |

> **为什么 `0` 不能用**：`0` 在 C# 里是 `int` 的默认值。
> 一旦允许 `id = 0`，**"忘了赋值"和"赋成了 0"就分不开了** —— 又是一个静默失败。

### 外键

| 规则 | 说明 |
| --- | --- |
| 写法 | `ref:表名`（单个）/ `ref:表名[]`（多个） |
| 校验 | 值必须**存在于对方表的主键集合**里；不存在 → 报错（指出是哪个表、哪个值） |
| 空值 | 只有 `ref:表名?` 允许留空（表示"无引用"） |
| 数组 | 逗号分隔，**允许重复**（M1 不查重）；支持 `ref:表名[]?` |
| **不做** | **外键环检测**（A → B → A）。M1 只做存在性检查，见 §十一 |

> **外键顺序**：工具按"表名的字典序"解析，若遇到引用关系则**递归先解析被引用表**。
> 因此**不要求**你在 Excel 里按依赖顺序排列文件。

## 六、空值策略（**这一节最容易出静默 bug**）

先看 Excel 的默认行为：

| 单元格空着时，各种类型会读到什么 |
| --- |
| `int` → `0` |
| `string` → `""` |
| `bool` → `false` |

**三者都是"看起来完全正常的值"**。策划漏填一格 `hp`，程序拿到 `0`，
然后你会看到"一个血量是 0 的英雄"—— 而不是"一个报错"。

### 所以规则是

| # | 规则 |
| --- | --- |
| 1 | **默认所有字段都不允许空**。空着 → **报错** |
| 2 | 确实允许为空的，类型**加 `?`**（`int?` / `string?` / `ref:Hero?` / `ref:Skill[]?`） |
| 3 | **"空"的唯一写法是"什么都不写"** |
| 4 | 写了 `-` / `--` / `null` / `NULL` / `无` / `N/A` → ⚠️ **报错**，并在提示里写"要表示无请留空" |

**规则 4 是刻意的**：策划的习惯是用 `-` 表示"无"。
如果我们默默接受它，那么一个 `string` 字段会拿到字符串 `"-"`，
一个 `ref:Hero` 字段会因为"`-` 不是数字"而报另一个更晦涩的错。
**与其让它以别的面目出现，不如在它出现的那一格就说清楚。**

### 可空字段的运行时语义

| 类型 | 空值在生成的 C# 里是什么 |
| --- | --- |
| `int?` / `long?` | `int?` / `long?` → `null` |
| `string?` | `null`（**不是 `""`** —— `""` 和"没填"是两件事） |
| `bool?` | `bool?` → `null` |
| `ref:表名?` | `int?` → `null` |
| `X[]?` | `null`（**不是空数组** —— 同上） |

> **`null` 与空集合要分开**：`skillIds = （空）` 意味着"这个字段没配"，
> `skillIds =` 后跟一个空字符串意味着"配了，但一个都没有"。
> 前者是**配置缺失**（该报错或该走默认），后者是**明确的零**。
> 这和 E1 那个"`N/A` 不是 `0`"是**同一条原则**：**宁可说不知道，也别编一个。**

## 七、校验规则（第 4 行）语法

规则**只允许下面这套**（封闭集合，不做表达式解析）：

| 规则 | 适用类型 | 含义 |
| --- | --- | --- |
| `key` | `int` | 声明主键（**有且仅有一个**） |
| `range(a,b)` | 数值 | 闭区间 `a <= v <= b` |
| `min(a)` | 数值 | `v >= a` |
| `max(a)` | 数值 | `v <= b` |
| `unique` | 任意 | 该列全表**不重复** |
| `view` | `float` | 声明"仅表现层数值"（**`float` 必须带**） |
| `len(a,b)` | `string` | 字符串长度区间（按**字符数**，非字节） |

多个规则用 **`;`** 分隔，例如：`range(1,100);unique`。

**未识别的规则名 → 报错**（不忽略）。
理由：`ranage(1,100)` 拼错时如果被忽略，这条校验就**静默消失了**，
而表照样导出成功 —— 这正是本项目最讨厌的那类失败。

## 八、报错格式契约（**这就是 C2 的验收标准**）

### 8.1 单条错误

```
[配置表] <文件相对路径> › <工作表名> 第 <Excel行号> 行 «<字段名>»（第 <列序号> 列，Excel 列号 <A>）：
    <一句话说明>
    期望：<规则或类型>
    实际：<单元格原文，空则显示 <空>>
```

**真实例子**：

```
[配置表] Assets/_Project/Configs/Design/Hero.xlsx › Hero 第 12 行 «hp»（第 5 列，Excel 列号 E）：
    hp 超出允许范围
    期望：range(1,999999)
    实际：0
```

⚠️ **"文件 + 表 + 行 + 列"四个要素缺一不可** ——
策划拿到报错的第一反应是"**在哪**"。少了任何一个，都要来回问一轮。

### 8.2 三条钉死的细节

| # | 规则 | 理由 |
| --- | --- | --- |
| 1 | **行号是 Excel 里的真实行号**（数据从第 5 行开始 → 第一条数据的报错就是"第 5 行"） | 否则"第 7 行"永远说不清是 Excel 第 7 行还是第 3 条数据。**策划打开的是 Excel，所以行号必须是 Excel 的行号** |
| 2 | **一次报出全部错误**，最后给总数（不是遇到第一个就停） | 策划改一轮就能全改完；错一个改一个要来回十几次 |
| 3 | **有错就阻止导出**（不生成半成品） | 半成品 SO 比没有 SO 更危险：游戏能跑，数据是错的 |

### 8.3 汇总报告（CFG-05）

不论成败都打印一张表（`导出报告`）：表名 / 数据行数 / 错误数 / 警告数 / 耗时。

**警告 ≠ 错误**：警告不阻止导出。M1 的警告只有一种 ——
"主键字段名是 `id` 但第 4 行没写 `key`"（能用，但不明确）。

## 十、M1 范围（**需要你确认**）

`Docs\16` 待决第 4 项建议 M1 只做 **3 张表**。我的建议是这三张：

| 表 | 覆盖到的规范特性 |
| --- | --- |
| **`Hero`** | 主键 / `int` / `string` / **`float` + `view`** / `ref:Skill[]`（数组外键） |
| **`Skill`** | **`enum:`** / `int[]` / `range` / `min` / **可空外键** `ref:Buff?` |
| **`Level`** | **`string` 非键** / `unique` / `len` / 多行数据 |

**为什么是"三张"而不是"全部十张"**：§10.4 列了十张表，
但**表多不等于流程通**。工具的价值在于**校验与报错**，
而三张表足以把 §四的类型系统、§五的外键、§七的规则全部覆盖一遍。
剩下的表（Monster / Buff / Drop / Item / GlobalConst / AiTreeParam / Localization）
**只是同一套流程重复**，M2 加进来是纯增量。

**示例（`Hero.xlsx` 的 `Hero` sheet 前 3 条数据的表头长这样）**：

| | A | B | C | D | E | F |
| --- | --- | --- | --- | --- | --- | --- |
| **1** | `id` | `name` | `hp` | `moveSpeed` | `critRatePerTenThousand` | `skillIds` |
| **2** | 编号 | 名称 | 生命值 | 移动速度（毫米/秒） | 暴击率（万分比） | 技能列表 |
| **3** | `int` | `string` | `int` | `int` | `int` | `ref:Skill[]` |
| **4** | `key` | `len(1,16)` | `range(1,999999)` | `min(0)` | `range(0,10000)` | |
| **5** | 1001 | 剑士 | 1200 | 5000 | 1500 | 2001,2002 |
| **6** | 1002 | 法师 | 800 | 4800 | 500 | 2003 |

## 十一、**故意不做**的东西（写清楚，免得以后以为漏了）

| # | 不做 | 什么时候做 |
| --- | --- | --- |
| 1 | 字符串主键 / 复合主键 | 不做（需求没要求；且会让外键语法复杂化） |
| 2 | 外键**环**检测（A→B→A） | 不做。M1 只做存在性检查。**风险如实写在这里**：环本身在配置里通常不是错（很多表就是互相引用），真正的错误是"运行时递归爆栈"，那个要由使用方加深度限制 |
| 3 | 合并单元格 / 公式 | **永不做**（一律报错，见 §三） |
| 4 | `.csv` 来源（CFG-10） | M2（P2） |
| 5 | 增量导出（CFG-06） | M2（P1）。**但生成物入库 + Diff 已经能看出"这次改了什么"** |
| 6 | 运行时热重载（CFG-07） | M2（P1） |
| 7 | 多语言拆列（CFG-12 / Localization 表） | 留接口，M2 |
| 8 | 导出 protobuf 给服务端（CFG-12） | M2（P2） |
| 9 | 单位自动换算（把"1.5 米"转成 1500 毫米） | **永不做**。单位是**人的约定**，工具只检查"注释里写没写单位"，不猜数值含义 |
