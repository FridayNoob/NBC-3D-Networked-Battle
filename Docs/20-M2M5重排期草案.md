## 一、两个"省下来的大钱"（先说这个，因为它决定了后面能做什么）

| 原本以为要做的 | 为什么现在不用做 |
| --- | --- |
| **AOI**（可见性裁剪：只同步玩家周围的实体） | **2~4 人**的房间制下，人人可见 → AOI 没有存在意义 |
| **分线 / 分服** | 单服玩家数远低于需要分线的量级 |

> 📌 **先定规模再定架构** 这条在这里直接兑现了。规模没定时讨论 AOI 是纯浪费 ——
> 这一条值得写进面试里：**"我问清了规模，于是砍掉了两个最贵的系统"**。

## 二、每个系统"最小可信闭环"是什么（**这是本草案的核心**）

Demo 的关键不是"做了多少"，而是"**每个系统都有一个能演示、能讲清的闭环**"。

| 系统 | 最小可信闭环（做完这个就算"有了"） | **明确不做**（除非后面有富余） |
| --- | --- | --- |
| **任务** | 接取 → 条件（击杀 N 只怪）→ 完成 → 交付 → 发奖励（经验/物品） | 任务链、多分支、日常/周常、自动寻路引导 |
| **副本 + 组队** | 2 人组队 → 进副本实例 → 打死 **1 个 BOSS** → 掉落进背包 → 退出结算 | 多阶段/多 BOSS、机制编排、难度分级、随机词缀 |
| **PVP** | 2v2 进小房间 → 打完一局 → 胜负判定 → 战绩落库 | 段位/赛季、平衡性调参、观战 |
| **成就** | 达成条件（累计击杀 10）→ 解锁 → 展示列表 → 落库 | 成就点数、奖励发放、隐藏成就 |
| **好友** | 加好友（按名字/ID）→ 列表 → 在线状态 → 删好友 | 推荐好友、黑名单、亲密度 |
| **聊天** | **私聊** + **世界频道**；分频显示 | 队伍/公会频道、语音、表情、富文本、离线消息队列（**这一项最容易低估**） |
| **开放世界** | 3~4 个区域，走区域边界/传送点切换加载 | 无缝地形、动态天气、载具 |

> ⚠️ **"最小可信闭环"的判据**：**能演示 + 能讲清"为什么这么设计"**。
> 例如聊天只做私聊+世界频道，但要能讲清"**频道为什么要和等级/过滤解耦**"、
> "**为什么离线消息我故意不做**"（成本 vs Demo 价值）。

## 四、任务与成就**共用一套条件系统**（避免造两遍）

这是 `Docs\19` §六 待办第 4 项，也是**最省事的一处复用**：

```
                    事件源（A3 EventCenter）
                            │  「击杀了一个怪」「到达了某区域」「用某技能命中 N 次」
                            ▼
        ┌───────────────────────────────────────────┐
        │  ConditionSystem                           │
        │   · 订阅事件 → 累加进度 → 判断是否达成      │
        │   · 进度可持久化（表：progress）           │
        └───────────────┬───────────────────────────┘
                        ▼  达成时通知"收集器"
        ┌───────────────────────┬───────────────────┐
        │  QuestRuntime         │  AchievementRuntime│
        │  （任务：交任务发奖励）│  （成就：解锁+展示）│
        └───────────────────────┴───────────────────┘
```

| 复用点 | 说明 |
| --- | --- |
| **条件描述** | 都用配置表描述（`ConfigKit` 加表）：`事件类型 + 目标 + 数量` |
| **进度累加** | 同一套"订阅 → 累加 → 判定"逻辑 |
| **持久化** | 同一张进度表（用 `kind` 区分任务/成就） |
| **不同的只有两头** | 来源（任务要"接取"才生效；成就**一直生效**）、触发后（发奖励 vs 解锁） |

> 📌 **设计要点**：条件系统**不认识**"任务"或"成就"这两个词 ——
> 它只认识"**事件 + 条件 + 进度 + 达成回调**"。
> 这和 M1 里 `ConfigPolicy`（项目知识不进 Core）是**同一种思路**：
> **把会变的东西隔离在两边，中间那层保持通用。**
