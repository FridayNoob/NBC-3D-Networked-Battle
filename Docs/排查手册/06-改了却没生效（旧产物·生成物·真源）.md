# 06 · 改了却没生效（旧产物 / 生成物 / 真源）

> 定位日期：2026-09-26（M3-S9 收尾）
> 现象一句话：**代码改了、提交了、也重启了，新加的那行日志就是不打印 —— 而且不报任何错。**

---

## ① 现象（负责人原话）

> 「重启服务端后，没有打印：`掉落：怪 6001 → 物品 9001×1~2@10000、9002×1~1@10000`。」

当时的处境很容易让人往错的方向查：

- 代码里**确实有**这段打印（`Server\NBC.Server.Host\Program.cs`，`foreach (int monsterId in tables.MonsterIdsWithDrops)`），而且**已经提交**（`95ddc05`）；
- `Configs\Design\DropTable.csv` 里 6001 的两行**确实**是 `10000/10000`；
- 「重启服务端」这个动作也**确实做了**；
- 但输出里连**一行红字都没有** —— 没有异常、没有警告、没有"跳过"。

> 📌 **"改了却没生效"这一类 bug 的第一特征就是：没有报错。** 所以它必须靠"证据"定位，不能靠读代码。

---

## ② 先确认是哪一层

拿第二节的分层排查图对照，这个现象**不是**③托管运行时、也不是④引擎运行时 —— **逻辑代码压根没被执行**。

正确的第一问**在分层图之前**：

> **第 0 问：我现在跑的 / 看的，是最新那一份吗？**

这一问能解释掉绝大多数"改了却没生效"。本项目到 2026-09-26 已经撞过**三次**，每次的"那一份"都不一样：

| 你改的地方 | 运行时**真正读/执行**的那一份 | 一眼看出来的判据 |
| --- | --- | --- |
| 服务端源码 `Server\**\*.cs` | `Server\NBC.Server.Host\bin\Debug\net8.0\NBC.Server.Host.dll`（**编译产物**） | 启动横幅的 `Built :`（本次新加） |
| Unity 侧配置资产 `DropTableConfig.asset` | 服务端读的是 `Configs\Design\DropTable.csv`（**真源**） | 启动逐条念「掉落：怪 … → …」 |
| `Configs\Design\*.csv` | Unity **运行**读的是**生成物**（`Config_*.cs` / `.tsv` / `.asset`） | 跑 ConfigKit → Unity 导入菜单 → 资产过期检查菜单 |

> ⚠️ 三行的共同点：**改的和读的不是同一个文件**，而**没有任何东西会提醒你**。

---

## ③ 定位步骤（照着做，每步都能得出"是/不是"）

### 第 1 步：比修改时间（最快的铁证）

```powershell
Get-ChildItem -Recurse -Filter "NBC.Server.Host.exe" Server | Select-Object FullName, LastWriteTime
Get-ChildItem Server\NBC.Server.Host\Program.cs, Configs\Design\DropTable.csv | Select-Object FullName, LastWriteTime
```

本次实测：

| 文件 | 时间 |
| --- | --- |
| `bin\Debug\net8.0\NBC.Server.Host.dll` | **2026-09-26 08:56:12** |
| `Server\NBC.Server.Host\Program.cs`（源码） | **2026-09-26 10:35:31** |
| `Configs\Design\DropTable.csv` | 2026-09-26 10:35:31 |

⇒ **产物比源码早了 1 小时 39 分** → 结论：**跑的是旧 exe**。到此已经可以收工，不需要再看任何代码。

### 第 2 步：直接跑一次产物，看它到底会打什么

```powershell
& "Server\NBC.Server.Host\bin\Debug\net8.0\NBC.Server.Host.exe" --port=7801 --ticks=1
```

`--ticks=1` 是特意留的"跑一帧就退出"，**不用起真服务端、不占端口、不改状态**，最适合做这种取证。

旧产物输出里**连 `[Check] 配置表：…` 这一行都没有** —— 说明那份构建比"打印配置表"这个改动还早。
（⇒ 反过来推：负责人看到的"其他日志都有"，不代表"这份是最新的"。）

### 第 3 步：重新编译，再跑一遍（阳性对照）

```powershell
dotnet build "Server\NBC.Server.Host\NBC.Server.Host.csproj" -m:1
```

结果（实测）：`0 个警告 0 个错误`，再跑 `--ticks=1` → 该有的三行都出来了：

```
  Built   : 2026-09-26 10:52:35
[Check] 配置表：副本 2、怪 3、英雄 3、技能 3、掉落 5（来自 …\Configs\Design）
        掉落：怪 6001 → 物品 9001×1~2@10000、物品 9002×1~1@10000
        掉落：怪 6002 → 物品 9001×1~3@7000
        掉落：怪 6003 → 物品 9003×1~1@10000、物品 9001×2~5@10000
```

**阳性对照成立**：同一份 CSV、同一份源码，只把产物换成新的，行为就从"没有"变成"有" ⇒ 变量锁定为**产物新旧**。

---

## ④ 根因（为什么会长这样）

**是我（AI）留下的坑，如实记：**

1. 前一天我改完 `Program.cs`（加掉落自述）时，负责人的服务端**正开着** → 编译到 `bin` 会撞 `MSB3027/MSB3021（文件被占用）`；
2. 为了不打扰他，我当时的验证只做了 **`-t:Compile`（只编译、不写输出目录）** —— 它**只证明"能编过"，不产生任何新产物**；
3. 于是 `bin` 里留着的还是几小时前的那份；
4. 负责人「重启服务端」时，重启的是**同一个旧 exe** —— 动作没错，**对象错了**。

> 📌 **一句话讲清根因：加了代码 ≠ 生效；编译器把输出写过去才算生效。**
> `-t:Compile` 是**语法体检**，永远不能当成"部署完成"。

---

## ⑤ 解决方案

给别人（或给未来的自己）的指令里，**"重启"两个字必须带上"先编译"**：

```powershell
# 1) 先关掉正在跑的服务端（否则 bin 被占用 → MSB3027）
# 2) 编译（把新代码写进 bin）
dotnet build Server\NBC.Server.Host\NBC.Server.Host.csproj -m:1
# 3) 再启动
Server\NBC.Server.Host\bin\Debug\net8.0\NBC.Server.Host.exe --port=7777
```

> 💡 `dotnet run --project ... --no-build` 里的 `--no-build` 同样是这个坑的表亲：**它明确表示"别编译，跑现成的"**。

---

## ⑥ 防复发（已经落成代码，不是"下次注意"）

1. **启动横幅打印构建时间** —— `Program.cs` 的 `BuildTime()` 读**程序集文件自己的时间戳**：

   ```
   Built   : 2026-09-26 10:52:35
   ```

   以后只要拿它和"我刚才改代码的时间"比一下：**产物早于源码 = 跑的是旧的**。一眼，不用查。
   （⚠️ 不用程序集里的 `Version`：项目里它一直是 `0.1.0.0`，**不会因为改了代码而变** —— 这也正是它当年没能拦住这个 bug 的原因。）

2. **启动时自述它真正读到的配置** —— 掉落逐条念出来（上一条 bug 已经加过，仍然保留）。
   它的价值在这次事件里再次体现：**旧产物连念都不念**，直接暴露"这份没这段代码"。

3. **顺手删掉一个走不到的分支**：我原本还想加"掉落表 0 行就警告"，做**阴性对照**时发现走不到 ——
   把 `DropTable.csv` 砍成只剩表头（4 行），加载器直接：

   ```
   [致命] 读配置表出错：DropTable.csv 少于 5 行（规范要求：表头 4 行 + 至少 1 行数据）
   ```

   退出码 `3`（**根本不启动**）⇒ "0 行"在启动前就被挡住了，兜底分支是**死代码**（看着像有保护）。
   已删，并把结论写成注释留在原地。事后校验：文件已还原，行数 = **9**（原样）。

## ⑦ 一句话讲清（面试版）

> 「改了却没生效」这类问题的特征是**全程没有任何报错**，所以不能读代码、只能拿证据：
> 我第一步是**比文件时间**（产物 08:56 vs 源码 10:35，早了 1 小时 39 分），一分钟锁定；
> 根因是我为了避开文件占用只做了 `-t:Compile`（只编译不写输出），`bin` 里仍是旧 exe，
> **加代码 ≠ 生效，编译器写过去才算**。
> 防复发我不写"下次注意"，而是**让产物自报身份**：启动横幅打出构建时间，
> 并让它把**真正读到的配置值**逐条念出来 —— 以后这类问题从"猜"变成"看一眼"。
